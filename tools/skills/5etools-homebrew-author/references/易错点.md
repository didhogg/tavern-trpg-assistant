# 易错点（只写已核实的；没核实的明说）

## 一、作者写法约定（出处：作者自制仓库 README *Conventions to Follow*）

- tab 缩进、LF、UTF-8 无 BOM；文件名 `作者名; 自制名.json`。
- `json` 来源名全库唯一，不显示，可以长；没网址就填 `https://github.com/TheGiddyLimit/homebrew`。
- `authors` 只写内容作者，转换者写 `convertedBy`（格式相同）。
- 图片、角色卡 PDF 之类资源不放进 JSON 仓库，作者另有图片仓库；本项目的规矩也是只存链接，不存图片文件。

## 二、校验器怎么报错（出处：`src/library/brew-validate.ts`、`scripts/validate.mjs`）

- 作者的条目结构是“完整条目”或“`_copy` 加改动”二选一，校验器会把“缺 `_copy`”“不符合任何一种写法”一起报出来，那是陪衬。`validate.mjs` 有真正的错误时会去掉它们；报错太多只给最深的一条。**先改这一条，再重跑。**
- 错误位置（`/spell/3/level` 这样的路径）加行列都给了，直接去那一行改。
- 常见几种：`required`（缺必填键）、`additionalProperties`（多出结构里没有的键 → 多半是字段名写错或自己编的）、`enum`（只能取给定值之一）、`type`（类型不对，例如该是数组写成了字符串）。

## 三、本机作者样例的已知问题

- 作者自己的 `boon/Sample - Giddy; Dubious Gifts.json` 在本机这版结构定义（5etools-utils 0.17.24）下**不通过**：条目里多了 `ability`，结构里没有。**别照抄它的 `ability`。**
- 本机作者自制仓库副本是没有版本记录的快照（见 `tavern-trpg-data-next/report/说明.md`），和 0.17.24 结构是否配套没有核实，所以“样例里有、校验器说不认”的字段，以校验器为准。

## 四、和 TRPG 助手对接

- 插件里条目用作者编号（`name` + `source`）指，所以包里**条目名和来源名定了就别中途改**；同一个包里同名同来源的条目会互相覆盖。（出处：仓库 `AGENTS.md` 常驻规则）
- 交给结算内核时，没有英文对照的自制条目会直接把中文条目交进去，并标“无英文对照”（出处：`docs/handoff/D2-P3_性能改进二_验收修复.md` §2⑤，第 46 行）。
- 同一批文档记录过：中文条目直接转换在小样本里出过错（例：职业标识为空，准备法术公式变成 `@classes..levels`，出处：`docs/handoff/D2-P3-2_a_接手进度.md` 第 85 行）。**自制的职业、子职、种族这类会进规则计算的条目，在内核里实际表现好不好，本 skill 没有实测过。** 交付时要告诉用户：请在插件里把它实际加到一个人物上试一次。
- 中文自制：中文仓库在带 `name` 的对象上加了 `ENG_name`（英文名），本项目校验器已允许它（出处：`tools/build-brew-validator.mjs`）。
- **插件认一个自制文件是中文，看顶层条目有没有字符串 `ENG_name`**，并用它做显示、配对、英文名搜索（出处：`src/library/custom-lang.ts` 第 35–42、163 行）。所以中文自制的每个顶层条目都要带 `ENG_name`；没有它，这个文件会被当成英文自制。嵌套对象（特性、动作）上的 `ENG_name`：校验器允许，项目里谁读它**没查过**。
- 中英自制包的配对按文件：同一目录 + `_meta.sources[].json` 有交集才配，且两个文件里同类数组的条目按**下标一一对应**（出处：`src/library/brew-pairing.ts` 开头注释）。只做中文包时用不上；以后要给同一个包配英文版，条目顺序要一致。

## 五、真实试跑记录与由此得到的教训

试跑是 1 次（1 个只带这份 skill、没有背景的 AI，一次要它做 6 类 7 个条目：种族、专长、法术、怪物、子职加 2 个子职特性、物品，中文加 `ENG_name`）。样本只有这 1 次，下面只是这一次看到的：

- **结构校验第一次就通过**（我另外独立重跑过一遍，同样通过）。仓库里没有被它写入别的东西。
- **“过校验”不等于“没编内容”**。同一份通过的文件里，它写了用户没给的东西：种族已经有结构化的 `darkvision: 60`，又凭印象多写了一条“黑暗视觉”文字特性；还自己加了法术 `miscTags`、物品 `wondrous`、嵌套特性的英文名、怪物伤害平均值。已写进 SKILL.md 红线 3。校验器管不到这类问题，要靠交付时的“哪些是我填的 / 哪些是建议值”清单让用户核对。
- **法术、怪物没有 wiki 页**，它靠结构定义里的 `util.json`、`util-time.json` 和怪物样例才写对（学派编码、持续时间 + 专注的写法）。这些已补进 SKILL.md。
- **子职写法没有验证**：它写了 `className: "Fighter"`、`classSource: "PHB"`（照 wiki 例子），`shortName` 用了中文，只列了两个不同等级的 `subclassFeature`，没写 `refSubclassFeature`。都过了校验，但**在 TRPG 助手里实际加到人物上好不好用没试过**，也没核对是否合作者习惯。
- 校验器默认只显示“最可能的原因”那一条，一次看不到全部问题 → `validate.mjs` 加了 `--all`。
- **没做的**：把生成的包导入 TRPG 助手、在作者的 5etools 页面里看渲染；这个 skill 到目前为止只证明过“结构合格”。
