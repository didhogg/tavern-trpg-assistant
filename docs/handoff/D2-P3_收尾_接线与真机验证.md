## 1. 接线（界面以后只从 `services.backend` 取）

```
 createServices()                         src/core/services.ts
   ├ db / rules / campaign / lock          （原有）
   └ backend                               src/core/backend.ts（组装根）
       ├ library  【库】服务、按战役取库、自定义库、下载任务、数据版本记号
       ├ kernel   结算内核：一个战役一个小窗，按需打开 / 复用 / 关闭     src/rules/kernel/runtime.ts
       │          记住每个人物的重建基准；rebuild（按引用重建）、compact（拆回引用/选择/状态）
       │          启动输入从 vendor/foundry/manifest.json 读（不写死系统和模块）  src/rules/kernel/input.ts
       └ kernelSave 内核存档：写入时按战役让结算内核拆人物（compactActors / mapRef 收 ownerKey）
```

| 改动 | 说明 |
|---|---|
| `KernelSaveService` 两个依赖改为收 `ownerKey` | 一个插件同时有多个战役，拆人物、对照编号都要知道是哪个战役；对照表在写入事务外取好 |
| 数据版本记号移进正式代码 `libraryDataVersion` | 原来只在测试里；按源登记表走，不写死中 / 英 |
| 世界编号 `worldIdOf(ownerKey)` | Foundry 只认字母数字短横线下划线；ownerKey 形如 `char:角色卡.png`，直接用会启动失败（本轮查出） |
| 诊断页两个真机入口都改为经服务入口 | `src/probes/services.ts`；用单独的用户数据库，不碰玩家真实战役；【库】用正式库 |

## 5. 发现的问题

1. **结算内核会直接上 GitHub 查自制包索引**（作者数据加载器碰到不认识的来源时查 homebrew / unearthed-arcana 的 `_generated/index-*.json`）。联网时会真的下载（绕过【库】）；断网时每次启动 12 条未处理的网络报错，结算结果不受影响。属 P3-2 结算内核与【库】的边界，未修，未加入可忽略名单。
2. 模拟酒馆测试服务没登记 `.mjs`，结算内核起不来（测试设施问题，已对齐【库】测试服务的类型表）。**真机上酒馆 / TauriTavern 发 `.mjs` 的类型对不对，是真机要确认的第一件事。**
3. 两个真机入口测试读结果时，元素不存在会一直等（B3 那份曾因此可能干等 15 分钟）；已改为先数再读、每步限时、进度实时打印。
