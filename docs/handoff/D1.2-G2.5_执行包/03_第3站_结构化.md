## 3d-1 效果数值是 0 的占位（13 个条目，`b2-zero-placeholder`）

- 用 T3 取清单（13 个）。已知：双持客 +1 护甲等级、灵活移动 +10 尺、低身机敏 +5 尺、动力步伐 +5 尺、快速移动 +10 尺、无甲移动（10→30 尺，随等级，用 `scale` 数值）、巨龙之翼（飞行速度等于步行速度，`equalsWalk`）、侦察兵卓越机动 +10 尺、蜥蜴人/穴蜥人天生护甲（护甲等级 base 公式）、矮人坚韧每级 +1 生命上限（`hpMax.perLevel`）、神枪手奥术火器 +1d8（伤害加值）、盗贼手套 +5 巧手。
- **怎么改**：逐条表（`set`），把 0 换成书上的数；保持效果 `kind` 不变。**来源**：PHB（种族、专长、职业）、XGE（神枪手/侦察兵…）、DMG（盗贼手套）。
- **验收**：样卡（`g2b-sample`）里的 `b1-ac`(2)、`b1-hp`(2)、`b1-speed`(2) 随之**自动消失**（不用单独改）。
- 放行：13 个条目，路径 `/data/effects/**`，`expect: 13`。
- 登记：`b2-zero-placeholder` 13 → 0；`b1-ac`、`b1-hp`、`b1-speed` → 0（**这三个是预期联动**，放进 allow）。
- `npx tsx tools/g2/registry-diff.ts --groups g2b-effects,g2b-sample --allow "b2-zero-placeholder=0,b1-ac=0,b1-hp=0,b1-speed=0"`

## 3d-9 纯文字特性 A 类：影响派生数值（144，`b3-A-derived-in-text`）

- **背景**：1,140 个纯文字机制特性经初筛，A 类（文字里写着会改变派生数值）144 个：熟练 64、抗性与免疫 47、速度 18、感官 7、先攻与被动 4、生命上限 4、属性值 3、护甲等级 2。逐条清单：`docs/probes/D1.2-G2_纯文字特性分诊.json`。**抽样 30 条里约 15% 是误报**（例：抑制元素其实是反应动作）。
- **怎么改**：**按类别分 8 个提交，每个提交 ≤ 20 条**（熟练 64 条分 4 个提交，抗性 47 条分 3 个提交）。每条：读特性文字（再对原书核对）→ 判定 ①确属 A 类：用 `insert` 加 `effects` 行（`proficiency` / `resistance|immunity|vulnerability` / `speed` / `sense` / `initiative|passive` / `hpMax` / `abilitySet|abilityBonus` / `ac`）；②误报：记入 `docs/probes/D1.2-G2.5_纯文字A类处置.json`（`{ id, verdict:'false-positive', reason }`），**不改数据**。
- **不允许**：猜测不明确的文字；一次写多条规则批量处理（这是逐条活）；新增效果 kind。拿不准的条目 → 记为 `verdict:'undecided'` 并在报告里列出请驾驶员定（00 第 11 节第 9 条），**不要自行判"不做"**。
- 放行：每个提交 `ids` 精确列本次改的条目，路径 `/data/effects/**`，`expect` ＝ 本次条数。
- 登记：`b3-A-derived-in-text`（144）每个提交按"已结构化＋已判误报"的数量减少；**最终必须为 0**（`undecided` 不算，需驾驶员定后才能清零，所以本项有可能留下少量待决定）。
- `npx tsx tools/g2/registry-diff.ts --groups g2b-triage --allow "b3-A-derived-in-text=<R>"`（`<R>` ＝ 144 − 到本提交为止累计「已结构化＋已判误报」的条数；每个提交报告里写出这个算式）
