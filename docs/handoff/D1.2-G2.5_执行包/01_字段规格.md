## A. 资源与休息（旧清单 2.5，驾驶员批准的方案 A）—— 第 4 站用

### A1. 次数池 `uses`（已有，不新增）
`uses: { max: 数字 | 公式, recharge: 恢复时机, per?: 文字 }`。恢复时机取值**已有**：`short`、`long`、`dawn`、`dusk`、`turn`、`round`、`special` 等（见 `enums.ts` 的 `RECHARGE`）。**`dawn`（黎明）单独记，不并入长休。**
魔法物品的"每天恢复多少"用**已有**字段 `charges.rechargeAmount`（字符串，如 `"1d6+1"`），不新增字段。

### A2. 消耗 `consumes`（特性级，新）
```json
"consumes": { "pool": "feature.bard-bardic-inspiration.phb", "amount": 1 }
```
- 含义：使用这个特性时，扣 `pool` 指向的那个特性（它自己带 `uses`）的次数池 `amount` 次。
- `pool`：**特性条目 id**（不是中文名）；必须能在构建时解析到一个**带 `uses`** 的特性，且依赖方向向下（该特性在本包或本包依赖的包里）。
- `amount`：正整数，默认 1。
- **一个特性有了 `consumes`，就不能再有自己的 `uses`**（否则重复计数）——这正是旧清单 `a18-consumes-other-pool` 要修的问题；构建期有校验。
- 与行动级 `consumption` 的关系：行动里**已有** `activities[].consumption.targets[{type, value, target}]`（41 个行动在用）。两处**同一含义**：`target`（行动级）与 `pool`（特性级）都写特性条目 id。**同一个特性里，同一个池只能由其中一处表达**，两处都有 = 重复计数 = 停手报告。

### A3. 恢复 `restores`（特性级，新）
```json
"restores": [
  { "pool": "feature.bard-bardic-inspiration.phb", "on": "short", "amount": "all" },
  { "on": "event", "event": "掷狂野魔法浪涌表", "amount": 1 },
  { "pool": "feature.warlock-the-fiend-fiendish-resilience.phb", "on": "initiative", "amount": 1, "condition": "投先攻时该池为 0" }
]
```
- `pool`：可省略，省略 = 本特性自己的 `uses`。写了就是特性条目 id；**保留字 `"spellSlots"` = 法术位**（奥术回想用，此时 `amount` 写公式，`limit` 写环阶限制文字）。
- `on`：`short`（短休）｜`long`（长休）｜`shortOrLong`｜`dawn`｜`initiative`（投先攻时）｜`event`（某个事件时，必须同时写 `event`）。
- `event`：纯文字，**只在 `on: "event"` 时有且必有**。
- `amount`：`"all"`｜正整数｜公式字符串（公式引擎语法，如 `"floor(level/2)"`）。
- `condition`：可选，纯文字，**只给人看**（不参与自动结算）。
- `limit`：可选，纯文字，说明数量限制（如"环阶合计不超过法师等级的一半"），**只给人看**。
- 用途：休息/先攻时【活动】系统逐个读取 `restores`，对 `pool` 恢复。

### A4. 状态 `tracker`（特性级，新）
不是"次数"、但要在休息时重置的状态。
```json
"tracker": { "kind": "escalate", "start": 10, "step": 5, "reset": "shortOrLong" }
"tracker": { "kind": "perTarget", "reset": "long" }
"tracker": { "kind": "choice", "reset": "shortOrLong" }
"tracker": { "kind": "cooldown", "cooldown": { "unit": "day", "amount": 7 } }
"tracker": { "kind": "cooldown", "cooldown": { "unit": "longRest", "amount": "1d4" } }
```
- `kind`：
  - `escalate`：递增数值（坚韧狂暴 DC 从 10 起每次 +5）。必有 `start`、`step`、`reset`。
  - `perTarget`：按目标记（对同一生物用过，到 `reset` 前不能再对它用）。必有 `reset`。
  - `choice`：每到 `reset` 要重新选择/重新获得（活动页休息时提示）。必有 `reset`。
  - `cooldown`：冷却。必有 `cooldown: { unit: "day" | "longRest", amount: 正整数 | 骰式字符串 }`；**无 `reset`**。
- `reset`：`short`｜`long`｜`shortOrLong`。
- 一个特性最多一个 `tracker`。

### A5. 通用规则（**不进条目**）
生命值、生命骰（长休恢复一半）、法术位（长休全恢复）是规则引擎的通用规则。魔契师契约法术位短休恢复已在其施法数据里。**不要**给它们写 `restores`。

## B. 状态与效果 —— 第 4 站用

### B1. 针对该生物的优势/劣势 `against`（优势/劣势效果上，新）
在**已有**的 `advantage` / `disadvantage` 效果上加可选布尔 `against`：
```json
{ "kind": "advantage", "on": "attack", "against": true, "scope": "近战攻击" }
```
- 无 `against`（或 false）= "它自己做某事时"的优势/劣势（现有含义，不变）。
- `against: true` = "**别人对它**做某事时"的优势/劣势。当前只允许 `on: "attack"`。
- 可选 `autoCrit`：`{ "within": 5 }`——攻击者与它距离在 `within` 尺以内且命中时自动重击（麻痹、昏迷用）。**只允许与 `against: true` 同用。**

### B2. 暴击范围 `critRange`、暴击额外骰 `critDice`（两个新的效果 kind）
```json
{ "kind": "critRange", "min": 19, "scope": "weapon" }
{ "kind": "critDice", "count": 1, "scope": "melee" }
```
- `critRange`：暴击从 d20 掷出 `min` 起（冠军战士 19；超越者 18 为 `min: 18`）。`min` 为 2–20 的整数；`scope` ∈ `melee`｜`ranged`｜`spell`｜`weapon`｜`all`。
- `critDice`：重击时额外掷 `count` 个武器伤害骰（野蛮人凶蛮重击 1/2/3）。`count` 正整数；`scope` 同上。
- 其它字段沿用效果的公共字段（`condition`、`when`、`duration`、`transfer`）。

### B3. 效果触发条件 `when`（已有字段，补用法）
效果已有 `when: requiresSchema`。第 3 站 `b2-when-text` 用它表达"狂暴中""未穿护甲""未穿护甲且未持盾"：
```json
"when": { "all": [ { "status": "rage" } ] }
"when": { "all": [ { "armor": "none" } ] }
"when": { "all": [ { "armor": "none" }, { "shield": "none" } ] }
```
**取值（`status`/`armor`/`shield`）的合法集合由第 0 站在 `requires.ts` 里定死并写进冻结记录；执行 agent 只用冻结记录列出的那几个。**

### B4. 效果上的 `spellGrant.level`（新）
天生法术"到几级才获得"：在**已有** `spellGrant` 效果上加可选整数 `level`（获得该法术的角色等级，1–20）。每个**需要各自次数/各自解锁等级**的法术写成**单独一个 `spellGrant` 效果**，各带自己的 `uses` 与 `level`：
```json
{ "kind": "spellGrant", "spells": ["spell.thaumaturgy.phb"], "mode": "innate", "ability": "cha" }
{ "kind": "spellGrant", "spells": ["spell.hellish-rebuke.phb"], "mode": "innate", "ability": "cha", "level": 3, "uses": { "max": 1, "recharge": "long" } }
```
（例子只演示形状。）

### B5. 亚种 `abilityBonus.replace`（新）
亚种的 `abilityBonus` 效果上加可选布尔 `replace`：`true` = **不再加种族本身的属性加值，以此为准**（变体人类）。无此字段 = 与种族加值叠加（现有含义）。只出现在**亚种**条目上。

## C. 法术 —— 第 1、3、4 站用

### C1. 升环 `upcast`（法术，新）【**驾驶员须先看形状**】
```json
"upcast": [
  { "kind": "damage", "dice": "1d6", "type": "fire", "step": 1 },
  { "kind": "heal", "dice": "1d8", "step": 1 },
  { "kind": "targets", "add": 1, "step": 1 },
  { "kind": "area", "add": 5, "unit": "ft", "step": 1 },
  { "kind": "duration", "table": [ { "slot": 5, "value": "8 小时" }, { "slot": 7, "value": "24 小时" } ] },
  { "kind": "note", "text": "…只留文字，不自动计算", "auto": false }
]
```
- 含义：用比法术本身环阶更高的法术位施展时，**每高 `step` 环**追加一次（`damage`/`heal` 追加 `dice`；`targets` 追加 `add` 个目标；`area` 追加 `add` 单位的范围）。`step` 默认 1。`duration` 用表：从 `slot` 环起持续时间变为 `value`。
- `note`（`auto: false`）：确实无法结构化的（旧清单说"其他"类），**只留文字**，读取器显示"需手动处理"。**执行 agent 不得新增 kind。**
- 一个法术的 `upcast` 是数组，可以同时有多项（例如既加伤害又加目标）。
- 原来的 `higherLevel` 文字**保留不动**。
- 来源：5etools 的 `{@scaledamage 基础|环级范围|每环增量}` 标签（第 1 站已导入 74 个）；其余 80 个第 3 站按类别结构化。

### C2. 材料成分 `components.m.cost` / `consumed`（已有字段，补数据；`consumed` 放宽类型）
- `cost`：铜币数（已有）。
- `consumed`：原为布尔；**放宽为 `true` | `false` | `"optional"`**（"可选消耗"）。第 1 站已导入。

### C3. 戏法成长 `cantripScaling`（已有）
魔能爆的射线数成长写法沿用 `scaleDiceSchema`：`{ label?, scaling: { "1": "1", "5": "2", "11": "3", "17": "4" } }`（键为角色等级、值为射线数；骰式成长的戏法已是这个形状）。

### C4. 把法术加进某职业的法术表 `joins[].as: "spell"`（新写法）
```json
// 写在扩展书（如塔莎）里的一个"锚点"特性条目 feature.ranger-additional-spells.tce 上：
"joins": [ { "to": "class.ranger.phb", "level": 0, "as": "spell", "spells": ["spell.aid.phb", "spell.hunters-mark.phb"] } ]
```
- **谁来登记**：被加入的职业（PHB）和法术（PHB）都不写任何东西；由**扩展书里的锚点条目**登记（每个涉及的职业一个锚点，约 5–6 个）。锚点是特性类型的条目（名字"可选扩展法术列表（职业）"）。
- `to`：职业条目 id；`level`：**固定写 0**（占位，法术环阶看法术本身——此约定以冻结记录为准）；`spells`：法术条目 id 数组（≥1）。
- 读取器：某职业的法术表 ＝ 法术自己 `classes` 里写了该职业的 ＋ 已安装的包里所有 `joins` 指向它、`as: "spell"` 的 `spells`。没装塔莎就没有这些。
- **依赖方向铁律**：锚点在扩展书里，指向下层书（PHB）的职业和法术；不得让 PHB 包依赖 TCE 包。5etools `classVariant` 里 `definedInSources` 的书如果没被收录（如 FTD），**跳过，不写锚点**。
- 构建期 `validateJoins` 与引用检查会校验：目标存在且在依赖里；`spells` 里每个 id 存在且是法术、在依赖里。第 0 站同步 `docs/包格式说明.md` §3.1、`joins.ts`、`refs.ts`。

## D. 物品与装备 —— 第 2、3 站用

### D1. 价格 `item.value`：允许**一位小数**（改已有字段的精度）
- 单位铜币（cp）。取值 ≥ 0，**最多一位小数**（0.2、0.1、2.5 合法；0.25 不合法，构建失败）。
- 转换代码 `tools/data/convert/item.ts` 第 172 行的 `Math.round` 在第 2 站按 02 去掉。**不要**把其它价格也改成小数——只有原始价格本来就带小数的才会变化（11 件）。

### D2. 起始装备项的 `id`（新，可选）
**已有**起始装备项是 `{ item: "羽毛笔", qty: 1 }`（`item` 是中文显示名）。新增可选 `id`：
```json
{ "item": "羽毛笔", "id": "item.ink-pen.phb", "qty": 1 }
```
- `id`：物品条目 id；能对上物品库的都写，**对不上的（书上本来就是描述性文字的物品）不写**——约定"没有 `id` = 自由文字物品"。`item` 显示名**保留书上的描述名**，不改。
- 依赖方向向下（SCAG/BMT 背景可指 PHB/SRD 物品；不得指向更高层的包）。

### D3. 起始装备的类别项 `{ category, qty }`（已有形状，新增**记号**）
类别项形状**已有**：`{ category: "weapon:simple", label?: "任意简易武器", qty?: 1 }`。第 0 站把下面这些记号定义好并让读取器 `expandToken` 能展开，执行 agent 只用这些，**不许自造**：

| 记号 | 含义 | 状态 |
|---|---|---|
| `weapon:simple` / `weapon:martial` / `weapon:firearms` | 任意简易/军用武器；火器 | 已有 |
| `weapon:simple-melee` / `weapon:martial-melee` | 任意简易**近战**武器 / 任意军用**近战**武器 | **新（第 0 站）** |
| `focus:arcane` / `focus:druidic` / `focus:holy` | 奥术法器 / 德鲁伊法器 / 圣徽 | **新（第 0 站）** |
| `tool:anyMusicalInstrument` / `tool:anyArtisansTool` / `tool:anyGamingSet` | 任意乐器/工匠工具/游戏用品 | 已有 |

### D4. 职业的工具熟练选择 `proficiencies.toolChoose`（新，可选）
职业现有的 `proficiencies.tools` 是**字符串数组**（里面混着固定工具的链接和"自选三种乐器"这样的纯文字）。**为了只增不改，不改 `tools`**，在它旁边新增一个可选字段：
```json
"proficiencies": { "tools": [ "自选三种{{ref:…|乐器}}" ], "toolChoose": { "count": 3, "from": ["tool:anyMusicalInstrument"] } }
```
- `count`：正整数；`from`：任选记号数组（`tool:anyMusicalInstrument`、`tool:anyArtisansTool`、`tool:anyGamingSet`）。`from` 有多个记号 = "这几类里任选"。
- 用在：吟游诗人（3，乐器）、武僧（1，工匠工具或乐器）、奇械师（1，工匠工具）的 `proficiencies`；吟游诗人的 `multiclass.proficiencies`（1，乐器）。
- 原来的 `tools` 文字**保留不动**（与背景的 `proficiencies.tools {choose, fixed}` 结构不同，别照背景的写法改 `tools`）。
- 旧清单 2.2 写的是"用背景已有的结构"，**以本节为准**。

## E. 种族、背景、专长、语言 —— 第 2、3 站用

### E1. 背景 `characteristicsFrom`（新，可选）
```json
"characteristicsFrom": "background.soldier.phb"
```
- 含义：这个背景的人物特征（特点/理念/牵挂/缺陷）**借用**另一个背景的特征表。值是**背景条目 id**，依赖方向向下。
- 若本背景已有自己的 `characteristics`，则两者**并存**（继承人另借平民英雄的表：自己的 1 张表保留，再加 `characteristicsFrom`）。

### E2. 专长/前置 `requires` 的种族前置
**已有**写法：`"requires": { "any": [ { "race": [ "race.elf.phb", … ] } ] }`。第 3 站 `a14-requires-text` 用它替换纯文字前置（2 个条目）。具体种族 id 以 XGE 专长小节为准。

### E3. 专长选法术池记号（新）【第 4 站】
在专长的 `advancement[].choices[]` 里，沿用"任选"记号体系，新增法术池记号：
```
spell:class=<职业短名|any|@选择id>,level=<环阶>[,school=<学派英文|学派英文>][,ritual=true][,attack=true]
```
- `class=` 取职业 id 的第二段（`class.wizard.phb` → `wizard`）；`any` = 任意职业；`@<选择id>` = 引用本专长里**前面某个选择**的结果（例如魔法学徒先选职业，后面的法术必须来自那个职业）。
- `level=` 为 0–9 整数；`school=` 可用 `|` 分隔多个学派；`ritual=true` 只要仪式法术；`attack=true` 只要需要攻击检定的法术。
- 例（魔法学徒的形状，只演示写法）：
```json
"choices": [
  { "id": "mi-class", "count": 1, "pool": ["class:bard","class:cleric","class:druid","class:sorcerer","class:warlock","class:wizard"] },
  { "count": 2, "pool": ["spell:class=@mi-class,level=0"] },
  { "count": 1, "pool": ["spell:class=@mi-class,level=1"] }
]
```
- **第 0 站在 `expandToken` 里实现并在冻结记录里列出支持的全部键，执行 agent 只用这些键。**

### E4. 语言与载具记号
- **`lang:other` 被禁止**：构建与读取器遇到 `lang:other` 一律**报错**（第 0 站实现）。啵灵蛙/穴蜥人/吉斯人换成 `lang:bullywug`、`lang:troglodyte`、`lang:gith`。
- 原初语方言：`lang:aquan`、`lang:auran`、`lang:ignan`、`lang:terran` 仍是合法代码，**读取器解析到原初语条目**（原初语条目的 `dialects` 写成 `[{ code, name }]`，第 3 站 `a17-no-entry` 做）。
- 载具熟练：`code:vehicles-land`、`code:vehicles-water`（两个固定代码，写进 `docs/模块数据约定.md`，不建条目）。**旧记号 `tool:vehicles (land)` 等在第 3 站改成这两个。**

## F. 怪物与世界 —— 第 3、4 站用

### F1. 带条件的抗性/免疫/易伤（怪物，新）
```json
"resist": ["cold", "fire"],
"resistConditional": [ { "damage": ["bludgeoning", "piercing", "slashing"], "except": "magical", "when": "来自非魔法攻击" } ],
"immuneConditional": [ { "damage": ["bludgeoning", "piercing", "slashing"], "except": "silvered", "when": "来自非银质武器" } ]
```
- `resist` / `immune` / `vulnerable` 里**只留纯伤害代码**；带条件的整条移到对应的 `*Conditional`（`resistConditional` / `immuneConditional` / `vulnerableConditional`）。
- 每项：`damage`（伤害代码数组，必填）｜`except`（`magical`｜`silvered`｜`adamantine`｜`magicalOrSilvered`｜`other`，可选）｜`when`（**书上原始条件文字**，必填，用于显示与兜底）。
- `except: "other"` 表示条件不在固定集合里（如"仅限某元素位面"），自动结算时按文字提示玩家。
- 原条目的"一整串文字"形式在迁移后**不再保留**（避免两处并存）；此项进 `g2-additive` 放行。

### F2. 充能动作 `rechargeRoll`（怪物动作，新）
