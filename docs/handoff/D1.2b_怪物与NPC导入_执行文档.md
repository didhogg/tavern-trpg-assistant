## 0. 一页纸

**做什么**：把 5etools 里核心十本书**以外**、2014 规则范围内的全部**怪物**（`bestiary`）程序化导入；从冒险正文里程序化提取「使用某某数据」的**具名 NPC**，生成 NPC 模板；给**全部怪物**（含核心十本书已有的 1,191 个）补上默认头像与 token 的**图片地址**和**头像裁切焦点**。

**为什么**：人物模块要能「点模板一键填入」——官方怪物、冒险特有怪物、具名 NPC 放在同一个模板池里按类别挑，并自带默认头像。

**不做什么**：
- 怪物以外的任何类别（物品、法术、种族、专长、背景、随机表、神祇、食谱、角色创建选项……）**这次都不导**；
- 书和冒险的**章节正文不导**（只**读**冒险正文来提取具名 NPC）；
- **据点（bastions）不导**；
- 冒险的结构（地点、任务、遭遇、区块、规则覆盖、系列与续作）不导，归以后的【模组管理与制作】；
- **不下载、不内置任何图片**进包或仓库；生物类型图标等界面工作不做（人物模块做）。

**怎么做**：一份文档、一条管线、内部分 7 批按顺序做完，**批与批之间不停、不等规划者**；最后统一验证一次、写一份报告。

**交付物**：
- 新的书籍包与冒险包（只含怪物与 NPC 模板）；
- 11 个核心包补上头像字段，所有包升到 **1.5.0**；
- 焦点数据文件 `tools/data/art/focus.json`；
- 报告 `docs/probes/D1.2b_报告.md`；
- 头像抽查页（给驾驶员看）；
- `NEXT.md` 更新、本地提交。**不推送**。

## 5. 字段规格（本文件冻结；执行中不得改形状，要改先停）

### 5.1 `monster.data.art`（所有怪物，含核心 1,191 个）

```ts
data.art?: {
  portrait?: {
    url: string | { $asset: string }  // 本次一律写第一张立绘的完整网络地址；{ $asset } 留给玩家在我的库 / 自制包里换成本地上传的图
    focus: { x: number; y: number; size: number }
    // 头像裁切：正方形，中心 (x, y)、边长 size，都按原图比例（0–1）：
    // x 相对宽度，y 相对高度，size 相对 min(宽, 高)；保证裁切框不出图（构建校验）
    method: 'token-match' | 'smartcrop'
    score?: number              // 仅 token-match：匹配得分 0–1，保留 3 位小数
  }
  token?: { url: string | { $asset: string } }  // 本次写 token 的完整网络地址；原样保存，不裁
}
```

- 有立绘写 `portrait`；有 token 写 `token`；两者都没有就**整个 `art` 不写**（不写空对象）。
- 立绘下载失败或焦点算不出：**不写 `portrait`**（不猜焦点），报告列出。
- `art` 不进 `i18n`、不进 `summary`、不进全文搜索。
- `fieldCoverage` 要改：`monster.hasToken`、`monster.token`（共用 token 的指向）、`monster.tokenCredit`、怪物 fluff 的 `images` 从 dropped 改为 mapped → `data.art.*`。`tools/data/config/fieldCoverage/image.ts` 的全局 `IMAGE_PATH` 规则**只为 monster 开例外**，其他类别照旧丢弃。

### 5.2 变体

data.variantDiff?: string[]    // 有差别的机制字段名，按字母序，如 ['ac', 'actions', 'hp']

## 6. 去重（D3、D4）

### 6.1 比谁

- **处理顺序**：三档书按出版日期升序 → 冒险按出版日期升序。
- **比较对象**：核心 11 个包 ＋ 本次已经处理过的来源。
- **找候选**：用英文名（`ENG_name`，没有就用 `name`）忽略大小写匹配。同名有多条时，优先 5etools 自己写明的关系（`_copy` 指向的那条、`reprintedAs` / `otherSources` 指向的那条），其次挑机制差别最少的那条。

### 6.2 比什么（机制字段）

`size, creatureType, alignment, ac, hp, speed, str/dex/con/int/wis/cha（abilities）, saves, skills, resist, immune, vulnerable, conditionImmune（含各自 *Conditional）, senses, passive, languages, cr, traits, actions, bonusActions, reactions, legendary, legendaryActions 次数, mythic, lair/regional（legendaryGroup 引用）, spellcasting`

- 动作类（traits / actions / bonusActions / reactions / legendary / mythic）比的是：名字、顺序、每条的结构化 `activities`（命中、伤害、豁免 DC、充能、次数）。
- 施法比：施法属性、DC、命中、法术 id 列表与次数。

不比：`src`、页码、`credit`、`i18n`、`summary`、`lore`、`art`、环境标签、`variantOf`。

### 6.3 文字归一

比较文字前统一：
- 全角 / 半角标点与括号；
- 连续空白与换行；
- 中英之间的空格；
- 行内标记 `{{…}}` 里的显示文字。

只比归一后的结果。

### 6.4 四类结果

| 类 | 条件 | 处理 | 报告 |
|---|---|---|---|
| A 相同 | 机制字段全等，文字归一后也全等 | **跳过** | 计数 + 「同 `<id>`」清单 |
| B 只差文字 | 机制字段全等，只有文字不同（多为译法） | **跳过** | 每条列出第一处文字差别（前后各 40 字） |
| C 变体 | 任一机制字段不同 | **保留**，写 `variantOf` 与 `variantDiff` | 每条一行：id、基于谁、差了哪些字段、前→后的值（数值字段写全，动作写名字） |
| D 新 | 找不到同名 | **保留** | 计数 |

再从 C 里挑出 **「同名异物」**：`creatureType` 或 `size` 不同，或 `cr` 相差 ≥ 3。单独列一栏，并改按 D 处理（不写 `variantOf`）。

### 6.5 一律不改已有条目

去重只决定新条目要不要进包，**绝不修改、删除、合并核心 11 个包或已处理来源里的条目**（`art` 与 `supersededBy` 例外，§8、§9 批 5）。

### 6.6 核对（驾驶员要求「有差别要注意核对」）

- **自动**：C 类每条的 `variantDiff` 必须非空；A、B 类每条都要能指出「同哪条」。测试断言这两点，不断言条数。
- **人工抽检**（写进报告的抽检表，每行：条目 / 字段 / 新值 / 已有值 / 原书或 5etools 原文 / 结论）：
  - C 类里差在 `cr`、`hp`、`ac`、`actions` 的**全部**；超过 60 条时按来源均匀抽 60 条，其余列清单；
  - B 类抽 20 条：确认真的只是译法；
  - 「同名异物」**全部**。
- 抽检发现「其实是数据源抄错，不是冒险真改」的：**不改数据**，在报告「来源本身的问题」列出，由驾驶员决定。

**用英文正文判定**（`data-bak/adventure/adventure-*.json`），中文正文只用来取名字和简介：英文句式规整，中文译法不一。

### 7.2 两档规则（确定性，不许用模型猜）

**H 高置信**：一个带 `name` 的正文块，`name` 是专有名词，即同时满足：
- 每个词首字母大写；
- 不是章节或地点通用词，排除表写在代码里并进报告：Area、Room、Chapter、Part、Level、Appendix、Encounter、Treasure、Development、Roleplaying……；

而且这一块的前两段里有：

- `(use|uses|using) the {@creature X} stat(istic)?s?( block)?`
- `has the statistics of (a|an) {@creature X}`
- `is (a|an) {@creature X}`（只在块首句）

NPC 名字 = 块的 `name`，属性块 = X。

**M 中置信**：任意段落里「专有名词短语 + 逗号或括号 + 上面的句式」，同一句里只有一个 `{@creature}`。NPC 名字 = 句首专有名词短语。

两档都不满足的，不提取。

### 7.3 排除与合并

- **排除**：
  - NPC 名字本来就是某个怪物条目（任何包里同名的 `monster`，比如冒险 bestiary 里已有完整属性块的具名角色）；
  - X 解析不到 `monster` 条目；
  - X 是 `{@creature}` 以外的标记。
- **合并**：同一冒险里同一名字出现多次，只出一条模板。属性块取 H 档那次，都不是 H 就取第一次。另外两条出处写进报告。
- 不同冒险的同名 NPC **各自保留**（冒险不同，身份可能不同）。

### 7.4 中文名与简介

- 中英正文按同一 JSON 路径对齐（R13 的对齐方式）。中文名取对齐位置块的 `name`，或句首相同位置的中文专有名词；简介取对齐的那一段中文。
- **对不齐就用英文名**，`name = nameEn`，并在 `credit.missing` 写 `zh`。**不许自己翻译**。

### 7.5 核对

- 报告列出 H、M 两档的数量（按冒险）。
- **M 档全部**进抽检表，H 档每个冒险抽 2 条。每行：名字 / 属性块 / 出处原句（英文）/ 中文名 / 对不对。
- M 档抽检错误率 > 20%：**整档不输出**，只出 H 档，报告写明。这一条只影响 NPC 这一项，不停整站。

## 8. 头像与 token（D6–D9）

### 8.1 地址：从网站源码推，不猜

1. 在 5etools-cn 的网站源码（`reference/5etools-cn-main（数据库）/js/`）里找到：
   - 媒体根地址的拼法；
   - token 地址的拼法（含共用 token：`token: { name, source }`）；
   - fluff 立绘 `href`（`internal` 的 `path`，`external` 的 `url`）转完整地址的拼法。

   把规则写进 `tools/data/art/urls.ts`，每个函数注释写源码文件与行号。
2. **探针**（第 0 批）：
   - 抽 30 个怪物（核心 10、三档书 10、冒险 10；有立绘的、有 token 的、共用 token 的都要有），请求真实地址；
   - 记录 HTTP 状态与 `content-type`，进报告；
   - 必须 30/30 是图片，才往下做头像。
3. 中文站地址打不开，就试英文原站的同名路径，两者都按源码规则推，不手写域名。两者都不行：**头像这一项停**，`art` 一律不写，其余照做，报告写明（§11）。

### 8.2 焦点：离线工具算一次，构建只读结果

- **工具**：`tools/data/art/focus.ts`（新建）。命令：

  ```bash
  npm run art:focus
  ```

  它是唯一联网的步骤，**不在 `build:data` 里联网**。
- 下载：
  - 并发 ≤ 4，失败重试 3 次（间隔 2s、4s、8s）；
  - 图片缓存在 `tools/data/out/art-cache/`，这个目录 gitignore，**不提交任何图片**。
- 输出 `tools/data/art/focus.json`（提交入库），按立绘地址做键：

  ```json
  { "<portrait url>": { "sha256": "<图片字节哈希>", "w": 1024, "h": 1280,
      "x": 0.512, "y": 0.287, "size": 0.46, "method": "token-match", "score": 0.873,
      "token": "<用来匹配的 token url>" } }
  ```

  下载或计算失败的写 `{ "error": "<原因>" }`。数字保留 3 位小数；键按字典序排；JSON 稳定输出。
- `build:data` 只读 `focus.json`：
  - 有焦点 → 写 `portrait`；
  - `error` 或缺键 → 不写 `portrait`，并计入报告「无焦点」。

  所以两次构建结果相同，哈希可以比。

### 8.3 焦点怎么算（D8：先匹配 token，再画面重心）

工具：
- `sharp`：解码、缩放、灰度；
- `@techstark/opencv-js`：WebAssembly 版 OpenCV，用 `matchTemplate`；
- `smartcrop-sharp`：画面重心裁切。

三者都是开发依赖，写进 `THIRD_PARTY_NOTICES.md`（Apache-2.0 / Apache-2.0 / MIT，以安装时 LICENSE 为准）。

**有 token 时：token 匹配**

1. 立绘缩到长边 768，token 缩到 256，都转灰度。
2. **只用 token 圆框里面的部分当模板**：以 token 中心为圆心、半径 = 0.80 × token 半径的圆作为掩码。这样圆框和框外伸出的部分（例如龙头伸出框外）都不参与匹配。
3. 多尺度：模板在立绘里的直径从立绘短边的 15% 到 100%，按 1.08 倍递增；每个尺度再试**水平翻转**一次（token 可能是镜像）。
4. 用带掩码的归一化相关匹配，取全局最高分。
5. 得分 ≥ 阈值 → `method: 'token-match'`。焦点 = 匹配位置的圆心；`size` = 匹配到的圆直径 ÷ 0.80，也就是还原成整个 token 的范围。裁切框出图时向内平移，再出图就缩小到正好贴边。
6. **阈值不拍脑袋**，按下面的方法定，结果写进报告：
   1. 先在 40 个有 token 的怪物上跑，得分分布写进报告；
   2. 在抽查页上人工看这 40 个；
   3. 取「看起来全对」的最低分与「看起来错」的最高分之间的值；
   4. 两者重叠时取 0.80，并在报告写明重叠情况。

**没有 token 或匹配不上时：画面重心**

- `smartcrop-sharp` 求 1:1 裁切，让它在整图里找最「有内容」的正方形，`minScale: 0.5`；
- `method: 'smartcrop'`，不写 `score`。

**只有 token、没有立绘**：不算焦点，只写 `token`（D6）。

### 8.4 抽查页（给驾驶员看）

`npm run art:focus -- --sheet` 生成 `tools/data/out/art-sheet.html`（不入库），里面 120 个怪物：
- token-match 60 个（高分、刚过阈值、低于阈值各 20）；
- smartcrop 40 个；
- 只有 token 的 20 个。

每格并排显示：原立绘（画出裁切框）、裁出的圆形头像、token。

驾驶员看这一页做真机前的验收，报告里写明路径与生成命令。

## 11. 停止条件

**停整站**（立即停手，写报告，等规划者）只有这四种：

1. 两次构建哈希不同；
2. 要改 §5 冻结的字段形状、或 §5.3 列出以外的 `src/` 才能继续；
3. 去重或任何步骤会**修改、删除**核心 11 个包里已有条目的非 `art`、非 `supersededBy` 字段（批 1 的 0 差异核对不过，也算这一条）；
4. `g2-oldext`（旧扩展装核心包）失败。

**只停当前这一项**：写理由与证据，接着做下一项，不留「以后再做」。包括：
- 某来源缺英文文件；
- 某来源包超体积；
- 地址探针不全过（头像整项不做）；
- NPC M 档错误率超 20%（只出 H 档）；
- 某条怪物转换报错（这条不导，列清单）；
- 体检指标因新来源未翻译而不过：这一项不放宽体检，改为该来源不出包，列清单；
- 文档和数据对不上、拿不准；
- 一项修 3 次不过。

**清单外的发现**：只记 `NEXT.md`「待议」，不做。

## 16. 规划者补充（2026-11-01，执行 agent 批 2 停手后）

1. **传奇组（巢穴动作、区域效应）只能从「同层或更低层」的来源取。** `tools/data/convert/monster.ts` 第 165 行在找不到「名字＋来源」完全一致的组时，会退回只按名字找。D1.2b 把三档书加进来源后，核心怪物（MM 的 4 种妖精龙）按名字匹配到了三档书里的同名组，英文对照多出巢穴动作与区域效应。这违反「核心包只能依赖更低层」，也让中英不一致。
   - 修法：新建 `tools/data/convert/legendaryGroupPick.ts`，导出 `pickLegendaryGroup(raw, groupRef, groups)`：先按 `BOOK_BY_SOURCE` 的层级过滤，只留组来源层级 ≤ 怪物来源层级的；再按原来的顺序找（先名字＋来源，再只按名字）。
   - `monster.ts` **只许改两行**：顶部加一行 import；第 165 行原地改为调用它。
   - 修完后核心 11 个包必须回到「只多 art 与版本号」，即 g2-additive 0 处未放行。
