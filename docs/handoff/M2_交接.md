## 2. 目标

把 SRD 与十本官方书（PHB、DMG、MM、XGE、TCE、SCAG、VGM、MTF、MPMM、BMT）转换成 formatVersion 2 的扩展包；证明每一种要管理的数据都能「导入 → 读取 → 使用 → 导出 → 再导入」，且结果一致；同时把安装器和数据库升级到能装下这些包。

### A. 数据定义（`src/`，运行时与构建共用）

### B. 安装器与存储（L1 里程碑表 M2 行，不做界面）

1. **识别**：formatVersion 2 的识别与限制，逐条实现 L1 §2.2 的「识别与限制」表，包括禁止 `.js` `.mjs` `.html` `.htm` `.svg` 和未知顶层目录。
2. **格式 1 兼容**：
   - `kind: data` 读作 `category: rules`，`kind: module` 读作 `category: adventure`；
   - `dependsOn` 读作 `relationships.requires`；
   - `assets/` 转入图片仓库。
3. **`PackManifest` 新字段**：`lineage`、`author`、`category`、`contributes`、`relationships`、`series`、`blobs`、`dataVersion`；`source` 枚举加 `user`（只加枚举）。
4. **安装预案**（L1 §3.5 新增的几种情况）：
   - lineage 不同时拒绝；
   - 同版本内容不同时标注出来；
   - `requires` 缺失时阻止；
   - `recommends` 缺失、`conflicts`、本版本不支持的功能，作为结构化结果返回。

   这几项都没有界面。
5. **Dexie 第 2 版**（L1 §2.6）：
   - 新增 `blobs` 表，`packs.blobHashes`；
   - 原 `assets` 按哈希迁入 `blobs`；
   - 建 `packTrash` 表（本次只建表）；
   - 迁移失败时保持第 1 版数据不变。
6. **安装不再改写当前数据**：删除现有安装器中修改各个当前数据 `enabledPacks.version` 的代码（`src/core/packs/installer.ts`）。
7. **内置包与推荐包**（L1 §3.3，数据层）：
   - `corePackIds` 与 `builtinPacks` 都改为 `['dnd5e2014-srd']`；
   - 新增 `meta` 键：`builtinRemoved`、`autoInstall`、`userRemoved`；
   - 推荐包自动安装函数：读取目录中的 `recommended`；跳过 `userRemoved`；有失败时保留未完成状态；不会把 `builtinRemoved` 里的包自动装回。
8. **自动存档原因**：`autoReason` 枚举加「改动模组前」。
9. **存档文件带图片**：`.trpgsave` 导出时带上存档引用到的图片 `blobs/<sha256>`，导入时校验（U2 §2.3、L1 §2.8）。我的包与库回收站的备份属于 M3，这次不做。

### C. 构建管线（`tools/data/`，D1 §6）

1. **运行方式**：本机 Node 为 22.23，能直接运行 `.ts`。但 `src/` 中的导入不带扩展名，构建脚本直接导入 `src/` 会失败。建议加开发依赖 `tsx` 来运行构建脚本，并在 NEXT 的「待议」中写明理由。
2. **输入快照与版本**：
   - `snapshot.json` 记录用到的每个输入文件的路径与 sha256，变化时构建失败，`--update-snapshot` 重新记录；
   - `published.json` 记录已发布版本与内容哈希，实现版本检查。
3. **转换**：抽取 → 展开 → 转换 → 标记 → 兜底 → 来源与摘要 → 分包 → 校验 → 打包 → 版本检查 → 报告（D1 §6 的 11 步）。
4. **确定性打包**：fflate 固定文件时间（1980-01-01）、固定压缩级别、键与文件按固定顺序排列。
5. **标签对照表**：`tools/data/markup/tags.ts`，遇到未知标签构建失败。
6. **随机表**：只收第一列是骰子范围的表；范围必须恰好覆盖骰子全部结果。
7. **规则选项**：按 D1 §4.7 的首批清单。
8. **报告与抽检**：
