驾驶员已定（2026-11-07 问卷与对话）：

| 项 | 决定 |
|---|---|
| 范围粒度 | 按书 / 按自制包归类，个别条目可单独例外 |
| 2014 / 2024 | 各做各的；P3 只做 2014 结算（现有规则界面就是 2014）；2024 以后单独排，不往 P3 塞 |

## 1. 三块共同的规矩

```
 内容是什么格式   → 归作者（官方数据、自制 JSON、作者加载器展开结果）
 内容在哪里可用   → 归 P3-1 的"范围"和"覆盖"管理记录（插件自己的管理数据）
 怎么计算         → 归 P3-2，一个战役选一套主规则（P3 只有 dnd5e2014）
```

- 条目只用**作者编号**指（`名|来源` 等，形状报告 §2.1）；不自造编号。
- 插件只定义自己的**管理记录、玩家记录、计算结果**；不给条目定义"我们的形状"。
- 依赖方向只能从下往上：存档/人物 → 结算 → 【库】。结算不读数据库，只接收【库】交来的条目。
- 作者有现成的就用作者的；作者没有的看 Plutonium / dnd5e；都没有才自写，自写部分在每节的表里列明。
- 作者工具跑不通时：停手，按 `SELF CHECK.md` 自查，报告驾驶员，确认后才手写。

## 2. P3-1 资料按规则管理

### 2.1 范围：一本书属于哪里

```
 范围 = 一组资料的使用标签。P3 先登记两个：2014、2024；用户可以另建自己的组。

 书甲 PHB(2014)      → 2014              ┐
 书乙 XPHB(2024)     → 2024              │ 初始建议：作者的 SourceUtil.isClassicSource
 书丙 某战役书       → 2014 + 2024       │  （vendor/en/js/utils.js:648：比 XPHB 出版早＝旧版；
 书丁 你的房规包     → 全局通用          │    自制看自己 _meta.edition，没写算旧版）
 书戊 判断不了的     → 未归类            ┘ 用户可改；判断不了的不猜成全局，也不丢

 例外（按单条）：书丙里某一条只算 2024 → 只给这一条记例外，其余跟书走
```

- 新来源从作者目录发现（B2 已有），不维护手写书单。
- 归类记录是插件管理数据，**不写进作者内容**。

### 2.2 一个战役看得到什么

```
       全局通用的书 / 条目
     ∪ 战役选的范围（新 2014 战役默认选"2014"）
     ∪ 这个战役额外加的书 / 条目
     − 这个战役排除的书 / 条目          ← 排除说了算
     ─────────────────────────────
     = 本战役的资料集合

 ✔ 同一条从多个范围进来只算一次（按 类别+作者编号 去重）
 ✔ 同名不同编号 = 两条，不按名字合并
 ✔ 每个战役各管各的：不改作者那份全局屏蔽表（ExcludeUtil 是全局的，改了会影响别的战役）
 ✔ 作者搜索默认藏"旧版来源"（omnisearch-backing.js:175，SourceUtil.isLegacySourceWotc），
   2014 战役查询时必须带上"显示旧版"，否则 PHB 这类书会搜不到
 ✔ "在范围里"和"已下载"分开回答；没下载的不冒充能读
 ✔ "在范围里"和"能不能自动算"分开回答（见 3.5）
```

这套过滤统一用于书目、查询、搜索、详情、取条目。

### 2.3 房规：可复原的覆盖

作者**没有**"用自制条目替换官方条目"的机制（本轮查证：作者的 `_copy` 产生的是一条新条目，原件并存；作者加载器缓存按 `类别+来源+编号` 存，后写的悄悄盖掉先写的，`utils-dataloader-dataloader.js:1071`）。所以插件加一层**覆盖记录**：

```
 官方 火球术 [PHB]   ← 人物、存档引用的始终是这个编号（不变）
        │
        │ 覆盖记录：目标 = spell | fireball_phb
        │           内容 = 你的可编辑自制条目（作者格式，用 _copy 指向原件、只写改动）
        │           生效处 = 本战役（默认）/ 当前规则下全部战役 / 全局
        │           开关 = 开
        ▼
 读这个编号：有开着的覆盖 → 交出房规版（附"房规，原件 PHB 火球术"）
            覆盖关掉     → 交出官方原件      ← 复原：只能回到官方原件，什么都不删
```

- 房规内容走作者的可编辑自制入口（`pGetOrCreateEditableBrewDoc`、`pAddSource`、`pPersistEditableBrewEntity`、`pRemoveEditableBrewEntities`，`vendor/en/js/utils-brew/utils-brew-impl-brew.js:58/135/92/119`），由作者加载器展开 `_copy`。
- 官方原件永远不改。复原 = 关覆盖（可再开）；删覆盖 = 连同那条可编辑自制一起删，原件回来。
- 不保留房规的历史版本（驾驶员定：只能复原到官方原件）。

### 2.4 包与包之间的冲突和覆盖顺序

```
 A 两个包有同一编号的条目（名字+来源都相同）
   作者：后装的悄悄盖掉先装的                         ✘ 不接受
   插件：安装/更新的解析步骤里检出 → 报"编号冲突"，列双方差别
         → 用户选：留甲 / 留乙 / 都不装；没选之前新包不生效

 B 多层覆盖压在同一条上（你的房规 + 导入的平衡补丁包）
   顺序：你的房规 > 导入的补丁包 > 官方原件（默认），每个战役可调
   查条目时给出整条链："生效：你的房规 ← 被压住：补丁包、官方"
   关掉一层 → 下一层自动生效

 C 一个包用 _copy 基于某条做了新条目，而那条被覆盖了
   规定：_copy 永远基于原件展开（作者加载器本来如此）；覆盖只在最后读出时生效
   → 改火球术不会连带改掉别人基于火球术做的"冰球术"，结果可预测

 D 删除 / 更新被依赖、被引用的包
   先列影响：哪些包依赖它（作者 _meta.dependencies）、哪些存档引用它、哪些覆盖用到它
   → 确认才执行；更新后原件变了 → 相关覆盖标"原件已更新，请检查"，不自动删
```

"导入的补丁包"怎么认：作者格式里没有"补丁包"字段。规则是——一个自制包里的条目如果和**已装的别的来源**撞编号，导入时问用户"当作覆盖"还是"当作冲突（A）"，选覆盖就生成覆盖记录。不靠猜。

| 用户要做的 | 走哪条路 |

### 2.6 导入、修改、更新走同一条流水线

```
 取得文件 / 编辑结果
   ▼ 识别：哪个数据体系、哪种语言、哪个版本
   ▼ 作者包管理器：依赖、旧写法迁移（utils-brew-content-migrator.js）
   ▼ 作者加载器解析
   ▼ 插件检查：编号冲突（2.4 A）、覆盖候选（2.4 B）、依赖缺失、解析错误 → 分别报告
   ▼ 预览给用户 → 确认 → 启用；任一步失败 → 保留原来已装的内容
```

- 同一个文件装两次只留一份（作者按校验和去重，`utils-brew-base.js:846`）。
- 作者迁移过的内容会和原件不同：保留原件，标明"作者已迁移"，不声称逐字相同。

## 3. P3-2 2014 结算内核

### 3.1 规矩

```
 输入：规则（dnd5e2014）+【库】交来的条目（生效版本）+ 人物（引用、选择、状态）
       + 这次的操作 + 已经掷出的骰点
 输出：结果预览 + 每个数的来源 + 待选项 + 不支持的写法 + 状态变更计划
 ✘ 不读数据库、不下载、不改条目、不存东西、不自己掷骰
 ✔ 同样的输入，结果永远一样
```

### 3.2 两层：准备层 + 纯计算层

作者的一些能力（骰子解析、遭遇规则、加载器）只在小窗里跑、而且是异步的。为了守住"同输入同结果"：

```
 准备层（异步）                         纯计算层（同步、纯函数）
 ─────────────────────                  ─────────────────────────
 问【库】：取条目(编号[])               拿到准备好的输入
 问小窗：骰式解析、遭遇规则等      ──►  算数 → 结果 / 预览 / 待选 / 不支持
 把结果固定成"准备好的输入"             可单元测试，不碰网络和小窗
```

### 3.3 五段（四类全做，按依赖先后，每段一个提交）

```
 a 基础数值 ──► b 物品装备 ──► c 战斗 ──► d 怪物 NPC ──► e 建卡升级
 （后面都要用）                                         （最复杂，要用到 a–d）
```

| 段 | 内容 | 主要来源 |
|---|---|---|
| a 基础数值 | 属性调整值、熟练加值、技能、豁免、先攻、被动感知、速度、AC 基础 | dnd5e `data/actor/templates/attributes.mjs`、`documents/actor/actor.mjs`（AC/先攻准备）；数值读作者数据 |
| b 物品装备 | 护甲与盾牌对 AC、`bonusAc` `bonusWeapon*` `bonusSavingThrow` `bonusSpellAttack`（形状报告 §10）、同调、充能与恢复、消耗品、魔法变体 | 作者 `Renderer.item` 变体展开 [调用]；Plutonium `Item` 转换器 [移植] |

### 3.4 写法登记表 + 未支持清单

```
 同一件事的多种写法（形状报告 §2.2：能力值 4 种、熟练 14 种、附加法术、起始装备、前置 13 种…）
   → 每种写法一行登记：写法识别 → 处理函数
   → 加一种写法 = 加一行，不改调用方
 没登记的写法
   → 结果里标"未支持"，附原文位置和受影响的数
   → 自动进"未支持写法清单"（体检里能看）
   → 绝不漏算一项还交出"完整最终值"
```

### 3.5 结果的五种状态

| 情况 | 交回 |
|---|---|
| 写法都支持、输入齐 | 完整结果 + 每个数的来源 |
| 等玩家选择 | 待选项 + 受影响的结果 |
| 有写法未支持 | 已算的部分 + 未支持项（原文、原因、影响） |
| 条目或依赖缺失 | 相关计算暂停，说明缺什么 |
| 执行出错 | 失败原因（不冒充"未支持"） |

## 4. P3-3 战役与存档

### 4.1 沿用 M1，扩展存什么

沿用：当前工作副本、命名存档、自动存档、分支、回收站、`.trpgsave`、单写窗口锁（`src/core/windowLock.ts`）、内容摘要（`snapshotHash`）。**不重造存档系统。**

| 存档里存 | 用途 |
|---|---|
| 规则（dnd5e2014）+ 内核版本 | 用哪套算法恢复 |
| 战役选书设置：选的范围、额外加的、排除的、覆盖顺序 | 跟着存档走（2.8） |
| 保存当时实际生效的覆盖（目标编号 → 房规条目） | 以后改房规，旧存档能察觉 |
| 条目引用（作者编号）+ 选择 + 个人调整 + 状态 + 已掷骰点 | 恢复人物和局面 |
| 数据版本指纹（官方数据版本、各自制包校验和） | 检查现在的资料和当时是否一样 |
| 修订号 | 防旧窗口覆盖新数据 |

不存条目内容，不存能重新算出的数值。玩家自己写的名字、备注照常存。内容摘要要把规则、范围、覆盖都算进去，否则改了选书设置，"有未保存修改"察觉不到。

### 4.2 预览 → 确认 → 写入 → 撤销

```
 结算内核交回"状态变更计划"
   ▼ 预览给玩家（P4/P5 界面）
   ▼ 玩家确认
   ▼ 短事务写入当前工作副本：先比对修订号 → 写 → 修订号 +1
   ▼ 记一条撤销记录（变更前后的值）
 撤销：反向应用撤销记录（同样比对修订号）
```

撤销记录存在工作副本里，存档时一起存；数量设上限（数字由设置决定，不写死）。

### 4.3 保存：先准备好，再短事务提交

```
 取工作副本和修订号
   ▼ 组装：范围、覆盖、引用、状态、版本指纹（这一步可能要问【库】，放在事务外）
   ▼ 用户数据库短事务：再比对修订号 → 写存档 / 当前副本 / 备份计数
   ▼ 提交成功才显示"已保存"；失败保留旧存档，不出现"保存了一半"
```

【库】和用户数据是两个数据库，不能一起原子提交（IndexedDB 的事务只管一个数据库）。所以存档只记**版本指纹**，读档时对比；不假装两边同时成功。

### 4.4 读档：先检查，再切换

```
 读存档 → 检查：结构版本、规则装没装、范围里的书在不在、覆盖还在不在、版本指纹变没变
        → 交回检查结果（不动当前战役）
        → 玩家确认 → 一个事务里：给当前战役做一份读档前自动存档 → 切换
```

| 检查结果 | 处理 |
|---|---|
| 都齐 | 正常恢复并计算 |
| 缺书 / 缺自制包 | 能看、能导出；相关结算暂停；数据不丢 |
| 版本变了 / 覆盖变了 | 列出差别；玩家选"恢复原样"或"采用现在的"，采用后存成新分支 |
| 存档结构太新 / 规则没装 | 不覆盖当前战役，原文件保留 |

不承诺"随便换了数据和程序，旧存档还能算出一模一样的结果"；本地没有旧数据时如实说"复算条件缺失"。

### 4.5 全局设置变了，旧存档怎么办

```
 改全局范围 / 全局房规
   ├─ 新战役：用新的
   └─ 已有战役：提示"可以采用新设置"，采用后产生新修订；旧存档不变
```

### 4.6 导出与备份

| 类型 | 包含 | 恢复时 |
|---|---|---|
| 单个存档 `.trpgsave` | 一份战役快照、版本指纹与依赖清单、用到的用户图片 | 需要对应资料已装；缺的列出来 |
| 完整用户备份 | 全部存档、当前副本、设置、范围与覆盖设置、用户图片、**你的自制和房规（作者格式原样）** | 先导入自制（走 2.6 流水线），再恢复存档；官方数据不进备份，按版本重新装，恢复报告列出 |
| 资料导出 | 2.5 的作者格式文件 | 交给作者程序导入，不当存档 |

备份前先显示大小（iPhone 存储小）。
