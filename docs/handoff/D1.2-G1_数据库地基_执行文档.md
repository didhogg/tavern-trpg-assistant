# D1.2-G1 执行文档：数据库地基

总览见 `docs/handoff/D1.2_后续流程大纲.md`。本文件是 G1 的唯一依据：没写到的事不做；范围外的发现写进 `NEXT.md` 待议。**驾驶员批准前不动代码。**

## 0. 一句话目标与判断标准

**目标**：资料库按「数据库」工作，而不是写死的数据。具体是：
1. 包之间的扩展只有一条通用规则；
2. 书目不写死；
3. 官方包与自制包走同一个格式和校验；
4. 设备能拿到新数据；
5. 用真实设备的状态测试。

**做每一个决定前先问自己三个问题（防跑偏）**

1. 这个做法换成一个**自制包**，能不能原样用？不能，就是写死。
2. 我修的是**一类**问题，还是驾驶员举的那一个例子？必须修一类。
3. 这个结论在**「新扩展 + 旧书 + 旧目录」**的设备上成立吗？没测过就不能说修好了。

### 1.4 应用端现状

- 安装器（`src/core/packs/recognize.ts`、`refs.ts`）只校验：
  - 规则存在；
  - `minAppVersion`；
  - `dataVersion ≤ SUPPORTED_DATA_VERSION`（3）；
  - 条目数；
  - L1 冒险格式的 `$ref`；
  - 修改版目标包已声明为依赖。
- 安装器**不校验**条目里的规则引用。`RuleDefinition`（`src/rules/registry.ts`）没有「列出条目引用」的接口。
- 安装队列逐个执行（`src/core/libraryQueue.ts`）。`withRequires` 先排依赖、再排本包，所以依赖总是先装好。
- 应用里只有 `src/ui/library/facts.ts` 读 `optional === 'tce-ocf'`（职业页显示），没有任何规则逻辑依赖它，规则选项里也没有「可选职业特性」开关。改数据格式不会破坏现有规则逻辑。
- 用户在应用里新建、复制的包写的是 `dataVersion: 2`（`src/core/library/mine.ts:72`、`src/core/packs/file.ts:53`）。

### 1.5 来源书目文件（`books.json`）与现有包名的差异

`books.json` 的名字与现有包名不完全相同。例如怪物图鉴在 `books.json` 里叫「怪物手册（2014）」，包名是「怪物图鉴（2014）」；MPMM 的冒号是半角。政策表要能写「覆盖名」，**现有 11 个包的名字、编号、lineage 一律不变**。

## 3. A：跨包扩展统一为「扩展包自己登记」

### 3.1 数据格式（写进 `docs/包格式说明.md`）

条目（目前只用于 `feature`；格式不限类型）可带一个数组字段 `joins`，声明「我加入别的条目」：

```ts
joins?: Array<{
  to: string            // 被加入的条目编号（职业、子职业、物品家族）
  level?: number        // 加入的等级（职业 / 子职业必填）
  as: 'optional'        // 可选授予：玩家可以选择获得
     | 'option'         // 加入该等级已有的「选择池」（如图腾三选一）
     | 'member'         // 加入物品家族的成员
  replaces?: string     // as=optional 时：选择它就不获得的那个特性（同在被加入的条目里）
  pool?: string         // as=option 时：该等级有多个选择池才需要，写选择池里任一现有成员的编号
}>
```

**规则（构建与安装都校验）**

1. `to` 必须在本包或本包**声明的依赖**里，否则失败。这样方向只能向下。
2. `as: 'optional'`、`'option'` 的 `to` 必须是 `class` 或 `subclass`；`level` 在 1–20 之间。
3. `as: 'option'` 时，`to` 在该等级必须有选择池；有多个时必须写 `pool`，且能唯一定位。
4. `as: 'member'` 时，`to` 必须是 `category: 'family'` 的物品。
5. `replaces` 必须是 `to` 在该等级（或更早）授予的特性。
6. 任何条目**不得**在升级授予里引用不在本包或依赖里的条目。旧的 `optional: 'tce-ocf'` 授予取消，构建遇到就失败。

**读法（人物模块、界面都按这个读）**

- 某职业或子职业在某一级的「可选特性」= 已安装的包里所有 `joins` 指向它、`as: 'optional'`、`level` 等于这一级的条目。
- 某选择池的选项 = 池里原有的 + 所有 `as: 'option'` 指向它的条目。

## 6. D：书目不写死

### 6.1 政策表

新文件 `tools/data/config/bookPolicy.ts`，一本书一行：

```ts
{ source: 'TCE', include: true, tier: 1, recommended: true, order: 6, version: '1.3.0',
  name?: '覆盖名（与 books.json 不同时才写）', nameEn?: '…', group?: '官方扩展 · 一档' }
```

- `name`、`nameEn` 默认取 `books.json`；现有 11 个包的名字不同的写覆盖名（第 1.5 节），保证名字不变。
- `packId` 规则固定为 `dnd5e2014-<来源代号小写，去掉连字符>`；`lineage` 沿用 `lineageFor(packId)`。现有编号不变。
- `order` 就是层级：「放在哪个包」的规则（展开物品、家族放在层级更高的包）依赖它，所以显式写出。
- `config/books.ts` 改为**由政策表 + books.json 生成** `BOOKS`、`BOOK_BY_SOURCE`、`BOOK_SOURCES`、`PACK_BY_SOURCE`、`BOOK_NAMES`。**导出名与形状不变**，56 个引用文件不用跟着改。

### 6.2 依赖与层级自动推导

- 删除 `validate/layers.ts` 的 `EXPECTED_REQUIRES`。
- 每本书的依赖 = 构建时按引用（含 `joins.to`）实际算出的包。现有的 `requiresFor` 已经在算，`requiresBooks` 手写值删除。
- 校验：
  - 依赖不成环；
  - 依赖只指向 `order` 更小的包；
  - **G1 前后 11 个包的依赖完全相同**（测试对照第 9 节的快照）。

### 6.3 去掉字面写死

第 1.2 节列出的 7 处代码、3 处测试，全部改成从 `BOOKS`（或政策表）取。`validate/index.ts` 的 `BOOK_CODES` 里的 2024 书（XPHB 等）改为「`books.json` 里出版不早于 2024-09-17 的来源」。

### 6.4 书名跟着包走

- 包清单加 `sourceNames: { [来源代号]: { name, nameEn } }`：本包条目出现过的所有来源代号，都写上书名。
- 界面的「出自《书》第 N 页」从已安装包的 `sourceNames` 里查。查不到（旧版包）时显示来源代号。
- 删除 `typeLabels.ts` 的 `BOOK_NAME` 与 `m2selftest.ts` 的 `BOOK_NAMES`（后者从包清单取）。

### 6.5 证明「加一本书 = 加一行」

- 在一个**不提交的临时分支**上，给政策表加一行 EGW（荒洲探险家指南），运行 `build:data`。
- 记录：要不要改代码（预期不用）、报了哪些数据格式差异（这些是 D1.2b 的工作，G1 不修）。
- 结果写进报告，分支删除。

  - 四种跨包扩展（`joins` 三种 `as`、`lore` 补丁、修改版）与它们的读法；
  - 引用规则（只能引用本包与声明的依赖）；
  - 版本与 `dataVersion` 的含义；
  - 一个完整的自制包示例。
- **共用校验**：新文件 `src/rules/dnd5e2014/data/refs.ts` 导出 `referencesOf(entry)`，列出一个条目的全部引用（结构字段、升级授予、`joins`、正文 `{{ref:}}`）。
  - `RuleDefinition` 加可选接口 `referencesOf`；
  - 构建端（`tools/data/validate/refs.ts`）与安装端（`src/core/packs/recognize.ts`）都用它；
  - 安装端到数据库里查：目标必须在本包或已安装的声明依赖里。
- **旧版包的处理（重要，防止误伤设备上已有的书）**：
  - `dataVersion < 3` 的包，引用不合规只记为**提示**（进体检），**照常安装**；
  - `dataVersion ≥ 3` 的包不合规就拒绝安装，提示具体是哪个条目引用了什么。
  - 应用内新建、复制的包改写当前 `dataVersion`（3），与官方包同等校验。
- **自制示例包**（测试夹具 `tests/fixtures/homebrew-cleric.trpgpack`，由测试代码生成）：
  - 一个新牧师领域（子职业，`classId` 指向 SRD 牧师）；
  - 一个特性 `joins` 牧师 2 级可选；
  - 一份给 SRD 怪物的背景补丁；
  - 声明依赖 SRD。
  - 测试：能安装；牧师页的反查能看到它；把它改成引用一个未声明的包后，安装被拒绝且提示明确。

## 12. 停止条件（立即停下报驾驶员，不自行变通）

1. 改动导致任何条目的**编号、名字、正文、所在的包**发生变化（`g1-additive` 失败且不是第 9 节放行的项）。
2. 自动推导出的依赖与快照不一致，且原因不是 `joins` 引入的、可以解释的变化。
3. 某条可选特性在来源里解析不出替代关系，且与 R15 的核对结果冲突。
4. 共用校验会拒绝**现有官方 1.2.x / 1.3.0 包**里的任何条目（说明格式说明或构建有漏洞）。
5. 旧目录读不了，且现场生成旧目录也做不到（升级场景就无法模拟）。
6. 需要改「修改版」机制或安装队列的行为。
7. 任何文件超过 400 行，或需要多行修改冻结文件（`tools/data/convert/` 下的 11 个审计文件；`convert/index.ts` 已满 400 行）。
