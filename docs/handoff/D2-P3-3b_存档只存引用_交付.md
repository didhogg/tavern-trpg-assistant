## 1. 做了什么

```
存档人物（改前）                      存档人物（改后）
┌────────────────────────┐          ┌──────────────────────────────┐
│ 引用：调用方手填         │          │ 引用：flags.plutonium 自动拆   │
│ 选择：空                 │          │ 选择：system.advancement.value │
│ 状态：条目全文 + 物品    │  41KB+   │ 状态：对比重建基准的差别       │  1.1KB
│ 战斗：挂在每个人身上     │          │ 战斗：战役层只存一份           │
└────────────────────────┘          └──────────────────────────────┘
```

- 人物段结构：`引用 + 选择 + 个人调整 + 状态差别 + 骰点`；状态差别按人物/物品/效果逐项存。
- 保存：事务外现取 `dataVersion` 与当前覆盖，再走 M1 的短事务保存。
- 读档：`checkSave` 只检查要读的存档；`loadSave({ precheck })` 在写自动存档/切换前运行，抛错则当前战役不动。
- 结构 5→6：旧人物的整份内容进 `legacyState`，`legacy=true`；不丢、不猜。
- 撤销上限：`settingsSchema.undoLimit`（默认 50），由调用方读设置传给服务。
- 结算小窗：新增 `rebuildCharacter`；建卡的“选择怎么填”优先用记下的 `advancement.value`，没记录才取第一个可选项；顶层条目即使没有成长步骤也会放进人物；装备加 `isStandardDragDrop` 避免 Plutonium 弹导入器提示；小窗关掉新手引导（会向服务器要默认场景）。

## 4. 没做 / 未验证

- **怪物重建没接**：`rebuildActor` 遇到 `monster` 引用返回“怪物的重建还没接”；本轮 P3-4 存档流程用真实【库】建的是英雄，怪物战斗仍在 `full-chain` 的结算内核回归里（7→3），但没有走“存档 → 读档 → 重建怪物”。这是本轮明确的缺口。
- **等级提升的选择没有按记录回放**：`levelUpApply` 仍用“第一个可选项”；本轮只接“建卡”的记下选择。
- 只验证了野蛮人/龙裔/侍僧这一组真实条目；其他职业、子职业、专长、法术书、起始装备等“选择写法”没有逐一跑重建。
- **房规备份恢复的已知现象**：Chrome 下作者把恢复的房规条目改名成 `火球术（PHB）`，旧房规编号查不到；备份检查只对官方/自制条目要求 0 缺，房规按 `houseRules > 0` 计。这是 P3-1 的恢复行为，未在本轮修。
- `compactActors` 目前由测试直接提供；P4/P5 的生产接线（什么时候抓重建基准、什么时候存）还需接。
- 界面、手机加载、TauriTavern 真机未测；2024 规则不在本轮。
- 旧存档只标 `legacy` 并保留整份内容；没有把旧人物自动转成引用（设计要求“不丢、不猜”）。
