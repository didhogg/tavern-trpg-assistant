## 0. 目标、红线、驾驶员已定的决定

**目标**：把中文数据里的文字毛病统一清理掉（规格 §5.9 + 体检 D 组）。R14 **允许改中文条目的文字**，但每一处改动必须能归到本文某一条规则，结构字段（id、数字、引用 id、骰式）一个都不能变。

**驾驶员已定**
1. `summary` **保留开头的名称**（用户要靠它知道这是哪个条目）；只去掉「复述条目类型」的那一段，并修掉空的一段。
2. 「中文（English）」：自动处理英文名边界清楚的情况，其余列成清单由我抽样复核，需保留的写进例外表。
3. 正文里没翻译的英文单词，**统一用 5etools 的术语对照直接替换成中文**（词典来源见第 4 节）。
4. 伤害类型统一写成「寒冷」和「暗蚀」（数据正文、摘要、界面标签都改；法术学派「死灵」不是伤害类型，不改）。

**红线**
- 条目 id、`type`、数字与结构字段、`{{ref:id|…}}` 里的 id 集合、骰式不变；`i18n.en` 的对齐率保持 100%（R13 测试继续全过）。
- 不改界面（`src/ui`）；唯一允许改的界面相关文字是 `src/rules/dnd5e2014/data/enums.ts` 的 `DAMAGE_LABELS`（`necrotic` 的「死灵」→「暗蚀」；`cold` 已是「寒冷」），以及因此要同步的测试断言（见规则 10）。
- 被审计引用的 11 个 `tools/data/convert/` 文件（blocks、common、featRule、foundry、item、items、monster、plan、spell、variants、versions）只允许**末尾追加或单行原地修改**；新逻辑写在新目录 `tools/data/clean/`；`tools/data/summary/summary.ts` 不在冻结范围。
- 不联网；不推送、不发布、不安装；推送要驾驶员再说「可以推送」。
- 不空 catch；单文件 ≤400 行；文档只写现状。

## 2. 总体设计

```
 转换器照常产出条目（中文那一遍、英文那一遍都一样）
        │
        ▼  convertAll 末尾（pruneRefs 之后、分包之前）调用一次
   cleanEntries(entries, lang)           ← 新目录 tools/data/clean/
        │   规则 1…9（见第 3 节），每条规则：纯函数 + 计数
        ▼
   报告：每条规则改了多少条目、多少处；D1 的括号清单
```

- `summary` 的两条规则直接改 `tools/data/summary/summary.ts`（它是生成摘要的地方），不走后处理。
- `abilityDc` 块在转换时修（后处理时属性已丢），做法见规则 8。
- **中文那一遍**所有规则生效；**英文那一遍**（`TRPG_DATA_LANG=en`）只生效与语言无关的规则：2、3（英文写法）、5、6、7、8（英文写法）；规则 1 的名称覆盖、4、9 只在中文生效。这样两边同时被清理，R13 的对齐不会被破坏。
- 每条规则的「前后样本」由清理器记录到 `tools/data/out/clean.json`（已被 `.gitignore` 忽略），报告里引用。

## 5. D1 规则 4 的算法（逐字，不得自行扩展）

先把文本切成「受保护片段」与「普通片段」：受保护的有 `{{…}}`（含嵌套 `|`）、`<$…$>`、`http(s)://…`、`@…` 公式记号、已在括号里的拉丁文（前一个字符是 `（` 或 `(`）。只处理普通片段。

在普通片段里找「汉字 + 拉丁串」（与体检 D1 同口径：汉字**紧挨**拉丁字母）。拉丁串 `RUN` 取最长的 `[A-Za-z][A-Za-z'’-]*`，后接空格再接首字母大写的词或连接词（`of the and in to de la von van`）时继续延伸；末尾的连接词去掉。`RUN` 的首词少于 3 个字母、或在 `latinAllow.ts` 白名单里（`NPC`、`DC` 等）：不处理。

对每个 `RUN`：
1. **词典命中且前文没有同义中文**（`RUN` 小写后，取最长前缀命中词典 `zh`；`RUN` 前面的文字不以 `zh` 结尾）：把命中部分替换为 `zh`。例：`7点piercing伤害` → `7点穿刺伤害`；`进行一次Dexterity豁免` → `进行一次敏捷豁免`。
2. **词典命中但前文已是同义中文**（以 `zh` 结尾）：当作注释，在 `RUN` 外加全角括号：`专精Expertise` → `专精（Expertise）`。
3. **词典没有**：在 `RUN` 外加全角括号：`幽寂大窟Great Dismal Delve` → `幽寂大窟（Great Dismal Delve）`；`九层地狱the Nine Hells，` → `九层地狱（the Nine Hells），`。
4. 例外表 `config/latinExceptions.ts`（键：条目 id + 原字符串；值：`keep`，并写依据）：命中的保持原样，不计入 D1 以外的任何计数；但体检 D1 仍会报出它们，所以例外只用于「确实不应改」且要**同时**加进 `latinAllow.ts` 白名单（写依据）。

**不得**：把 `RUN` 翻译成词典以外的中文；改动 `RUN` 里的大小写或拼写；处理中文后的拉丁字母不足 3 个的情况；碰受保护片段。

**复核清单**：清理器把每一处「规则 4.3 的加括号」（预计最多）与「4.1/4.2」的前后文记入 `tools/data/out/clean.json`；我在报告里：①列出歧义词与例外表；②按固定间隔（每 N 处取 1，N 使总数约 200）抽样，逐条标记对错并写进报告；③任何一条抽样错误都要追加规则或例外，再重跑，直到抽样全对。

## 11. 术语对照
