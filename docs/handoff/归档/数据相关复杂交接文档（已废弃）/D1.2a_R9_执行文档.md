- `ref` 表每行的 `cells.length` 必须等于 `cols.length`；若来源没有列标题，`cols` 写 `第1列`、`第2列`……（来源只有 2 张这样的表：VGM「怪物学识」「阶级，地位和头衔」）。

  ③ 同一个包内，表的 `name` 不重复。
  ④ 所有表 id 符合第 10 节格式。

## 6. 骰子标签与行范围（正式规则，原型代码见 `D1.2a_R9_参考实现/lib.mts.txt`）

**可掷表 = 第一列标签能解析成骰子。** 解析函数（逐步，不得简化）：

1. 标签是字符串 `s`。若 `s` 形如 `{@dice X}` 或 `{@dice X|显示}`：取 `X` 作为 `s`；若 `显示` 里含「牌」字（`卡牌`、`纸牌`），记 `deck = true`。
2. 若 `s` 含 `#$prompt_number:title=提示语$#`：记 `modifierPrompt = 提示语`，并把这段从 `s` 里删掉。
3. 去掉所有空白、转小写、去掉末尾的 `+`。
4. 必须匹配 `^\d*d\d+(\+\d*d\d+)*$`，否则**不是可掷表**（`神`、`角色等级`、`CR`、`职业`…这类标签的表就是对照表）。
5. 规范写法：每一项缺省的数量补 1（内部用 `1d6`）；**写进条目时**把每一项开头的 `1` 去掉（`1d6→d6`，`1d12+1d8→d12+d8`，`3d6` 不变）。
6. `lo` = 各项数量之和；`hi` = 各项数量×面数之和。

**行范围**（可掷表第一列）：整数 `n`（包括数字类型），或字符串 `n`、`a-b`（`–`、`—`、`−` 视同 `-`），或对象 `{type:'cell', roll:{exact:n}}` / `{roll:{min,max}}`。其中 `0`（或 `00`）表示 `hi`。`encounters.json`、`names.json` 的 `min/max` 为 `0` 同理。解析不了的行 → 整张表不导入（只有 2 个混合表如此：DMG「受害者；反派的计谋」「受害者；反派的手段」）。

**剩下的列**（可掷表）：`cols` = 标签列表去掉第一项；每行 `cells` = 去掉第一列之后的单元格。**对照表**：`cols` = 全部标签，`cells` = 整行单元格。单元格类型：字符串原样；数字转字符串；对象单元格 `{type:'cell', roll}`：`exact:n` → `n`，`{min,max}` → `min—max`，有 `entry` 则取 `entry`；其他对象形状→停（核心范围没有）。**行对象**：来源行可能是数组，也可能是 `{type:'row', style:'row-indent-first', row:[…]}`（核心 134 行）：取 `row` 数组为 `cells`，并写 `indent: true`。表对象上的 `data`、`isStriped`、`colStyles`、`srd`、`basicRules`、`reprintedAs` 等不进表条目（`srd` 决定包，`reprintedAs` 指向 2024 的 `dropped 2024-only`）。

`deck` 表：第一列是牌面（如 `A ♠`），不是点数；`rows` 的 `min = max = 行序号 1..N`，`cells = [牌面, …其余列]`，`dice = dN`（N = 行数）。

## 8. 去重（正式规则）

**可掷候选**：在**同书**（`source` 相同；唯一例外：L 与任何来源可跨书）、**骰子相同**、**行范围序列完全相同**之间判断。**对照候选**：在**同书**、**列数相同**、**行数相同**之间判断；可掷与对照**永不互相去重**。满足下列**任一**条件就是重复，归并成一组（并查集，允许传递）：

1. **内容完全相同**：每行的单元格经 `normRaw` 后相同。`normRaw(s)`：反复把 `{@标签 参数...}` 换成第一个参数（取 `|` 前的部分），直到没有 `{@`；再去掉所有非汉字非字母数字的字符；转小写。
2. **行相似度 ≥ 0.8**：`sim = 逐行相同的行数 / 行数`（单元格用 `normRaw` 连接比较）。
3. **同名且相似度 ≥ 0.6**：`cap` 相同且 `sim ≥ 0.6`。`cap`：B = `normRaw(块名)`；G/GG = `normRaw(caption，没有则名称最后一段)`；X = `normRaw(名称在 '·' 之后的部分)`；L = `normRaw(职业/背景名，去掉末尾括号)`；其他 = `normRaw(name)`。
4. **正文表与非正文表同名且页码相差 ≤ 1**：`cap` 相同，且两个候选里恰有一个是 B（或 X 恰有一个与非 X），页码都存在、相差不超过 1。
5. **出身原因表配对**：L 与 G/GG，`cap` 相同。
6. **宝藏表按挑战等级配对**：X（loot）与 G/GG：名称同属「个人宝藏/个体宝藏」或同属「宝藏堆/库藏宝藏」，且名称里的挑战等级写法相同（`0~4`、`0-4`、`0—4` 视同；`17+` 视同）。
7. **挑战等级怪物数值配对**：M 与名称含「对应挑战等级的怪物资料」的 G/GG 对照表（DMG 274 页）。

**每组留一张（幸存者）**：按来源优先级 `X > B > N > V > L > D > O > M > GG > G`，**但来自 R11 新类型条目（`planR11` 产出的条目）的正文表一律排在全部来源之后**（它们多是书本章节表的转抄，与书中表重复时让书本表当幸存者，保住已有编号；与别的正文表重复时让别的正文表当幸存者）；同优先级取候选列表里靠前的（B 按条目在 `planAll` 里的顺序，再按块在条目里的顺序）。幸存者**补字段**（不覆盖）：自己没有 `chapter` 就取组里别人的；没有 `footnotes` 就取别人的。幸存者的 `kind`：对照组为 `ref`；可掷组 = 组里所有候选 `kind` 的并集中按 `loot > names > encounter > life > deck` 取第一个，都没有则 `roll`；`srd` 取幸存者自己的。被丢掉的候选记在参考清单的 `merged` 里；被丢掉的旧 id 进 `idRedirects.ts`（第 13 节）。

> 规则 2—7 是为了处理「同一张表在书里有不同译法」的情况（例如 DMG「魔法物品表B」「伤患·伤残」、XGE 休整期的各个「困境」表）。**不要**再增加别的模糊规则；某张表该不该合并，以参考清单为准。

去重后的 `kind` 补充（只对 `roll` 的幸存者；来源为 G/GG 才适用）：名称含「名字」「姓名」且无所属条目→`names`；名称含「遭遇」→`encounter`；`source===XGE` 且章为「角色选项」且页码 62—73→`life`。

## 9. 所属条目（parent）与所属章节（chapter）

**规则：能确定所属条目就写 `parent`，否则写 `chapter`，两者恰好一个。**

所属条目：
- **B**：包含这个表格块的条目 id（`type:'lore'` 补丁条目取其 `_target`）。
- **G/GG** 的 `parentEntity`（核心 5 条）：`prop` 为 `subclass|variantrule|item`（`variantrule`→`rule`），`uid` 第一段是名称、最后一段是书；按（类型，名称，书）在 `planAll` 的条目里找。
- **N**：种族按名称映射 `龙裔→dragonborn 矮人→dwarf 精灵→elf 侏儒→gnome 半兽人→half-orc 半身人→halfling 人类→human 提夫林→tiefling`，找 `race.<英文名>.phb`；**吉斯人没有对应种族条目**，写 `chapter`。
- **L**：职业按名称找 PHB 的 `class`；背景按名称（去掉末尾括号）找 PHB 的 `background`。
- **D**：牌组名（去掉末尾括号）找同书的 `item`，找不到再找任何书的同名 `item`。
- 其他来源（X、V、O、M、没有 `parentEntity` 的 G/GG）没有所属条目，写 `chapter`。
- 幸存者的 `parent` 先取自己的，没有就按上面规则试组里别人的 `parentEntity`。

所属章节 `chapter = { book, name }`：`book` = 幸存者的 `source`；`name`：先取组里任一候选的 G/GG `chapter.name`；没有就用**页码推导**：读 `reference/5etools-cn-main（数据库）/data/book/book-<书小写>.json` 的 `bookData[0].data` 里 `type:'section'` 且有数字 `page` 的顶层章节，取起始页 ≤ 表页码的最大那一章，章名去掉开头序号前缀（正则 `^(第[一二三四五六七八九十百]+章|附录[A-Za-z]?)[：:]\s*`）。页码缺失且没有 `chapter` → 停（参考清单里没有这种情况）。

## 11. 正文表格 → 表术语（`tableRef`）

- **块的形状**：`{ tableRef: { id: string, label: string } }`；`label` = 表名 +（有骰子时）`（骰子）`，骰子用存储写法（`d8`、`3d6`、`d12+d8`）；对照表只写表名。`src/schemas/text.ts` 的 `textBlockSchema` 增加该块；`summary`/`plainText` 等处理文本块的函数遇到它取 `label`。
- **怎么替换**：在 `build.ts` 里 R11 条目并入 `plan.entries` 之后、`convertAll` 之前，由新函数 `planR9(plan, 选项, 传奇组列表, R11 条目 id 集合)`：
  1. 先对全部 B 候选（可掷+对照，共 630）做完去重与幸存者选择，得到每个 B 候选的幸存者 id；
  2. **然后**才修改原文：对每个 B 候选，在它所在的数组里把那个原始 `table` 块（用「数组 + 下标」或对象引用定位；**先全部收集定位，再一次性替换**，因为同一个数组可能被多个条目共享，例如魔法变体展开出来的条目）替换成 `{ type: 'tableRef', id: <幸存者 id>, label: <label> }`；同一位置只替换一次；
  3. `tools/data/convert/blocks.ts` 里**只做一处原地单行修改**：把现有那一行 `if (type === 'hr' || type === 'image' || type === 'gallery') return []` 改成在同一行内先处理 `tableRef`：`if (type === 'tableRef') return [{ tableRef: { id: str(input.id), label: str(input.label) } }]; if (type === 'hr' || type === 'image' || type === 'gallery') return []`（行数不变；先确认该行不被 `r8b` 审计引用；若被引用，改成放在 R11 的钩子 `extra` 里处理，并让新旧类型都传该钩子）。
