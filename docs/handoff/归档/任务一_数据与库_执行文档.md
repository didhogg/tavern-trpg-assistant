## 3. 做法

### 3.1 数据结构（批 1）

1. `monsterDataSchema` 加下列**可选**字段，`cr` 改为可选；其他字段一个不动：

   | 字段 | 形状 | 说明 |
   |---|---|---|
   | `classes` | `[{ class: 条目编号, subclass?: 条目编号, level: 1–20 }]` | 玩家角色的职业与等级 |
   | `race`、`subrace`、`background` | 条目编号 | |
   | `inventory` | `[{ ref?: 物品条目编号, name?: 1–80 字, qty: 整数 ≥ 1（默认 1）, equipped?: 布尔, attuned?: 布尔, container?: 本列表下标, chargesUsed?: 整数 ≥ 0 }]`；`ref` 与 `name` 至少一个 | 怪物与人物共用的背包 |

2. 构建端字段登记（`tools/data/config/plannedFields.ts`、`outputTypes.ts` 等现有登记处）登记这几个字段。
3. `structuralRefs` 登记：`classes[].class`、`classes[].subclass`、`race`、`subrace`、`background`、`inventory[].ref`。
4. 所有读 `cr` 的地方改成「没有就不显示 / 不参与」：至少 `src/ui/library/facts.ts`（`formatCr`）、`src/rules/dnd5e2014/data/formula.ts`（`ctx.cr`）、`tools/data/summary/summary.ts`；批 0 用 `grep` 列全，贴进报告。
5. 规则定义（`src/rules/registry.ts` 的 `RuleDefinition`）加 `entryDataSchema(type)`，`dnd5e2014` 用 `entryDataSchemaFor` 实现，供 §3.3 存条目时按类型校验。

### 3.2 怪物装备进背包与核查（批 2）

1. 新建 `tools/data/convert/inventory.ts`，在怪物转换的最后一步生成 `inventory`：
   - `ac[].items`（护甲、盾牌）→ 每件一项，`equipped: true`；
   - `attachedItems`（携带物）→ 每件一项，`equipped: true`；
   - 同一物品只出现一次；来源写了数量就用，没写就是 1；
   - **引用规则**：物品所在的包在怪物所在包**现有的依赖范围内**才写 `ref`；不在范围内的只写 `name`（中文名），**不新增包依赖**；两种各多少条写进报告。
2. 核查（写 `docs/probes/任务一_怪物装备核查.md`），对**全部包的全部怪物**逐项给出数字与明细：
   1. 来源 `ac[].from` 里有 `{@item …}`，但没解析成物品编号的；
   2. 来源 `attachedItems` 没解析的（`carryStats.attachedItemsUnresolved` 的明细）；
   3. 攻击动作名里提到携带武器、但没连上的；
   4. `ac[].from` 是纯文字的护甲名（没有 `{@item}`）、能按名字唯一对上物品的——在转换器里补上，列出补了哪些；
   5. 来源原始数据里其他像装备的字段（列出字段名与出现次数），确认没被导成别的东西或丢掉；
   6. 用 `inventory` 里的护甲 + 敏捷按规则算出的 AC 与书上 AC 不同的——**只报告，不改书上的值**。
   能确定的漏连当场在转换器里修掉；拿不准的单列一节「交规划者」。
3. `PACK_VERSION` minor +1；`TRPG_DATA_TAG=main npm run build:data` 两次哈希相同；数据比对只允许：怪物多了 `inventory`；版本号；第 2 条第 4 项补上的 `ac[].items`。在 `tests/data/g2-allow/t1.ts` 逐类登记放行。
4. `g2-oldext` 必须通过（旧扩展能装新包）。

### 3.3 我的库：服务（批 3）

在 `src/core/library/mine.ts` 补：

| 能力 | 规则 |
|---|---|
| 默认包 `ensureDefault(ruleId)` | 每个规则一个「未分组」包，编号固定 `u-unsorted-<ruleId>`（符合 `idSchema`），`category: rules`；打开【我的】时与存条目时确保存在；没有内容也在 |
| 默认包的限制 | 不能改名（简介可改）、不能删除、不能被「复制为新包」覆盖身份（复制出来的是普通新包，名字「未分组（副本）」）；`rename`、`remove` 遇到它报「默认包不能改名 / 删除」 |
| `store({ ruleId, packId?, entry, mode? })` | 不给 `packId` 就存进默认包。① 按类型校验（`rule.entryDataSchema(type)` + `entrySchema`），不合法报「条目内容不合法：…」；② 同包里已有**同类型同名**条目时：没给 `mode` 就返回 `{ conflict: { entryId } }` 不写入；`mode: 'update'` 覆盖那一条；`mode: 'new'` 另起编号写入；③ 新条目编号：`<类型首字母>-` + 10 位随机小写字母数字；④ 条目里引用到的、不在本包里的条目，所在包自动加进本包 `relationships.requires`（L1 §3.17）；⑤ 写入后跑 `checkPack`，有问题就回滚并报错；⑥ 版本号末位 +1；返回 `{ packId, entryId, version }` |
| `renameEntry(packId, entryId, name)` | 1–80 字；同包同类型重名报「这个包里已经有叫『X』的<类型>」；版本号 +1 |
| `moveEntries(fromId, toId, entryIds)`、`deleteEntries(packId, entryIds)` | 批量版本，一次事务，各包版本号只 +1 一次；移动时目标包需要的依赖照 ④ 补上 |
