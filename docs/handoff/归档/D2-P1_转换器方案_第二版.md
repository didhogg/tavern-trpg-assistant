# D2-P1 转换器方案（第二版，驾驶员 2026-11-05 批准）

> 用途：写转换器和之后查阅时的依据。大白话＋示意图；字段名细节以代码为准。
> 上位文件：`D2-P1_数据库全量重建_执行文档.md`（总规则、红线、步骤）。本文件只展开第④步。
> 驾驶员对第二版的批示：自制数据先不进最终库；**任何来源导入失败的条目（文件格式正确的前提下）都要列清单**；接受"一个格式写一次适配"的边界。

## 1. 一句话

把三个参考库（5etools 中文、5etools 英文、不全书网页）翻成本项目的**一种统一写法**，分成 2014、2024 两个书架。"通用"的意思是：**新增同一格式的数据，不改转换器**；新词汇只在词典里加一行；不认识的绝不丢、不挡路，全部进清单。

## 2. 流水线

```
 5etools中文 ─┐
 5etools英文 ─┤  (同一种格式 → 一个"5etools 适配")
 不全书网页 ──┤  (网页格式 → 一个"网页适配")
 ※考试用 homebrew-master (不进最终库)
      │
      ▼
 第0关 文件体检：打不开/格式错 → 【文件级清单】，该文件跳过
      ▼
 第一道 自动装箱：任何新类别、新字段原样带过去，不手写名单
      ▼
 第二道 通用引擎＋词典：展开继承、展开模板、中英配对、统一选择题、
        抽引用、读句式、判版本；不认识的词 → 兜底保留 + 【条目级清单】
      ▼
 第三道 整理成 9 种升级条目
      ▼
 分书架 2014 / 2024 → 按书切包 → 五道自动关 → 导入报告＋两份清单
```

## 3. 每条记录只有三种结局（不允许第四种"悄悄没了"）

| 结局 | 意思 | 进清单吗 |
|---|---|---|
| ① 完全读懂 | 每个词都认识 | 不进，只计数 |
| ② 部分兜底 | 整条落库，有几处没看懂，那几处原样保留 | 进条目级清单，写明哪几处 |
| ③ 导入失败 | 整条没能落库（如要复制的原条目不存在） | 进条目级清单，写明原因 |

- 文件级清单：哪个文件、第几行、什么错误。
- 条目级清单：来源、文件、哪一条（中英文名）、类别、结局、原因；并**按原因汇总**，不让人逐条看。
- 恒等式：① + ② + ③ = 总记录数。

## 4. 通用引擎与词典

引擎做 8 件事（写一次，所有类别共用，按"做什么"分，不按"哪个类别"分）：展开继承、展开模板、配对合并、统一选择题、抽出引用、读句式、判版本、整理升级条目。

词典（可编辑文件，新词加一行不改代码）：继承操作表（12 个；自制数据带来 5 个新的）、`{@标记}` 表（96 种）、伤害类型词、怪物动作句式表、升级条目识别句式（加属性、专精）、筛选条件词（中→英，自动从名称对照生成）。

继承操作表的"一行"是指向引擎里一个基本动作（替换、追加、前插、插入、移除、设值）的名字；新操作若能映射到已有动作，只加一行；不能映射的需要有人先说明含义（renameArr、replaceName 连 5etools 官方也不认识）。

## 5. 升级条目（9 种）与可靠度

加生命、得到特性、从几个里选、数值随等级变、加属性、得到熟练项、定体型、选子职业、修改物品。字段形状借 Foundry，数据全部来自 5etools。

| 可靠度 | 条目 |
|---|---|
| 结构化直接读 | 加生命（`hd`）、得到特性（`classFeatures`）、选择、数值（`classTableGroups`）、体型、子职业 |
| 可靠 | 开局熟练、兼职熟练 |
| 靠文字句式 | 职业升级的加属性（认出 88%）、专精（认出 27%，逐步扩充） |
| 5etools 无对应写法 | 修改物品（本轮可能 0 个，不编造） |

认不出的升级项变成"得到一条特性（文字）"，标部分兜底。

## 6. 怪物动作（全自动结算目标）

从动作文字读出：范围、豁免（属性、DC）、伤害（骰子、类型、何时）、成功时（减半等）、攻击（加值、触及或射程）、状态；充能、每日次数、传奇消耗读**动作名字**。读不出的片段保留原文并标待确认。实测（英文库）：伤害类型 98.1%、攻击触及 99.3%、豁免 DC 98%。

## 7. 合并与分书架

按（类别，英文名，来源书）配中英文；5etools 自带的 `foundry-*.json` 补充文件作为补丁贴到主条目（装不进的按原写法保留）；按出版日期判版本，没有 `source` 时依次看 `inherits.source`、`_copy.source`、文件名里的来源代号；仍无归属的通用内容两个书架各放一份。2014 条目里指向 2024 重印版的链接移到规范库的"跨版本对照表"（不进包、不删）。

## 8. 通用性考试（homebrew-master）

转换器写完后**不改任何代码**，一次导入 1,318 个自制文件（只在临时位置，不进最终库、不进包）。交卷：文件级打不开 N 个；条目级 ①②③ 各多少（合计必须等于总记录数）。及格线：不崩溃、不丢条、失败有原因；不设读懂率门槛。结果放进停点3的汇报。

## 10. 风险（未验证）

- 8 件引擎能力的覆盖率只量过怪物动作句式和职业加属性两项。
- 2014 书架粗估 33–38MB，离 42MB 上限近；不全书两版本占比未分开量。超限停下问驾驶员，不擅自删。
- 魔法物品展开约 6,900 件是粗估，约 5,500 件模板的版本待判。
- 自制数据的"读懂率"要转换器写好后用考试得出。
- 旧扩展能否安装新包：本任务不验证（执行文档第⑪步）。

## 11. 沿用的六项推荐（驾驶员 2026-11-05 说"按推荐"，未逐项改动）

1. 加属性、专精用句式识别；测试时临时读 Foundry 参考库对照，不存进库。
2. `foundry-*.json` 补充文件贴到主条目。
3. 跨版本重印链接移到"跨版本对照表"。
4. 无版本归属的通用内容两个书架各放一份。
5. 不全书网页单独成包（按书切包的一部分）；**体积上限作废（见第 12 节）**。
6. 修改物品本轮可能 0 个，不编造。

> 第 1 条的"句式识别"于 2026-11-05 被第 12 节取代：读取只经上游自己的代码（R3），不再由 agent 手写句式。

## 12. 防复发硬规则 R1–R6（驾驶员 2026-11-05 批准；停点3 之后加入，R6 随后追加）

**为什么加**：停点3 的可用性测试发现：我拿"字段在包里"当"读懂了"，从没打开 5etools 的 `js/`（404 个文件、约 16 万行）和 `node/`（107 个文件）；手写的怪物读取器把豁免属性读成 DC 数字（2,625 条全错）而五道自动关全过；排除名单是凭想法列的，误排了 `encounterbuilder.json`（遭遇规则）和 `generated/`（上游生成的查找表）。这正是旧项目死循环的同一个根：agent 凭知识臆断"数据该有什么"。

| 编号 | 规则 | 防的环节 |
|---|---|---|
| R1 | **排除名单为空。** 除非上游自己标明，agent 不得自己加排除项。agent 手里现有的名单（如 `growthCategories`、`refFields`、版本回退规则、变体展开范围）逐个写明依据——上游哪个文件哪一行；说不出依据的删掉 | 选择性不导入 |
| R2 | **对账关是构建失败条件。** 源数据每条路径（含嵌套）要么有去处，要么原样保留，要么列清单；出现"没处理"即失败 | 忘导入 / 又发现有数据没导 |
| R3 | **读取只经上游代码。** 要读懂的含义（标签、识别器、规则常量）运行上游自己的 `js/`、`node/` 代码取得；跑不起来就**停下报告，不得退回手写** | 手写镜像转换器 |
| R4 | **输出以上游结构为准。** 先对现有"统一外壳＋升级条目"做工具盘点：哪些字段是 agent 加的、上游没有的。自加字段只允许是通用整理（编号、中英配对、版本分库、引用解析），不允许是"想让界面有的字段" | agent 臆断字段 |
| R5 | **锁定数据形状后才开 P2 界面。** 界面所用字段清单由程序从真实包生成（开发规范第 15 条）；数据形状一旦改动，重新生成清单并列出对界面的影响 | 改数据→改界面→又发现缺数据 |
| R6 | **写任何读取、转换、常量表之前，先搜上游代码里有没有。** ① 每个新写的函数在文档里写明“上游对应位置”，或写明“上游无”及搜过哪些文件；② 每次开工先由工具生成整个参考仓库的目录与文件类型统计，附在汇报里，防止缩小范围；③ 被替换的手写实现必须做差异对照：同一批记录，上游函数与旧手写函数各跑一遍，由工具列出不一致的条目（工具对账，不是人工核对数据） | 重新发明上游已有的东西；缩小范围 |

附加（驾驶员 2026-11-05）：① 中英配对的英文一侧用中文仓库自带的 `data-bak`（2.39.0，与中文数据同版本）；英文仓库 src-main 整份仍在原样库但不参与配对（它的 1,188 条“节”行与 bak 里的 adventureData/bookData 是同一内容的不同打包）。② **图片文件一律不入库**（连路径登记都不做，只数个数）；唯一允许入库的是图片的网页链接，由 `report/图片链接对账.md` 逐个对账。③ 中英第二轮配对：同文件同类别、两语言条数相同且按顺序来源逐条一致才按顺序配（只做配对整理）。

附加：缺口只出**清单和数字**，不再把"这条怎么修"当问题抛给驾驶员；体积不设上限，中英文必须连带（执行文档"驾驶员决定"8）。

**已知盲区（诚实记录）**：R2 只保证字段"有去处"，不保证值是对的；即使读取改用上游代码，agent 写的衔接代码仍可能出错，目前没有自动手段覆盖这一点。界面里手写数据（环节①）目前也没有自动检查。

**执行顺序（驾驶员批准）**：第 1 步 导入 17 个曾被排除的数据文件 → 第 2 步 `js/`、`node/`、`test/` 文本原样入库 → 第 3 步 试跑上游代码 → 第 4 步（拆为 4a/4b/4c，每块做完先出差异对照再往下）：4a 继承展开（`_copy`/`_mod`）、魔法物品模板展开、引用串解析改用上游函数；4b 标签、常量表、骰子解析改用 `Renderer.tag`、`Parser`、上游骰子解析器；4c 怪物动作读取器删掉手写句式，只读上游标签（“豁免成功减半”“多重攻击次数”上游没有结构，保留原文）；上游函数在无浏览器环境跑不起来则按 R3 停下报告 → 第 5 步 全类别全路径对账。第 3 步若需安装 5etools 的 npm 依赖，先停下问。Foundry 是否作为来源，待第 1–5 步做完用对账数字再定。
