```

**总规则（驾驶员定；2026-11-05 追加三条例外，见下方"驾驶员决定"）**

**驾驶员决定（2026-11-05，写普查之后追加）**

1. **Foundry 数据不进库。** Foundry（`dnd5e-6.1.x`）的记录不入原样库、不参与合并、不进任何包。理由：5etools 的内容已覆盖书的内容；Foundry 独有的多是预展开的魔法物品成品、单独成条的怪物特性、效果预设、示例角色、随机表，其来源书字段几乎全空，无法进按书切的包。
   **保留的只有它的"写法"**：成长项 9 种的字段形状、活动类型、两种成长项存放方式、文本增强器清单等，存在原样库的 `foundry_forms` 表和 `report/Foundry写法` 里，供第④步借用格式、核对读法。Foundry 的 9 种成长项**格式**仍照用（开发规范 §10），**数据**由 5etools 经转换器填。
2. **不全书的 256 个非文本文件**（图片、Office 模板、脚本、备份）留在参考库，不导入、不进库，原样库里只登记路径、大小、哈希。文本类文件（htm、html、xml、txt、md）照常全部入库。以后做界面需要插图时再从参考库取。
3. **怪物动作的目标是全自动结算（C 档）。** 转换器把动作文字的固定句式和标记读成字段：伤害骰、伤害类型、攻击加值、豁免属性、DC、成功减半、充能、使用次数等；读不出的标成"待确认"，不编造、不手补。普查实测英文库 98.1% 的伤害骰标记后面紧跟伤害类型词，其余是"同武器类型""从下列中选"这类真正没有固定类型的情况。结构从英文库读，中文库只取文字。
4. **魔法物品模板要展开。** 5etools 的 `magicvariant`（`requires`/`excludes`/`inherits`）是模板，成品（长剑 +1）没有单独记录；转换器必须按模板展开。展开后条目增加多少、包会不会变大，在第④步草案里写清楚；包大小的停止条件（第六节）照旧。
5. **转换器按"一个格式写一次适配"做，详见 `docs/handoff/D2-P1_转换器方案_第二版.md`。** 每条记录只有三种结局（完全读懂／部分兜底／导入失败），恒等式为三者之和等于总记录数。
6. **任何来源导入不了的条目都要列清单**（前提是文件本身格式正确）：文件级清单（打不开的文件）＋条目级清单（兜底和失败的条目，按原因汇总）。官方数据与自制数据同样处理，不静默丢弃。
7. **自制数据 homebrew-master 先不进最终库**，只当"通用性考试"的考卷：写完转换器后不改代码一次导入，交卷报告放进停点3汇报。
8. **不设体积上限（2026-11-05 驾驶员定）。** 不设总大小上限、不设单包上限；安装哪些包由用户自己决定。**所有条目中英文连带对照**，不得把英文对照拆成"可选包"或任何形式的可选内容。
9. **完全镜像上游数据结构（2026-11-05 驾驶员定）。** 目标是镜像并尽量贴合上游（5etools 等）的数据结构，一键导入；规则、数据用途、可结算的结构化数据从上游自带的结构和上游自己的代码里取，不由 agent 凭对 DND 的了解臆断"应该有哪些字段""界面应该显示什么"。
10. **防复发硬规则 R1–R6**（驾驶员批准，R6 为 2026-11-05 追加；详见 `docs/handoff/D2-P1_转换器方案_第二版.md` 第 12 节）：R1 排除名单为空；R2 对账关为构建失败条件；R3 读取只经上游代码、跑不起来就停下不得退回手写；R4 输出以上游结构为准，自加字段只限通用整理；R5 锁定数据形状后才开 P2 界面；R6 写任何读取、转换、常量表之前先搜上游代码有没有，并用差异对照验证被替换的手写实现。

**红线**

1. **不写手写转换表。** 不按条目、不按字段路径、不按职业或种族名单写配置。读法按"写法"写，一种写法写一次，所有类别共用。
2. **不做数据质检员。** 不逐条对照原书或 PDF，不逐条抽检，不手工修数据。数据内容是否正确归上游（5etools 等的维护者）管。比对报告里不得建议驾驶员逐条核对。
3. **不自行缩小范围。** 草案、报告、代码注释里不得出现"暂不做""不结构化""只显示文字""不进包"这类决定。源里是文字，就按源导入文字；源里有结构，就一个字段不落地导入结构。
4. **参考库只读。** `/Users/xxx/DND- reference（DO NO DELETE！）` 下的任何文件都不得写入、移动或删除。
5. **不推送、不打远端标签。** 本任务只在本机提交；回退标签只在本机打。推送在 P2 之后，另行授权。
6. **不让子 agent 或自评判"通过"。** 结果由驾驶员确认。
7. **2024 内容和 2014 完全隔离。** 不进 2014 库，不进 2014 的下载目录，这一轮不推送。
8. **不加新依赖。** 新增 npm 依赖需要驾驶员同意。SQLite 用 Node 22 自带的 `node:sqlite`（实验特性），不稳就改用 macOS 自带的 `sqlite3` 命令。

## 四、统一格式

- **外壳不变**：编号、类型、名称、英文名、摘要、关键词、唯一、中英对照，以及 data 里的出处、署名、正文。编号规则沿用现有的"类型.英文名.来源"，保证旧存档的引用不断。
- **人物构建类**（职业、子职业、种族、亚种、背景、专长、特性、角色创建选项）里"每级获得什么、能选什么"，统一成 **9 种成长项**，字段形状照 Foundry 官方写法（只借格式，不用它的数据）：
  - 生命、获得、选择、数值、属性提升、熟练、体型、子职业、修改；
  - 专精是"熟练"成长项的一种模式（Foundry 的写法）；
  - 涉及法术的"获得"和"选择"带法术设置：施法属性（固定或几选一）、次数、恢复方式。
- **选择池**：所有"从这些里选 N 个"统一成一种写法，候选可以是"明确列出的条目"，也可以是"按条件筛选"。5etools 的 choose、from、any、anyStandard、fromFilter，以及 "level=0|class=…" 这类筛选字符串，全部翻成这一种。中文版把筛选值也翻成了中文（例如 class=法师），要按名称表换回英文代码。
- **其余所有类型和字段**：按自动搬运规则原样进入统一格式。新类别（冒险正文、配方、卡组等）的格式由 Schema 和实测形状自动生成，不手画。冒险正文沿用"书籍正文"的章节、目录、正文结构，并保留区域锚点（房间编号）。
- **贴合不了的写法**：按官方原写法原样导入，字段名和结构照搬，同时在写法目录里计数。

## 五、执行步骤

### ① 准备
- 新建 `tavern-trpg-data-next/` 和上面的子目录。`AGENTS.md` 的第三个工作文件夹已由规划者写好。
- 在助手仓库建 `tools/db/`，在 `package.json` 加 `db:build`、`db:diff`。
- 可以复用旧管线里的**通用函数**：读文件、`{@标记}` 转换（`tools/data/markup`）、英文对照（`tools/data/english.ts`、`tools/data/i18n`）、打包与哈希（`tools/data/publish/write.ts`）、书目日期（`tools/data/config/books.ts`）。**不复用**旧的手写配置表（`tools/data/config` 里的职业列、熟练特质、特性规则等）和 overlay。

### ② 原样库
5etools 中文、5etools 英文、不全书三个参考库全部原样入库，一条原始记录一行：来源库、文件、类别、名字（中/英）、来源书、规则版本（2014/2024）、原文 JSON 或 HTML。不排除任何文件（R1）；Foundry 数据与不全书非文本文件按"驾驶员决定"1、2 处理。上游的 `js/`、`node/`、`test/` 代码文本同样原样存入（R3 的读取来源）。
- **退出条件**：每个参考库导入的条数等于源文件里数出来的条数（程序现数，不写死）。

### ③ 写法普查
- 以 Schema 打底、以真实数据为准，统计每种写法出现在哪些类别、多少条，并分成三类：
  - 简单值（走 A 层）；
  - 带含义的写法（要写 B 层读法）；
  - Schema 里没有、数据里出现了的。
- Foundry 按它自己的数据定义做同样的普查，结果只存为"写法"（`foundry_forms` 表和 `report/Foundry写法`），不存记录。
- **产出**：`report/写法目录`。
- **★停点1（做完 ③ 就停）**：向驾驶员汇报普查结果，ASCII＋大白话，至少包括：
  - 普查范围：三个入库的参考库各扫了多少文件、Foundry 写法扫了多少、多少条记录（程序现数）；
  - 写法三分类（简单值／带含义／Schema 里没有）各多少种，每种给出现的类别数、条数、1 个写法例子；
  - 带含义的写法逐种列出，说明它在源里表示什么、准备在 ④ 怎么读（只说思路，不写代码）；
  - Schema 里没有的写法全部列出，不省略；
  - Foundry 的普查结果；
  - 没扫到或没法判断的地方、未验证项。
  汇报后停下，不进入 ④。

### ④ 通用转换器
- **A 自动搬运**：简单值原样搬过去；名称、出处、正文、96 种 `{@标记}` 共用一套；新类别的格式自动生成。
- **B 写法读法**：每种带含义的写法写一个读法，所有类别共用。例如选择与筛选、"名字|来源"引用、"累计还是新增"（5etools 是累计；Foundry 是每级新增，只作为格式参考）、额外法术、各类熟练、伤害与抗性、速度、施法、`_copy`/`_mod` 继承。
- **C 成长项**：把读出来的内容翻成 9 种成长项。
- **合并**：同一样东西只留一条，按"类型＋英文名＋来源书"认。以 5etools 为准，不全书补 5etools 没有的中文正文。每个字段在出处表里记下取自哪一家；几家的值不一致时以 5etools 为准，并自动记进冲突表（只计数和分类，不逐条处理）。
- **分库**：按第二节的分法写入 2014 或 2024 规范库。两个库之间不互相引用。
- **★停点2（写转换器代码之前）**：先向驾驶员出"④ 写法草案预览"，ASCII＋大白话，至少包括：
  - A／B／C 三层各管哪些写法、各多少种；
  - 每种 B 层读法：输入长什么样、读成什么、哪些类别共用（各给 1 个输入→输出的例子）；
  - 9 种成长项各自的字段形状，和旧的 8 种怎么对应；
  - 选择池统一写法的字段形状；
  - 合并规则和冲突怎么记；
  - 贴合不了、按原写法原样导入的写法清单及其落地形状；
  - 风险与不确定项（例如"累计"与"每级新增"能否统一）。

### ⑤ 发布包与自动关
