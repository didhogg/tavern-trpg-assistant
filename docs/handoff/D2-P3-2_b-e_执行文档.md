## 1. 每段开工固定三步（a 段教训，必须做）

1. **先读**：蓝图本段那一行 + 本文本段 + dnd5e / Plutonium 里对应的官方入口（先看作者目录、注册表、`CONFIG.DND5E`、Plutonium 导入器清单，再精准查找）。写出“文档已定什么、官方入口是什么”。
2. **先预览**：给驾驶员一段 ASCII + 大白话的本段预览（做什么、用哪个官方函数、场景怎么生成、怎样算完成），**驾驶员没回应也可按已批准的 b→e 连续执行**，但预览必须写进本段报告。
3. **先查原件再写代码**：先用 `KERNEL_FILE_LOG=1` 或在官方页上跑一次，看官方实际读了什么、调了什么；第一次失败先查方法，不连续换写法；同一问题两种方法不行就按 §6 停下。

## 2. b 物品装备

| 项 | 内容 |
|---|---|
| 做什么 | 穿上/脱下、同调/取消同调、使用物品扣次数（药水、卷轴、带充能的魔杖等）、充能恢复（短休、长休、黎明，dnd5e 物品自己写的恢复规则原样）；Plutonium 物品（含魔法变体，例如 +1 长剑）接入世界 |
| 官方入口（先核实） | dnd5e 物品文档的 `update`（装备 `system.equipped`、同调 `system.attuned`）、物品活动 `activity.use({ configure:false })`、次数恢复走 dnd5e 休息 / `recoverUses` 一类官方流程；Plutonium 物品转换已在 a 段 `convert` 命令里（`item` 3,761 条） |
| 新增命令 | 例如 `equip(actorId,itemId,on)`、`attune(actorId,itemId,on)`、`useItem(actorId,itemId,points)`、`recover(actorId,period,points)`；返回 a 段同一结果格式（五种状态 + 变更计划 + 出处） |
| 场景生成 | 从现成角色的物品批量生成：每件可装备物品穿/脱各一次；每件需同调物品同调/取消；每件有次数的物品使用一次 + 用尽后再用一次（应得“不支持/次数不足”的官方结果）；每个角色短休、长休、黎明各一次看恢复。另取【库】魔法物品经 Plutonium 转换后放进一个角色再跑同样操作 |
| 完成标志 | 物品场景：插件小窗 vs 官方 0 差异（数值、变更计划、出处）；Chrome、WebKit 一致；`npm run check` 通过 |
| 不做 | 物品界面；存档；手写物品数据或物品名单 |

## 6. 每段结束

1. Chrome、WebKit 跑本段场景 + 回归（`candidate.mjs`、`session.mjs`、`dice.mjs`、`convert.mjs`）。回归里只允许已单列的项（见交接 §5）。
2. `npm run check`、`npm run build`。
3. 更新 `D2-P3-2_b-e_交接.md` 的进度表与 `NEXT.md` 一行。
4. 一个本地提交，**只**加本段文件（交接 §6 列了不能提交的文件）。
5. 进入下一段；e 段结束后报告并停下。

## 7. 停下报告（照蓝图 §6，其余不停）

1. 按官方行为接好后仍有**解释不了**的差异，换两种方法仍不行。
2. dnd5e 或 Plutonium 原代码需要**修改**才能跑。
3. 需要手写数据、补条目、写死名单（先按 `AGENTS.md`“强制自检触发”自检再报告）。
4. 需要改设计规矩（输入输出、五种状态、存档内容）或改界面。
5. 需要新依赖或外部服务。
6. 演示站不可用，无法对答案。

报告格式：先结果，再 ASCII + 大白话；写清已证实与推测；列未验证项；最后读 `SELF CHECK.md` 只写“我做错了什么”。
