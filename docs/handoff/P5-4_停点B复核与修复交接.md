### 2.2 停点 B 后端｜从删除目标反向查实际使用者

~~~text
C ──需要──► B ──需要──► A ──需要──► D

选择删除 A
  ├─ D 是 A 用的资料，保留
  ├─ B 若失去必须的数据，加入同删
  ├─ C 只在 B 加入同删且 C 也失去所需数据时加入
  └─ 如果作者仍能从 X 取到 B 所需的数据，B、C 都保留
~~~

1. **定准对象。** 官方按资料集和作者书号或冒险号。自制按资料集、作者管理器和 `docIdLocal`。整套官方卸载保留独立意图。中英同删只按明确的目标集合。用当前版本核对目标实际存在，失效身份明确报错。书与其所在自制包的安装身份若不同，预览讲清操作的单位。
2. **核对依赖方向和实际提供者。** 读取同一版本的官方已装范围、作者书目、作者自制及试玩稿的原始元数据和作者编号索引。保留依赖类别和来源，必要时保留作者实际引用的条目编号。`dependencies`、`includes` 及作者确实用于取数据的其他声明按各自的作者路径处理。`otherSources` 等形状先核对实际合并语义，普通交叉引用、标签、房规或存档引用只报告对应影响。避免把已存在的缺依赖归到本次删除。
3. **只追本次新增的缺失。** 从选中对象出发，比较移除前后，查仍安装的使用者是否真的失去必需数据。按作者解析顺序核对剩余提供者。遇到同来源多个提供者、同名不同类别等歧义时，用已有隔离作者窗口或对应作者入口复算所涉数据形状，给出证据或明确无法判定。由已证实新增缺失的包继续反向扩展，去重并处理循环。
4. **预览和执行同一份计划。** 计划明确选中项、必须同删的包及缺失原因、可保留但受影响的对象、房规、版本选择、战役及存档。存档和战役内容只读。取得现有修改租约后，用同一基线再核对目标与影响。锁内复核结果变更就要求重新预览。用现有准备版本及一次发布执行全部确认对象。核对作者实际删除数量及结果，失败或部分未执行必须有准确反馈。
5. **移除与回收分开。** 新版查询、正文、搜索、目录和定位尊重移除后的清单。持有旧版本的读者可以读完。仍由其他书或包使用的文件保留。报告逻辑移除和实测释放或暂存字节，保持与现有回收边界一致。
