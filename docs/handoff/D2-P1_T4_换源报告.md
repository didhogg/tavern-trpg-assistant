# D2-P1 T4：换源（只换数据源指针）

日期：2026-11-06
状态：完成，**未提交**。范围只有「换源」：数据怎么拉、读、展开、装包，全部留给 P2【库】后端。

## 一句话

```
设置里的「当前数据源」  旧库（默认） ｜ 5etools 上游
        │ 选上游
        ▼
读源清单 manifest.json（主地址 → 备用地址）
        │ 校验：格式、版本、账目自洽
        ▼
成功：得到「来源 → 文件」索引      失败/未配置：自动退回旧库 + 提示（不抛错）
```

## 做了什么

| 项 | 文件 | 说明 |
|---|---|---|
| 当前数据源指针 | `src/core/source/pointer.ts` | `resolveDataSource()`：旧库模式不联网；上游模式读主地址、再读备用地址；任何失败退回旧库并带提示 |
| 清单读取与自检 | `src/core/source/manifest.ts` | zod 校验（保留未知字段）；`reconcileManifest()` 自检账目；`buildSourceIndex()` 用 `files[].sourceIds` 建来源→文件 |
| 设置 | `src/schemas/campaign.ts` | 新增 `dataSource`（默认 legacy）、`sourceManifestUrl`、`sourceManifestFallbackUrl`（默认空）。三项都有默认值，旧设置照常读出 |
| 错误码 | `src/core/errors.ts` | 新增 `E_SOURCE_NOT_CONFIGURED`、`E_SOURCE_UNAVAILABLE`、`E_SOURCE_MANIFEST_BAD` |
| 源登记表增补 | `tools/db/source/repos.ts` | 新增第 6 个源 `official-2014-src`（见下）；拉取函数改为通用的稀疏克隆 |
| 清单对账 | `tools/db/source/check.ts`，`npm run db:source:check` | 用插件同一套代码读真实清单，对 T3 校验报告的数字，并检查登记表与清单的仓库一一对应 |
| 新旧比对 | `tools/db/compare/`，`npm run db:diff` | 列出「切到数据源后旧库哪些条目会消失」。原 `db:diff` 指向不存在的文件，已修好 |
| 测试 | `tests/unit/data-source.test.ts` | 9 个，不写死条目数量 |

## 交付后自查修正（2026-11-06，比对工具三处）

| 缺陷 | 修正 |
|---|---|
| 写死只数 `official-cn`，并断言"官方仓库内容重复" | 实测并不重复（英文源码仓库有 880 条中文仓库没有、反之 370 条；2014 站另有 96 条两边都没有）。按书/按类别统计改为所有官方仓库（以清单 kind=official 为准）去重合并后数 |
| 手写"哪些字段算名字"清单 | 删除。改为"旧条目英文名整体等于哪个字段的值就登记"，字段分布由程序统计并写进报告 |
| 配对规则是自己定的，"2,622 条消失"当准确数 | 报告改称"对不上"，给出严格口径（2,622）与宽松口径（只比字母数字，2,615）的范围；配对规则归 P2 后端 |

残留：①"名字在官方别处出现"与"所有源都没有"的划分现在包含非名字字段（如 type、tag）的命中，字段分布已列出；对不上的总数不受影响。②"同名同书"不分类别，同名同书的不同类别记录可能互相算作对上。
