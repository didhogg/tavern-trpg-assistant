- 只记录公开可见的页面、截图和文案；登录后的完整工作台没有账号就不冒充“已看过”。
- 只看结构、信息层级、交互模式和视觉原则，不复制别人的视觉资产、图标或代码。
- 每项都写“可以借什么 / 不能借什么”，避免把“参考”变成“照搬”。

| 参考 | 公开证据 | 可借鉴 | 不借鉴 | P4 落点 |

### 1.3 从参考里提炼的模式

```text
① 战役身份要一直看得见
   Kanka：侧栏顶部战役名
   Roll20：进入游戏后仍知道自己在哪场战役

② 首页只给一个主动作
   Roll20：“Play / Join a Game”
   D&D Beyond：“My Campaigns / Create”

③ 当前对象放右侧，工具小窗独立
   Foundry：设置、聊天、战斗等独立窗口
   Kanka：实体页 + 侧栏 + 上下文卡片

④ 内容页用“标题 + 标签页 + 安静正文”
   LegendKeeper：标题清楚，标签页切换内容
   → P4 只借页头/标题层级，不借深色奇幻皮肤

⑤ 不要把 VTT 的密度搬进首页
   Roll20 / Foundry 的工作台是“游戏进行中”的密度
   我们的首页是“进入战役前/后”的控制台，应该更安静
```

### 1.4 `ui-ux-pro-max` 的使用记录

本地库对 “TRPG campaign management dashboard warm minimal editorial” 的匹配结果主要是 **Flat Design / Feature-Rich Showcase**，并给出了青绿色 SaaS 配色。

- 采纳：Flat、少阴影、清晰的排版层级、可访问性检查。
- 拒绝：青绿色主色、营销页式 Feature Showcase、通用 SaaS 卡片堆叠。
- 原因：与已确认的“暖黄红 + 暖灰 + 深红主操作”冲突；工具只作为候选，不替我拍板。

| 位置 | 现象 | 用户会怎么想 | 严重度 |
|---|---|---|---|
| 首页空态 | 一张很大的横幅，规则/开始/存档/设置的关系不清楚 | “我该先选规则，还是先点开始？” | S2 |
| 首页战役态 | 大横幅之后只有一个“库”概览格，快捷功能少 | “跑团中要用的东西还要去侧栏找” | S2 |
| 存档抽屉 | “保存存档 / 分支存档 / 导出”在上，“新存档 / 导入”在下 | “保存、分支、新建战役到底区别是什么？” | **S1** |
| 存档抽屉 | “本卡 / 全部”把所有卡混在一个列表里 | “这是当前战役的存档，还是别人的？” | **S1** |
| 存档抽屉 | 自动存档、最近删除、其他规则分散 | “我之前的存档还在不在？” | S2 |
| 顶部提示条 | 底部出现，压住宿主输入框 | “我正在打字，提示挡住输入框” | **S1** |
| 骰盘入口 | 主窗右下角小圆覆盖内容 | “想调骰盘，但它挡住了正文” | S2 |
| 向导 | 步骤栏 + 大片空白，缺少当前选择和完成的反馈 | “这一步做了什么？下一步会发生什么？” | S2 |
| 设置 | 内容少、留白大，次要文字偏淡 | “页面很空，但重点也不明显” | S3 |
| 整体配色 | 羊皮纸米黄 + 大面积酒红 + 金色 + 衬线标题 | “暖色方向对，但像模板/手游，不够现代” | S2 |
| 深色模式 | 大面积金色块 + 近黑底，层级靠颜色硬顶 | “金色太抢，眼睛累” | S2 |

> 只作为下一步流程和线框的输入；最终视觉由 Gate 3/4 决定。

## 3. 用户调查结果

> 说明：只有驾驶员一位填答人，所以它是**设计偏好访谈**，不是统计问卷；结论只支持 P4 决策，不外推成“用户普遍认为”。

### 3.1 A 轮：使用场景与现状

| 主题 | 回答摘要 | 设计约束 |
|---|---|---|
| 设备 | 平板、笔记本、手机都用；SillyTavern 和 TauriTavern 都用；常用笔记本大屏 | 三宽度都要成立；宿主差异要测 |
| 明暗 | 白天浅色，晚上深色 | 两套主题都要完整，不是简单反色 |
| 使用节奏 | 一场跑团通常一直开着插件；常改战役信息、调骰盘、看资料 | 长会话不重置；常用功能随手可达 |
| 首页空态 | 不强制教程；一眼看到选规则、开始战役、新建存档、设置 | 空态要给出清楚的起步路径 |
| 首页战役态 | 一眼看到常用功能快捷入口；侧栏每个功能清楚 | 首页是控制台，不是信息墙 |
| 最不喜欢的首页 | 信息巨大、与自己操作无关、复杂、挤成一团、太空也不行 | 信息位置必须合理；密度有节奏 |
| 外壳 | 悬浮球精致化；左栏不改；页头/关闭可改 | 不改骨架，只改外观和反馈 |
| 最难用 | 存档抽屉、骰盘、库 | 库归 P5；骰盘只改调出方式；存档是 P4 最高优先 |
| 向导 | 现在差不多能用，但视觉简陋；希望简短、易用、明细 | 保留四步，补层级和反馈 |
| 存档恐惧 | 无法读取、没有存档、看不到之前的存档、误删找不回 | 存档可见性、可恢复性、错误提示必须明确 |
| 配色 | 暖黄红，但现在的羊皮纸红太 AI；要专业配色 | 保留暖黄红方向，去掉羊皮纸和过度装饰 |
| 不能动 | 首页—向导—左侧栏—右侧拉栏的结构 | 结构锁定 |

### 3.2 B 轮：视觉偏好

| 主题 | 回答 | 记录 |
|---|---|---|
| 喜欢的参考 | 3 张现代 AI 概念界面（仅风格参考，AI 图不准确） | 现代、可用、简约、配色舒服；不复制图 |
| 不喜欢的参考 | 5 张旧界面/旧人物页 | 粗糙、AI 味、没有交互提示、视觉不好看 |
| 风格组合 | 规则书 / 战役手账 + 现代生产力工具 + 冒险册 | 现代简约，但保留 D&D 风味和交互 |
| 浅色配色 | A：暖白/砂色底；暖灰做侧栏/栏目；深红只做标题和主按钮；琥珀极小面积 | 暖灰必须加入；不能大面积酒红 |
| 深色配色 | C：夜间暖黑，暗红/暖金强调 | 深色与浅色同一套语义，不另起一套 |
| 背景质感 | 完全平整，不要纹理 | 不做羊皮纸 |
| 字体 | 全部现代无衬线；术语用衬线 | 术语 + 下划线/高亮，详情在 P5；外壳先统一高亮方式 |
| 密度 | 首页空态 1–2；战役首页 3；存档抽屉 3；设置 4 | 空态松、设置紧，战役页中等 |
| 圆角 | 2–3；更利落，但该柔和处柔和 | 不是全 0，也不是全 10px |
| 装饰 | 安静简约；仅首页一张主视觉/头图 | 一个记忆点；不要满屏装饰 |
| 品牌黄 | 保留现有“经典黄色”色号作为品牌感 | 只做小面积强调，不做大块金色 |
| 深色倾向 | A–B 之间：暖黑/暖炭灰，带一点棕，但不过分 | 不要纯黑，也不要蓝黑 |
| 绝对不要 | 鲜艳饱和的绿色/其他颜色乱塞，破坏平衡 | 语义绿只用于成功状态，且低饱和、文字/图标同时表达 |

**B8 的解释：** “保留现有经典黄色，但不要旧图里那种僵硬、没有视觉层次的画面。” 如果你原意不是这个，请在 Gate 1 确认时指出。

| 题 | 回答 | 处理 |
|---|---|---|
| C1 首页空态 | 选择规则、开始新战役、读取已有存档、设置、最近打开都要有 | 最近打开先留入口/空态，不造假数据；详细页后续接入 |
| C2 战役首页快捷入口 | **未回答** | Gate 1 待确认；流程里用“快捷入口区（待定）”占位，不擅自定 |
| C3 悬浮球 | A：精致化，用现成、免费、单色、纯色的骰子 SVG，不要太花哨 | 不新画图标；不新增花哨颜色 |
| C4 骰盘调出 | 保留悬浮小圆和现在样子；可在插件窗口内部拖动；改 SVG 和圆颜色 | 只改调出方式；不改骰盘内部 |

| C8 存档命名 | `保存存档 / 分支存档 / 新建战役 / 导入存档` | 不再用“新存档”指新建战役 |
| C9 存档行 | 存档名、更新时间、规则、自动/手动、父存档、备注 | 至少要显示这 6 项 |
| C10 删除 | A+B+C+D：最近删除、删除前确认、彻底删除二次确认、自动存档保留 | 可恢复优先 |

| C12 向导 | A：保留四步，只改视觉和反馈 | **与当前代码冲突**：当前只有两步；四步需要新的资料/冒险选择与后端接入，见 §13.2 |

## 4. 方向 A：存档模型

```text
酒馆角色卡 / 聊天（ownerKey）
│
└─ 当前工作区
   │
   └─ 战役（根存档：branchedFrom = 空）
      │
      ├─ 当前存档（currentSaveId）
      │   ├─ 保存：更新当前存档
      │   ├─ 分支：从当前时间线开子存档
      │   └─ 导出
      │
      ├─ 这场战役的其他分支存档
      ├─ 自动存档（读档前、新战役前等）
      └─ 最近删除（软删除）

其他角色卡 / 聊天
└─ 其他战役（默认折叠，可用“全部”查看）
```

### 4.1 术语

| 现在的说法 | 问题 | P4 说法 |
|---|---|---|
| 新存档 | 实际会新建一场空战役 | **新建战役** |
| 存档 | 有时指当前节点，有时指整个战役 | 当前战役 = 根；存档 = 节点/分支 |
| 保存存档 | 对“更新当前节点”不够明确 | 保留“保存存档”，放在当前战役区 |
| 分支存档 | 容易被理解成复制文件 | 保留，配一句“从当前时间线开新档” |
| 本卡 / 全部 | 本卡/其他卡混在一起 | 本卡优先；其他卡折叠 |
| 最近删除 | 位置不显眼 | 固定入口，可恢复 |

### 4.2 与现有实现的关系

- 现有代码里 `startNewCampaign` 创建空工作区与第一个 manual save；`branch` 从当前数据创建子存档；`branchedFrom` 已能表达父子关系。
- 方向 A 不需要新增后端“战役”实体；P4 只做 UI/UX 层的分组、命名、树形/父子展示。
- 如果以后要“一个战役下多个并列存档，不是分支”，那是方案 B，需另立后端任务，不在 P4。

### 5.2 状态清单

- 没打开聊天：不能开始战役；首页提示先打开聊天。
- 没有战役：空态；显示规则、开始、读取、最近打开、设置。

- 当前存档有未保存改动：保存按钮可用；读档前确认。

- 其他角色卡：本卡优先，其他折叠；读取时复制成本卡存档。
- 最近删除：可恢复；彻底删除二次确认。
- 导入：预览、合并/覆盖、失败原因。
- 手机：底部抽屉；安全区；不出现横向滚动。

## 7. 配色管理规则（Gate 4 使用）

按“品牌色 / 布局色 / 语义色 / 交互色”四类管理，避免后期色板膨胀。

### 7.1 品牌固定色

- **深红**：标题、主按钮、当前选中态。只做小面积，不做整屏大块。
- **经典黄/金**：保留现有品牌感，做小面积强调；不做大面积金色背景。
- **暖中性色**：不作为“品牌色”本身，属于布局色。

品牌色一旦定稿就锁定，不在每个页面重新发明。

### 7.2 布局与结构色

- 浅色：暖白/砂色背景；暖灰做侧栏、栏目、输入框边界。
- 深色：暖黑/暖炭灰；比背景略亮的灰做层级；不做纯黑。
- 亮色低对比灰与暗色次要文字可以交叉复用，减少灰色数量。
- 所有正文/次要文字满足对比度；不能靠“淡淡的灰”做层级。

### 7.3 语义色

- 错误/警告：使用与品牌深红**不同**的语义红/橙；避免“品牌红 = 失败”的心理绑定。
- 成功：低饱和绿；必须同时有图标/文字，不只靠颜色。
- 禁用：降低不透明度；仍保证可读。
- 用户明确不要鲜艳绿色或其他颜色乱入；语义色只在状态出现，不做装饰。

### 7.4 交互色

- 只保留一个交互基色（深红系）；hover/pressed 做明度阶梯。
- 链接/术语的交互样式统一；术语用衬线 + 下划线/高亮，详情在 P5。
- 命名规范在 Gate 4 定：如 `primary`, `primary-hover`, `primary-pressed`，不在组件里写死色值。

> 色值现在不选。Gate 4 从有出处的专业色阶（如 Radix Colors、Material 3、Tailwind 色阶）做 3 套候选，给出浅/深/对比度对比，再让驾驶员选。

## 8. 设计法则核对

| 法则 | P4 的应用 |
|---|---|
| **Aesthetic–Usability** | 好看不能替代可用性；Gate 5 必须测试操作，不只看截图 |
| **Doherty Threshold** | 交互反馈目标 <400ms；加载超过 300ms 显示骨架/进度 |
| **Jakob's Law** | 保留左侧栏、首页、右侧抽屉；不要求玩家重新学导航 |
| **Miller's Law** | 存档分组、首页分区；5–9 个一组；不把“7”当硬上限 |
| **Hick's Law** | 每屏一个主动作；保存/分支/新建战役分开，不在一排抢注意力 |
| **Fitts's Law** | 触控目标 ≥44×44；悬浮球和小圆可点区域足够；主按钮位置稳定 |
| **Law of Common Region** | 当前战役、这场战役的存档、其他战役、最近删除用明确区域分隔 |
| **Law of Prägnanz** | 少而清楚的形状；不做复杂纹理和过度装饰 |
| **Law of Proximity** | 战役名/存档名/保存状态靠近；操作靠近对应对象 |
| **Law of Similarity** | 链接、术语、按钮、状态使用统一视觉语言 |
| **Law of Uniform Connectedness** | 存档父子关系用连线/缩进/层级表达，不只靠名字 |
| **Von Restorff Effect** | 每屏只突出一个主动作；深红只给主操作，不遍地强调 |
| **Occam's Razor** | 首页不堆放无关信息；能删的装饰删掉 |
| **Pareto Principle** | 80% 时间用于开始/继续、保存、分支、骰盘、设置；这些优先 |
| **Parkinson's Law** | 不为了填满空白加无意义内容；空态保持安静 |
| **Postel's Law** | 输入宽容（名字、导入、跨卡读取），输出清楚（错误、来源、确认） |
| **Tesler's Law** | 复杂度由系统承担：默认规则、自动存档、分组、渐进展开 |
| **Serial Position Effect** | 页头/顶部放当前战役和存档；存档列表首尾放最重要项 |
| **Zeigarnik Effect** | 未保存标记、向导进度、未完成选择可见，促使用户完成 |

5. **下载进度**：向导里**不显示下载进度、不放大圆圈**；只在侧栏库标签上有一个**小环 + 数字**（有任务在下载或失败时才出现）；鼠标悬停（触屏点按）弹出紧凑小窗，移开即消失，**只列"正在下载 / 下载失败"的项**，不提英文原件、不列已完成项，**没有取消、继续按钮**（P5 库页再做）。
6. **下载时机**：向导里不下载；点"开始冒险"、战役创建完成之后，才在后台【库】里开始下载。向导里只用浅灰提示文字告知。
7. **提示条**：显示在**酒馆页面顶部栏下方**（酒馆自己的提示条出现的位置，宿主层），**不在插件窗口里**；点击消失；成功约 4 秒、可撤销约 6 秒、失败约 8 秒。
8. 页头[保存]与抽屉[保存存档]两处都留；分支按钮名改为**[新建分支存档]**。
9. 设置页：**[备份与撤销 ▸]**（点进去看到三项）、**[诊断 ▸]**、**[关于 ▸]**。
10. 下载进度由界面定时读 `library.tasks.list()`；资料语言**固定中文**（中英切换留到 P5 的数据条目页）。结算内核需要英文原件，会一并安装，但对用户不展示。
11. **向导错误规则**：只有两种情况会挡住按钮——第②步"核心资料目录取不到"（[下一步]不可点）、第④步"战役名为空"（[开始冒险]不可点）。冒险目录或其他书目取不到，统一只写一行"当前拉取不到书目，请之后再去库里添加"，不挡。
12. 存档抽屉：**每个战役一张卡片**，卡头是战役名（没有[读取]），卡内是这个战役的所有存档，每行左对齐、不缩进；当前存档用高亮外框（见 14.7）。
