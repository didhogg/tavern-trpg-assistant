## 1. 要改的 6 处（都是设计原文要求）

| # | 设计原文 | 现在 | 改成 |
|---|---|---|---|
| 1 | §4.1 不存条目内容，不存能重新算出的数值 | 状态里存条目全文 | 存档人物只留：引用、选择、个人调整、状态差别、骰点 |
| 2 | §1、§4.1 条目只用作者编号指 | 引用手填 | 从每件东西身上 Plutonium 自带的编号自动拆出 |
| 3 | §3.1、§3.2 内核输入是“【库】条目 + 人物（引用、选择、状态）”，先问【库】取条目 | 没有这一步 | 补“重建”：引用 → 【库】取条目 → Plutonium 导入 → 按记下的选择建卡 → 叠状态 |
| 4 | §4.3 保存时现取版本记号与覆盖，再短事务比对修订号 | 版本记号只在绑定时由调用方给一次 | 每次保存前现取（事务外），再进短事务 |
| 5 | §4.4 读档先检查要读的存档、不动当前战役；确认后自动存档再切换；缺书时相关结算暂停 | 只能检查当前战役；`loadSave` 不检查；缺书照样算 | 对存档槽做读前检查；读档走“检查 → 确认 → 自动存档 → 切换 → 重建”；缺书的那几件结算返回“缺失” |
| 6 | §4.2 撤销上限由设置决定，不写死 | `UNDO_LIMIT = 50` | 读设置 |

已经符合设计、不要动的：规则绑定、选书设置、覆盖差别、恢复原样 / 采用现在的（新分支）、修订号冲突、`.trpgsave` 格式、完整备份与大小、未保存判定。

## 2. 已查证的前提（2026-11-08，规划者在结算小窗里实测）

```
 Plutonium 导入（isTemp）后，东西身上 flags.plutonium 自带作者编号：
   火球术  → { page: spells.html, source: PHB, hash: fireball_phb,   propDroppable: spell }
   长剑    → { page: items.html,  source: PHB, hash: longsword_phb,  propDroppable: item  }
   龙裔    → { page: races.html,  source: PHB, hash: dragonborn_phb, propDroppable: race  }
   牧师    → class 导入器同样可取
 dnd5e 把建卡选择记在物品的 system.advancement[].value 上
   （龙裔：AbilityScoreImprovement {type: asi}、Size {size: med}）
 Foundry 官方 foundry.utils.diffObject 可直接找两份数据的差别
 【库】按战役取详情时带英文对照：src/library/scoped.ts ScopedDetail.english
```

导入入口（结算小窗里，Plutonium 完整启动后）：

- 法术：`game.modules.get('plutonium').api.importer.spell.pImportEntry(entry, { isTemp: true })`
- 物品、种族、职业：`await api.importer.pGetImporter({ prop: 'item' | 'race' | 'class' })`，再调用该导入器的导入方法。职业另有 `pImportEntryClass`，**先读 Plutonium 自己的用法再调**。
- 怪物：d 段已有 `api.importer.creature.pImportEntry`（`src/rules/kernel/frame/commands-monsters.ts`）。

结论：作者编号和建卡选择，官方程序本来就会记下来。这次只把它们读出来存进存档，**不自己发明记录方式，不列字段清单**。

## 3. 用词对照

| 原术语 | 大白话 | 这次的意思 |
|---|---|---|
| 引用 | 这件东西是哪本书的哪一条 | 【库】条目身份（`set/prop/hash`，见 `src/schemas/kernel.ts`） |
| 选择 | 建卡、升级时选了什么 | dnd5e 记在物品上的成长选择 |
| 状态差别 | 玩着玩着变了的东西 | 现在的人物 对比 重建出来的人物，用 `diffObject` 求出 |
| 重建 | 照着清单重新组装人物 | 引用 → 取条目 → 导入 → 按选择建卡 → 叠状态差别 |
| 版本记号 | 存档时资料的版本号 | `dataVersion`（官方版本 + 各自制包校验和） |
| 改动编号 | 每改一次加 1 | `revision` |

## 4. 改完后的流程

```
 存档
 建卡 / 打一场（结算内核）→ 改动清单 → 确认 → 写入（改动编号对得上）→ 能撤销（上限读设置）
   ▼ 拆开：
   │  引用      ← flags.plutonium 编号 → 对应到本战役【库】条目
   │  选择      ← system.advancement[].value
   │  状态差别  ← diffObject(重建出来的人物, 现在的人物)
   │  骰点      ← 照旧
   │  战斗      ← 没有归属人物的战斗改动，战役层只存一份（最少必要，不扩展战斗功能）
   ▼ 保存：事务外现取版本记号与当前覆盖 → 短事务比对改动编号 → 写

 读档
 选存档 → 读前检查（当前战役不动）
   ├ 都齐            → 确认 → 自动存档 → 切换 → 重建 → 与存档前一致
   ├ 缺书            → 列“哪个人物 · 哪件东西 · 哪本书”；能看能导出；
   │                   用到它的结算返回“缺失”；引用、选择、状态都不删
   ├ 资料 / 房规换过 → 列差别 → 恢复原样 / 采用现在的（新分支）（已有，接进读档）
   └ 结构太新 / 规则没装 → 不切换，原文件不动
```

## 5. 步骤（固定顺序，每步出问题先查方法）

| 步 | 做什么 | 出口 |
|---|---|---|
| ① 验证能否原样还原 | 用【库】真实条目：导入 → 建卡 → 拆成引用/选择/状态差别 → 重建 → 逐项比。**先写探测脚本放 `work/`，不写正式代码** | 0 差别才进 ②；有差别先查方法，两种方法仍不行按 §7 停下 |
| ② 拆分 | 内核改动 → 引用 / 选择 / 状态差别；战斗改动放战役层 | 单元测试 |
| ③ 重建 | 引用 → `ScopedLibrary` 取条目（中文战役取英文对照）→ 结算小窗里 Plutonium 导入 → 按记下的选择建卡（沿用 `commands-level.ts` 的“选择怎么填”接口，把“取第一个”换成“取记下的”）→ 叠状态差别 | 结算小窗命令 + e2e |

| ⑤ 读档 | 读前检查存档槽 → 确认 → 自动存档 → 切换 → 重建；缺书的结算返回“缺失”（五种状态之一） | 单元测试 + e2e |

| ⑦ 结构升级 | 存档结构 5→6，带迁移：旧存档里的整份内容原样保留，标“旧格式”，不丢、不猜 | 迁移单元测试 |
