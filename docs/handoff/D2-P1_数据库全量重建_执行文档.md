## 一、目标、红线、完成标准

```
 目标：新建 2014、2024 两个隔离的数据库；用通用转换器把参考库的全部游戏内容导进去；
       和旧库全量比对；驾驶员按类别确认后，在本机覆盖旧库并提交；
       推送留到 P2【库】界面修好之后
 完成：两个库建好 → 自动关全过 → 驾驶员确认比对结果 → 本机覆盖并提交 → 按 §0 第 2 条汇报
```

**总规则（驾驶员定，没有例外）**

```
 参考库里有的内容、字段、写法，一律导入：
   能贴合统一格式的 → 贴合
   贴合不了的       → 按官方原写法原样导入（字段名和结构照搬）
 不删、不跳过、不推迟、不手写补、不逐条核对
```

**红线**

1. **不写手写转换表。** 不按条目、不按字段路径、不按职业或种族名单写配置。读法按"写法"写，一种写法写一次，所有类别共用。
2. **不做数据质检员。** 不逐条对照原书或 PDF，不逐条抽检，不手工修数据。数据内容是否正确归上游（5etools 等的维护者）管。比对报告里不得建议驾驶员逐条核对。
3. **不自行缩小范围。** 草案、报告、代码注释里不得出现"暂不做""不结构化""只显示文字""不进包"这类决定。源里是文字，就按源导入文字；源里有结构，就一个字段不落地导入结构。
4. **参考库只读。** `/Users/xxx/DND- reference（DO NO DELETE！）` 下的任何文件都不得写入、移动或删除。
5. **不推送、不打远端标签。** 本任务只在本机提交；回退标签只在本机打。推送在 P2 之后，另行授权。
6. **不让子 agent 或自评判"通过"。** 结果由驾驶员确认。
7. **2024 内容和 2014 完全隔离。** 不进 2014 库，不进 2014 的下载目录，这一轮不推送。
8. **不加新依赖。** 新增 npm 依赖需要驾驶员同意。SQLite 用 Node 22 自带的 `node:sqlite`（实验特性），不稳就改用 macOS 自带的 `sqlite3` 命令。

## 四、统一格式

- **外壳不变**：编号、类型、名称、英文名、摘要、关键词、唯一、中英对照，以及 data 里的出处、署名、正文。编号规则沿用现有的"类型.英文名.来源"，保证旧存档的引用不断。
- **人物构建类**（职业、子职业、种族、亚种、背景、专长、特性、角色创建选项）里"每级获得什么、能选什么"，统一成 **9 种成长项**，照 Foundry 官方写法：
  - 生命、获得、选择、数值、属性提升、熟练、体型、子职业、修改；
  - 专精是"熟练"成长项的一种模式（Foundry 的写法）；
  - 涉及法术的"获得"和"选择"带法术设置：施法属性（固定或几选一）、次数、恢复方式。
- **选择池**：所有"从这些里选 N 个"统一成一种写法，候选可以是"明确列出的条目"，也可以是"按条件筛选"。5etools 的 choose、from、any、anyStandard、fromFilter，以及 "level=0|class=…" 这类筛选字符串，全部翻成这一种。中文版把筛选值也翻成了中文（例如 class=法师），要按名称表换回英文代码。
- **其余所有类型和字段**：按自动搬运规则原样进入统一格式。新类别（冒险正文、配方、卡组等）的格式由 Schema 和实测形状自动生成，不手画。冒险正文沿用"书籍正文"的章节、目录、正文结构，并保留区域锚点（房间编号）。
- **贴合不了的写法**：按官方原写法原样导入，字段名和结构照搬，同时在写法目录里计数。

## 五、执行步骤

### ① 准备
- 新建 `tavern-trpg-data-next/` 和上面的子目录。`AGENTS.md` 的第三个工作文件夹已由规划者写好。
- 在助手仓库建 `tools/db/`，在 `package.json` 加 `db:build`、`db:diff`。
- 可以复用旧管线里的**通用函数**：读文件、`{@标记}` 转换（`tools/data/markup`）、英文对照（`tools/data/english.ts`、`tools/data/i18n`）、打包与哈希（`tools/data/publish/write.ts`）、书目日期（`tools/data/config/books.ts`）。**不复用**旧的手写配置表（`tools/data/config` 里的职业列、熟练特质、特性规则等）和 overlay。

### ② 原样库
四个参考库全部原样入库，一条原始记录一行：来源库、文件、类别、名字（中/英）、来源书、规则版本（2014/2024）、原文 JSON 或 HTML。只排除第二节列出的网站自用文件。
- **退出条件**：每个参考库导入的条数等于源文件里数出来的条数（程序现数，不写死）。

### ③ 写法普查
- 以 Schema 打底、以真实数据为准，统计每种写法出现在哪些类别、多少条，并分成三类：
  - 简单值（走 A 层）；
  - 带含义的写法（要写 B 层读法）；
  - Schema 里没有、数据里出现了的。
- Foundry 按它自己的数据定义做同样的普查。
- **产出**：`report/写法目录`。

### ④ 通用转换器
- **A 自动搬运**：简单值原样搬过去；名称、出处、正文、96 种 `{@标记}` 共用一套；新类别的格式自动生成。
- **B 写法读法**：每种带含义的写法写一个读法，所有类别共用。例如选择与筛选、"名字|来源"引用、"累计还是新增"（5etools 是累计，Foundry 是每级新增）、额外法术、各类熟练、伤害与抗性、速度、施法、`_copy`/`_mod` 继承。
- **C 成长项**：把读出来的内容翻成 9 种成长项。
- **合并**：同一样东西只留一条，按"类型＋英文名＋来源书"认。以 5etools 为准，Foundry 补 5etools 没有的结构字段，不全书补 5etools 没有的中文正文。每个字段在出处表里记下取自哪一家；几家的值不一致时以 5etools 为准，并自动记进冲突表（只计数和分类，不逐条处理）。
- **分库**：按第二节的分法写入 2014 或 2024 规范库。两个库之间不互相引用。

### ⑤ 发布包与自动关
- 按书切包，版本 1.8.0，生成 2014 的 `catalog.json`；2024 只生成包，不生成下载目录。
- 自动关（任何一关不过即失败）：
  - 所有记录都已导入（贴合或原样）；
  - 登记过的字段在包里必须真有；
  - 两次构建结果哈希相同；
  - 包内引用不断链；
  - 2014 库里没有任何指向 2024 的引用。
- 单个包超过 20MB 时，停下告诉驾驶员。

### ⑥ 新旧全量比对（只比 2014）——**在这里停下等驾驶员**
- **旧**：`tavern-trpg-data` 的 86 个包＋SRD 包；**新**：`tavern-trpg-data-next/dnd5e2014` 的包。
- **配对**：先按编号；编号不同时按"类型＋英文名＋来源书"。配不上的分成"新增条目"和"旧库独有"。
- **逐字段比较**：成长项和选择池部分，新旧都先换算成同一张简表（第几级、获得什么、选几个、从哪些里选）再比，避免把"写法变了"算成"内容变了"。
- **旧手写修正自动判定**：新库值等于修正后的值 → 已不需要；等于修正前的值 → 新库没覆盖到；第三种值 → 冲突。
- **报告**：按类别、按书、按字段三种看法，每类给条数、原因统计和 5 个例子。分类包括：完全相同、多出字段、值不同、含义不同、新增、旧库独有、改了编号（自动生成重定向）、旧修正判定、包大小前后对比。最后给一句结论。
- 2024 库没有旧库可比，只出导入清单：书、类别、条数。
- 驾驶员对每个类别选"用新"或"保留旧"。**报告里不得建议逐条核对或手工修数据。**

### ⑦ 合并
程序按驾驶员的选择生成最终 2014 库，再跑一次比对，确认结果和选择一致。

### ⑧ 回退标签（只在本机）
- `tavern-trpg-data`：标签 `pre-d2-v1.7.1` → `c7585c9`。先确认工作区干净，86 个包和 `catalog.json` 都在。
- 助手仓库：标签 `pre-d2` → 覆盖前的最新提交。

### ⑨ 本机覆盖并提交（不推送）

- **助手仓库**：
  - 换上新 SRD 包、改版本号，加入 `tools/db/`；
  - 旧管线 `tools/data/` 移进 `tools/归档/`；
  - 依赖旧管线、旧配置或 `docs/probes` 夹具的数据测试移进归档；

## 六、停止条件（遇到就停下告诉驾驶员）

- 需要新增 npm 依赖。
- 发现本文件与 `docs/开发规范.md` §0 冲突。
