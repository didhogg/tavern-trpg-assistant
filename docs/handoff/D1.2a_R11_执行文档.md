### 3.1 `language`（语言）— 64 条（PHB 18、SCAG 20、MM 21、VGM 4、MTF 1）

```ts
languageDataSchema = z.strictObject({
  ...entryCommonFields,
  code: z.string().min(1).max(40),                    // 小写英文 id，见第 5.1 节；= ENG_name 小写，去掉首尾空白
  type: z.enum(['standard','exotic','secret']).optional(), // 来源 type：standard 8、exotic 8、secret 2，其余无此字段（不写）
  script: z.string().max(40).optional(),              // 来源 script 原样（中文名，如「龙语」「通用语」「迪泰克文」）
  scriptRule: z.string().optional(),                  // 软指针：script 对应 rule(category:'script') 的条目 id，找得到才写
  typicalSpeakers: z.array(z.string().max(120)).default([]),  // 内联字符串
  dialects: z.array(z.string().max(60)).optional(),
})
```

- **配方的数量占位**：来源 `{=amount1/v}`、`{=amount2/c}` 之类的占位由 `amountN` 填，后面的字母是**修饰符**：`v` 带分数写法（如 0.75 → ¾）、`r` 四舍五入、`f` 向下取整、`c` 向上取整、`x` 数字转文字、`l`/`t`/`u`/`a` 大小写与冠词。实现照 `reference/5etools-cn-main（数据库）/js/render.js` 的 `Renderer.applyProperties`（含修饰符的执行顺序：先 `r f c`，再 `v x`，最后 `l t u a`）与 `js/parser.js` 的 `Parser.numberToVulgar`/`Parser.numberToText`。**范围内实际出现的写法只有 5 种**：`{=amountN}`（无修饰符，原样输出数字）、`/v`、`/c`、`/xt`、`/cxt`（预盘点已核实）；其他修饰符遇到就转换失败。
- **怎么接进现有渲染器**：`renderInline`（`tools/data/markup/inline.ts`）遇到 `{=键}` 时取 `ctx.vars[键]`，键就是 `{=` 与 `}` 之间的整段（如 `amount1/v`）。配方转换器处理每一行时：扫描这行 entry 里所有 `{=键}`，按上面规则用该行的 `amountN` 算出结果，放进一个**只用于这一行的** `ctx.vars` 再调用 `renderInline`；**不要**把 `vars` 留在共享上下文里（会污染别的条目）。
- **`{@unit 数量|单数|复数}` 标签**（配方里 96 处，如 `{@unit {=amount1/v}|蛋|鸡蛋}`）：5etools 的显示规则是「数量不是数字（如分数 `½`、文字 `two`）→ 单数；数量大于 1 → 复数（没写复数就用单数）；否则单数」。数量要先把里面的 `{=…}` 渲染掉再判断。实现放在 `tools/data/markup/inline.ts` 的 `textValue` 里新增 `unit` 分支。
- **`noteCook`（厨师笔记）** → `text`（字符串 → `{p}`；`{type:'entries', entries:[{name,source,type,entries}]}` 的嵌套 → `{h, body}`）。
- **`alias`**（矩阵 `lost`）→ `data.alias` 并进 `keywords`；**`miscTags`**（矩阵 `lost`）→ `data.tags`。T1 规则「`data.tags` 只放标签类字段」：`miscTags` 本来就是标签，允许。
- **`ingredient` 块**：食材/器具字段由上面的专用转换器处理，不经过 `convertBlocks`；预盘点显示配方的 `entries`（正文）里没有 `ingredient` 块。若盘点发现有，用第 6 节钩子里的 `ingredient` 规则（渲染其 `entry`）。
- **测试**：从范围内数据各取 5 条（**配方按中文名排序取前 5；角色创建选项按（来源，名称）排序取前 5**，不挑好看的），转换 + zod 校验通过，并核对字段值：配方核对 `makes`、第一条 `ingredients[0].text`（占位已替换）、`serves`；角色创建选项核对 `optionType`、名称、正文第一段。另加 3 条定向用例：含 `amount2` 的配方（如「"剩菜"烤蛋」）的第二条食材 `text` 里 `{=amount1/c}`、`{=amount2/v}` 被正确替换；含 `{@unit …}` 的配方行（如「"剩菜"烤蛋」的鸡蛋行：6 个 → 复数形式）输出正确；含分组食材（`{type:'entries', name, entries}`）的配方得到 `{group, items}`。样本只在测试内存里，**不写进任何包**。

## 4. 编号、分包、名称、i18n 汇总

- id 格式沿用 `类型.名称slug[-附加].书`；类型前缀即条目 `type` 值（`language`、`deity`、`reward`、`cult`、`hazard`、`object`、`vehicle`、`monsterpart`（id 用小写）、`rule`、`recipe`、`charoption`）。`monsterPart` 的条目 `type` 是驼峰（`outputTypes.ts` 已这样映射），id 前缀写 `monsterpart`。

- 名称：`name` 中文，`nameEn` 英文（来源 `ENG_name`），缺英文名时 `nameEn` = 中文名，并计入 `missingName` 统计（沿用 `plan.ts`）。
- **SRD 包不得出现指向非 SRD 条目的硬引用**（现有校验已有；新类型也适用）：语言→文字系统用软指针；技能/感官等都是 SRD；神祇 SRD 条目的正文引用非 SRD 条目时，按现有「SRD 包引用非 SRD 条目」处理方式（去引用、留纯文本）——先看 `validate/refs.ts` 现有行为再沿用，不要另写。

## 5. 引用接通（阶段 D）

### 5.1 语言编号 → `language` 条目

**已核实的事实**（从已构建的包里取出的实际编号）：种族、亚种族、背景里的语言编号是**小写英文 id**，实际用到：`abyssal、aquan、auran、celestial、common、draconic、dwarvish、elvish、giant、gnomish、goblin、halfling、infernal、orc、other、primordial、terran、undercommon`；代码里的枚举 `LANGUAGES`（`src/rules/dnd5e2014/data/enums.ts`）还有 `ignan、sylvan、deep speech、thieves' cant、anystandard`。怪物的 `languages` 是**自由中文文字**（如「通用语」「能理解深渊语但无法说」），不是编号，**不在本检查范围**。

- **保持这些编号不变**（不改成条目 id，避免破坏界面 `trCode` 与已有数据），做成「可解析」。分三类，每个编号必须落在其中一类，否则构建失败：
  1. **有同名语言条目**：编号 = 语言条目 `data.code`（`ENG_name` 小写）。例：`common`、`dwarvish`、`deep speech`、`thieves' cant`、`sylvan`、`primordial`、`undercommon`。
  2. **方言编号**（4 个，没有独立语言条目，是「原初语」的方言；来源 `Primordial` 记录的 `dialects` 为 `['气族语','水族语','火族语','土族语']`）：写进新文件 `tools/data/config/languageCodes.ts` 的 `LANGUAGE_DIALECT_CODES = { auran: { parent: 'primordial', zh: '气族语' }, aquan: { parent: 'primordial', zh: '水族语' }, ignan: { parent: 'primordial', zh: '火族语' }, terran: { parent: 'primordial', zh: '土族语' } }`。测试：每个方言编号的 `parent` 有语言条目，且 `zh` 出现在该条目的 `data.dialects` 里。
  3. **伪编号**（2 个，不是具体语言）：`anystandard`（任选一种标准语言）、`other`（其他语言，见种族说明），写进同一文件的 `PSEUDO_LANGUAGE_CODES`（含中文含义）。

## 6. 正文块补全：只对 R11 的新类型生效（块转换钩子）

**原则（先看清，再动手）**：`tools/data/convert/blocks.ts` 的现状会丢信息——带名称的 `inset` 被展平丢标题、`item`/`itemSub` 只读 `entry` 不读 `entries`、没有 `type` 的命名块只递归 `entries` 丢名称、`attack` 块只拼字符串字段（`attackEntries` 等数组被丢）、`actions` 块丢名称。预盘点显示这些写法在已有数据里也大量存在（带名称的 `inset` 约 65 处、带 `entries` 的 `item` 约 358 处、无 `type` 的命名块约 2889 处）。**这些是已有条目的老问题，R11 不修**（修了会改动已有包，超出范围；已写进 `NEXT.md` 待议，留给 R14 文字清洁）。**R11 只让新类型的正文走一套更完整的转换，已有类型的输出一个字节都不能变。**

### 6.1 实现方式（照这个做，不要换方案）

1. 新文件 `tools/data/convert/blocksR11.ts`：导出 `r11BlockOptions: BlockOptions`，其中的 `extra` 是一个钩子函数 `(input, ctx, options) => TextBlock[] | undefined`：返回数组表示「我处理了」，返回 `undefined` 表示交回 `convertBlocks` 原有逻辑。
2. `BlockOptions` 接口加一个可选字段 `extra`：**用 TypeScript 模块增强**，写在 `blocksR11.ts` 里：`declare module './blocks' { interface BlockOptions { extra?: BlockExtra } }`（`BlockOptions` 已经是导出的接口）。**不要去改 `blocks.ts` 里的接口定义（会让行号移动）。**
3. `blocks.ts` 里**只做一处原地单行修改**：把第 76 行 `if (!isObj(input)) return []` 改成同一行内的 `if (!isObj(input)) return []; const hooked = options.extra?.(input, ctx, options); if (hooked) return hooked`（总行数不变，行号冻结规则不被打破；该行不被审计引用，已核实）。`convertBlocks` 内部递归时都把 `options` 原样往下传，所以嵌套块也会走钩子。
4. **所有 R11 新类型的转换函数**（语言、神祇、奖励、教团、陷阱危害、物件、载具、怪物制作部件、各 `rule` 新分类、速查、配方、角色创建选项）调用 `convertBlocks` 时一律传 `r11BlockOptions`；已有类型一律不传。
5. 回归保证：写测试 `tests/data/r11-old-types-unchanged.test.ts`——**R11 之前已有的 16 个类型的全部条目，构建前后逐条 `JSON.stringify` 相同**（唯一允许的差异是 5.3 的引用转换，这部分用纯文本比较覆盖；对「R11 前已有条目」的 `data` 做比较时，先把 `{{ref:id|显示}}` 换成显示文字再比）。快照在阶段 A 开始前由脚本生成，存 `tests/data/fixtures/r11-old-entries-before.json.gz`（体积太大就改存每条目哈希）。
