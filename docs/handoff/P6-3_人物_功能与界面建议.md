## 1 一句话结论

**三个标签（队伍 / NPC / 敌人）用同一个列表、同一个详情页，只是过滤条件不同。** 列表页管"找人、加人、整理"；详情页是一张"看得清、点一下就能掷骰、随时能改也能找回"的人物表。所有"改"都走同一套机制：**小操作立刻生效 + 可撤销；大操作先预览再确认；每一次改动都进"改动记录"，能一键退回或解除手改**。

## 5 界面建议（线框，ASCII）

### 5.1 用户流程

```
F1 最常用：新建 → 从模板（数据库）→ 加入 → 做检定
   [人物页，当前在「敌人」标签]
        │ ＋ 新建 ▸ 从模板（库）…
        ▼
   [模板面板：搜索 / 按书、挑战等级筛 → 点一个看资料卡 → 数量 3 →「加入」]（面板不关，可继续加）
        │ 提示条「已加入 地精 ×3 · 撤销」
        ▼
   [列表里出现 地精 1·2·3（归在敌人）] ──点一行──▶ [详情页] ──点技能 / 攻击──▶ （骰盘，P7）

F2 自建人物存进库，以后当模板
   新建 ▸ 分步建卡 / 空白人物 ──▶ 填好 ──▶ 人物页 ⋯ ▸ 存入我的库…（选哪个包）──▶ 提示"已存入 我的库 ·《包名》"
   以后：新建 ▸ 从模板（库）… ──▶ 在「我的库」里选这个模板 ──▶ 加入

F3 遭遇结束清怪（没有专用入口）
   「敌人」标签 ▸ 选择 ▸ 全选 ▸ 删除 ──▶ 提示条「已删除 5 人 · 撤销」

F4 敌人变 NPC、NPC 变队伍
   选中人物 ▸ 移到… ▸ NPC / 队伍 ──▶ 提示条「已把 地精首领 移到 NPC · 撤销」
```

## 7 仍要你定的两件架构问题

### C1 人物存引用，还是存数据？

```
          A 现状：存引用            B′ 存数据 + 记录来源                  C 引用 + 缺书时用的快照
关书后     人物能看、能导出，          人物完全不受影响，只有术语         人物仍可用，术语资料片没了
          用到缺书条目的结算暂停      资料片没了
条目更新    人物自动跟着变             不自动跟；有更新时提示可同步，      平时自动跟
                                      并显示差异
读档       要按引用重建一遍           直接读回，不重建                   和 A 一样要重建
体积       很小                      大（旧格式每人约 188KB）            中等
对已做后端  已完成                    推翻 P3-3b 的重建流程，最大         在 A 上加存 / 读快照
```

- **调研者倾向（未采纳）：B′。** 理由：①Foundry 官方就是这么做的（物品拖到人物身上是独立副本）；②你最早的设计就是"副本 + 记录来源，模板更新时提示可同步并显示差异"（`docs/基本蓝图.md` 第 23 行）；③它直接解决你最怕的"读档后人物不对"和"关书后人物受影响"。代价是改动最大。**如果觉得改动太大，退一步选 C。**

### C2 玩家角色"存进库当模板"用什么格式？

5etools 作者格式里没有玩家角色类别（怪物 / NPC 有 `monster`）。

| 选项 | 做法 | 后果 |
|---|---|---|
| ① 存成怪物条目 | 零例外 | 丢职业和成长信息，套用后不能按职业升级 |
