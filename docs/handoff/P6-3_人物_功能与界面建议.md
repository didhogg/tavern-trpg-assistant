任务表：P6 = B1 人物后端 → B2 列表页 → B3 详情页。你定的顺序：**需求（`P6-2`）→ 界面设计（本文）→ 逐条查后端（`P6-1`）→ 后端 → 界面实现**。
本文只做 UI 六阶段的**第 1–2 阶段**（用户流程 + 线框，ASCII）。颜色、字体、视觉等第 3 阶段起的内容，等你确认本文后再做；那时用 `oil-ui`、`ui-ux-pro-max`、`frontend-design`。
已载入的 UI skill：`ux-primer`、`interaction-patterns`、`laws-of-ux`。
界面只显示内核给的值，不在前端算数、不在前端存数据；每个功能旁标依赖的缺口行号（G 开头，见 `P6-1`），**后端我没有查**。

已定的架构（驾驶员 2026-11-15，**暂定**，后端调查时二次查证更好的做法）：
- **C1 = B′**：人物存数据（副本）并记录来源；有更新时提示可同步并显示差异。
- **C2 = ②**：玩家角色存进库用引擎原生的人物数据（批准"只收 5etools 格式"的一个例外）。

## 1 一句话结论

**三个标签（队伍 / NPC / 敌人）用同一个列表、同一个详情页，只是过滤条件不同。**
- 人物自带数据，打开不依赖库在线；库里的书被关掉 / 卸载，只是人物里的术语链接显示"资料不可用"。
- 所有"改"走同一套机制：**小操作立刻生效且可撤销；大操作先预览再确认；每次改动都进"改动记录"**，可一键退回或解除手改。
- **三种"保存"分得清清楚楚**（见 §5.0）：编辑设定的保存、保存存档、存进我的库，是三个不同的按钮。

## 5 界面预览（ASCII，第 2 阶段）

### 5.0 总览：页面和弹出面板怎么摆

```
外壳（左侧栏）──「人物」──▶ [列表页] ⇄ [详情页]        （同一区域换页，‹ 返回，不弹窗）

弹出面板（宽屏：居中模态；窄屏：底部上拉）：
   新建菜单 · 模板面板 · 分步建卡 · 选包（存入我的库）· 改动记录 · 套用模板预览
   升降级预览 · 状态与效果（自制表单）· 来源与同步
   原则：弹层里不再叠第二层弹层（decisions 2026-10-29），内容在弹层内换页

三种"保存"，位置和意思都不同（D16）：
   ┌ 人物详情页顶栏 ──────────┐   ┌ 外壳页头 ────────┐   ┌ 人物 ⋯ 菜单 ───────────────┐
   │ [保存]  = 编辑设定的草稿    │   │ ● 保存存档        │   │ 存入我的库…                │
   │          写进当前人物       │   │ = 整个战役写进存档 │   │ = 这个人物作为模板放进     │
   │          （离开即丢草稿）   │   │                   │   │   我的库的某个包           │
   └──────────────────────────┘   └──────────────────┘   └───────────────────────────┘
   游戏中的小操作（HP、法术位、次数）不经任何保存按钮：即点即生效，进"改动记录"
```

### 5.1 用户流程

```
F1 最常用：新建 → 从模板（数据库）→ 加入 → 做检定
   [人物页，当前在「敌人」标签]
        │ ＋ 新建 ▸ 从模板（库）…
        ▼
   [模板面板：筛选 → 点一个看资料卡 → 数量 3 →「加入」]（面板不关，可继续加）
        │ 提示条「已加入 地精 ×3 · 撤销」
        ▼
   [列表出现 地精 1·2·3（归在敌人）] ──点一行──▶ [详情页] ──点技能 / 攻击──▶ （骰盘，P7）

F2 自建人物存进我的库，以后当模板
   新建 ▸ 分步建卡 / 空白人物 ──▶ 填好 ──▶ 详情页 ⋯ ▸ 存入我的库… ──▶ 选包 ──▶ 提示"已存入 我的库 ·《包名》"
   以后：新建 ▸ 从模板（库）… ──▶ 来源「我的库」里选 ──▶ 加入（得到一份独立的副本）

F3 遭遇结束清怪（没有专用入口）
   「敌人」标签 ▸ 选择 ▸ 全选当前标签 ▸ 删除 ──▶ 提示条「已删除 5 人 · 撤销」

F4 敌人变 NPC、NPC 变队伍
   选中人物 ▸ 移到… ▸ NPC / 队伍 ──▶ 提示条「已把 地精首领 移到 NPC · 撤销」

F5 点错了找回
   详情页顶栏 [改动记录] ──▶ 找到那条 ──▶ [撤销到此] 或 [回自动]

F6 来源有更新（B′）
   详情页徽章「3 项有更新」──▶ 来源与同步面板 ──▶ 逐项 [同步] / [保留我的] ──▶ 提示条「已同步 2 项 · 撤销」
```

### 5.16 设计检查（`laws-of-ux`、六原则）

| 检查 | 做法 |
|---|---|
| Hick（选项数） | 新建 4 项；行尾 ⋯ 6 项；分页 5 个 |
| Fitts（点得到） | 法术位小圆点、[−][＋] 在手机上点击区不小于 44px（视觉阶段落实） |
| Jakob（惯例） | HP 点数字就地改、法术位小圆点、状态整排开关，都是 Tidy 5e / 官方表的惯例 |
| Miller（分组） | 身份与生命、战斗数值、属性、法术位、分页，五块；每块不超过 7 项 |

| Tesler（复杂度放哪） | 自动算、来源比较、同步差异都由后端做，界面只显示 |

## 8 没核实的

- **后端全部没查**（你定的顺序）：本文每个功能旁只登记依赖缺口行号。
- 线框是 ASCII 示意，不是视觉稿；颜色、字体、间距等第 3 阶段才定。
- "同步并显示差异"在 Foundry 里没有现成功能（摘要），所以这是新做；能否复用重建流程是推断（G24）。
- 钱币物品和角色身上 `currency` 字段的关系没核对（G19）。
- 参考项目没有运行；"简约好用"只对我看过的截图有效（Tidy 5e 偏深色、信息密）。
- 内核"认识"哪些状态、自定义效果能否落成人物身上的效果，都没核对（G10、G20）。
