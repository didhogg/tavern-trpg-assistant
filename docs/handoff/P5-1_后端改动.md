# P5-1 后端改动（为【库】界面）

日期：2026-11-10。来源：`P5-0_用户调查与需求.md` §1.1（R23–R91）与驾驶员 2026-11-10 的全部答复。**驾驶员已批准：按本文顺序一次做完，中间碰到问题再停下来问。**
每项一个本地提交，不推送；只跑相关单元测试和对应的快速 e2e 子集（`RULE LIST`：日常不跑全量）。

## 0. 已定口径（驾驶员 2026-11-10）

| 事项 | 口径 |
|---|---|
| 数据格式 | 只认作者（5etools）格式；自制、冒险、我的库一律不加适配层，读不出来就是没接作者现成读取 |
| 存档 | = 对资料条目的**引用** + 存档级改动（数量、等级、充能…）。资料更新不改旧存档里存的任何东西，详情默认显示新版 |
| 设置 | 全局设置、战役设置都不进存档；读档、回档不改任何设置 |
| 读档提示 | 只在三种情况：缺包（默认勾选下载）、包在但本战役关着（默认不勾）、条目版本变了（一行提示）。P4 读取确认页去掉【恢复原样】，不列差别 |
| 编辑 / 覆盖 | 所有条目都能编辑 / 覆盖；官方源的覆盖后可复原；现有"房规"（`_copy` 指向原件）就是这套 |
| 存入我的库（Q-C 甲） | 本地**原样副本**，不受源仓库更新、卸载影响；不是"变成可编辑态" |
| 官方更新（Q-A 甲） | 官方数据跟上游新提交；**只有上游作者程序版本号与插件里带的一致时才跟**，不一致提示"要升级插件" |
| 变体（R50） | 只做变体在条目旁边正确显示；覆盖功能先不做 |

## 2. 逐项设计（实施时按"实施结果"一列回填）

| 编号 | 做什么 | 怎么做（用现成的） | 实施结果 |
|---|---|---|---|
| B-20 | 战役设置不进存档 | 战役 = 一棵存档树（`core/saves/view.ts`，没有独立记录）。选书设置存在 `meta` 表 `campaignLibrary:<树根存档编号>`，同一棵树的所有存档、分支共用；读档不碰它。第一次读不到时用工作副本里的 `library` 当初值。存档里仍留一份副本（保存时同步），只作导出 / 另一台设备导入时的初值，**读档时不读回**。`setLibrary`、`check`、`checkSave`、内核 `campaignOf` 都改走它 | 待回填 |
| B-19 | 单条启用 / 停用 | 照 `chooseSource` 写单条版本 `chooseEntry`，条目单位 `entryUnit` 进 `include / exclude`（`viewOf` 早已认） | 待回填 |
| B-32 | 已下载默认开 | `viewOf`：没归类 / 不在范围的已下载来源也算看得见；排除说了算 | 待回填 |
| B-22 | 设置字段 | `librarySettingsSchema` 加 `overrideLevel`（`campaign` / `rule` / `global`，默认 `campaign`）；全库搜索书目栏折叠复用 `collapsed` | 待回填 |
| B-24 | 缺依赖一键下载 | 小窗新命令 `brewSourceUrl(source)` → 作者 `BrewUtil2.pGetSourceUrl`；`service.brewInstallSource(source)` = 查网址 + 现有 `brewAddUrl`（作者自动追装依赖） | 待回填 |
| B-34 | 读档检查三张清单 | `checkSave` 增加 `plan`：`missingPacks`（缺的包 → 怎么下，默认勾）、`closedPacks`（在但本战役关，默认不勾）、`versionChanged`（一行提示）；`scoped.fetch`：本战役关着的只要文件在也给内容；删掉 `keepSaved`、`adoptCurrent`，P4 读取确认页同步去掉对应按钮 | 待回填 |
| B-25 | 卸载连带 | `removalImpact` 的依赖从一层改传递闭包，`dependents[].mustRemove` | 待回填 |
| B-21 | 覆盖按稳定标识 | 备选编号 `doc:<docIdLocal>` 改记包的稳定标识（来源 json + 文件名 / 网址）；旧记录迁移 | 待回填 |
| B-31 | 同编号拆行 | `scoped.query / search` 增 `expand: 'alternatives'`：每个备选单独成行，带包名和"生效中"；En / 中文按包取 | 待回填 |
| B-33 | 变体显示 | 职业 / 子职特性变体数据里本来就有且作者已排在原特性后面；作者"版本"生成条目加反查 `scoped.versionsOf(ref)`（按 `_versionBase_hash`） | 待回填 |
| B-29 | 自制书 / 冒险正文 | `brew.ts` 不再跳过 corpus 加载器，走和官方同一条 `parseCorpus`（作者 `DataTypeLoaderCustomBook` 本来就读自制的 `book + bookData`） | 待回填 |
| B-18 | 排序 | 作者 `filter-<类别>.js` 的 `ModalFilter*`：`_getColumnHeaders`（列与能否排序）、`_getListItem().values`（排序值）、`fnSort`。先实测小窗能否加载；不行停下报告 | 待回填 |
| B-26 | 日志 | 各来源安装 / 解析报告已在库里；补任务失败、读档检查失败、小窗报错的按时间记录（滚动保留）+ 列出 / 导出入口 | 待回填 |
| B-28 | 拉取更新 | 自制：照作者 `pPullAllBrews` 的比较写"只检查"；官方：取上游最新提交 + GitHub 目录树指纹比出变化文件；版本号一致才可更新（Q-A 甲） | 待回填 |
| B-27 | 存入我的库 | 本地原样副本：官方书 = 库里该来源的所有条目（解析结果里每条带 `source`，插件按来源索引）经作者 `DataUtil.cleanJson` 去掉运行时字段，套 `_meta.sources`（取自作者书目）写成作者格式文件，走现有本地导入（来历 = import，进【我的库】）；自制包 = `custom.exportBrew` 原文再导入。同编号与原件按 B-31 并排 | 待回填 |
