# P6 完整建卡器第 3 段第 4 步 · 本机离线中文化

本轮按驾驶员批准的方式 A 实施。建卡画面统一使用中文显示设置，战役资料集仍可选中文或英文。现有词表中能确认是作者显示用途的文字，在离线生成时换成中文。

```text
私人完整版原件 + 现有词表最终稿 / 驾驶员批复
                 │ npm run gen:plutonium-zh
                 ▼
          本机中文构建 + 两个文件指纹
                 │
起建卡 ──▶ 建卡画面用中文设置 ──▶ 核验原件和中文构建
   │                                      ├─ 对得上 → 用中文构建
   └─ 资料与包仍按战役设置读取            └─ 对不上 → 用私人英文原件
                 │
                 ▼
        作者正常建人 → 现有保存、读回
```

## 文件和使用方式

- `tools/build-plutonium-zh.mjs` 读取本机 `vendor/private/modules/plutonium/js/Bundle.js`、现有底稿和驾驶员批复。把结果写进被 Git 忽略的 `vendor/private/lang/zh/modules/plutonium/js/`。重跑工具即可更新本机副本。
- `tools/lib/plutonium-zh.mjs` 沿用仓库已有的 TypeScript 解析器识别作者程序。自动处理已核实的显示入口，例如作者的 HTML 组件、弹窗、通知、按钮文字。比较、过滤键、选项值和模板里的计算表达式保留原样。
- `native-build.ts` 指定完整建卡器的中文界面语言。`input.ts` 允许界面语言和资料集分开设置。`frame/plutonium-build.ts` 与 `frame/plutonium-zh.ts` 在已有模块加载入口校验本机文件。缺中文构建时使用原件，指纹不符或文件异常时回退并在浏览器控制台提醒重新生成。作者的模板、数据、样式和语言包继续走现有入口。日常结算不走这个中文构建。
- 现有语言包仍给统一取字服务使用。测试从同一份底稿取按钮译文。浏览器重建产物输出到 `work/p6-zh-pack/test-dist`，保留接手时工作区已有的 `dist`。

## 实际覆盖

335 条最终稿或批复文字中，135 条在可核实的显示位置生效，共替换 293 处。135 条中有 41 条同时出现在需保留的位置。另有 158 条只有保留位置、42 条没有识别到匹配。前一轮按字段名估算的数量包含用途不明的字段。本轮采用实际调用位置作为依据。

截图能看到「选择等级」「模式」「筛选」「上一步」「下一步」「完成建卡」等中文。仍有英文的包括顶部页签、部分下拉选项和过滤项、完成进度提示。作者的规则数据、资料名及正文沿用现有流程。详细计数见 `work/p6-zh-pack/step4-build.json`。

## 收尾自检

第一版测试用静态服务器的请求日志推断浏览器成功加载了哪个版本。并发时该日志会把状态挂到后一条记录，造成误判。已改成直接监听浏览器实际响应。以后验证加载文件也用浏览器端响应和实际画面这两项。

自制包回归最初按按钮的无障碍全名查找确认控件，带图标的按钮在画面上已显示却没被找到。已沿用主建卡测试验证过的可见文字定位。以后先用作者真实弹窗验证定位，再把这一操作加进回归。
