## 4. 坑（规划者实测或前几段踩过）

1. **结算小窗在 iframe 里。** 测试脚本要先 `page.frames().find(f => f.url().includes('frame.html'))`，再在那个 frame 里取 `game`。在顶层页面直接用 `game` 会报 `game is not defined`。
2. **Plutonium 的 Bundle.js 一个小窗只能执行一次。** `convert` 命令会再执行一次作者转换器，只能在 `openKernel(..., { moduleIds: ['lib-wrapper'] })` 的小窗里用。完整启动的小窗里调 `convert` 会报 `Cannot redefine property: IS_VTT`。这次取作者编号要走完整启动 + `api.importer`，**不要用 `convert`**：`convert` 的结果行不带 `flags`。
3. `api.importer` 只直接挂了 `spell`、`creature` 等少数导入器；`item`、`race`、`class` 要用 `pGetImporter({ prop })`。不给 `prop` 会报 `One of "page" or "prop" must be provided!`。`item` 的直接属性上没有 `pImportEntry`。
4. 中文条目直接交给 Plutonium 会让规则数据出错（a 段已查明：职业标识为空，准备法术公式会坏）。中文战役重建时用 `ScopedDetail.english` 喂英文条目；**引用存的是本战役【库】里的那一条**，不要存英文那条。
5. 现成测试角色（Akra 等）的物品来自 dnd5e 自带资料包，没有作者编号。设计 §1 只允许作者编号，所以测试人物必须从【库】条目建。
6. 重建出来的东西内部编号要稳定。a 段已有确定随机源（`src/rules/kernel/frame/random.ts`，同输入同编号），先确认重建能用上它；对不上时先查这里，不要按名字硬配。
7. `levelUpApply` 没等到官方完成信号时会返回 `pending`（§3 小修已改）。重建时同样不能把超时当成功。
8. 读档会先问【库】，比现在慢：别让测试卡在等不到的操作上，每步要有超时并报出是哪一步卡住。
9. 回归里只允许已单列的报错：Entrap（转换）、`api/plutonium` 404 及成对 404、0×0 窗口提示、`KERNEL_NEEDS_INPUT` 界面渲染、`gendata-nav-adventure-book-index.json`。其他报错一律 FAIL。
10. 整套界面 e2e 会覆盖驾驶员的 M3 截图，这次不跑整套界面 e2e。
