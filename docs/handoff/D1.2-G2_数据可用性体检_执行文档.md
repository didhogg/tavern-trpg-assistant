## 0. 目标、红线、已定的决定

**目标**：用「模拟后续模块来取数」的方式，证明 M4–M7、M9 各模块要用的数据**拿去算得出结果**；**只查不修**：查出的问题登记进发现登记表，统一在 G2.5 修；交付一份「模块数据约定」，后续模块（U6.1、R1.1、L1B、U6.2、U5.x、R1.2、M7、M9）以它为准。

**为什么要做、为什么放在 D1.2b 之前**

- D1.2a 只证明了「数据存在、格式合法、和书对得上」，没证明「拿去算得出结果」。
- 后续模块不只人物：M4 里还有 L1B（全库搜索、选择器、随机表页）和 U6.2（加入敌人、随机名字），所以怪物、随机表、搜索字段在 M4 就要用。
- D1.2b 用同一套转换代码再导入 40 本书。转换代码的毛病现在修一次，50 本书都受益；导入之后再修就要全部重建。

**红线**

- **期望值不读构建输出**：每条检查的期望值来自独立来源——本地官方书中译文字（`reference/龙与地下城官方资料/txt/`：PHB、DMG、MM、XGE、TCE、SCAG、MPMM 等）、英文 PDF（TCE、SCAG）、5etools 原始数据，或按书上规则手算并在测试里注明页码。数据自己跟自己比的检查（如怪物豁免 = 调整值 + 熟练）叫「自洽检查」，报告里单独列，不算「和书对照」。
- **G2 不改数据**：不动 `tools/data/` 的转换输出、不改包、不升版本、不动 `src/rules/dnd5e2014/data/` 的 zod 模式、不动包格式；11 个包的哈希在收尾时必须与开工快照一致。修复规则（只增不改、新字段可选、旧扩展兼容、冻结文件、包版本）写在 G2.5 文档。
- 新增的代码只有测试用的读取器和工具（`tests/data/consumer/`、登记表工具）；单文件 ≤400 行，不写空 catch。
- **不改界面**。界面小毛病（起始装备括号逗号、挑战等级 0.25、摘要里的 `family·普通`）归 G3，不在 G2 做。发现界面读数据读错，记进报告留给 G3。
- 不跑整套 e2e；不推送；官方书与 `reference/` 下的参考材料只用于核对，不进数据。
- 凡下文检查项里写「补」「修」「结构化」「修正」的，G2 只做到**登记**（数量、条目清单、建议修法、`fixSource`），不动数据。
- 跨包内容一律「扩展包自己登记」（G1），读取器不得写死任何书或包。

**已定的决定**

1. **参考读取器**：一组纯函数放在 `tests/data/consumer/`，只在测试里用，模拟后续模块的读法；它们同时是「模块数据约定」里每个字段怎么读的可执行示范。后续模块可以照抄思路，不直接依赖测试目录。遇到不认识的形状**抛错**，不静默返回空；数据缺陷则记入登记表（第 8 节）。
2. **「任选」统一展开成条目编号或代码列表**；约定里只规定一种「选项池」写法。没有范围的「任选语言」约定为「全部可学语言」，不改数据。
3. **名字对不上条目的起始物品**：来源里本来就是描述性文字的（如「家系族谱」），约定为「自由文字物品」，不硬造条目；漏配的登记，G2.5 补条目编号。
4. **能力、技能、语言、伤害类型、状态、物品属性**用小写英文代码（`str`、`arcana`、`common`、`fire`、`prone`、`finesse`），约定里附对照表；界面显示的中文由对照表或条目名给出。
5. **纯文字机制特性**（只有文字、没有结构化字段的机制特性）：G2b 全部分诊成 A、B、C 三堆；A 类（影响派生数值）在 G2.5 变成结构化数据，其余按此前的决定在对应模块细化，G2 只出清单。
6. **约定改名**：「人物模块数据约定」改为 `docs/模块数据约定.md`，按模块分章。

**职业法术表的写法（a16b，驾驶员 2026-11-01 已定）**：现在法术自己写「我属于哪些职业」（`classes`）。法术在低层的包、职业在高层的包时（PHB 的法术、塔莎的奇械师），法术不能指向高层的包，于是奇械师的列表缺了大半。定下的写法：

- **职业自己的列表写在职业身上**：奇械师（在 TCE）的条目里列出全部法术编号（向下指 PHB、XGE，符合依赖方向）。
- **塔莎「扩展法术列表」**（给 PHB 职业加法术的可选规则）：由 TCE 登记，用 `joins` 新增一种 `as: "spell"`（`to` 指向职业，表示「把这个法术加进该职业的法术表，可选」）。

读法统一为：某职业的法术表 = 法术自己写的 `classes` + 职业自己列出的 + 已安装包登记进来的。**G2 只量缺口并按这个读法写好读取器的“应有读法”测试（缺口登记为 `fixSource: import-5etools`）；格式扩展和导入在 G2.5 做。**

## 8. 发现登记（G2 只查不修）

G2 **不改任何数据**：不动转换代码的输出、不改包、不升版本、不动 `src/rules/` 的 zod 模式。查出的问题登记下来，统一在 G2.5（`docs/handoff/D1.2-G2.5_数据修正_执行文档.md`）修。

1. **两种失败，处理不同**
   - **形状不认识**（读取器遇到没见过的写法）：读取器抛错，测试失败，当场处理——补读法，或停下报驾驶员。这不算数据缺陷。
   - **数据缺陷**（形状认识，但数据缺、错、对不上书）：记入发现登记表，测试通过。
2. **发现登记表** `docs/probes/D1.2-G2_发现登记.json`，每条一项：`id`、`check`（检查编号，如 `b8`）、`kind`（`data-defect` 数据缺陷 / `source-defect` 来源本身与书不符 / `decision` 需驾驶员决定）、`count`、`entries`（条目编号清单，超过 50 个只存前 50 个并写总数）、`expected`（期望值来源）、`fixSource`（`import-5etools` 5etools 原始数据里有 / `import-ref` 参考核对材料里有 / `self-structure` 要自己结构化 / `reader-only` 只需读取器处理 / `decision` 待决定）、`note`。
3. **登记表是测试的基线**：每个检查实时算出自己的发现，与登记表逐项比对——多出来的未登记发现让测试失败；登记表里有但这次没复现的也让测试失败（提示「已修复或检查失效，更新登记表」）。这样 G2.5 每修一类，测试会逼着更新登记表，最后登记表里的 `data-defect` 清零。
4. **自洽检查**（数据自己互相核对，如怪物豁免 = 调整值 + 熟练）单独标 `selfCheck: true`，不算「和书对照」。
5. 登记表和报告里的数字由脚本写出，不手填。

## 11. 停止条件（报驾驶员，不自行变通）

1. 读取器遇到不认识的形状，且不是一个小读法能解决的。
2. 来源数据与官方书矛盾，又判断不了以谁为准。
3. 某个检查的期望值找不到独立来源，只能用数据自己跟自己比（改标为自洽检查前先报）。
4. 需要改数据、转换代码或界面才能继续（G2 都不做，登记并继续；只有登记无法表达时才停）。
5. G2b 的 A 类（影响派生数值的纯文字特性）超过 150 个：照常登记，报告里单独写，等驾驶员决定 G2.5 是否分批。
