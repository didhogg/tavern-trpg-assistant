## 1 数据形状（先看数据，再谈界面）

人物在存档里只存三样（`D2-P2_B1_后端整体分块.md` §4.3、`D2-P3-3b_存档只存引用_交付.md`）：**引用**（条目的作者编号）、**选择**、**状态**（和重建出来的基准人物的差别）。条目内容不复制进人物。读档时按引用重建人物。

存档里的人物段（`src/schemas/kernel.ts`）：

| 字段 | 含义 |
|---|---|
| `id`、`name`、`seed` | 编号、名字、建卡时内核生成的种子（读档重建用） |
| `refs` | 引用的条目（`kind / set / prop / hash`） |
| `choices` | 在条目给的可选项里选了什么 |
| `state` | 和基准人物的差别：人物本身、每件物品、每个效果、新增 / 删除的物品与效果 |
| `adjustments`、`dice` | 个人调整；已掷骰点 |
| `legacy` / `legacyState` | 旧格式原样保留 |

**界面要显示的数值**（HP、AC、属性、技能、法术位……）**都由结算内核算出**。内核里跑的是 dnd5e 6.1.0 原代码，Plutonium 原包，"规则计算一行不改写，只写接线"（`D2-P3-2_结算内核实现蓝图.md` 第 14 行）。前端只显示，不算。

### 2.3 缺口（在 `src/` 里查到的；开工前要再核一次）

1. **没有给界面读人物的统一入口。**
   - `preparedActors` 的注释写明是"对答案用"，只被重建（`rebuild.ts`）和探针用。
   - `actorSummary`（`frame/commands-monsters.ts`）只服务怪物导入校验，字段是 AC / HP / 六维 / 技能 / 挑战等级 / 物品。
   - 界面现在没有现成数据能画人物行和人物页。
2. **人物登记信息没有存放处。** 旧 U6 设计里的分类（队伍 / NPC / 敌人）、标签、置顶、头像、回收站，存档人物段里没有这些字段；`src/core`、`schemas`、`stores` 里没有队伍 / 头像相关的结构。
3. **界面上没有"人物"页和入口**（`src/ui/shell`、`home`、`App.vue` 里没有）。
4. **几个检定没有接线**，见 §2.4。**注意：这是"没接线"，不是"引擎没有"。**

### 2.4 检定与结算：引擎有，内核接线有 / 没有

引擎方法来自本机 `dnd5e-6.1.x/module/documents/actor/actor.mjs`（行号为该文件）；"角色表怎么调"来自 `module/applications/actor/api/base-actor-sheet.mjs` 第 1431–1445 行的 `#roll` 处理。内核接线来自 `src/rules/kernel/frame/commands*.ts` 的命令登记。

| 角色表按钮 | 引擎方法（actor.mjs 行） | 内核命令 | 状态 |
|---|---|---|---|
| 技能 | `rollSkill`（1363） | `skill` | ✔ |
| 豁免 | `rollSavingThrow`（1625） | `save` | ✔ |
| 专注 | `rollConcentration`（1822） | `concentrationCheck` | ✔ |
| 用物品 / 法术 / 动作 | `activity.use` / `item.use` | `useItem`、`cast` | ✔ |
| 攻击、伤害 | 动作的 `rollAttack` / `rollDamage`；`applyDamage` | `attack`、`damage` | ✔ |
| 长休 / 短休 | `longRest`（2356）/ `shortRest`（2345） | `rest` | ✔ |
| 战斗里掷先攻 | 战斗的 `rollInitiative`（`commands-combat.ts` 第 69 行调用 `Combat#rollInitiative`） | `combatStart` | ✔ |
| 通用骰式（可选 d20 / 伤害 / 基础骰类，带选项） | Foundry 的 Roll | `roll` | ✔ |
| **属性检定** | `rollAbilityCheck`（1602） | — | **引擎有，内核命令没有** |
| **死亡豁免** | `rollDeathSave`（1729） | — | **引擎有，内核命令没有** |
| **工具检定** | `rollToolCheck`（1392） | — | **引擎有，内核命令没有** |
| **生命骰** | `rollHitDie`（2049） | — | **引擎有，内核命令没有** |
| 角色表上掷先攻（战斗外） | 角色的 `rollInitiativeDialog`（1967）、`rollInitiative`（2003） | — | 引擎有，内核命令没有 |
| 掷职业 / NPC 生命值 | `rollClassHitPoints`（2168）/ `rollNPCHitPoints`（2221） | — | 引擎有；建卡 / 导入时是否已用到，没核对 |

- 已有命令的写法都是同一个模板：`operate(points, async () => actor(actorId).rollXxx({...}, NO_DIALOG, NO_MESSAGE))`（`commands.ts` 的 `save`、`skill`）。上面没接线的几项，引擎方法签名完全相同。
- 通用 `roll` 命令不能代替：它是"给骰式和数据掷一次"，不会走引擎的 `rollAbilityCheck` 那套熟练加值、优势来源、效果加值。
- 补这几项属于后端，**必须经驾驶员批准**；若补，应按"同一个入口、同一种写法"一次做完，不拆成几个零碎任务。

### 2.5 人物各节的字段在哪（取数参考：GG Sheet Export 的 `extractActorData`）

GG Sheet Export 是 MIT 许可的 Foundry 模块（见 §5），它的 `scripts/extract.mjs` 把 dnd5e 人物取成各节，**字段路径是现成的、带版本差异注释的**。它的 `module.json` 写 dnd5e 最低 3.0.0、**已验证到 5.3.3**（发布页的系统版本栏另写了 6.1.0，是否真支持页面没明说），所以**路径要对着 6.1 再核**。整理如下（路径相对 `actor.system`，或写明 `items`）：

| 节 | 取自哪里 |
|---|---|
| 职业与等级 | `items` 中 `type: class` 的 `system.levels`、`system.identifier`；子职用 `class.subclass`（官方取值器），或 `type: subclass` 的 `system.classIdentifier` 对上 |
| 种族 / 背景 | `items` 中 `type: race` / `background` 的名字（旧数据回退 `details.race` / `details.background`） |
| 总等级、阵营、经验、NPC 挑战等级 / 类型 | `details.level`、`details.alignment`、`details.xp.value`、`details.cr`、`details.type.value` |
| 六维 | `abilities.<键>.value / .mod / .save`（`.save.value`、`.save.proficient`） |
| 技能 | `skills.<键>.total / .passive / .ability / .proficient` |
| 熟练加值、AC、先攻 | `attributes.prof`、`attributes.ac.value`、`attributes.init.total` |
| 生命 | `attributes.hp.value / .max / .temp`；生命骰 `attributes.hd.value / .max`；死亡豁免 `attributes.death.success / .failure` |
| 速度、感官 | `attributes.movement.<类型>` + `units`（类型清单取 `CONFIG.DND5E.movementTypes`，不要遍历全部键）；感官在 `attributes.senses.ranges.<类型>` + `units`（**6.1 数据模型已核对**，`character.mjs` 第 219–221 行；旧位置 `attributes.senses.<类型>` 只剩兼容层） |
| 灵感、负重、货币 | `attributes.inspiration`、`attributes.encumbrance`（`.value`、`.thresholds`）、`currency.<键>` |
| 抗性 / 免疫 / 易伤 / 状态免疫 / 语言 | `traits.dr / di / dv / ci / languages` |
| 攻击 | `items` 中武器；**以"攻击类动作（activity）"的 `labels.toHit` / `labels.damage` 为准**，物品自己的 `labels` 只给骰面不带加值 |
| 法术 | `items` 中 `type: spell`：`system.level`、`system.school`、`system.method`（字符串）+ `system.prepared`（**6.1 里是数字不是布尔**，`item/spell.mjs` 第 52–53 行；各数值含义没核对）、`system.properties`（专注、仪式） |
| 法术位、契约、法术豁免 | `spells.spell<N>.value / .max`、`spells.pact.value / .max / .level`（6.1 里 `spells` 是按键映射，键含 `pact`，`templates/creature.mjs` 第 104、138 行）；法术豁免 DC 是 **`attributes.spell.dc`**（`templates/attributes.mjs` 第 155–157、649 行；GG 先读的旧名 `attributes.spelldc` 在 6.1 数据模型里没有）；施法属性 `attributes.spellcasting` |
| 特性 | `items` 中 `type: feat`：`system.type.value / .label`、`system.uses.value / .max` |
| 背包 | `items` 中 weapon / equipment / consumable / tool / loot / container：`system.quantity`、`system.weight.value`、`system.equipped`、`system.container`（所在容器编号）、容器的 `system.capacity.weight.value` |
| 背景故事 | `details.biography.value`（HTML）；物品描述 `system.description.value`，用 `TextEditor.enrichHTML` 处理 |

该文件作者在注释里写明的坑（B1 若做读取入口要避开）：
- 5.3 起 `attributes.senses.darkvision` 一类旧位置每次读取会报弃用，"6.1 支持消失"，要先读新位置。
- 遍历 `attributes.movement` 会把 `speed`、`max` 之类的派生值当成移动方式。
- 子职不能"随便挂给一个职业"，兼职时会错。
- 伤害公式里有 `@mod` 这类未解析变量，要用 `Roll.replaceFormulaData` 并补 `mod`。

只调研，**所有取舍写"待驾驶员定"**；我的看法单独标"调研者倾向（未采纳）"。"原文"= 我打开并读过的文件；"摘要"= 网页搜索摘要，没打开原文。

### 10.1 模板、保存、导入怎么区分（需求 R02–R07，待定 C2）

**常见做法：两层分开——库（包）和战役里的人物，动作各是各的。**

```
 Foundry
   Compendium 包（库） ──导入（拖进目录 / 右键 Import）──▶ World Actors（战役里的人物）
                       ◀──导出到 Compendium（解锁的包才能写）──
   单个人物：Export Data（导出 JSON）/ Import Data（导入 JSON，会覆盖这个人物）/ Duplicate（复制）
   场景里放下的 Token：是人物的独立副本，可以再"链接回"原人物
```

- Foundry（原文：本机 `foundryvtt-master/articles/actors.html`、`compendium.html`、`items.html`）：以上动作都是分开的；系统 / 模块自带的包里改的东西，更新时会丢。
- Roll20（摘要）：[Character Vault](https://wiki.roll20.net/Vault) 把人物表连同 Token 存进个人库，再导入别的战役；[Transmogrifier](https://wiki.roll20.net/Transmog) 是付费功能，在自己的两个战役之间复制，不能搬别人的战役。
- D&D Beyond（论坛摘要）：用"复制人物"当作备份办法。
- **和你的原则对得上**：库 / 战役分开，"导入 ≠ 保存 ≠ 套用"，在 Foundry 里就是三个不同菜单项。

**5etools 作者格式里没有"玩家角色"类别（待定 C2）。** 我打开 `report/作者的schema/brew/homebrew.json`，顶层共 111 个类别，查过 char / player / pc / sheet / party：只有 `charoption`（黑暗赠礼这类建卡选项）、`encounter`，没有人物。怪物 / NPC 有 `monster`。

玩家角色要"保存进库当模板"，可选做法（后果）：

| 选项 | 做法 | 好 | 坏 |
|---|---|---|---|
| ① 存成怪物（NPC 属性块） | 旧 U6 的做法 | 用现成 `monster` 格式，不新增格式 | 丢职业成长、等级流程，套用后升级不方便 |
| ② 存成"建卡配方"（引用 + 选择）放在用户数据库 | 配方 = 内核建卡用的 `{ 名字, 条目引用, 装备, 选择 }` | 保留成长信息 | **不是 5etools 条目**，要你批准；导出分享没有标准格式 |
| ③ 存"人物完整数据快照"（Foundry 的 Export Data 那种） | 和 §10.3 的 B 选项相关 | 套用后和原人物一模一样 | 同样不是 5etools 格式；体积大 |
| ④ 玩家角色不进库，只做"复制人物 / 存档导出" | — | 最省事 | 达不到你"自建人物存进库再套用"的需求 |

**统一接口（只是方向，调研者倾向，未采纳）**：不新造格式，而是"模板来源登记"——官方下载包、自制包、我的库、存档里的人物，各自登记成一个来源，对外都提供同样的几个操作（列出、预览、套用）。符合"登记 / 声明式、接口统一"；R03 的"统一接口"就是这个。

### 10.2 手改覆盖与随时可改（需求 R22–R25）

**引擎自带"覆盖 + 空值回自动"的做法**（原文：`dnd5e-6.1.x/module/data/actor/templates/attributes.mjs`）：
- AC：`attributes.ac.override` 默认空；有数字就盖过算出的 AC（第 348 行 `if Number.isFinite(ac.override) ac.value = ac.override`），清空回自动。dnd5e 1.4.0 发布说明（摘要）写"删掉最上面那个大数字即取消覆盖"。
- HP 最大值：`hp.max` 可以为空（第 77 行 `nullable: true`），另有 `hp.tempmax` 临时上限、`hp.temp`、`hp.value`。
- **其他数值多数是"来源值 + 加成"，没有统一的覆盖字段**，要靠我们存档人物段里的 `adjustments`（个人调整）或效果。

D&D Beyond（论坛摘要）：有"覆盖 AC"、"覆盖基础护甲 + 敏捷"两种覆盖；最大 HP 覆盖在长休后被重置是玩家常见抱怨。

**随游戏变化的值（你说不局限于血量和法术位）——在 6.1 数据模型里逐个核对过（原文，同在 `module/data/`）：**

| 值 | 位置 |
|---|---|
| 当前 HP、临时 HP、临时最大 HP | `attributes.hp.value / temp / tempmax`（`actor/templates/attributes.mjs` 77–82） |
| 生命骰 | `attributes.hd`（`actor/character.mjs` 172） |
| 死亡豁免、灵感 | `attributes.death`、`attributes.inspiration` |
| **力竭** | **不是数字字段**：由"力竭效果"的等级算出（`attributes.mjs` 453），要靠加 / 去效果改 |
| 法术位、契约法术位 | `spells.spell<N>.value`、`spells.pact`（`actor/templates/creature.mjs` 104、138） |
| 物品次数 | `uses.spent`（`shared/uses-field.mjs` 20；剩余次数是算出来的） |
| 数量、装备、同调 | `quantity`、`equipped`、`attuned`（`item/templates/physical-item.mjs`、`equippable-item.mjs`） |
| 货币 | `currency`（`shared/currency.mjs`，是**角色身上的字段**，不是物品；待定 C4） |
| 经验 | `details.xp.value`（`actor/character.mjs`） |
| 自定义资源 | `resources`（`actor/character.mjs`、`npc.mjs`） |
| 专注 | 效果（`attributes.mjs`、`templates/common.mjs` 里有专注的定义） |

这些**都落在存档人物段的"状态差别"里**（人物 / 物品 / 效果三类，`src/schemas/kernel.ts`），撤销走存档的 `undo`（默认上限 50，`D2-P3-3b` 交付文档）。**这几家产品的撤销做法我没查到可靠信息，不写结论。**

两种"手改"含义不同，界面要分清：
- **覆盖一个算出来的值**（AC、最大 HP 这类）：有覆盖 / 解除覆盖。
- **改当前状态**（当前 HP、法术位、次数）：直接改、可撤销，没有"解除覆盖"的概念。

### 10.3 人物存引用还是存数据（需求 R26，待定 C1）

**本项目现状（原文，本地文档）：**
- `D2-P2_B1_后端整体分块.md` §4.3：人物只存三样——引用、选择、状态；"条目一更新，人物看到的就是新内容；人物数据里没有过期副本"。
- `D2-P3-3b_存档只存引用_交付.md`：存档人物从 188KB+ 缩到 1.3KB；怪物走同一条。
- **缺书时**（`D2-P3_整体设计.md` 第 400 行、`D2-P3-3b…执行文档.md` 第 84–111 行）："能看、能导出、相关结算暂停、数据不丢"；读档前检查会列出"哪个人物 · 哪件东西 · 哪本书"缺了，当前战役不被动；读档后人物能打开，用到缺书条目的结算返回"缺失"。

**别家（Foundry 为原文，其余为摘要）：**
- **Foundry：存数据。** 官方文章（`items.html`）："把物品拖到人物身上会创建一个'拥有物'**副本**，与原物品互相独立，改原物品不会影响拥有物，反过来也一样"。这就是你说的"人物直接带数据"。
- D&D Beyond（论坛摘要）：内容跟着账号权限和每个人物的"内容开关"走；有玩家反映含自制装备的人物表打不开，办法是"复制人物"或重建（单个用户的说法，非官方）。
- Roll20（摘要）：Vault 整张人物表连同 Token 一起存，导到别的战役。

**三个做法对比（不选，你定）：**

| | A 现状：引用 + 选择 + 状态 | B 存完整数据（Foundry 式） | C 混合：引用不变，再存一份"已解析数据快照"，缺书时当后备 |
|---|---|---|---|
| 关书 / 卸载后 | 能看、能导出；用到缺书条目的结算暂停 | **人物完全不受影响**，只有术语资料片没了 | 平时和 A 一样；缺书时用快照，**人物仍可用**，术语资料片没了 |
| 条目更新、房规变化 | **人物自动跟着变** | 不跟（副本过期），要决定何时刷新 | 平时跟着变；快照只在缺书时用 |
| 体积 | 很小（1.3KB 级） | 大（旧格式 188KB 级） | 中等 |
| 对现有后端 | 已完成 | **推翻 P3-3b 的重建流程**，工作量最大 | 在 A 上加"存快照 / 缺书时读快照"，不动重建主流程 |
| 要额外决定 | — | 副本何时刷新、房规怎么影响 | 快照什么时候更新；快照与引用不一致时听谁的 |

和你的话对照：你要的"关书只是丢术语"，**B 和 C 都能做到**；A 做不到（缺书条目的结算会暂停）。

我没核对的：C 的"快照"能不能复用已有的"条目换算缓存"（`P5-7` 提到装书时换好的 2014 条目缓存）。

### 10.4 升级与降级（需求 R19，待定 C5）
