1. **界面不手写任何数据。** 规则正文、名称、页码、数值表一律读已安装的包；读不到就不显示，**不回退到手写文字**。判断标准：换一个数据包这段内容就该变，它就是数据。
2. **视觉以 artifact 为准，不是"参考"。** 链接 https://claude.ai/artifact/AMEiuLvooi7WCM1XMzvFg4 ，本地全文 `/Users/xxx/.claude/projects/-Users-xxx/97e3c5f5-0de9-4e30-881b-01428a961d1b/tool-results/artifact-4bb59481-1793730212-5bcb.html`（这是我自己写的那个画板，落地版必须长得像它）。每个任务动手前先读对应画板的 CSS/结构；交付时截图旁边放同一画板的参考图，并写明"和参考图还差什么"。
3. 截图必须自己逐张看（`AGENTS.md`）；截图前 `npm run build`（截图服务读 `dist`），不拿旧图交差。
4. 不"拆东墙补西墙"：改一处要查它影响的别处（窄屏/宽屏/Chrome/WebKit/暗色）。
5. 同一份名称/数据只允许一个来源（库）。不另造第二份。
6. 只在 `tavern-trpg-assistant`、`tavern-trpg-data` 两个文件夹里工作，直接在 `main`，一个任务一个本地提交，做坏了 `git revert`。推送、打标签、发布每次要驾驶员授权。
7. 大白话汇报，先说结果；失败和未验证项如实写。

## 2. 视觉标准：artifact 画板（落地版要对齐的具体样子）

画板共 8 个：**角色｜敌人｜新人物｜手机｜抽屉与弹窗｜骰盘｜状态与反馈｜对照清单**。对应关系：人物页整体、生命、属性、档案 → 「角色」「敌人」「新人物」「手机」；身份弹窗、资料弹窗、添加效果、等级管理 → 「抽屉与弹窗」。

### 2.1 色与字（artifact 的 token，已与项目一致，别再另调）
纸色 `--paper #f4ecdd`、卡片 `--card #fffcf6`、面板 `--panel #eee5d3`、描边 `--line #cbbca3` / `--line2 #e3d8c3`、墨 `--ink #2b211c`（次级 `#6c6255`）、主色酒红 `--primary #7a2e26`、金线 `--gold #b8954a`（浅 `#f1e4c3`）、危险 `--danger #a3352b`、血条 `--hp #8c2f2a`；暗色另有一套。**标题与大数字用衬线（Noto Serif SC），正文用 Noto Sans SC。**

### 2.2 骨架与密度（对应 Q0）
- 外框 `.frame`：纸色底、圆角 14、内边距 16、区块间距 14，**`container-type: inline-size`**（按容器宽，不按视口宽）。
- 卡片 `.card`：`--card` 底、1px `--line2`、圆角 12、内边距 `14px 16px`、极轻阴影 `0 1px 2px`；卡片头 `.ch`：标题 16–17px 衬线、右侧铅笔 `.ib` 38×38。
- **宽屏两栏**：`.g1 = grid-template-columns: minmax(320px, 400px) 1fr`，左栏＝身份＋生命（`.card.id`），右栏＝战斗读数＋属性（`.col` 纵向）；**容器宽 ≤ 900px 才折成单列**。图 39 在约 1500px 宽时仍是单列，说明断点/容器判断出了问题（要查是按视口还是按容器、阈值是不是被外壳栏位吃掉），不是"画得不对"。
- 下方 `.g3` 三张档案卡等宽 `repeat(3, minmax(0,1fr))`，≤ 980px 折成单列；`.g2 = 1.2fr 1fr` 用于法术/特性等并排。
- 信息密度判据：宽屏（容器 ≥ 1100px）首屏不滚动要同时看到 身份、生命、战斗读数、属性；空白区域不超过卡片内边距。
