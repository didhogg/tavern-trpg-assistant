## 1. 做了什么

```text
本战役设置（关了哪些书 / 条目）
   │ 开建卡时现算（native-scope.ts，用现有 scoped.query 的 visible，和全局搜索同一份结果）
   ▼
本战役选不到的行 ──追加进──▶ 作者自己的屏蔽名单（ExcludeUtil，作者默认行保留）
                                   │
┌── 建卡专用小窗（native-build.ts，每次建卡开一个）──────────────┐
│ 作者程序：vendor/private/modules/plutonium/（私人完整版）       │
│ 作者收下的本战役自制包 → 登记成作者「额外自制文件」（§3）        │
│   作者来源窗口 → 作者装候选（过屏蔽名单）→ 完整建卡器 → Finalize │
│   （frame/commands-native.ts：作者公开入口 charactermancer.pOpen， │
│     等作者开过的窗口全部关上；人物变了 = 建好，没变 = 取消）       │
└───────────────────────┬────────────────────────────────────────┘
                        ▼ 整份人物
   people.buildNative → 日常小窗按完整人物建回（和复制 B′ 同一条路）→ 写进存档 bases
   玩家取消 / 失败 → 存档不变；关掉专用小窗
```

| 文件 | 作用 |
|---|---|
| `.gitignore` | 加 `vendor/private/`（私人完整版不进 git、不推送） |
| `src/rules/kernel/input.ts` | `privateModules`：私人文件夹里有的模块用它，登记进 `KernelInput.moduleRoots`；换算缓存钥匙按实际模块版本算 |
| `src/rules/kernel/frame/module-roots.ts`（新） | 小窗取 `modules/<编号>/…` 文件的唯一改道处：先私人文件夹，没有（如我们自己的语言包）再自带的 |
| `frame/main.ts`、`frame/plutonium-build.ts` | 启动时装改道；非锁定版本的程序按实际取到的地址加载 |
| `src/rules/kernel/host.ts`、`open.ts` | 宿主答小窗 `modules/` 文件用同一登记；作者收下的自制包按 `brews/<包编号>/<原文件名>` 供应（§3） |
| `frame/commands-native.ts`（新）、`frame/commands.ts` | `nativeBuild` 命令 |
| `src/rules/kernel/native-scope.ts`（新） | 战役范围 → 作者屏蔽名单行（中文战役经 englishPairs 换英文编号；类别按资料实际有的全部类别，不写清单） |
| `src/rules/kernel/native-build.ts`（新） | 建卡专用小窗：开、算名单、跑、交回、关；`stop()` 放弃 |
| `src/rules/kernel/people.ts`、`src/core/backend.ts` | `buildNative` / `stopNative`；后台接线 |
| `tests/e2e/library/p6-native-build.mjs`（新）、`p6-native-brew.mjs`（新）、`harness.ts` | 端到端测试（本机没有私人完整版就跳过） |

日常结算小窗**仍用自带公开版 2.20.4**：现有重建 / 特质来源 / 起始装备等功能靠附加在公开版指纹上的出口（`plutonium-build.ts`），换完整版会断。只有建卡专用小窗用完整版。要全部换用完整版，只改「哪个小窗传 privateModules」一处，但那些出口要另行处理。

## 3. 自制包进作者建卡器（决定③停下 → 驾驶员批准修法 → 已接上）

起初（中文 2014 战役，试跑包开着）：包在作者内存仓库里（我们 `loadBrews` 用 `pSetBrew` 装的），但作者来源窗口只列 5etools / Custom URL / Upload File。原因（私人包 `Bundle.js` `Vetools._pGetLocalPrereleaseBrewSources`、`DataPipelinesListBase._pGetPipelinesBrew`）：作者的「自制」来源只来自作者设置 `dataSources.localHomebrew`（额外自制文件地址清单）和本地自制文件夹，作者按地址自己读文件（`pAddBrewFromUrl` + `DataUtil.loadJSON`）；不看内存仓库。

修法（只在建卡专用小窗登记，一处）：

```text
openKernel：作者收下的每个自制包（P5-8 准备好的那份，和作者内存里同一份）
    → 记成小窗文件 brews/<包编号>/<原文件名>
宿主 file()：认 brews/ 开头的地址，交这份（作者读文件本来就都经这一个出口）
nativeBuild：开作者来源窗口前，把这些地址写进作者设置「额外自制文件」（作者公开入口 api.config.setValue）
    → 作者来源窗口列出「试跑者; 试跑包」（本地自制）→ 玩家加选 → 作者自己读进候选
```

`p6-native-brew`（新，Chrome / WebKit 全过）：来源窗口本地自制一行 = 试跑包原文件名；加选后战士子职业候选「月影斥候 [TRP]」1 行（3 级特性「月下潜行」、7 级「月光步」显示）、种族候选「月影猫人 [TRP]」1 行；Finalize 后存档人物带两样、22 件无重复；关小窗读档读回一致。回归 `p6-native-build` Chrome 过，`make test-changed` 过。截图 `work/p6-native/brew-{chrome,webkit}/`。

没测 / 已知：

- 作者内存里同一个包有两份（我们装的 + 作者按地址读的）；这次候选、人物都没重复，包之间互相引用、本战役关掉自制包里某一条目时未测。
- 作者来源窗口不会自动勾上自制包，玩家要按住 Ctrl / Cmd 加选（作者的「世界默认来源」机制未查）——建卡页体验问题，归第 3 段。
- 房规备选（同一类自制文档）没单独测。
- 试跑包的专长「老练斥候」缺 list 条目，作者合并属性时报错（日常小窗公开版），包本身的格式问题，和登记无关。
