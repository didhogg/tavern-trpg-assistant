## 7. 小节目录与锚点（接口，格式冻结）

**锚点**：来源数据里每个 `section`、`entries`、`inset`、`insetReadaloud` 节点都有三位十六进制的 `id`，同一本书内唯一（已核实，十本书 0 重复）。**锚点 = `<书代码小写>-<id>`**，如 `phb-006`、`dmg-0aa`。全库唯一。不得自编锚点、不得重新编号。

**目录项的收集规则（对每一章独立做，先于任何改写，在原始章节点上做）：**

1. 从章节点本身开始：目录第 0 项是章本身（`level: 0`，`kind: 'section'`，`anchor` = 章锚点，没有 `parent`）。
2. 深度优先、保持数组顺序遍历章节点的所有子节点；**不进入** `type` 为 `table`、`tableGroup`、`image`、`gallery`、`statblock`、`list` 的节点（它们的子节点不是标题）。
3. 遇到 `type` 为 `section`、`entries`、`inset` **且有非空 `name`** 的节点：追加一项。`level` = 它的深度（**只数有名字的这三种祖先**；没有名字的 `entries` 不增加深度）；`parent` = 最近一个已收集的祖先的锚点（直接在章下的，上级就是章锚点）。
4. 字段：`kind` = 节点 `type`；`title` = `plainTitle(name)`；`titleEn` = `plainTitle(ENG_name)`（没有就不写）；`page` = 节点的 `page`（没有就不写）。
5. `plainTitle`：对字符串反复执行（最多 8 轮）把 `{@标签 内容|…}` 换成「`|` 前的第一段」，再不做别的处理。例：`智力（{@skill 自然}）{@dc 10}` → `智力（自然）10`。
6. **没有名字的节点、`insetReadaloud` 不进目录**，但它们的子孙若是有名字的 `section/entries/inset` 仍按第 3 条收集。

**正文里的对应：** 每个目录项（第 0 项除外）在章节条目的 `text` 里**恰好对应一个带同样 `anchor` 的标题块 `h`**；`text` 里带 `anchor` 的标题块**恰好是**目录项（第 0 项除外）。章本身的锚点只存在于 `data.anchor`，章标题不在 `text` 里重复出现。

**接口测试（冻结）：** 锚点格式、`parent` 的存在与层级关系（子项的 `level` = 上级 `level` + 1）、第 0 项的形状、目录与标题块的一一对应、全库锚点唯一。

## 8. 正文转换规则

正文由 `convertBlocks`（`blocks.ts`，不改）加书籍专用钩子 `blocksBook.ts` 转换。钩子沿用 R11 的 `r11BlockOptions.extra`（`blocksR11.ts`）的写法：`options.extra` 先于通用逻辑被调用，返回 `undefined` 表示交给通用逻辑；书籍钩子**先处理下表的类型，剩下的再交给 R11 的钩子**。选项：`{ preserveSection: true, tableGroup: false, scalarCells: true }` 加 `extra`。

| 来源节点 | 输出 |
|---|---|
| 有 `name` 的 `section`、`entries`、`inset` | `{ h: renderInline(name), body: 子节点转换结果, anchor: <书代码小写>-<id> }`（有 `id` 才带 `anchor`；嵌入的背景文字里的节点没有 `id`，就没有 `anchor`） |
| 没有名字的 `entries`、`section`、`inset` | 不产生标题，子节点直接展开（现有行为） |
| `insetReadaloud` | `{ read: […] }`（现有行为） |
| 字符串 | `{ p: renderInline(…) }` |
| `list` | `{ list: […] }`（`style`、`columns` 丢弃）；列表项本身又是 `list` 时压平成同一个 `list`（来源 3 处，均在「制作组」章：BMT、TCE、MPMM） |
| `item`（有 `entry`） | `{ p: 名称 + 正文 }`（现有行为）；`item` 带 `entries` → 标题块，无 `anchor`（R11 钩子的现有行为） |
| `quote` | `{ quote, by }`；**有 `from` 时 `by` = `by + '，' + from`，只有 `from` 时 `by` = `from`**（共 8 处，测试独立核对） |
| `abilityGeneric` | `{ p: renderInline(entry) }`（来源有 1 处，现有转换器会丢掉它） |
| `inlineBlock` | 展开它的 `entries`（来源 1 处：PHB「状态」章，一句说明加一个列表；现有转换器只认 `entry`，会把它变成空段落，所以书籍钩子单独处理） |
| `statblock` | 第 9 节 |
| `table`、`tableGroup` | 第 10 节 |
| `image`、`internal`、`gallery`、`square`、`none`、`hr` | **丢弃**（`none` 指网格节点 `{type:'none', size, distance, units}`，不是缺 type） |
| 没有 `type`、也没有 `name` 和 `entries` 的对象（`{reprintedAs}`、`{area, points}` 等元数据） | 丢弃，计数写进报告 |
| 其他任何 `type` | **构建失败**（报出类型与所在章），不得默默丢掉 |

白名单（构建期检查，违者失败）：`entries section inset insetReadaloud statblock table tableGroup list item quote image internal gallery square none abilityGeneric inlineBlock cell row`。`cell`、`row` 只出现在表格里，由第 10 节处理。

## 9. statblock → 引用列表；怪物族谱背景文字嵌入

### 9.1 引用列表

在 `planR12` 里、改写正文节点时，对**每个数组**（`entries` 或嵌入的背景文字里的 `entries`）按顺序处理其中的 `statblock` 兄弟节点：

1. 维护一个「当前串」。遇到 `statblock`：
   - 若它有 `tag`：把一项 `{ tag, name, nameEn: ENG_name, source }` 加入当前串；
   - 若它有 `prop: 'monsterFluff'`：先把（上一步加入后的）当前串收尾成一个节点 `{ type: 'bookRefList', items: […] }`（串为空就不产生），**然后**把它的背景文字节点接在后面（9.3），当前串清空；
2. 遇到任何非 `statblock` 的兄弟节点：当前串收尾（同上）后原样保留该节点；
3. 数组结束：当前串收尾。
4. 没有 `tag` 也没有 `prop: 'monsterFluff'` 的 `statblock`：**构建失败**（来源里没有这种）。

`bookRefList` 由钩子转成一个 `{ list: [字符串…] }`，每项一个字符串，**顺序与来源完全相同**。每项的生成：

```
display = 来源 statblock 的 name（中文名）
对每个 (尝试) 依次试，第一个得到 {{ref:…}} 的就用，都不行就用纯文字 display：
  ① renderInline(`{@<tag> <name>|<source>|<display>}`)      // 没有 source 时写 `{@<tag> <name>||<display>}`
  ② renderInline(`{@<tag> <ENG_name>|<source>|<display>}`)
  ③ 仅 tag 为 race：ENG_name 形如 `A (B)` 时，renderInline(`{@subrace <B> <A>|<source>|<display>}`)
     （`Dwarf (Duergar)` → 找 `Duergar Dwarf`；`Half-Elf (Variant; Drow Descent)` → `Variant; Drow Descent Half-Elf`）
deity 例外：`{@deity <name>||<source>|<display>}`（显示文字在第 4 段）。
```

`tag` 到行内标签的对应：直接用 `tag` 作标签名（`creature`、`spell`、`item`、`race`、`subclass`、`optfeature`、`reward`、`feat`、`condition`、`trap`、`hazard`、`background`、`class`、`action`、`variantrule`、`object`、`deity`、`disease`），由 `markup/tags.ts` 现有表（加上第 11 节的 `trap`）解析；**用 `renderInline` 的现有解析**，不要自己再写一套查找。`trap` 对应 `hazard` 类型（R11 把陷阱放在 hazard 里）。

结果：`{{ref:<目标 id>|<display>}}`；目标不在本章所在的包、SRD 包里时，`convertAll` 里现有的 `pruneRefs` 会把它降成纯文字 `display`——**这是预期行为**，参考嵌入块里 `pruned: true` 的 12 个就是这种；**不要**为了让它变成引用而改依赖。

参考文件里每个 statblock 有 `target`（目标 id）与 `pruned`。验收（`r12-embeds.test.ts`）：把章节条目 `text` 按深度优先顺序展开成所有 `list` 块的所有项，**参考嵌入块里 `mode` 为 `ref` 或 `refAndFluff` 的各项依次（保持顺序）必须是这个序列的子序列**：`pruned` 为 false 的项等于 `{{ref:<target>|<name>}}`，`pruned` 为 true 的项等于纯文字 `<name>`。未解析（`target` 为 null 且 `mode` 不是 `fluff`）的数量必须是 **0**。

### 9.2 `prop: 'monsterFluff'` 的背景文字（471 个）

数据来自构建里已经读入的 `data.fluff`（`FluffRecord`，`kind === 'monster'`，已经解决了 `_copy`）。查找键：`ENG_name` 或 `name` 与 statblock 的 `ENG_name` 或 `name` 相同，且 `source` 相同。找不到、或 `entries` 为空：**构建失败**（已核实 471 个全部找得到、全部有内容）。

### 9.3 嵌入方法

1. `structuredClone(record.raw.entries)`（**必须深拷贝**，原对象与怪物条目的 `_lore` 共用，R9 已就地改过）。
2. 若拷贝出的数组第一个元素是 `section` 或 `entries`、有名字、且名字（中文或英文）与 statblock 的相同（共 68 个）：去掉这一层，保留里面的内容和后面的兄弟（与 R8 的 `unwrapLore` 同一规则；对应 `isSkipRootName`）。
3. 对拷贝里的节点应用本章的全部改写（嵌套的 `statblock`、表格、图片等，规则相同；其中的有名字节点**没有 `id`，所以没有锚点**，也不进小节目录）。
4. 把结果节点数组**直接接在**引用列表节点之后（`tag` 与 `monsterFluff` 同时存在时：先引用列表，后背景文字）。

背景文字会和怪物条目自己的 `_lore` 重复一份（121 个有 `tag` 的）：这是有意的——书里就是这样排版的。

## 10. 表格 → `tableRef` / 行内表

### 10.1 匹配（必须按这个算法，用 R9 的函数，不得改它们）

`r9lib.ts` 已有 `parseLabel`、`rangeOf`、`cellText`、`refRows`、`normRaw`，`planR9.ts` 返回 `survivorByCandidate`。**本轮对 `planR9.ts`（新文件，不在冻结范围）只加两处**：返回值多带 `pool: R9Candidate[]`（候选全表）；导出一个函数 `tableLabel(survivor)`，规则就是现在 `planR9` 里算 `label` 的那一行（表名 +（可掷表）`（骰子存储写法）`）。

对来源里每个 `table` 节点（顺序见 10.3），计算「内容键」：

```
parsed = parseLabel(colLabels[0])                     // 可掷表有，对照表没有
行 = 每个 row（数组，或 {type:'row', row:[…]} 取 .row）
可掷：每行 rg = rangeOf(row[0], parsed.hi)；任何一行失败 → 本表「不可匹配」
      cells = row.slice(1).map(cellText)；键 = JSON.stringify([parsed.expr, 行.map(r => [r.min, r.max, r.cells.map(normRaw).join('|')])])
对照：行 = refRows(rows)（任何行失败 → 不可匹配）；键 = JSON.stringify([null, 行.map(r => [null, null, r.cells.map(normRaw).join('|')])])
候选键：对 R9 的 pool 里每个候选 c，同样算一遍（可掷用 c.expr，ref 用 null；行用 c.rows 的 min/max/cells）
匹配集 = 键相同 且 c.source === 本书代码 的候选 → 取它们的幸存者（survivorByCandidate；候选自己是幸存者就是它自己）→ 去重后的 id 集合
```

- 集合恰好 1 个 → **`tableRef`**：`{ type: 'tableRef', id, label: tableLabel(幸存者) }`；
- 集合为 0 个，或「不可匹配」→ **行内表**（10.2）；
- 集合 ≥ 2 个 → **构建失败**（已核实 0 个；内容相同的两张阵营表「NPC阵营」与「智能魔法物品阵营」靠骰式和范围区分，所以**键里必须包含骰式和范围**）。
- **只做精确匹配，不做相似度匹配**（已核实 674 个全部精确命中，相似度匹配一个都没用上）。
- 幸存者的 `source` 必须等于本书代码，或幸存者在 SRD 包（已核实 0 个违例）；违例就停。

### 10.2 行内表（3 个：DMG「反派的计谋」「反派的手段」，MM「龙的年龄层」）

`bookTable` 节点由钩子转成 `{ table: { caption?, cols, rows } }`：
- `caption` = `renderInline(caption)`（没有就不写）；
- `cols` = `colLabels` 每项 `renderInline(refCell(label))`；若某一行比 `cols` 宽，`cols` 末尾补 `第N列`（N 从 `cols.length + 1` 起，补到最大行宽；R9 的同款规则）；
- `rows` = 每行（数组，或 `{type:'row', row}` 取 `.row`）每格 `renderInline(refCell(cell))`；数字单元格按 `String(n)`；`refCell` 是 `r9lib.ts` 的现有函数（支持字符串、数字、`{entry}`、`{roll:{exact}}`、`{roll:{min,max}}`、`{type:'entries',entries:[字符串…]}`，其他形状抛错）；
- 行数必须与来源相等（44、107、4）。

### 10.3 顺序与嵌套（测试按这个顺序对照）

- 表块的**文档顺序** = 深度优先、数组顺序遍历章节点；遇到 `statblock` 且有背景文字时，背景文字里的表**紧接在该 statblock 之后**按同样顺序遍历（9.3 的嵌入位置）。
- **嵌套表**：表格的某个单元格本身是一个 `table` 节点（只有 2 个，在 DMG「魔法物品表G」「魔法物品表I」里）。外层表**照常**按 10.1 匹配（外层单元格在键里是 `cellText` 的结果，即空串；已核实与 R9 的候选一致，对上了），换成 `tableRef`；内层表**不丢**：R9 已把这两张子表补成独立的可掷表（`table.magic-item-table-g.dmg-row12-14`「魔法物品表G·异能塑像」d8、`table.magic-item-table-i.dmg-row76`「魔法物品表I·魔法护甲」d12；外层表的对应行带 `then`，见 `r9Nested.ts`），所以内层表按 10.1 同样匹配成 `tableRef`，紧跟在外层表之后输出，多个内层表按它们在外层表里出现的行、列顺序。输出里嵌套表的下标就在外层表后面（参考表对应里 `nestedIn` 记录外层的序号）。
- `tableGroup`：`{ h: renderInline(name), body: [成员表按 10.1/10.2 的结果…] }`，**没有 `anchor`**，不进小节目录；`tableGroup` 来源有 15 个，成员顺序不变。
- **嵌入的背景文字里可能已经有 `tableRef` 节点**：R9 把怪物条目 `_lore` 里的表就地换成了 `tableRef`，而背景文字与 `_lore` 是同一批对象，所以深拷贝出来的节点里这些表已经是 `{ type: 'tableRef', id, label }`。**原样保留**，算作一个 `ref` 表块（参考表对应里该位置的 `tableId` 必须与它的 `id` 相同；不同就停，第 16 节第 3 条）。仍是 `table` 的才按 10.1 匹配。
- 验收（`r12-tables.test.ts`）：按深度优先顺序遍历每章 `text`（含 `h.body`、`read`），收集所有 `tableRef` 与 `table` 块，**顺序与数量必须与参考表对应里该章的列表逐项一致**：`mode` 为 `ref` 的对应 `tableRef.id === tableId` 且 `label` 相同；`mode` 为 `inline` 的对应 `table` 块且 `caption` 与行数相同。全库书籍章节里除这 3 个外**不得有别的 `table` 块**。

> 这两张子表在 R9 里的位置：它们在来源里是外层表某一行的单元格，不是独立的表块，所以不在 R9 的 1,552 个候选里；`planR9` 选完幸存者后由 `r9Nested.ts` 补建（R9 表总数 1,097），并给外层表对应行（「魔法物品表G」第 12—14 行、「魔法物品表I」第 76 行）加 `then`。
