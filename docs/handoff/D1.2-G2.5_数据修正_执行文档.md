## 0. 目标、红线

**目标**：把 G2 登记的全部 `data-defect` 修掉（`source-defect` 与 `decision` 按驾驶员的决定处理），使发现登记表里的 `data-defect` 清零，后续模块读到的数据都能直接用；并按「资源与休息」结构把休息恢复、资源消耗做成结构化数据，供【活动】系统自动结算。较多时分批，每批独立验证、独立提交。

**红线**

- **修在转换代码里，由构建产出**，不手改包。`tools/data/convert/` 下 11 个冻结文件（blocks、common、featRule、foundry、item、items、monster、plan、spell、variants、versions）只允许末尾追加或单行原地修改；新逻辑写新文件。单文件 ≤400 行，不写空 catch。
- **只增不改优先**：能「在旁边加一个解析好的字段」解决的，不改已有字段；必须改已有字段的（`uses` 删除或改写、价格小数、亚种体型等），逐条进 `g2-additive` 放行清单并写理由，基线是 G2 开工快照（`docs/probes/D1.2-G2_快照.json`）。
- **新字段一律可选**，`dataVersion` 保持 3；已发布的扩展 0.2.0（提交 `f4eddfe`）必须仍能安装 G2.5 之后的新包——有专门的测试。已核实：扩展安装时只按条目外层格式校验（`src/core/packs/recognize.ts` 用 `entrySchema`，`data` 是任意对象），不按各类型字段校验，所以新字段与小数价格不会让旧扩展拒收。
- 数据格式的改动同步 `src/rules/dnd5e2014/data/` 的 zod 模式、`docs/units/D1_数据管线.md`、`docs/包格式说明.md`（涉及包作者的部分）、字段覆盖矩阵、`docs/模块数据约定.md`。没登记的字段让构建失败（沿用现有规则）。
- 期望值仍来自独立来源（见 G2 文档第 14 节）；**从 5etools 导入的数据，核对时不能拿 5etools 自己当期望值**，要用原书或 D&D 5e API / Foundry 的 SRD 数据。
- 跨包内容一律「扩展包自己登记」；不改界面（界面归 G3）；不跑整套 e2e；不推送。
- 参考材料（`reference/`）只核对，不进数据；要把其数值写进仓库的测试夹具，先问驾驶员。

## 1. 修正原则（驾驶员 2026-11-01 定，全程适用）

1. **从简 = 降低玩家操作**，不是删结构、降精度。能让系统替玩家自动处理的（休息时恢复哪些资源、特性消耗哪个次数池、价格算账）都做成结构化数据。
2. **不给数据加对玩家没用、只会徒增操作的内容**；规则里少见的特例不加开关，留在文字说明里，让玩家看到后自己在人物面板里手动处理（例：奇械师的条件性火器熟练）。
3. **数值不丢精度**：货币以铜币为单位，精确到一位小数。
4. 拿不准是否要结构化时，**先给驾驶员预览、征求意见**，不自行判定「不做」。
5. 只删真正错误的数据，不靠删数据来「简化」。

### 2.5 资源与休息（方案 A，驾驶员 2026-11-01 批准）

给【活动】系统（短休、长休、过一天/黎明）和人物卡「使用特性」自动结算用。四样结构：

| 结构 | 管什么 | 字段 |
|---|---|---|
| 次数池 `uses`（已有，扩充） | 最多几次、什么时候恢复、恢复多少（默认全部） | 已有 `max`、`recharge`；恢复时机词表加 `dawn`（黎明，**单独记**，不并入长休；活动页怎么触发留到活动模块定）；新增可选 `recoverAmount`（如「黎明恢复 1d6+1」，不写 = 全部） |
| 消耗 `consumes`（新） | 用一次扣哪个池、扣几次 | `consumes: { pool: 池的特性编号, amount: 数 }` |
| 恢复 `restores`（新） | 在什么时机给哪个池恢复多少、有什么限制 | `restores: [{ pool, on: short/long/shortOrLong/dawn/initiative, amount: "all"/数/公式, condition?: 文字, limit?: 次数池 }]` |
| 状态 `tracker`（新） | 不是次数、但休息时要重置的状态 | `tracker: { kind: escalate/perTarget/choice, start?, step?, reset: short/long/shortOrLong }` |

生命值、生命骰（长休恢复一半）、法术位（长休全恢复）是**通用规则**，在规则引擎里，不进条目；魔契师契约法术位短休恢复已在其施法数据里。

## 4. 每批的做法与验证

```
 选一批
   ↓ 改转换代码 / zod 模式 / 包格式
   ↓ 构建（TRPG_DATA_TAG=main npm run build:data），两次哈希相同
   ↓ g2-* 测试按新结果更新登记表（该批的 data-defect 减少）
   ↓ g2-additive 通过（改了已有字段的逐条有理由）
   ↓ 旧扩展 0.2.0 装新包通过
   ↓ npm run check、npm run test:data
   ↓ 快速 e2e 子集（库）+ 升级场景（E2E_SUITE=upgrade）
   ↓ 报告写一节，本地提交，停下等驾驶员「继续」
```

- 批次顺序：① 导入类 → ② 统一写法类 → ③ 结构化类 → ④ 格式扩展类（资源与休息、`as: "spell"`）。④ 的新字段先写格式与读取器测试，再填数据。
- **包版本**：G2.5 全部做完后统一升到 **1.4.0**；若分多次推送，每次各升一个小版本。批次之间不推送；推送、刷新目录缓存仍按当次授权。
- 数据有变化时才跑快速 e2e 与升级场景；整套 e2e 只在 G2.5 全部结束且驾驶员同意时跑。

## 6. 停止条件

1. 某项修复必须改已有字段的含义，或波及超过放行清单的条目。
