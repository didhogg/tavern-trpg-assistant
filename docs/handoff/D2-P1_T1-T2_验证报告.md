## 1. 背景与边界

旧 P1 的方向是“把 5etools 转成自定义数据库，再打成自定义包”。  
这次验证换了一个根因方向：

```
不把 5etools 转成第二套数据；
直接把 5etools 原样记录放进现有 .trpgpack 的 data 字段；
插件读 raw 字段，算它需要的结果。
```

本报告只覆盖：

- 现有库能不能识别、下载、安装这种包；
- 后端能不能从 raw 字段读出法术/怪物/物品/职业；
- 读不出的地方有没有被静默丢掉。

本报告**不覆盖**：

- 全量所有书、冒险、种族、背景、专长、随机表（T3 已扫源清单，但本报告仍不覆盖全部读取结果与界面）；
- 法术/怪物正文的最终界面；
- 中英切换界面；
- 真机 SillyTavern；
- 旧/新全量比对和按类别切换。

## 3. T2：后端读取跑通

### 3.1 目标

把 T1 装好的 4 个包读成后端能直接用的结果，并统计每类有多少条能读、多少条只能显示原文。

### 3.2 做法

1. 先只读扫描 4 个包的真实字段，不猜 DND 字段。
2. 新增后端只读读取器：
   - `src/core/source/5etools/reader.ts`
   - `src/core/source/5etools/index.ts`
3. 标签解析：
   - 5etools 行内标记（`{@damage}`、`{@dc}`、`{@hit}`、`{@atk}`、`{@scaledamage}` 等）读成骰子/DC/命中/攻击。
   - 项目里已有 `tools/data/markup/inline.ts`；后端只保留计算需要的子集，不处理网页样式。

4. 职业特性按 raw 引用串归位：
   - `名字|职业|来源|等级`
   - `名字|职业|来源|子职业|子职业来源|等级`
5. 全量跑 1,934 条，输出覆盖报告。
6. 加 5 个单元测试，跑类型检查和构建。

## 4. 关键结论

```
旧做法：
5etools → 手写转换器 → 第二套数据 → 自定义包 → 界面

新做法：
5etools 原样 → 现有 .trpgpack 的 data → 现有库 → 后端读取器 → 界面
```

- 不需要重建一个自定义数据库。
- 不需要重写安装器/识别器。
- 不需要按书、按条写转换表。
- 需要的是：包内查找表、全量包生成、校验、以及后续 UI 按真实数据接入。
