# P5-6 规则方向与扩展调研（Foundry VTT / Roll20）

> 2026-11-12。驾驶员当日批准方向（三层路线，见 §4）；任务总纲已加 P5.6「规则接入口设计与区分实现」、进阶 P13「插件可拓展性」、P14「规则变换、Roll20 角色卡兼容」。

## 1. 两家怎么适配不同规则

```
   Foundry VTT                          Roll20
   ┌────────────────────┐              ┌────────────────────┐
   │ 底座：不懂任何规则    │              │ 底座：不懂任何规则    │
   └─────────┬──────────┘              └─────────┬──────────┘
             │ 装一个「规则系统包」               │ 选一张「角色卡」
   ┌─────────▼──────────┐              ┌─────────▼──────────┐
   │ system.json 声明    │              │ sheet.json 声明     │
   │ 数据结构（人物/物品）  │              │ 一张 HTML 表单       │
   │ 计算程序（JS）        │              │ 每个格子 = 一个属性   │
   │ 资料包（怪物/法术）    │              │ 小脚本：改 A 自动算 B │
   │ 效果（改数值）        │              │ 掷骰按钮 + 结果模板   │
   └─────────┬──────────┘              └─────────┬──────────┘
   再往上：模块（钩子、加功能）              再往上：宏（一行聊天文字）
           宏（聊天宏 / JS 脚本宏）               Mod 脚本（服务器上跑）

   自动化深，一种规则要做几周到几个月          轻，一张卡就是一个表单，覆盖面广
   （官方文档原话）                            （公开仓库约 990 张卡）
```

- **Foundry**：规则 = 程序 + 数据结构（`system.json` 的 `documentTypes` + DataModel），模块从 v11 起也能加子类型。宏分「聊天宏」和「脚本宏（JS，可调全部接口）」，快捷栏 5 页 × 10 格，每个用户各有一套。也有不写代码的规则搭建系统：Sandbox、Custom System Builder。依据：本机参考库 `foundryvtt-master/articles/{system-development,system-data-models,module-sub-types,macros}.html`。
- **Roll20**：规则 = 一张会算数的表单。属性格子叫 `attr_xxx`，可增删的行叫 `repeating_xxx`；卡脚本（sheetworker）用 `getAttrs / setAttrs / on("change…")` 联动；掷骰按钮写骰式加结果模板 `&{template:…}`；宏是一行聊天文字（`[[1d20+@{属性}]]`、`?{询问}`）。

## 2. 我们现在的位置

```
   插件
   ├── 【库】   5etools 数据（作者格式）                ✔ 已做
   ├── 结算小窗  Foundry 底座 + dnd5e 6.1 + Plutonium   ✔ 已做（P3 路线 B，`D2-P3-2_结算内核实现蓝图.md`）
   ├── 规则登记  RuleRegistry：dnd5e2014 / 2024，代码里登记 ◐ 只能写代码加（`src/rules/registry.ts`）
   ├── 骰子      5etools 作者的骰子程序                  ✔ 基础版（`src/library/runtime/dice.ts`）
   └── 宏 / 脚本 / 扩展入口                              ✘ 没有
```

插件内核本来就是 Foundry 式，缺的是外面几层：规则包入口、宏、扩展钩子。

## 3. 可以直接拿来用的现成东西

| 东西 | 是什么 | 许可 | 能省什么 |
|---|---|---|---|
| Foundry 规则系统：dnd5e、pf2e、CoC7 | 现成的规则程序 | MIT / Apache-2.0 / **GPL-3.0** | 别的规则也能装进现有结算小窗（**没实测**） |
| Roll20 角色卡仓库（`Roll20/roll20-character-sheets`） | 约 990 张卡（2026-11-12 数目录） | MIT（README 原话只写了 HTML/CSS） | 覆盖大量小众规则 |
| dice-roller-parser（npm） | 读 Roll20 骰式的程序 | 包页面写支持完整的 Roll20 骰子规范 | 导 Roll20 卡时不用自己写骰式解析 |
| roll20-sheetworker-ts、K-scaffold | Roll20 卡脚本的类型定义 / 写卡框架 | MIT | 写「假 Roll20 环境」时可参考 |
| 酒馆自带：斜杠命令（`SlashCommandParser.addCommandObject`）、STScript 脚本、快速回复按钮 | 酒馆的宏系统 | 酒馆本体 | 宏系统基本不用自己造 |
| Owlbear Rodeo SDK | 轻量 VTT 的扩展接口（扩展放在 iframe 里跑） | MIT | 设计「插件扩展接口」时的参考 |

**没找到**：能在 Roll20 外面直接运行 Roll20 角色卡的现成工具。网上和 GitHub 换了 5 种说法搜过，只有类型定义和写卡框架，没有现成的运行环境。

Roll20 卡实例（克苏鲁 7 版 `Call_of_Cthulhu_7th_Ed`）：

- 一个 1.2MB 的 HTML，856 个属性格子、19 组可增删的行；
- 卡脚本里读属性 113 处、写属性 127 处，还有 13 个自动掷骰按钮（`startRoll / finishRoll`）；
- 另带 `sheet.json`（含用户选项）和 `translation.json`。

## 4. 方向（驾驶员 2026-11-12 批准）

```
 第①层 规则 = 装一个包（不写代码就能加规则）            → P5.6
   深规则：Foundry 规则系统包 → 进现有结算小窗（5e 已通）
   浅规则：Roll20 角色卡 → 进一个新的「表单小窗」          → P14
   两种都用对方自己的格式（system.json / sheet.json），不造新格式

 第②层 宏 = 借酒馆的                                    → P7 / P11
   插件往酒馆注册一批斜杠命令：/trpg-roll /trpg-hp /trpg-check ...
   用户用酒馆自带的「快速回复」排成按钮栏 = Foundry 的宏快捷栏
   AI 输出被正则抓到 → 调同一批命令

 第③层 扩展接口                                         → P13
   插件公开一个事件出口：掷完骰、生命变了、回合切换……
   别的酒馆插件或用户脚本可以监听 = Foundry 的钩子 / 模块
   JS 脚本宏放沙箱小窗里跑，最后再考虑
```

## 5. 待驾驶员定的取舍

1. **Foundry 许可风险会随这个方向变大。** Foundry 授权协议「扩展包开发有限许可」第 1 条：带底座代码的包，在没有 Foundry 本体的情况下发布、运行，是不允许的；带底座代码只限「包正常运行严格必需」的部分。插件现在随身带 `foundry.mjs` 在酒馆里跑，2026-11-07 决定 8 里驾驶员已说明风险自担。多规则若靠多装 Foundry 规则系统，插件更离不开这个底座。建议 P5.6 的规则接入口只认「规则适配器」，留出以后换底座的退路。
2. **非 5e 规则的资料来源。** 总纲写「数据源一律 5etools 格式」，可 5etools 只有 D&D。其他规则的资料只能用对方规则包自带的格式（Foundry 系统包的资料包、Roll20 卡的属性表）。调研者的看法：这仍是「上游原格式」，不算造新格式。
3. **GPL 的规则系统**（例如 CoC7）不能随插件打包发布，只能像资料一样让用户自己下载。
4. **人物数据会因规则而不同。** 5e 人物用怪物属性块（decisions 2026-11-02），Roll20 卡人物是一张属性表。P6 人物页外壳不能写死 5e 字段，这一点由 P5.6 先定。

## 6. 没核实的

- 别的 Foundry 规则系统能不能装进现有结算小窗：没实测，工作量未知。Plutonium 只管 5e，其他规则没有 5etools 到 Foundry 的导入层。
- Roll20 Mod 脚本要不要付费 Pro 账号：没查到原文。
- Roll20 新的写卡工具 Beacon SDK 还在封闭测试，许可不明，暂不考虑。
- 现有酒馆 TRPG 插件（例如 RPG Companion）只查了名字，没看实现。
