## 1. 做了什么（P3-3）

在已有 M1 存档（`src/core/saves/campaign.ts`）上**加一段**，不重建存档系统：

```
一份存档（M1 原有）
  ├─ 战役当前数据（原样保留）
  ├─ 规则 ruleId（原有）
  └─ kernel（新增，可选；旧存档没有就是“还没绑定结算内核”）
       ├─ rule + kernelVersion
       ├─ library：本战役选书设置（范围、额外加、排除、版本选择）
       ├─ dataVersion：当时官方数据版本 + 各自制包校验和
       ├─ actors[]
       │    ├─ 引用 refs（作者编号：set/prop/hash，附标签）
       │    ├─ 选择 choices
       │    ├─ 状态 state（HP、法术位、物品/效果等；由变更计划写入）
       │    ├─ 个人调整 adjustments
       │    └─ 已掷点数 dice
       ├─ revision：修订号（防旧窗口覆盖新数据）
       └─ undo[]：撤销记录（最多 50 条，记录受影响人物改前状态）
```

三个动作：

```
读档前检查（check）
  存的人物引用 → P3-1【库】按战役 fetch
    ├─ ok                    → 正常
    ├─ not-installed         → 书没装/被关
    ├─ not-found             → 条目没了
    ├─ excluded              → 本战役排除了这本书
    ├─ out-of-scope          → 不在本战役范围
    └─ unclassified          → 未归类
  → 只列出来，不删引用、不改存档、不丢数据

预览 → 确认 → 写入（preview / apply）
  变更计划（结算小窗的 changes[]）
    → preview：逐条交回改前/改后，不写
    → apply：先比对 revision；一致才写；revision +1；记撤销记录
    → 旧窗口 revision 不一致 → E_REVISION_CONFLICT，不覆盖新数据

撤销（undo）
  反向恢复受影响人物的 state；同样比对 revision
```

规则绑定：`bind` 要求 `kernel.rule === workspace.ruleId`，不一致直接拒绝（`E_RULE_MISMATCH`）；读档检查时规则不在注册表里报 `ruleMissing`。
