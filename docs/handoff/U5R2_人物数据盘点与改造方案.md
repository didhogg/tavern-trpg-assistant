### 怎么保证"一键重导不会把现在好好的数据库改坏"（现有 4 道保险 + 新增 3 条）

```
已有：
 ① 输入快照   构建先对 200 个源文件算哈希，和 tools/data/snapshot.json 比，
              有一个对不上就拒绝运行（要显式加 --update-snapshot）
 ② 只增不改   tests/data/g2-additive：重导后每个条目的每个变化路径，
              都必须在 tests/data/g2-allow/ 的放行表里登记，条数写死，多一个少一个都红
 ③ 哈希稳定   同一输入连建两次，包的 sha256 必须一样
 ④ 版本号     包内容变了必须升版本，否则设备上不会更新；推送/打标签/刷新 CDN 要驾驶员授权
新增（本方案要求）：
 ⑤ 先写到临时目录再比对   构建加"输出到临时目录"的开关，先和已发布的包逐条对比，
                           比对干净、驾驶员看过差异清单，才覆盖 packs/ 与数据仓库
 ⑥ 新字段全部可选         不改 dataVersion，旧扩展照常安装（沿用 G2.5 的做法）
 ⑦ 一个任务一个提交       做坏了 git revert；已发布的包不删旧版本
```

## 3. 数据怎么进入人物页、怎么生效

```
  内容包 (.trpgpack)                        安装器                        IndexedDB 库
  条目: class/race/background/feature/…  ──▶ 校验引用、依赖 ──────────────▶ 条目表（只读）
                                                                                │
        用户在身份弹窗点「选用 野蛮人」                                              │ cardData.ts 按已启用的包读
                                                                                ▼
  EntryFlow 选择→补选→分配 ──▶ derive/grants.ts 算出"应分配的熟练项"（带来源 auto:class.barbarian…）
                                    │
                                    ▼
                          写进 人物.block（草稿）  ← 点右上「保存」才写入存档
        block.classes / race / background / proficiencies / senses / resist …
                                    │
                    derive/*（纯函数，读 block + 库）算出：
                    属性调整值、熟练加值、AC、HP 上限、速度、先攻、被动、法术位、豁免、技能
                                    │
                                    ▼
          页面各卡显示；点任何药丸 → 打开"库条目资料片"（和库页面同一个组件）
```

要改的地方只有两处，其余照旧：
```
  现在（错）                                       改后（对）
  档案药丸弹窗 = 手写一句话 + 页码      ──▶      档案药丸弹窗 = 嵌入库条目资料片（正文、页码来自条目）
  经验值/购点/熟练加值/法术位 = 代码里的表 ──▶    读库里的表和条目（删掉代码里的表）
  代码→中文名 = zh.ts / enums.ts          ──▶      读包里的 glossary（转换器输出），删手写表
```

## 6. 现状风险（实测）

- 你放回的 `5etools-cn-main` 与当初构建所用的**不是同一版**：200 个输入文件里 41 个哈希不一致（含 items.json、races.json、backgrounds.json、spells-phb.json、变体规则、约 30 个怪物书）。快照保护会拒绝构建——这是它该起的作用。重导前必须先弄清差异（临时目录构建 + 对比），或找回原版。
- 数据测试 400 项里 9 项现在失败：它们要用 5e API 汇总 JSON（`dnd5eapi-SRD法术（核对用）`）和 PHB/MM 中文文本（`龙与地下城官方资料`），这两样不在放回的文件夹里；另有书籍致谢/目录对照受版本差异影响。
- `foundry-dnd5e-open/` 缓存没了：可用放回文件夹里的 `dnd5e-6.1.x/packs/_source` 重建，或联网按固定提交下载（需授权）。重建后必须和发布包哈希对比确认一致。

## 7. 执行顺序（每步一个提交，做完给截图/差异清单）

1. T1 页面读库：档案弹窗、感官、力竭、骰盘/读数说明 → 嵌入库条目；删手写文字
2. T2 页面读库：经验值、购点、熟练加值、法术位、体型、技能、语言、状态名
3. T3 修转换器：glossary 输出；时长缺口；先临时目录比对，驾驶员看差异后才发布
4. T4 布局：宽屏两栏、生命值/生命骰溢出、属性显示
5. T5 身份弹窗首屏、模板人物入口、铅笔
6. T6 添加状态与效果："自定义"独立标签
7. T7 收尾：检查、数据测试、e2e、再扫一遍确认没有新增手写数据
