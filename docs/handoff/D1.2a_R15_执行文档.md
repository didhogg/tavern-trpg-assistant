## 0. 目标、红线、驾驶员已定的决定

**目标**：D1.2a 收尾——①字段覆盖矩阵里 481 条 `lost` 清零；②定版（体检拦截、版本号、id 稳定、英文入库）；③最小界面改动、截图、人工抽检、报告；④本地发布提交。

**驾驶员已定**
- A：R15 只清 `lost`，**不做**「文字转结构」的深化；报告里列出仍是纯文字的机制特性清单，作为后续工作包的依据。
- B：怪物模板、传奇组模板等写理由丢弃（`dropped`），不导入成条目；若核对发现有怪物依赖模板才能显示，先报告驾驶员。

**红线**
- **只增不改**：已有条目的已有字段一个字节不变；R15 只能新增字段（新增的字段写进 zod 模式，可选）。
- `lost` 清零只有两条路：补进输出（`mapped`），或写出具体理由改成 `dropped`；**不得**用「核心无样本」之外的笼统理由，不得同一句理由用于不同字段。
- 被审计引用的 11 个 `tools/data/convert/` 文件只允许末尾追加或单行原地修改；新逻辑写新文件。
- 界面只做规格 §9 的四件事，不重排布局。
- 不联网；不推送、不发布、不安装；推送要驾驶员再说「可以推送」。
- 不空 catch；单文件 ≤400 行；文档只写现状。

## 2. 分诊：每条 lost 的处理（单一依据文件）

`docs/probes/D1.2a_R15_lost分诊.json`：每条 `lost` 路径一行：`{ path, bucket, action, to?, kind?, why? }`。
- `action`：`supply`（补进输出，`to` 写目标字段）、`mapped-i18n`（英文名，`to` 为 `i18n.en.name`）、`drop`（`kind` + `why`）。
- 由脚本 `tools/data/report/lostTriage.ts` 按下面的规则**生成初稿**，我逐条核对修订后固定；之后矩阵登记由同一份文件改写（一次性脚本），测试保证两者一致。

**分类规则（按顺序）**

| 桶 | 判定 | 处理 |
|---|---|---|
| N0 核心无样本 | `affected = 0` | `drop`，kind `out-of-scope`，why 写「核心十本书里没有该字段的记录；D1.2b 扫描非核心来源时重新评估；出现时由未登记字段检查拦截」（带路径，不得复用同一句给别的字段——why 里要含路径本身） |
| EN 英文名 | 路径以 `ENG_name`、`.caption` 结尾 | 路径含受保护词（`name`、`entries`、`activities`、`level` 等，不允许 `dropped`）→ `mapped-i18n` 到 `i18n.en.name`；否则 `drop`，kind `derived`，why「英文名由 `i18n.en` 承载（R13）」+路径 |
| TP 模板 | 路径首段含 `template` | `drop`，kind `out-of-scope`，why「模板的结果已体现在展开后的条目里，核心输出没有对应条目」+路径；**核实**：对每个模板类型，抽样确认展开结果里没有缺失（有缺失就停，第 9 节第 2 条） |
| FM 版式 | 末段是 `style`、`colStyles`、`type`（位于 `items[]` 下）、`referenceSources`、`additionalSources` 等只管排版/出处的键 | `drop`，kind `layout` 或 `internal-meta`，why 写具体键名与路径 |
| TG 分类标签 | 末段含 `Tags`、`tier`、`wondrous`、`miscTags`、`scfType`、`poison*` | `supply` 到第 3 节的 `facets` 或标量字段 |
| ST 其他 | 剩余 | 逐组 `supply`（第 3 节）；确实无法也无必要进输出的（如 Foundry 内部元数据）`drop` 并写具体理由 |

## 3. 补进输出的约定（目标字段，必须照此命名）

**分类标签 → `data.facets`**（新增，可选，`Record<string, string[]>`，值保持来源代码）：
- 怪物：`sense`（senseTags）、`language`（languageTags）、`trait`（traitTags）、`action`（actionTags）、`spellcasting`（spellcastingTags）、`saveForced`/`saveForcedSpell`/`saveForcedLegendary`（savingThrowForced*）、`conditionInflict`/`conditionInflictSpell`/`conditionInflictLegendary`、`damageSpell`/`damageLegendary`（damageTagsSpell/Legendary）。
- 种族、亚种族：`trait`（traitTags）。
- 物品、物品家族、基础物品：`misc`（miscTags）、`reqAttune`（reqAttuneTags）、`poison`、`poisonTypes`、`scf`（scfType）。
- 物品的 `tier`（major/minor）、`wondrous`（布尔）写成**标量字段** `data.tier`、`data.wondrous`。
- `data.tags`（已有的混合数组）**不动**。

**怪物**
- `attachedItems` → `data.attachedItems: string[]`，物品条目 id（用引用索引解析；解析不到的计数写进报告，不输出）。
- `spellcasting[].type/displayAs/hidden/footerEntries/chargesItem` 与 `spells.N.lower` → 写进 `data.spellcasting[]` 对应同名字段（`footerEntries` 转文字块，名为 `footer`）。
- `resist[].cond`、`immune[].cond`、`vulnerable[].cond` → 抗性、免疫、易伤项里的 `condition` 文字（转行内文字）。
- 标量与短文本原样带入（同名）：`alignmentPrefix`、`group`、`dragonAge`、`dragonCastingColor`、`familiar`、`summonedBySpell`、`summonedBySpellLevel`、`summonedByClass`、`pbNote`、`shortName`、`sizeNote`、`actionNote`、`legendaryHeader`、`type.swarmSize`（→ `creatureType.swarmSize`）、`speed.*.condition`、`speed.alternate`、`cr.xp`、`initiative`、`skill.other`。
- 怪物自带的 Foundry `effects`（6 个条目）：转成现有 `effects` 种类；转不成的输出为 `note` 种类，保留 key、mode、value 文字，不丢。

**物品、物品家族、魔法变体展开后的物品**
- `attachedSpells`（含 `daily`、`will`、`charges`、`limited`、`other`、`ability`）→ `data.attachedSpells`：`{ ability?, will?: id[], daily?: Record<'1'|'1e'|…, id[]>, charges?: Record<'1'|'2'|…, id[]>, limited?: Record<…, id[]>, other?: id[] }`，法术用法术条目 id。
- `ability`（`str/dex/…`、`choose`、`amount`、`from`、`count`）→ `data.abilityGrant`；`modifySpeed`、`light`、`staff`、`curse`、`tattoo`、`sentient`、`focus`、`spellScrollLevel`、`carryingCapacity`、`speed`、`grantsProficiency`、`grantsLanguage`、`conditionImmune`、`vulnerable`、`critThreshold`、`bonusAbilityCheck`、`bonusProficiencyBonus`、`bonusWeaponDamage`、`weightNote`、`ammoType`、`age`、`typeAlt` → 同名字段原样（文字转行内文字）。
- 载具类物品字段（`crew`、`capCargo`、`capPassenger`、`vehAc`、`vehHp`、`vehSpeed`、`vehDmgThresh`、`seeAlsoVehicle`、`seeAlsoDeck`）→ 同名。
- `additionalEntries`（基础物品 17、物品 7）→ 追加进该条目 `text`（按现有块转换；表格走 `table`）。
- 魔法变体元数据里会影响展开结果的（`inherits.attachedSpells`、`inherits.light`、`inherits.rechargeAmount` 等）：确认展开后的物品已带上这些字段（同上目标）；变体自身的 `inherits`、`type`、`referenceSources` 等是展开用的元数据 → `drop`（kind `internal-meta`，why 说明结果已在展开的物品里）。
- `_merge.effects`（Foundry 效果合并）→ 复用现有 Foundry 效果转换，无法转的 `note`。

**其他**
- `spell.abilityCheck`（32）→ `data.abilityCheck`（能力代码数组）；`action.seeAlsoAction` → `data.seeAlso`（规则条目 id 数组）；`legendary-group.page` → 写进展开后怪物的 `lair`/`regional` 说明的出处页（若无处安放则 `drop`，写理由）；`legendary-group._versions` 等模板化字段按 TP 处理。
- 以上命名的任何偏差，写进报告「命名决定」。

## 9. 停止条件（报驾驶员，不自行变通）

1. 补字段会改变已有字段（只增不改被破坏）。
2. 模板核对发现有怪物依赖模板才能完整显示（决定 B 的前提不成立）。
3. 某条 `lost` 既不能补、又给不出具体理由。
4. id 稳定检查发现 1.0.1 的 id 丢失且无法给出合理重定向。
5. 包体积超限（单包 3 MB、合计 12 MB）。
6. 界面需要超出第 5 节的改动才能正确显示。
