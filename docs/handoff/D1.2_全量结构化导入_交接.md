3. 构建时遇到未登记的字段路径就失败。报告列出每个来源文件的字段数与三种处理方式的数量。
4. 把体检报告 §1–§4 的每一项做成构建校验（`tools/data/validate/`），附例外表；例外每项写理由。
5. **去向必须真实**：`mapped` / `text` 的目标字段必须是字段真正送达的位置。`data.tags` 只用于来源字段名以 `tags`/`Tags` 结尾或为 `environment` 的标签字段（另有逐条登记理由的例外表）；其他路径指向 `data.tags` 一律拒绝。字段尚未交付的，目标写规格字段或 `plannedFields.ts` 里的规划字段，`wp` 写负责的包，该包完成后的兑现检查才会要求它出现在输出里。每个工作包完成时，除了兑现检查，还要有「去向抽查测试」：取有代表性的来源记录，断言值出现在登记的输出路径。

这样任何来源字段都不会被悄悄漏掉；以后上游新增字段时构建也会提示。

## 5. 数据结构

### 5.1 升级操作与特性（修复 D1.1 的结构错误）

- `itemGrant`：同一等级的全部特性都列出；特性正文里嵌套引用（`refClassFeature`、`refSubclassFeature`）的子特性一并授予。
- `itemChoice`：`{ kind, level, count, pool?: string[], optionKind?: string[], replaces?: string }`；5etools 的 `options{count}` 转成 `pool`。
- 新增 `trait`：`{ kind: 'trait', level, grants: string[], choices?: [{ count, from: string[] }] }`；值用标准编号加前缀：`skill:`、`save:`、`armor:`、`weapon:`、`tool:`、`lang:`。用于子职业、种族、亚种族、背景、专长的熟练授予；职业 1 级熟练仍在 `class.proficiencies`。
- `abilityScoreImprovement`、`subclass` 增加 `explain`：说明这一步的特性 id。
- `optional: 'tce-ocf'` 与 `replaces`：TCE 可选职业特性；由规则选项 `optional-class-features`（来源 TCE，`engine: 'character.optionalClassFeatures'`）控制。
- 特性 `role`：`mechanic`（默认）、`procedure`（属性值提升、选择子职业、「道途特性」等占位）、`intro`（子职业开头简介，正文同时写入子职业 `text`）。人物卡只显示 `mechanic`。
- 可选特性：去掉 `owner: optional`；`optionKind` 为编号数组（`EI` 魔能祈唤、`MV:B` 战技、`ED` 元素戒律、`AI` 奇械注法、`AS` 奥秘射击、`RN` 符文、`PB` 契约恩赐、`MM` 超魔、`FS:F` / `FS:P` / `FS:R` / `FS:B` 战斗风格等，完整列表以 5etools `featureType` 为准），中文名在 `enums.ts`；`prerequisite`：`{ level?: { class, level }, pact?, patron?, spell?, feature?, race?, ability?, other? }`。
- 背景特性名称去掉「特性：」前缀。

### 5.2 通用字段（所有条目可选）

| 字段 | 含义 |
|---|---|
| `lore` | 描述文字（5etools fluff），正文块数组 |
| `supersededBy` | 被重印后的新版条目 id（来自 `reprintedAs`，只指向收录范围内的书） |

| `nameSuffix` | 同书同名时的区分后缀 |

### 5.3 物品的内部结构

| 字段 | 来源 | 含义 |
|---|---|---|
| `contents: [{ item, qty }]` | `packContents` | 套组、背包的内容物；拆开后每件都是独立物品 |
| `contentsChoice?: [{ count, from: [{ item, qty }] }]` | `packContents` 中的选择项 | 内容物里需要选择的部分 |
| `atomic: true` | `atomicPackContents` | 整体使用、不拆开（如一捆箭） |
| `container: { weight?, items? }` | `containerCapacity` | 容器容量 |
| 家族条目 `data.category: family`，带 `members[]`（成员条目 id）；成员**不存**指向家族的字段，界面按 `members[]` 反查；家族名称统一加「（系列）」后缀，`nameEn` 加「 (Family)」；一个物品可以属于多个家族。家族正文 `text` 取来源 `itemGroup.entries`（说明与表格，含抗性护甲的 d10 表、夸尔羽符的 d100 表等），来源没有说明的家族 `text` 为空数组；仅含「此物品组与物品……同名」脚注的不导入。家族页 = 来源说明 + 成员对照表（名称、稀有度、是否同调，界面从成员读取）；治疗药水、巨人之力腰带、巨人之力药水三个家族另有 `keyValue: { label, values }` 要点列（恢复量、力量值），由成员正文提取，提取不到则构建失败 | `itemGroup`（如巨人力量腰带 6 种、工匠工具 17 种）。来源里内容完全相同的重复组合并为一个 | 先选家族，再选具体一种 |
| 通用变体模板 `variantTemplate: { requires, excludes, bonus? }` | `magicvariants`（如 +1 / +2 / +3 武器） | 模板本身是条目；展开的具体物品带 `variantOf` 与 `baseItem` |
| `attunement: { required, by?: string[] }` | `reqAttune` | 「需由法师同调」转为编号 |
| `activities`（施法） | `attachedSpells`、`charges` | 物品可施放的法术与消耗的充能 |
| `effects` | `ability`、`resist`、`immune`、`vulnerable`、`conditionImmune`、`modifySpeed`、`bonusAc`、`bonusWeapon`、`grantsProficiency`、`grantsLanguage` | 被动效果 |
| `light`、`ammoType` | 同名 | 照明半径、使用的弹药 |

+1 / +2 / +3 的同类模板放在同一家族，物品栏里选「基础物品 + 加值档」。

### 5.4 怪物的内部结构

- 传说动作组（`legendarygroups.json`，白名单内 67 组）：`lairActions`、`regionalEffects`、`mythic`，挂到对应怪物。
- `environment`（编号）、`tags`、`variants`、`summonedBy`（召唤它的法术）、`family`（如龙的年龄段同组）。
- `variants: [{ name, nameEn?, kind: 'variant' | 'inset', text, src?, version? }]`：来源 `variant` 数组（书中「变体：……」「定制龙类」等小节）；`version` 原样保留来源 `_version`（`name`、`addAs`、`addHeadersAs`），由 R10 解析；变体里的施法块按文字渲染（环数与法术位、随意、每日），不生成可执行的施法数据；图片丢弃。目标怪物在 SRD 包时，`variants` 写进描述补丁（§5.12），不写进 SRD 条目。
- `attachedItems`：怪物携带的物品引用。

### 5.5 随机表

- `table` 增加 `parent?: { id }` 或 `chapter?: { book, name }`（至少一个）、`kind?: 'roll' | 'names' | 'life' | 'deck' | 'loot' | 'encounter'`。
- 牌组表每行可带 `text`。
- 正文块 `{ tableRef: { id, label } }`：原位置显示为可点术语。
- 来源：`generated/gendata-tables.json`、`tables.json`、`life.json`、`names.json`、`decks.json`、`loot.json`（个人宝藏、宝藏堆、龙的宝藏、宝石、艺术品、魔法物品表、龙族巢穴的普通物品）、`msbcr.json`（DMG「按挑战等级的怪物数值」，`kind: 'cr'`，列：CR、熟练加值、AC、生命值区间、攻击加值、伤害区间、豁免难度）、`encounters.json`（按环境的随机遭遇表）、条目正文。

### 5.7 地点

**世界地点（位面、国家、城镇、要塞）不从书的标题层级推导。** 书中地点的文字就是 `book` 条目的小节文字，用 `data.outline` 的锚点定位（`{ book: 章节条目 id, anchor }`）。结构化的世界地点库（含坐标，供地图模块直接使用）留给地图模块的单元蓝图，数据源待定（候选：Toril GIS 由用户自行导入，须先核实使用条款；FR 维基信息框须先处理 CC BY-SA 许可）。

冒险内带编号的房间与区域（5etools `area` 编号，如「1. 洞穴入口」）属于冒险（R17）：

`location`（仅冒险内容项）：`{ parent?, aliases?, text, lore?, tables?: string[], related?: string[], book?: { id, anchor }, areas?: [{ code, name, text }], mapRegions?: [{ map, area, points }] }`

- 层级来自冒险自己的章节与标题层级；`mapRegions` 只存坐标与地图名，不存图片。
- 来源与预计数量：80 个冒险的章节地点与约 9,900 处区域引用、651 张带分区的地图。

### 5.8 中英对照

- 条目信封增加 `i18n.en`：`{ name, summary?, fields: { [path]: string | TextBlock[] } }`。`path` 是 `data` 内带文字的字段路径（如 `text`、`lore`、`traits.0.name`、`traits.0.text`、`table.cols.2`、`rows.3.cells.1`）；只有字段覆盖矩阵里登记为文字的路径才能出现。结构化字段（数字、编号、公式）与语言无关，不重复。

### 5.11 包的层级与引用方向（D1.2a 第 7 轮后增补）

- 核心书的层级（低 → 高）：`SRD(0) < PHB(1) < SCAG(2) < DMG(3) < MM(4) < XGE(5) < TCE(6) < VGM(7) < MTF(8) < MPMM(9) < BMT(10)`，登记在 `tools/data/config/books.ts` 的 `layer`。
- **引用只能向下**：一个包的条目只能引用本包、更低层的包里的条目；包的 `requires` 只能指向更低层的包。构建时检查，违反即失败，包间不会出现依赖环。
- **展开物品的归属**：通用变体模板展开出的具体物品（如「银质反物质步枪」），放进「模板所在包」与「基础物品所在包」中层级更高的那个；条目 id 不变。只有模板与基础物品都在 SRD 里，展开物品才放进 SRD 包并保留 `srd` 标记；否则 `srd` 标记为假。
- **家族条目**放进「来源组所在包」与「全部成员所在包」中层级最高的那个。
- **唯一允许的向上引用（软引用）**：升级操作里带 `optional: 'tce-ocf'` 的特性授予，指向 TCE 的可选职业特性（共 29 条）；消费方在目标条目未安装时忽略这一步。

### 5.12 描述文字（lore）与 SRD 边界

- 描述文字（5etools fluff）不是 SRD 内容，扩展仓库的 SRD 包里不得出现。目标条目在非 SRD 包时，描述文字写进条目的 `data.lore`；目标条目在 SRD 包时，生成**描述补丁**条目，放进该 fluff 来源书所在的包。
- 描述补丁：类型 `lore`，id 为 `lore.<目标条目 id>`，`data` 为 `{ target, lore?, variants?, src, credit }`（`lore` 与 `variants` 至少一项非空）；`target` 是硬引用，目标所在包层级不得高于补丁所在包；同一目标只有一个补丁。该类型是隐藏类型，不出现在库的列表、分类、搜索与包详情的类型统计中；读取条目时，内嵌的 `lore` / `variants` 优先，否则取补丁。
- fluff 里的 `_copy` / `_mod` 先解析再取正文；`images` 丢弃；最外层与条目同名的 `section` / `entries` 去掉标题层级。
- `_copy` 衍生的记录不继承基础记录的 `srd`、`basicRules` 标记。
