## 5. 数据结构（新增与修改）

### 5.1 升级操作

- `itemGrant`：同一等级的全部特性都要列出；特性正文里嵌套引用的子特性一并授予。
- `itemChoice`：`{ kind, level, count, pool?: string[], optionKind?: string, replaces?: string }`。5etools 的 `options{count}` 转成 `pool`；可选特性按 `optionKind` 选择。
- 新增 `trait`：`{ kind: 'trait', level, grants: string[], choices?: [{ count, from: string[] }] }`。值用 D1.1 的标准编号，前缀区分类别：`skill:`、`save:`、`armor:`、`weapon:`、`tool:`、`lang:`。用于子职业、种族、亚种族、专长的熟练授予；职业 1 级熟练仍在 `class.proficiencies`。
- `abilityScoreImprovement`、`subclass` 增加 `explain: string`，指向说明这一步的特性 id，供升级向导显示说明。
- 增加 `optional: 'tce-ocf'`：TCE 可选职业特性；`replaces` 写被替换的特性 id（没有则不写）。由规则选项 `optional-class-features`（来源 TCE，`engine: 'character.optionalClassFeatures'`）控制。

### 5.2 特性

- `role`：`mechanic`（默认，能力型）、`procedure`（属性值提升、选择子职业、「道途特性」等占位）、`intro`（子职业开头简介）。人物卡只显示 `mechanic`；库里三种都显示。
- 可选特性：`owner` 去掉（不再写 `optional`）；`optionKind` 用编号，中文名在 `enums.ts`：`EI` 魔能祈唤、`MV:B` 战技、`ED` 元素戒律、`AI` 奇械注法、`AS` 奥秘射击、`RN` 符文、`PB` 契约恩赐、`MM` 超魔、`FS:F` / `FS:P` / `FS:R` / `FS:B` 战斗风格（战士 / 圣武士 / 游侠 / 吟游诗人）；一个特性可属多种，写成数组。
- `prerequisite`：`{ level?: { class, level }, pact?, patron?, spell?, feature?, other? }`，从 5etools 结构字段导入。
- 子职业开头简介的正文同时写入子职业的 `text`。
- 背景特性名称去掉「特性：」前缀。

### 5.3 通用字段（所有条目可选）

| 字段 | 含义 |
|---|---|
| `lore` | 描述文字，正文块数组，格式同 `text` |
| `supersededBy` | 被重印后的新版条目 id |
| `versionGroup` | 同一物品的变体或同名版本的组 id；组内条目互为版本 |
| `playable` | `false` 表示不能作为玩家选项（DMG NPC 种族） |
| `nameSuffix` | 同书同名时的区分后缀，如「（无伤害版）」 |

### 5.4 随机表

- `table` 增加 `parent?: { id }`（所属条目）或 `chapter?: { book, name }`（所属章节，二者至少有一个）、`kind?: 'roll' | 'names' | 'life' | 'deck'`。
- 牌组表的每行可带 `text`（该牌的说明，正文块数组）。
- 正文块新增 `{ tableRef: { id, label } }`：原位置显示为可点术语，点开随机表页面。
- 名称：表名与所属条目名相同时只用一个；同一条目下多张表用「条目名·表名」。

### 5.5 新增条目类型

| 类型 | 主要字段 |
|---|---|
| `language` | `kind`（standard / exotic / secret）、`script`、`speakers` |
| `deity` | `pantheon`、`alignment`、`domains[]`（领域 id）、`symbol`、`title` |
| `reward` | `kind`（blessing / charm / epicBoon / supernaturalGift / demonicBoon）、`text`、`effects?` |
| `hazard` | `kind`（trap / hazard）、`tier?`、`text`、`activities?` |
| `location` | `kind`（plane / layer / region / settlement / site）、`parent?`（上级地点 id）、`text`、`lore?`、`tables?: string[]`、`related?: string[]` |

技能与感官做成 `rule`，`category: 'glossary'`，技能另带 `ability`。载具与攻城器械本次不做，写入待议。新增类型若旧版应用不能安全忽略，`dataVersion` 升到 3 并补兼容测试。

### 5.6 文字清洁

- 中文后紧跟英文原名的，统一为「中文（English）」；在 `tools/data/config/` 维护例外表。
- 武器属性只存代码（`AF`），来源部分去掉。
- 公式与标记：`{{spellcasting_mod}}` 改为公式 `@mod`；`uses.max` 必须通过公式解析器。
- 武僧「Ki」中文名「气」。
- 空段落、空列表项删除；表格空单元按原表合并单元的意思补「—」或合并。
- 职业表列名统一为「1环」…「9环」「戏法」等中文。
- `summary` 不再重复名称与类型。
- 正文里逐条复述结构化字段的列表（背景、种族开头的「技能熟练项：…」「语言：…」「装备：…」）标记 `restated: true`，详情页默认收起。

## 8. 随机表的导入与核对

1. **导入前**：列出 5etools 白名单可掷表 496 张、`life.json`、`names.json`、`decks.json`（DMG、BMT）与现有 164 张独立表的对照清单：已有、待导入、重复、不可掷。
2. **去重**：行内容相同（规范化后哈希相同）的只保留一张，其余引用改指向保留的那张。
3. **替换正文表格**：正文里第一列是骰子的表，在随机表条目中找到行数与每行文字都一致的那张后，才把正文表格替换为 `tableRef`；对不上的不替换，列入报告。
4. **导入后核对**，报告逐项给出数量与清单：
   - 正文里仍是可掷表格的（应为 0，或列入例外并说明）；
   - 没有所属条目也没有所属章节的随机表（应为 0）；
   - 重复表（应为 0）；
   - 行骰点范围不连续、有重叠或超出骰子面数的；
   - 行里引用断链的；
   - 名称重复拼接的。
5. 不可掷的表（如价格表、说明表）保持正文表格。
