## 2. 底座（第 1 层，官方原件）

### 2.1 来源与范围（决定 8，2026-11-07 改定）

- `tools/vendor-foundry-kernel.mjs` 跑一次演示站官方完整启动，录下实际取过的文件，原样存进 `vendor/foundry/`（目录同 Foundry 服务器）。清单 `vendor/foundry/manifest.json` 由工具生成，不手改。
- 原“按 7 类手写约 7 千行”作废；手写版已删除。体积裁剪（只留 dnd5e / Plutonium 用到的部分）以后再做（驾驶员定）。

### 2.2 接线（src/rules/kernel/）

1. `frame/main.ts`：整页加载完才 import `foundry.mjs`；组世界数据；官方 `Game.initialize`，只省画布、键鼠、手柄、音视频、界面渲染。
2. `frame/server.ts`：本地回答官方客户端的 Socket.IO 请求（模板、时间、资料包读取、临时资料包、文档写入 → 变更计划）。
3. `frame/random.ts`：编号随机源按种子确定（同输入同编号）。
4. `packages.ts`：包清单补服务器路径前缀（标准答案与小窗共用）。
5. 插件侧复用作者小窗宿主 `src/library/runtime/host.ts`；小窗要的 `packs/…`、`data/…` 由插件 / 【库】回答。

### 2.3 启动顺序：照官方 `Game.create → initialize → setupGame` 原样走

```
 官方步骤                      我们的底座怎么做
 连服务器、取世界数据      →  ★ 由插件组好“世界数据”交给小窗（§3.1）
 new Game(view, data)         照做（含 release、packages、settings、i18n、packs 等）
 init 钩子                    照做（dnd5e、Plutonium、libWrapper 在此注册）
 注册设置、本地化             照做（语言文件由小窗本地供给）
 界面：教程、监听、视图        不做
 权限                         照做
 游戏时间 + 与服务器同步   →  ★ 世界时间取自存档（§3.1）
 初始化配置、资料包            照做；资料包内容 ★ 由插件供给（dnd5e 2014 SRD 包）
 世界文档、目录树              照做
 setup 钩子                   照做
 音频、键鼠、画布、侧栏、表单  不做
 战斗配置初始化                照做（回合、到期要用）
 文档索引                     照做
 ready 钩子                   照做（dnd5e 的界面、迁移部分由界面空类吸收；报错记录不吞掉）
 ★ = 5 处“碰服务器”的地方，换成插件的东西；其余照官方
```

## 3. 插件侧接线（自写，都是“接线和结果格式”）

### 3.1 世界数据组装（取代“从服务器取世界数据”）

```
 存档（引用 + 选择 + 状态 + 世界时间）+【库】条目
   → Plutonium 转换（小窗里）→ dnd5e 文档
   → 世界数据：1 个 GM 用户、dnd5e 清单与文档类型（每类含 base）、规则设置 legacy、
               人物/怪物 actors、物品、战斗、资料包清单（dnd5e legacy 包）
   → 交给小窗启动
```

- 中文战役：Plutonium 按英文名合并旁路数据，所以喂同一作者编号的**英文对照条目**（P3-1 已有英文配对）。结果按作者编号挂回，显示用中文。没有英文对照的直接转中文条目，出处标“无英文对照”。
- dnd5e 2014 资料包：参考目录里只有作者的 YAML 源（`packs/_source`）。构建时用 js-yaml 原样转 JSON 随插件发布，不改内容（路线测量已用同样方式读入）。

### 3.2 每次操作的流程

```
 插件 → 小窗：{ 世界数据 | 增量, 操作, 已掷点数[] }
 小窗：启动（或复用已启动的世界）→ 调 dnd5e 官方入口 → 收集结果
 小窗 → 插件：{ 状态（五种之一）, 数值与出处, 变更计划, 待选项/需确认, 未支持项, 还要掷的骰 }
```

- **骰点**：底座的掷骰从“已掷点数”队列取值，等同官方随机数入口 `CONFIG.Dice.randomUniform` 的位置。队列不够时停在那里，返回“还要掷的骰式”，插件掷完再算一遍。同输入同结果。
- **出处**：用 dnd5e 自己的 `getAttributionData`（`actor.mjs:2735`，AC、移动、效果来源），加上 Plutonium 写进文档的来源标记。不另写出处计算。

### 3.3 变更计划（取代“写数据库”）

- 底座的数据库后端不保存，而是把每次 create/update/delete 记成变更计划。
- 同时在小窗内存里生效，保证一次多步操作前后一致。
- 例（实测）：伤害 5 点挥砍 → `地精 system.attributes.hp.value: 7 → 2`；短休 → 法术位/资源变化。
- 变更计划交给 P3-3 预览、确认后写入存档。

### 3.4 待选项与需确认（取代“弹窗”）

- 调 dnd5e 入口时一律传“不弹窗”（`dialog: { configure: false }`），选择项由插件显式传入。
- 升级、建卡：`AdvancementManager.forLevelChange / forNewItem`（`applications/advancement/advancement-manager.mjs:386/241`）不弹窗就能算出步骤（实测牧师 1→2 级共 5 步），这些步骤原样作为待选项交回。玩家选完，按 dnd5e 成长流程应用。
- 兜底：任何界面渲染或等待用户的调用都被界面空类截住，结果标“需玩家输入”，附调用位置。不卡死，也不编造选择。

### 3.5 战斗流程串联（薄，只按顺序调 dnd5e 官方函数）

```
 攻击：activity.rollAttack（attack.mjs:83）→ 与目标 AC 比 → 命中则 rollDamage（mixin.mjs:857，暴击照 dnd5e）
       → 目标 applyDamage（actor.mjs:786，抗性/免疫/易伤由 dnd5e 算）
 豁免：目标 rollSavingThrow（actor.mjs:1625）对 DC → 伤害按动作的 onSave（全伤/半伤/无伤）
 专注：dnd5e 受伤时自动发起专注检定（attributes.mjs:705）→ 作为“需掷骰”交回
 回合：战斗推进下一回合 → Foundry 内置到期时机 + dnd5e 伪到期时机（来源/目标回合开始/结束）
 休息：shortRest / longRest（actor.mjs:2345/2356）
```

- 状态优劣势：启动时把 midi 状态规则表的效果改动加到 dnd5e 状态效果上（midi 的做法：状态效果创建时附加改动）。数据文件注明 MIT 出处。

### 3.6 未支持检测（自动，不手写名单）

- 效果改动的目标路径，在 dnd5e 数据模型里找不到对应字段的，在 Foundry 里会走“无字段”路径。底座在这条路径上记一笔，结果标“未支持”，附原文。
- 只有 midi/DAE 才认识的写法（`flags.midi-qol.*`、`flags.dae.*`、`macro.*`），统一列入未支持。
- JS 条件不执行，交“需确认”。
