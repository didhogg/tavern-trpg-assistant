驾驶员已批准本文件的范围与全部决定；本文件是 R10、R10b 的唯一依据，与 `docs/handoff/D1.2a_执行交接.md`、`docs/handoff/D1.2_全量结构化导入_交接.md` 冲突时以本文件为准。执行者是规划 agent 本人，R10 与 R10b 各自一次本地提交，不推送、不发布、不安装。

## 0. 驾驶员决定（逐字落实，不得改动）

1. **`playable` 标记做。** DMG 282 页的 **16 个** NPC 种族写 `playable: false`；「阿斯莫」（DMG 286 页，玩家种族）保持可玩。`playable` 的含义写进规格与任务纲目：它**只作为「玩家严格建卡模式」的参考**；解除严格模式后，建人物的种族选择器**不受它限制**，可以选 NPC 种族，只是这些种族缺少「可玩种族」才有的建人物复杂流程数据（属性加值选择、特性授予、熟练选择等）。
2. **版本拆开做：** R10 做重印标记、NPC 种族、同书同名；R10b 单独做 `_versions` 备选版本与 `versionGroup`。
3. **本轮不动界面。** 被取代的旧版默认隐藏、同名版本切换等，等「统一数据库优化改好后」重新构建库页面时再做；本轮只做数据。
4. **指向「范围外但不是 2024」的重印标记，到 D1.2b 导入那些书时补上。** 本文件第 7 节已把它写进任务纲目，防止遗忘。
5. 官方书籍原文（`reference/龙与地下城官方资料`、`txt/`）只用于手工核对规则，不进数据、不发布。

## 2. R10 要做的事（数据层）

### 2.1 新文件（避免移动已被审计文档引用的转换器行号）

- `tools/data/convert/versions.ts`：`reprintTargets`、`resolveSupersededBy`、`markNpcRaces`、`disambiguateNames`。
- `tools/data/config/npcRaces.ts`：16 个 NPC 种族的英文名清单（见 3.2）。
- 在 `convert/index.ts` 的 `convertAll` 里只加调用，不改已有行。

### 2.2 `supersededBy`

- 来源 `reprintedAs` 的写法：字符串数组 `"名称|书"`；对象数组 `{ uid: "名称|书", tag }`；子职业等用 `"名称|职业|…|书"`。**书代码取各段里属于 `BOOK_SOURCES` 或 2024/D1.2b 书代码集合的那一段**，不要取第二段想当然（子职业的第二段是职业名）。
- 解析：只认目标书 ∈ `BOOK_SOURCES`（十本书）；在同类型（怪物→怪物、种族→种族；亚种族可指向亚种族或种族）、该书、中文名相同的条目里找；多个范围内目标时取层级最高的包（`BOOKS[].layer`）；写 `data.supersededBy = 目标条目 id`。
- **跨包软引用**：`supersededBy` 的目标可能在尚未安装的包里（旧版在 MM 包、新版在 MPMM 包），**不能**因此给旧版所在的包加依赖。`structuralIds` 不含该字段（保持），引用校验器 `tools/data/validate/refs.ts` 对 `supersededBy`、`versionGroup` 只要求目标在全部包里存在，不要求在依赖闭包内。
- 目标书在范围内、但找不到条目：记入转换统计 `unresolvedReprints`（路径、来源、目标），构建通过但**报告列出**；测试要求该清单为空，不为空就停下查原因（多半是中文名对不上）。
- 目标在范围外：不写，也不报错；**目标是 D1.2b 的书（EFA、FRHoF、FRAiF、AU 等）的，记入统计 `deferredReprints`**，D1.2b 导入对应书时补上（第 7 节）。目标是 2024 新版（XPHB、XDMG、XMM）的不记。

### 2.3 `playable`

- 16 个 NPC 种族：DMG 282 页的种族。清单写在 `tools/data/config/npcRaces.ts`（英文名：Aarakocra、Bullywug、Gnoll、Gnome (Deep)、Goblin、Grimlock、Hobgoblin、Kenku、Kobold、Kuo-Toa、Lizardfolk、Merfolk、Orc、Skeleton、Troglodyte、Zombie），转换时按「来源 DMG + 英文名在清单内」写 `data.playable = false`；测试断言恰好 16 条，且「阿斯莫」（DMG）没有该字段。
- 其他种族不写 `playable`（缺省即可玩）。

### 2.4 同书同名 `nameSuffix`

- 在 `convertAll` 开头（建引用索引之前）对规划条目（含表格）按（类型、来源书、中文名）分组，**特性（`feature`）不处理**；组内多于 1 条时：
  - 魔法变体展开出的物品，用变体名（`_variant.name`）里的括号内容作后缀（「+1 武器 (无伤害)」→ 后缀「无伤害」，英文「No Damage」），带括号的那条改名为「名称（后缀）」「Name (Suffix)」，另一条不动；
  - 仍然重名的，按 id 排序后第二条起写「（2）」「（3）」……
- 改名发生在规划条目上，所以条目 `name`、`nameEn`、`keywords`、摘要、引用显示文字一起变；条目 id 不变；`data.nameSuffix` 记后缀文字。
- 统计 `nameSuffixed`（条数与清单）、`featureNameGroups`（特性同名组数，只报数）。

### 2.5 引用校验与结构

- `src/rules/dnd5e2014/data/entries/base.ts` 的通用字段加 `supersededBy`（条目 id）、`versionGroup`（条目 id）、`playable`（布尔）、`nameSuffix`（字符串，≤40）。
- `tools/data/validate/refs.ts`：`supersededBy`、`versionGroup` 改为「目标存在即可」（不检查依赖闭包）。

## 5. R10b：`_versions` 备选版本与 `versionGroup`

### 5.1 做什么

把来源里的 `_versions` 备选版本生成为**独立条目**（怪物 126、种族 12、亚种族 12），每个备选版本与基础条目同属一个 `versionGroup`（组 id = 基础条目 id；基础条目自己也写 `versionGroup` 指向自己，备选版本指向基础条目）。

### 5.2 怎么做

- 新文件 `tools/data/extract/versions.ts`：`expandVersions(list, sink)`，对每个带 `_versions` 的记录，每个版本按 `_copy` + `_mod` 的同一套规则生成新记录：以基础记录为底，覆盖版本自己给出的顶层字段（`name`、`ENG_name`、`source`、`type`、`alignment`、`variant: null` 等），再应用版本的 `_mod`；`_abstract` + `_implementations` 的版本把 `_variables` 代入模板里的 `{{变量}}`。
- `applyMods`（`tools/data/extract/load.ts`）补两个模式：`renameArr`（把数组里某项的 `name` 改成新值）与 `addSpells`（把法术加进怪物 `spellcasting` 的对应块；做不到的写入 `sink`）。其余已有模式不动。
- 备选版本的条目 id 由名称生成（`monster.living-star-necrotic.bmt`）；与已有 id 冲突时按规划器现有的去重后缀处理，并在报告里列出。
- 传奇组的 `_versions`（10，带 `_templates`，要套用怪物模板）**不在 R10b**：它们是「某怪物的模板变体」的巢穴与区域效应，登记为 `lost`，理由写明，留给模板应用的单独工作包（规划 agent 之后决定，写进任务纲目待议）。
- 无法生成的版本（模式不支持、基础记录找不到）逐条写入报告 `unsupportedVersions`，数量要接近 0；不为 0 时矩阵对应行保持 `lost` 并列出原因。

### 5.3 矩阵与验收

- `monster._versions*`、`race._versions*`、`subrace._versions*` 各行按真实去向登记（`to` 为 `data.versionGroup` 或新生成条目），`DELIVERED_WP` 加入 R10，`checkDelivered` 通过。
- 数量验收：新增怪物条目 = 实际生成数（报告写明与 126 的差额及原因）；种族 + 亚种族新增 = 实际生成数；每个备选版本的 `versionGroup` 指向存在的基础条目；基础条目、已有条目的内容不变（除 `versionGroup` 字段）。
- 金样：活体星辰（暗蚀）的正文里「光辉」已换成「暗蚀」；阿斯莫「死灵斗篷」版本的 3 级特性是「天界启示（死灵环绕）」。
