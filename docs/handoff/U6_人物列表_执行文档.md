## 0. 一句话

先把数据结构统一（怪物结构加可选字段、挑战等级可选、装备进 `inventory`，并用转换器核查全部怪物的装备导入），再做「人物」主页面：人物数据层 + 人物列表 + 模板弹窗（L1B 选择器锁定怪物与具名 NPC）+ 存到我的库 + 库里用人物卡改怪物条目 + 回收站、标签管理、分类管理。**人物卡外壳在同一个任务里做**（外壳批次在外壳规格批准后并入），所以不做占位页。

### 批 1：数据结构统一与怪物装备核查（两个仓库）
1. **怪物结构**（`monsterDataSchema`）只加下面这些可选字段，并把 `cr` 改为可选；不改其他任何字段：

   | 字段 | 形状 |
   |---|---|
   | `classes` | `[{ class: 条目 id, subclass?: 条目 id, level: 1–20 }]` |
   | `race`、`subrace`、`background` | 条目 id |
   | `inventory` | `[{ ref?: 物品条目 id, name?: 1–80 字, qty: 整数 ≥ 1, equipped?: 布尔, attuned?: 布尔, container?: 本列表下标, chargesUsed?: 整数 ≥ 0 }]`，`ref` 与 `name` 至少有一个 |

   在构建端的字段登记（`plannedFields`、`outputTypes` 等）里登记这几个字段。所有读 `cr` 的地方改为可选。
2. **转换器**：把怪物身上的装备写进 `inventory`：
   - `ac[].items`（护甲、盾牌）→ `equipped: true`；
   - `attachedItems`（携带的武器等）→ `equipped: true`；
   - 同一物品只出现一次，`qty` 照来源（来源没写就是 1）。
   - 旧字段 `ac[].items`、`attachedItems`、攻击的 `item` **保留不动**（0.4.0 旧扩展在读），新代码只读 `inventory`。
3. **核查**（写进 `docs/probes/U6_怪物装备核查.md`），对**全部包的全部怪物**：
   - 来源的 `ac[].from` 里有 `{@item …}`，但没解析成物品 id 的（列出怪物、原文、原因）；
   - 来源 `attachedItems` 没解析的（`carryStats.attachedItemsUnresolved` 的明细）；
   - 攻击动作名里提到携带武器、但没连上的；
   - `ac[].from` 是纯文字的护甲名（没有 `{@item}`）、能按名字唯一对上物品的（列出，并在转换器里补上）；
   - 来源原始数据里其他像装备的字段（逐个列出字段名与数量），确认没有被导成别的东西或丢掉；
   - 用 `inventory` 里的护甲 + 敏捷按规则算出的 AC 与书上的 AC 不同的（只报告，不改书上的值）。
   能确定的漏连在转换器里修掉；拿不准的列表交规划者。
4. `PACK_VERSION` minor +1；`build:data` 两次哈希相同；数据比对只允许：怪物多了 `inventory`、版本号变化、核查里修掉的漏连带来的 `ac[].items` / `attachedItems` 增加（逐条写进放行规则 `tests/data/g2-allow/u6.ts`）。
5. `g2-oldext` 通过（0.4.0 旧扩展能装新包）。

## 5. 停止条件（只有这四种才停整站）

1. 两次 `build:data` 哈希不同；
2. 数据比对出现批 1 第 4 条以外的变化；
3. `g2-oldext` 失败，或已有 e2e（`library`、`upgrade`、存档）因本任务失败且两次修不好；
4. 迁移会改变旧存档里已有的数据（不只是补三个键）。

**其余问题当场解决，不停、不另开任务**：规格没写清的小细节按规格 §11「总原则」自己定，写进报告「与规格不同之处」；核查里拿不准的装备列表交规划者，不因此停下；单文件超 400 行就拆。
