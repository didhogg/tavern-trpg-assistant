## 0. 一句话

在扩展里加一个「人物」页：人物数据层（人物、分类、标签、回收站、撤销）＋人物列表（分类、收藏、置顶、搜索、标签筛选、排序、多选、行尾菜单）＋新建（从库里选、空白人物）＋三个管理页。**不做人物卡**（下一个 Unit），点人物先打开一个只读的占位页。

## 2. 前置不全时的做法（不许因为它们停下）

| 缺的 | 本 Unit 怎么做 |
|---|---|
| L1B 全库选择器（还没做） | 「从库里选」先自己做一个简单版：分段「怪物 / 具名 NPC」+ 搜索框（名字、英文名）+ 挑战等级筛选下拉 + 虚拟列表；数据用库数据库的 `[ruleId+type]` 索引查已启用包里的 `monster`、`npc` 条目。**把它写成独立组件 `LibraryPicker.vue`，对外只暴露「选中了哪个条目」**，以后 L1B 直接替换它 |
| R1.1 派生数值（还没做） | 行内摘要 `rowSummary` 只读人物身上已有的值：属性块（`cardType: block`）读 `data` 里的挑战等级、AC、生命上限；完整卡读 `data` 里已有的职业与等级、种族，AC 和生命上限**没有就不显示**。函数签名留一个可选的 `derive` 参数，R1.1 做完后接上 |
| 人物卡（下一个 Unit） | 点行打开 `PersonPlaceholderPage.vue`：顶部「‹ 人物」、名字、第二行摘要、生命与 AC（有就显示），一句「人物卡正在制作」。打开时调用 `touch(id)` |

## 3. 分批（每批结束本地提交，信息以「U6 批 N：」开头；批与批之间不停）

- 干净副本、`npm ci`、`npm run check` 与 `npm run test:data` 全绿、记录起点提交。

- 纯函数（规格 §8.4）：`src/ui/people/list.ts`（`filterPeople`、`sortPeople`、`groupPeople`）、`naming.ts`（`nextNames`）、`hp.ts`（`hpFromEntry`）、`rows.ts`（`rowSummary`）。

## 5. 停止条件（只有这三种才停整站）

1. 要改内容包、数据管线或 `src/rules/**` 才能继续；
2. 迁移会改变旧存档里已有的数据（不只是补三个键）；
3. 已有 e2e（`library`、`upgrade`、存档）因本 Unit 失败且两次修不好。

**其余问题当场解决，不停、不另开任务**：规格没写清的小细节按规格的总原则自己定，写进报告「与规格不同之处」；单个文件超 400 行就拆。
