## 驾驶员批准与追加要求（2026-11-11）

- 顺序 A→B→C→D→E。开工前后端先做：G2（`ResolvedTag.part` 补 `ixNamedSection`）、G3（跨条目 / 书的反向关联表）、G5（自制更新的对象计划、按书 / 按语言的准确估算）、G6（书目 / 包行带另一语言名字，书架和下载页中英名都能搜到，原第 18 条）。做 B 时补自制包按包下载进度。自制包和冒险的暂停 / 继续暂不需要。其他后端问题，查到后停下报告。
- 修后端前先查 handoff 里归档以外的文档，确认之前是否做过，然后在原实现上精准修，不另起炉灶。
- 【库】下载悬浮窗现在被压在插件框下面看不见。要求是让它看得见（可以超出插件框），不是限制在框内。
- 规则标签（2026-11-11 驾驶员定）：书架、下载页、包标题等所有显示规则版本的地方，不再写「旧版 / 新版」或「2014 规则 / 2024 规则」。作者归为 2014 规则的标「5e」，归为 2024 规则的（含 2025 年出版的）标「5.5e」；分不出规则的不标；从自制源下载的包标「自制」。
- 依赖按作者程序处理（2026-11-11 驾驶员定，取代当天先批的「装 mod 方式 / 保留暂停」）。实测发现：缺一个依赖，作者会让**全部**自制条目消失（见 §6），所以不提供「保留」：
  - 下载自制包前弹预览，列出会一起下载的依赖包、需要的官方书（可勾选一起下载）、找不到的依赖。可以选「以后下载不再提示」（设置 → 库里也能改），依赖仍然自动一起装。
  - 卸载一个被别的包依赖的数据源时，预览列出会一起删除的包（作者规则，不可取消）。
  - 包 ⋯ →【管理】→【依赖包】标签：列出这个包依赖的所有包（自制包或官方书），标出已装或缺；缺的附下载按钮。管理页顶部有缺依赖时自动提醒。
  - 点进因缺依赖读不到的条目：说明需要哪个依赖包，联网时自动拉取一次；失败时显示原因和【重试拉取】。
  - 读档补包按书、按包给，不再整套下载；自制包补装时作者自动带上依赖。
  - 修复单本卸载漏掉「只有来源、没有书号」的来源。
- 多选的分组全选（2026-11-11 驾驶员定，所有多选都照这个）：进入多选后，每个分组标题行右侧有一个框。`[ ]` 一个都没选 → 点一下全选这一组；`[−]` 这一组选了（全部或部分）→ 点一下取消这一组全部。
- 下载页（C 段，2026-11-11 驾驶员定）：「官方资料」和「冒险」合成一栏「官方资料与冒险」，按作者分类分组，有类型筛选（全部 / 书 / 冒险）和规则筛选；底部【下载全部…】弹窗里勾选全部书 / 全部冒险。
- 所有错误用横幅提示。下载类失败在横幅或下载悬浮窗里重试。任何情况下（下载中、断网、某项出错、读不出）都不能跳页、卡在某页、标志一直不消，也不能操作后整页空白。

### B. 下载、更新和进度

### 12.1 下载 / 删除自制包报「自制解析失败：_getMastery」（已修）

- 现象：删除《Sample - Giddy; 《乏味巫师指南》.json》、下载《Adventurers League; DDEX1-01 - 菲兰的抗命》等报「自制解析失败，没有发布：_getMastery@…render.js:13025」。

## 16 后端问题：按书安装 / 卸载 / 更新（2026-11-12 真机反馈 + 实测，修法待驾驶员批准）

四个问题出在同一处：官方资料的「已装集合 + 来源目录过滤」。按书下载成为默认后才暴露出来。

### 16.1 职业类目录被当成「按来源」过滤 → 所有职业清零
- 现象（驾驶员）：5e / 5.5e 核心书一起装，卸 5.5e 后「两边共有的条目」一起没了，只能卸载重装。
- 实测（真实中文资料副本，整套装着 → 只卸 XPHB → 触发重新解析）：PHB 2322→1595、TCE 845→356、XGE 915→576，另 14 本书 / 冒险都少；少掉的全是 class / subclass / classFeature / subclassFeature / classFluff / subclassFluff，全部清零。卸载后版本里 `cn|data/class/index.json` 与 `fluff-index.json` 被过滤成 `[]`。
- 根因：作者 `_DataUtilPropConfigMultiSource` 的目录有两种键：怪物 / 法术是来源缩写（`MM → bestiary-mm.json`），职业是职业名（`fighter → class-fighter.json`，一个文件里同时有 PHB 和 XPHB 版）。`frame/directory-commands.ts sourceFiles()` 把它们都交成「来源 → 文件」，`uninstall.ts stageOfficialParts` 和 `plan.ts officialPlan` 都按来源过滤每一个目录 → 职业名不是来源，全部滤掉。按书安装同样如此（`officialPlan(books: ['PHB'])` 的 `sourceIndexes` 里职业目录也是 `[]`，单元计算核实）。
- 修法：作者小窗交目录时标明「键是不是来源」（用作者自己的来源表判断，不手写）；键不是来源的目录（职业类）永远完整、不参与按书过滤。读取时对旧版本里已被滤空的职业类目录同样按完整处理 → 旧库下次解析自动恢复，不用迁移、不用重装。

### 16.2 过滤方向写反：只留「还装着的」→ 误删作者书目没列的来源
- 根因：卸载按 `remainingSources = 全部已装 − 这次卸的` 留键，「全部已装」只取作者书目来源 + 本机统计来源；怪物目录里的 ESK、MCV2DC、MisMV1 等不在里面，被一起删。
- 修法：从当前生效的目录出发，只去掉这次卸的来源，其余一律不动。

### 16.3 书之间的依赖没考虑 → 卸掉被依赖的书后再装什么都失败
- 实测：卸掉 MTF 等书后再装一本，作者加载器报 `Could not find prerelease/brew URL for source "MTF"`，整个怪物解析失败，任务失败。
- 根因：作者在 159 个文件的 `_meta` 里声明 `dependencies` / `otherSources`（解析时要先读别的书），另有 1144 个条目跨来源 `_copy`（冒险怪物抄 MM 最多）。按书卸 / 按书装都没看这些依赖。
- 修法（落实 P5-3 §T2「区分用户安装内容与仅用于依赖的内容」）：按书装时读下载好的文件里作者写的依赖和跨来源 `_copy`，被依赖的书自动一起装为「隐藏依赖」（文件和目录在，书架 / 搜索不显示，不算用户选了它）；卸载时还有已装的书依赖它 → 只从可见清单去掉，文件和目录保留，没人依赖了再由自动回收清掉。

### 16.4 更新：任何数据变化都被判成「牵连共用文件 → 整批更新」
- 现象（驾驶员）：已经按书下载，拉取更新仍提示「这次要整批更新……会一起更新：城主指南（2014）（共用文件）约 23.9MB」，同一个弹窗里又写「已经是最新的」。
- 根因：`official-update.ts check` 里只有「书正文 / 冒险正文」文件算归属到某本书，按来源拆的文件（`bestiary-mm.json`、`spells-phb.json` 等，归属是来源）一律算「共用」→ `shared = true` → `apply` 拒绝单本更新。弹窗里的「已经是最新的」是更新完成后书架上「有更新」的旧检查结果没清掉。
- 修法：按来源拆的文件按作者书目（书号 ↔ 来源）归到对应的书；只有真正的共用文件（目录、职业文件、多来源单文件类别）才算牵连整批。更新发布后清掉旧的检查结果。

### 16.5 更新任务带着检查时的计划排队 → 把之后新装的书从已装清单里抹掉
- 现象（驾驶员）：卸载任意包报「选中的书已经不在已装集合里，请刷新后再预览」，过一会儿这个包从列表里消失，或一直卡在那里。
- 根因（代码确认，真机具体顺序未复原）：`official-update.ts apply` 把检查时算好的 `plan` 交给 `tasks.startOfficial`；任务里 `plan` 给了就不再按当时的已装状态重算，发布时直接写 `plan.books / plan.sources / plan.sourceIndexes`（`tasks.ts`、`install.ts`）。检查之后、更新开始之前新装的书（按书下载排在前面的任务、中英配对的另一种语言）被抹掉：文件还在，书架（未刷新）显示在，卸载预览判断不在，刷新后消失。
- 修法：任务开始时（拿到修改锁后）一律按最新已装集合重算计划；外面带进来的计划只当「要更新到哪个提交」用，不能覆盖已装集合和目录。卸载报错后前端重读一次书架，不留粘滞行。

### 16.6 验证计划（作者真实数据，不手写书单）
- 按书只装 PHB → 有职业；装 5e + 5.5e 核心 → 卸 XPHB → 重新解析后其他书条目数一条不少；卸 MM 而保留依赖它的冒险 → 冒险怪物还在、书架看不到 MM；之后再装别的书不失败。
- 检查更新：只改了某本书的来源文件 → 可以单本更新；改了真正的共用文件才要求整批。
- 先排一个更新、再按书下载一本、更新跑完 → 新装的书仍在已装清单里；卸载它不报错。
