## 2. 统一实施方案（名称为建议，审批后才写代码）

### 2.1 一份管理视图，作者对象不变

```text
LibraryDatabase（同一个库）
  已发布目录指针 ─► 版本 R
                     ├ 官方：仓库提交＋已装书/冒险＋文件版本引用
                     ├ 自制：作者原件 KV 范围＋包身份
                     └ 派生：解析/备选/搜索/报告所在的版本范围

操作 O：基于 R → 准备 R' → 验证 → 短事务比较 R 仍有效 → 指针换 R'
                                  失败/过期 → 不发布
```

**建议落法**：新增有限的插件管理记录（版本清单、操作记录、不可变文件版本），继续使用现有 derived/kv 保存作者结果与存储。文件版本按已有来源、路径、gitSha 定位，提交号记在版本清单，未变文件复用同一原件。具体表名/键在 T0 迁移预览冻结，不能执行中任意再造数据结构。

版本清单只说明保存位置、安装集合与依赖用途，不重新定义法术/怪物/书的字段。旧 files 的初始数据可作为只读“旧版本原件位置”被引用；新版写入新位置，禁止继续覆盖旧 files。这样无需第一次迁移就把约 150MB 文本复制两份；若采用其他保留旧读者的落法，先证明等价并报告。

派生键/作者 scope 带版本；`manage` 的范围/覆盖选择、用户库里的战役设置仍沿用原职责。读取开始捕获版本 R，一次查询/一个作者窗口只读 R，不能每次文件请求都改读最新版本。发布后的新请求取 R'；已有操作须结束或显式重试，不静默混版。

### 2.2 只有一条修改流程

外部概念入口保持小：**预览计划、确认执行、读操作状态、取消/重试、按对象浏览**；可以在现有 backend.library 内实现，不要求建立一层只转发的“总管理器”。现有 startOfficial/startAdventure/brew* 在过渡期仅作为转入这条流程的薄接线，不能保留两套可写实现。

计划至少交代：所选真实对象、基于哪个可读版本、目标仓库版本、必需依赖及理由、复用/新增/移除文件、预估新增字节、影响清单、错误/未能检查项。确认执行重检版本/对象，过期就重做计划而不是继续删。

任务状态与内容状态分开：任务有排队、准备、检查、发布、成功/部分成功/失败/取消/中断；资料另有可读版本与结算准备状态。终态保存实际目标结果和是否已发布，不能仅用 Promise 是否 resolve 判断成功。

### 2.3 发布、取消、恢复与空间回收

1. 网络、作者计算、哈希检查都在短事务外做；待原件、作者 KV 的两种存储、解析/索引/必需报告全部落库后，才允许发布。
2. 发布事务在同一库内比较基线版本/操作令牌/取消标记，同时写新指针和操作提交结果；事务结束后才通知缓存和前端。不把跨两个数据库的影响预览叫成一个事务。
3. 同一资料环境修改串行，多环境操作按稳定顺序获取锁；跨标签页用库内租约/令牌及发布比较保护，不能只有 JS Map 锁。取消和重试使用新执行令牌，过期回调不能再写/发布。
4. 发布前取消：不发布，旧版可读；发布已经提交：返回实际已提交结果，不能显示取消成功却偷偷生效。请求、窗口与每阶段都要响应取消，关闭无关窗口不算取消。
5. 重开时读取持久操作：未发布标中断、允许重试；已经发布而通知没发出，照实际版本恢复成功。不要启动就自动重跑全量下载。
6. 旧读者未释放的原件暂不回收。卸载先发布移除，再回收无活动版本/准备操作/读者引用的文件；显示实际释放与待释放空间。用户自制原件不能被当作临时缓存清掉。
7. Git revert 只能退代码，不能替代数据迁移回退；迁移要可中断/幂等，旧数据完整保留到新读路径验证成功。配额不足、数据库被旧标签页阻挡都要给明确原因，不清库硬过。

### 2.4 明确的部分安装规则

官方书用作者来源/书目编号；冒险另带正文 id；自制用作者 docIdLocal 和现有稳定标识，来源缩写只是出处；`EntryRef` 与用户已存引用不改。

共用文件可含多本书，物理已缓存 ≠ 用户已安装全部来源。安装集合和依赖用途控制库目录/查询/搜索；生成条目的归属与依赖用作者 SourceUtil/加载器/已有变体标记，不凭 DND 知识删字段。依赖仍可满足已引用条目，但不能偷偷在书架当成用户选中全部书。

新增一本书默认使用该环境当前仓库提交；更新到新提交时，计划列出既有已装书与共享文件的连带变化。第一版不引入“同一环境每本书任意不同官方提交”的新产品能力。中英按已有对照规则列出相应目标及其失败结果，不假设任一本中文都必有英文对应。

- 阅读窗口也可能因作者初始化/迁移/搜索偏好产生写请求，不能因此改写版本 R 的内容 KV；内容修改必须入准备操作，非内容会话写入隔离保存。对所有 kv-set/local-set 检查窗口角色和令牌，不只保护显式下载按钮。
- derived、corpus、备选、文档/嵌入表格、配对与内核原件读取也统一用视图；保留作者对象不变，旧 source/EntryRef 不变。
- 在同一基线提交完成读通路的必要接线；不要把半接新键的版本装到真机。旧键兼容仅用于迁移接续，不留第二套业务计算。

### T1.3 任务记录、取消和窗口收尾

- DownloadTasks 从只靠内存 Map 改成可恢复操作记录；同环境修改排队并带执行令牌，旧任务编号可查询但重试生成新执行。
- 将 AbortSignal 传到 fetchVerified/FileProvider 和作者窗口；窗口 call 有阶段超时，取消/关闭/克隆失败清除 pending。关闭后 call 直接拒绝，不留永远等不到的 Promise。
- early 的同步存储请求建立可等待的排空/确认入口，发布前检查错误与落库；方法需复用现有 request 通道，不延长固定 sleep 当作正确性证明。
- 作者原生外部自制请求不全走 FileProvider，取消要终止该操作专属小窗，并在宿主写入口校验令牌；已发出的迟到存储请求不再获准写入。

### T1.4 发布与崩溃恢复

- 准备清单及全部必需结果持久化后，在短事务内检查基线/锁令牌/取消标记，切活动指针＋写终态；网络/iframe 调用禁止放事务内。
- 取消与发布交界按事务结果裁定，提交成功却通知失败不回滚为“下载失败”。重启根据已提交指针恢复，未发布准备标中断。
- 引入旧读者释放/安全保留规则；先保证不删活数据，再回收无引用版本。不能用清空整个 derived 替代版本切换。

**相关验证**：扩展 db/files/fetcher/brew 单元；新增管理状态/原子发布/迁移/取消局部集成用例。至少验证写入失败、发布事务回滚、重启恢复、两个实例争锁、旧读者读取旧文件、新窗口读取新文件。

**退出条件**：无新版本准备时的活动文件覆盖；模拟失败后 R0 可读且用户 KV/引用不丢；同一操作不会重复发布；两套库数据库实例不互相污染提交号。提交 T1，记录迁移结果和未测边界。

## 5. T2：按书/包安装计划与共享依赖（修架构）

**依赖**：T0 部分安装方法已验证、T1。**对应**：H1/M4/M5 的计划基础。**主要位置**：plan/directory/download-estimate/frame commands、sources 登记与相关测试。

### T2.1 分清安装对象与文件

- 目录尚未取回时返回未知大小/原因，不能把未知当 0。用 get/peek 的缓存路径保留离线书目，不重新手写内置书单。

### T2.2 作者驱动的文件与依赖解析

- 从作者登记表/目录映射及 T0 已验证入口生成文件计划；类机制可登记，具体书/文件名单不手抄。根据作者 `_meta.dependencies/includes` 与加载器依赖机制处理已声明依赖；不要把 includes 都当成必须删除的依赖。

- 作者加载过程中出现额外必要读取，必须反映在可解释计划里；计划不足时重新预览/执行验证，不能在界面显示 1MB 却静默下完整资料。
- 单来源文件原样保存，共用文件原样保存；runtime 解析结果保留完整作者形状，展示/可用来源受安装集合约束；审计区分用户安装内容与仅用于依赖的内容。

### T2.3 估算、差异更新与卸载回收共用计划

- 估算新增传输字节 = 所需文件里未通过本地指纹验证的字节，不用“整套未 installed”反推全量大小；另列本地写入空间需求。
- 更新比较已装书与已装冒险正文；未装冒险不全下；作者程序版本不兼容继续拒绝。保留当前提交下增装与新提交更新的区别。
- 文件移除/类别移除形成明确差异；成功发布时替换结果集合，失败保旧。共享资源仍有人使用就保留，不能误删自制/我的库依赖。

**相关验证**：扩展 plan/download-estimate/official-update 单元；实际作者文件清单和部分安装浏览器用例。核对“全装仍可选”“少量书不全装”“未选书不冒充已装”“估算与实际请求一致”“复用共享文件”。

**退出条件**：同一份计划被估算和执行消费；每个文件有来源/依赖理由；新增/更新/卸载范围可解释，不能只把 150MB 按钮拆成若干外观按钮。提交 T2。

## 6. T3：装、导、删、更新统一入流程，发布联动（修架构）
