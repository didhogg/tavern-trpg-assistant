# D1.2a 执行交接：核心数据全量结构化导入

本文件是 D1.2a 的**执行手册**：做什么、按什么顺序、每步怎么验收、什么时候必须停。字段定义只以 `docs/handoff/D1.2_全量结构化导入_交接.md`（下称「规格」）为准；两者冲突时以规格为准，并停下报告。

## 0. 一页摘要

- **你是谁**：执行 agent。规划 agent 写规格、审批；驾驶员（用户）最终验收。你不能宣布验收通过。
- **做什么**：对 SRD 与现有十本书（PHB、DMG、MM、XGE、TCE、SCAG、VGM、MTF、MPMM、BMT），完成规格 §6 的 R0–R15：修复结构错误、导入全部类别与子结构、书籍正文与地点、中英对照、文字清洁、构建校验。
- **不做什么**：其余 2014 版书与冒险（D1.2b）；全库搜索、语言切换等界面（L1B）；规则引擎（R1）；人物数据层（U6）；推送、发布、安装。
- **怎么交付**：每个工作包一次本地提交；中途在检查点 1 停下等审批；全部完成后交一份报告，写明「未经审批，未验收」。

## 1. 术语（全文按这里的意思理解）

| 术语 | 意思 |
|---|---|
| 条目 | 内容包 `entries/<type>.json` 里的一项：`{ id, type, name, nameEn, summary, keywords, unique, data, i18n? }` |
| 来源记录 | 5etools JSON 里的一条记录（一个法术、一个物品……） |
| 字段路径 | 来源记录里的字段位置，数组下标写成 `[]`，如 `item.packContents[].item` |
| 字段覆盖矩阵 | `tools/data/config/fieldCoverage.ts`：每个字段路径登记 `mapped` / `text` / `dropped` |
| 子结构 | 条目内部的结构化部分：物品内容物、家族成员、变体模板、怪物巢穴动作、特性的选项池等 |
| 孤儿特性 | 有归属（职业或子职业）却没有被任何升级操作授予或列入选择的特性 |
| 流程型特性 | 只描述升级步骤、本身不是能力的特性（属性值提升、选择子职业、「道途特性」占位） |
| 可掷表 | 第一列是骰点（`d6`、`d100`、`01–02` 等）的表 |
| `tableRef` | 正文块 `{ tableRef: { id, label } }`，界面显示为可点的随机表术语 |
| `i18n.en` | 条目上的英文原文：名称、摘要、各文字字段 |
| 对齐率 | 有 `i18n.en` 的条目数 ÷ 该类型条目总数 |
| 核心范围 | SRD 与上述十本书；只对它们生成包 |
| 检查点 | 必须停下、提交、等规划 agent 回复「通过」才能继续的位置 |

### 7.2 地点 `kind` 判定

只按 `tools/data/config/locations.ts` 中逐条列出的名称判定，不按关键词猜。DMG：星光位面、以太位面、妖精荒野、堕影冥界、元素混沌、四元素位面与各外层位面为 `plane`；「内层位面」「外层位面」为 `realm`（分组）。SCAG：「剑湾与北地」「领主联盟」「北地的矮人要塞」「诸岛国」「独立国度」「幽暗地域」为 `region`；城市与城镇为 `settlement`；要塞与遗迹为 `site`。规则性小节（如「位面旅行」「外层位面游历」）不是地点。判定不了的列入报告并停下。

## 8. 完整性的三道保险

1. **字段覆盖矩阵**：任何来源字段都有去处（R0）。
2. **数量对账**：每个类型、每个子结构都与 5etools 核心范围的记录数对账，差异逐条说明（报告 §2）。
3. **反向检查**：从数据出发查——孤儿特性、没有归属的表、断链引用、没有内容物的套组、没有成员的家族、没有对应语言条目的语言编号，都必须为 0。
