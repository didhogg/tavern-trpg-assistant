# D1.2a 执行交接：核心数据全量结构化导入

本文件是 D1.2a 的**执行手册**：做什么、按什么顺序、每步怎么验收、什么时候必须停。字段定义只以 `docs/handoff/D1.2_全量结构化导入_交接.md`（下称「规格」）为准；两者冲突时以规格为准，并停下报告。

## 0. 一页摘要

- **你是谁**：执行 agent。规划 agent 写规格、审批；驾驶员（用户）最终验收。你不能宣布验收通过。
- **做什么**：对 SRD 与现有十本书（PHB、DMG、MM、XGE、TCE、SCAG、VGM、MTF、MPMM、BMT），完成规格 §6 的 R0–R15：修复结构错误、导入全部类别与子结构、书籍正文与地点、中英对照、文字清洁、构建校验。
- **不做什么**：其余 2014 版书与冒险（D1.2b）；全库搜索、语言切换等界面（L1B）；规则引擎（R1）；人物数据层（U6）；推送、发布、安装。
- **怎么交付**：每个工作包一次本地提交；中途在检查点 1 停下等审批；全部完成后交一份报告，写明「未经审批，未验收」。

## 1. 术语（全文按这里的意思理解）

| 术语 | 意思 |
|---|---|
| 条目 | 内容包 `entries/<type>.json` 里的一项：`{ id, type, name, nameEn, summary, keywords, unique, data, i18n? }` |
| 来源记录 | 5etools JSON 里的一条记录（一个法术、一个物品……） |
| 字段路径 | 来源记录里的字段位置，数组下标写成 `[]`，如 `item.packContents[].item` |
| 字段覆盖矩阵 | `tools/data/config/fieldCoverage.ts`：每个字段路径登记 `mapped` / `text` / `dropped` |
| 子结构 | 条目内部的结构化部分：物品内容物、家族成员、变体模板、怪物巢穴动作、特性的选项池等 |
| 孤儿特性 | 有归属（职业或子职业）却没有被任何升级操作授予或列入选择的特性 |
| 流程型特性 | 只描述升级步骤、本身不是能力的特性（属性值提升、选择子职业、「道途特性」占位） |
| 可掷表 | 第一列是骰点（`d6`、`d100`、`01–02` 等）的表 |
| `tableRef` | 正文块 `{ tableRef: { id, label } }`，界面显示为可点的随机表术语 |
| `i18n.en` | 条目上的英文原文：名称、摘要、各文字字段 |
| 对齐率 | 有 `i18n.en` 的条目数 ÷ 该类型条目总数 |
| 核心范围 | SRD 与上述十本书；只对它们生成包 |
| 检查点 | 必须停下、提交、等规划 agent 回复「通过」才能继续的位置 |

### 7.2 地点 `kind` 判定

只按 `tools/data/config/locations.ts` 中逐条列出的名称判定，不按关键词猜。DMG：星光位面、以太位面、妖精荒野、堕影冥界、元素混沌、四元素位面与各外层位面为 `plane`；「内层位面」「外层位面」为 `realm`（分组）。SCAG：「剑湾与北地」「领主联盟」「北地的矮人要塞」「诸岛国」「独立国度」「幽暗地域」为 `region`；城市与城镇为 `settlement`；要塞与遗迹为 `site`。规则性小节（如「位面旅行」「外层位面游历」）不是地点。判定不了的列入报告并停下。

### 22.5 `_copy` 与 `_mod` 的解析（`tools/data/extract/load.ts`）

fluff 文件里大量记录是「复制另一条再追加或替换」：种族 56 条、怪物 460 条、子职业 22 条带 `_copy`。解析后才有正文。

**现有 `applyMod` 的缺陷（已核实）**：

| 缺陷 | 后果 |
|---|---|
| 不认识 `prependArr`、`setProp`（fluff 里共 332 + 15 处）、`removeArr` | 退化为对象展开，数组被当成对象覆盖，**静默产生错误数据** |
| `_mod` 的属性值可以是**操作数组**（如 `action: [{ mode: 'appendArr', … }]`、`'*': [{ mode: 'replaceTxt', … }]`），现有代码只处理单个对象 | 数组被整体当作新值写入，操作没有执行 |

**改法**（只改 `applyMod` / `applyMods`，不改别处）：

1. 支持 `prependArr`（`items` 可以是单个对象或数组，放在原数组最前）、`setProp`（用 `value` 整体替换）、`removeArr`（`names` 可以是字符串或字符串数组，按 `name` 删除；删不到时保持原样，不报错）。
2. 每个属性值既可以是一个操作，也可以是操作数组，按顺序依次执行；`'*'` 同理（`replaceTxt`）。
3. **未知模式不再静默**：保持原值不变，并登记到构建报告 `unsupportedMods`（记录名、来源、模式）；**核心十本书范围内的记录出现未知模式 → 构建失败**。
4. `images` 属性上的任何操作直接跳过（图片整体丢弃）。

**这一改动会让主数据里少数记录的输出变化**（以前被静默忽略的操作现在生效）。规划 agent 已核实，核心十本书里受影响的记录只有：3 个变体背景（PHB）、4 个 BMT 拘禁无人机、厄兆猎犬（XGE）、3 个布耶格奴仆（VGM）；另有 3 个怪物模板（PHB，不输出条目）。

- 报告逐条列出构建前后输出发生变化的**非 lore** 条目（条目 id、变化的字段、一句话原因）。
- 如果变化的条目超出上面这 11 个（模板除外），**停下报告**。
- 已评审通过的内容不得因此回退：基线 id 5,985 个全在；`d12a-r7-audit`、`d12a-layers` 全部继续通过。

### 22.6 描述文字的匹配与转换规则

**匹配**：用解析后的 fluff 记录的 `ENG_name` + `source`，与输出条目的英文名 + 来源书匹配；匹配必须使用 `plan.ts` 生成条目的同一套名称与 id 规则，不另写一套。

| 类型 | 匹配方式 |
|---|---|
| 种族、背景、职业、子职业、怪物、法术 | `ENG_name` + `source` 与对应类型的条目一致 |
| 亚种族 | fluff 名为「种族 (亚种族)」（如 `Dwarf (Hill)`），对应 id 为 `subrace.<种族>-<亚种族>.<书>`（与 `plan.ts` 生成 id 用同一个 slug 函数）；规划 agent 预检 43 条里 36 条能匹配 |
| 匹配不上的 | 不新建条目、不猜测；列入报告「未挂上的 fluff」，写明 `ENG_name`、来源、原因。已知情况：怪物的「组基础」记录（如 `Angels`、`Hags`、`Black Dragon`，只作为 `_copy` 的基础，约 118 条）、种族的「(Base)」记录（5 条）、SCAG 的 `Tiefling (Variant…)`（2 条）；这些可以不挂，其余**任何**未挂上的有正文的核心 fluff 记录都要逐条写原因，超过 10 条无法解释 → 停下报告 |

**转换**：

1. 用 `convert/blocks.ts` 的 `convertBlocks`，与条目 `text` 同一套行内标记规则（`{@creature …}` 等转成 `{{ref:…}}`）。
2. 最外层元素是 `section` 或 `entries`，且其名称与条目自己的名称（中文名或 `ENG_name`）相同的，**去掉这一层标题，把内容提升到最外层**。结果：野蛮人的 `lore[0]` 是段落「披裘执斧的高个男人……」，不是标题。无名称的外层 `section` / `entries` 同样只提升内容。其余层级的小标题照常转成 `{ h, body }`（如矮人的「矮小而结实」）。
3. `quote` 保留 `by`；`inset`、`insetReadaloud` 按现有规则；`list`、`table`（含 `cell` 里的 `roll`）按现有规则。
4. **`tableGroup`**（德鲁伊 PHB「学习野兽形态」一节下的一组 10 张表）：其中每张 `table` 都转成独立的表格块，**一张都不能丢**；现有转换器对这种块的处理未经验证，必须写金样测试（§22.8 第 6 条）。
5. 转换结果为空数组的，不写 `lore`。
6. 全部 `lore` 文字不得出现：`[object Object]`、`undefined`、`{@`、`{=`；不得出现 `images`、`href` 这类图片字段残留；表格单元格来源非空的，输出不得为空串。

**落点（核心规则）**：

```
目标条目在非 SRD 包  ──▶  写进条目自己的 data.lore（内嵌）
目标条目在 SRD 包    ──▶  不写进 SRD 条目；生成「描述补丁」条目 lore.<目标 id>，
                          放进该 fluff 来源书所在的包（PHB、MM、VGM……）
```

- 原因：fluff 全部没有 SRD 标记，是非 SRD 的官方文字；D1 规定扩展仓库里只能有 SRD 内容。SRD 包里任何条目**不得**有 `data.lore`。
- 判断「在不在 SRD 包」使用**最终**归属（§22.3 之后的结果，不是 `srd` 标记的原始值）。
- 规划 agent 预检：约 290 个目标在 SRD 包（职业 12、种族与亚种族约 13、怪物约 266、背景 1），其余约 830 个内嵌；以实测为准。

### 23.3 A：矩阵去向审计

**目标**：矩阵里每条路径的 `to` 都是真实的送达位置；真丢失的内容要么本轮补上，要么挂到会交付它的工作包上，不能再挂在 `data.tags`。

**允许继续指向 `data.tags` 的路径**：来源字段名（路径最后一段，去掉 `[]`）以 `tags` 或 `Tags` 结尾，或恰为 `environment` 的；另外可在 `tools/data/config/tagTargets.ts` 里逐条登记例外（路径 + 一句理由）。例外清单写进报告，由规划 agent 审。

**方法（值追踪，禁止按路径前缀或后缀批量赋值）**：

1. 对每条待审路径，取核心十本书里该路径有值的记录最多 5 条（优先取不同类型、不同值）。
2. 用转换器产出这些记录对应的条目，在输出条目里搜索该路径的值（标量原样；数组逐项；正文用前 12 个字符匹配；数字用相同数值；枚举看转换后的编号），记录**实际找到的输出路径**与证据（条目 id）。
3. 判定四类之一：
   - **已送达**：找到了，且位置固定 → 把 `to` 改成该真实路径，`wp` 按 `expectedWp` 规则或沿用。
   - **真丢失**：所有样本都找不到 → 见下。
   - **延后**：属于后续包的交付（如 `_versions` 属于 R10，`variants` 版本关系属于 R10）→ `to` 改成在 `plannedFields.ts` 登记的规划字段（`origin: 'source-mirror'` 或规格章节），`wp` 写负责的包；兑现检查到那个包完成时才会要求它出现。
   - **应删除**：确属站点内部、布局、图片、2024 专用 → 改为 `dropped` 并写 `kind` 与具体理由。
4. 「真丢失」处理：属于 §23.4 / §23.5 的内容，本轮补上；**其余真丢失一律不在本轮实现**，列入「真丢失清单」（路径、受影响条目数、建议负责的包），规划 agent 决定归属。某一类真丢失影响 ≥ 50 个条目的，同样列入清单并在汇报开头点名。
5. **不得**因为难判断就保留 `data.tags`；也不得为了让路径「有去向」而新增 `knownEmpty`。

**产出**：`docs/probes/D1.2a_R8b_去向审计.md`，每条被修改的路径一行：来源路径 | 旧 `to` | 新 `to` | 判定 | 证据（样本条目 id + 输出路径）。

### 23.5 C：怪物变体 `variants`

**字段**（加进怪物 `data` 的 zod；`monsterDataSchema`）：

```
variants?: Array<{
  name: string               // 变体名（中文）
  nameEn?: string            // 来源 ENG_name；R13 之前允许存在
  kind: 'variant' | 'inset'  // 来源 type；variantSub 嵌套在正文里，不单独成项
  text: TextBlock[]          // 正文块
  src?: { book: string; page?: number }   // 来源块自带的 source / page
  version?: { name: string; addAs?: string; addHeadersAs?: string }  // 来源 _version 原样保留，R10 解析
}>
```

**转换规则**：

1. 每个 `monster.variant[]` 元素对应一项；顺序保持。
2. `text` 用 `convertBlocks`，`style`、`items`、`entry` 按现有规则；`variantSub` 作为小标题块 `{ h, body }`（`Satyr` 的「Satyr Pipes」是金样）；来源块上的 `token`（图片）整体丢弃，已在矩阵登记为 `image`。
3. **`spellcasting` 块**（来源变体里共 12 个，如绿鬼婆「共享施法（仅集会）」）：按文字渲染为 `{ h: 名称, body: [ {p: headerEntries}, {list: [...]}, {p: footerEntries} ] }`，不生成可执行的施法数据。`list` 每行格式：
   - 戏法（键 `0`）：`戏法：A、B`
   - N 环（键 `1`–`9`）：`N 环（M 个法术位）：A、B、C`；来源没有 `slots` 时：`N 环：A、B、C`
   - `will`：`随意施放：A、B`
   - `daily`：键 `1` → `每日 1 次：A、B`；键 `2e` → `每日 2 次（每个）：A、B`；键以 `e` 结尾表示「每个」
   - 法术名用 `{{ref:spell.…|名}}`（与正文同一套规则）；顺序保持来源顺序
4. **SRD 边界**：目标怪物在 SRD 包时，`variants` **不写进 SRD 条目**，写进 R8 的 `lore` 补丁条目（`lore.<目标 id>`，所在包为怪物来源书的包）。为此把补丁的 `data` 改为 `{ target, lore?, variants?, src, credit }`，`lore` 与 `variants` 至少一项非空（用 `refine` 校验）；R8 里「`lore` 必填」的 schema 相应放宽；同一目标仍只能有一个补丁，已有 `lore` 补丁的目标把 `variants` 并进同一个补丁。目标在非 SRD 包时内嵌 `data.variants`。
5. `lore.ts` 增加 `variantsOf(entry, index)`（规则同 `loreOf`：内嵌优先，否则取补丁），附单元测试。
6. 矩阵：`monster.variant*` 各路径改到真实位置（`data.variants[].text`、`data.variants[].version` 等）；`_version.addAs`、`_version.addHeadersAs` 的 `wp` 写 R10（它们的解析归 R10），`to` 写 `data.variants[].version.addAs` 等。
