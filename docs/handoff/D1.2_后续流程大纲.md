# D1.2 后续流程大纲（G1–G3 与 D1.2b）

驾驶员 2026-11-01 定的顺序：**G1 数据库地基 → G2 数据可用性体检（只查不修）→ G2.5 数据修正 → G3 显示整理 → D1.2b 导入**。每一步先写执行文档、驾驶员审阅后再动手；本文件是总览，细节以各步执行文档为准。

## 0. 为什么是这个顺序

- **地基先行**：资料库是数据库，不是写死的数据。包怎么存、包之间怎么扩展、书目怎么登记、设备怎么拿到新数据，这些定了，数据和界面才不会返工。
- **反例（已发生）**：先做的「显示快修」（S1，已推送）在写死的数据上做修饰。SRD 等包的职业里写死了 45 处指向塔莎的可选特性，界面就只能显示「（可选 · 需要《塔莎的万事坩埚》）」并提供「一键安装」；底子一改，这层修饰就作废。
- **真机暴露的另一半问题**：设备上的书籍包停在 1.0.1，看不到背景描述与可选特性。原因有两个：
  - 数据目录被浏览器缓存最长 7 天（CDN 响应 `max-age=604800`，代码下载目录时没有要求重新检查）；
  - 旧书没有醒目的更新提示。
- **测试缺口**：此前只测「全新安装最新版」，从没测过真实设备的状态（新扩展 + 旧书 + 旧目录）。
- **修问题按「一类」修**：驾驶员举一个例子时，指的是同一类的全部（「包括且不限于」）。

## 2. 各步

### G1 数据库地基（执行文档 `docs/handoff/D1.2-G1_数据库地基_执行文档.md`；已完成并本地提交，报告 `docs/probes/D1.2-G1_报告.md`）

1. **跨包扩展只有一条通用规则：「扩展包自己登记」**
   - 一个包对别的包能做的事只有四种：
     - 给某职业或子职业的某一级加特性（可选、或替换某个特性）；
     - 往某个选择池加选项；
     - 给某个条目补背景描述（补丁）；
     - 提供修改版。
   - 官方包与自制包用同一套规则。
   - 构建校验：任何条目引用了不在自己依赖里的包，构建直接失败。
   - 要改走这条规则的：塔莎可选职业特性 29 条与受祝击等子职业变体 16 份（删掉 SRD 等包里 45 处指向塔莎的授予）、剑湾图腾选项 6 份、卓尔装备「系列」（改成任何包都能声明的通用系列）。
   - S1 的「显示名 + 一键安装」随之撤掉。
2. **书目不写死**
   - 书目与冒险从 5etools 的 `books.json`、`adventures.json` 自动读出，只留一张「政策表」（收不收、第几档、推不推荐、例外）。
   - 依赖与层级由引用自动算出并校验。
   - 测试只检查规则（无悬空引用、无未登记字段、构建可重复），总数只写进报告。
3. **包格式说明与同一个校验器**：`docs/包格式说明.md`；导入的自制包与官方包走同一个校验器；用一个自制示例包证明能安装、能扩展官方职业。
4. **更新机制**
   - 下载目录时要求重新检查，不吃浏览器缓存；
   - 库里醒目提示「有 N 个资料包有新版本」并能一键全部更新；
   - 旧版数据在列表里标注缺什么；
   - 内置 SRD 与书籍包的数据代际不一致时提示。
5. **书名跟着包走**：包清单带「来源代号 → 书名」，删掉界面里写死的书名表。
6. **升级场景测试**：模拟真实设备，新扩展 + 已装旧版书 + 旧目录 → 看到更新 → 全部更新 → 可选特性与背景描述出现。以后每次数据改动都跑这个场景。
- **验收**：
  - 指向依赖外包的引用为 0；
  - 在政策表加一本书不需要改代码；
  - 自制示例包通过校验并能扩展官方职业；
  - 升级场景通过；
  - 界面没有写死的书名。

## 3. 常驻规则（防遗忘）

- **推送**：每一次推送都要驾驶员当次明确授权；发布、打标签、刷新 CDN、安装、删除用户数据同样要单独授权。
- **验证方式**：
  - 改动后跑 `npm run check`、`npm run test:data`、相关的快速 e2e 子集，以及 G1 起的**升级场景**。
  - 约 35 分钟的整套 e2e 只在阶段收尾、且驾驶员同意时跑；报告如实写明「整套 e2e 未在最终版本上运行」。
- **数据包版本**：包内容变了就升版本，否则设备上已装的不会更新。数据仓库目录用 `TRPG_DATA_TAG=main npm run build:data` 生成。
- **生成物还原**：构建与 e2e 之后先还原 `docs/probes/D1.1_人物数据_报告.md`、`docs/probes/D1_抽检.md`、`docs/reviews/M3-*.png`；构建报告与 R13、R14 报告在数据真的变化时随提交更新。
- **代码约束**：
  - `tools/data/convert/` 下 11 个审计过的文件只允许末尾追加或单行原地修改；
  - 单个文件不超过 400 行；
  - 不写空 catch。
- **官方书**：中文 `reference/龙与地下城官方资料/txt`、英文 `/Users/xxx/Downloads/龙与地下城官方资料/Tashas_Cauldron_of_Everything.pdf` 与 `Sword_Coast_Adventurer_Guide.pdf`。只用于手工核对，不进数据。
