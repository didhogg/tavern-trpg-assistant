## 2. 目标

让 D&D 5e（2014）内容包里**所有人物相关的规则数据都是结构化的**：规则引擎与人物界面读数字、读公式、读标准编号，不去解析中文文字或表格列名。

范围是"凡是创建人物、升级、计算数值、使用能力、结算时要用的数据"，包括但不限于：

- 职业：法术位表（含契约位）、已知戏法与已知法术数量、准备法术公式、随等级变化的资源值（狂暴次数与伤害、武艺骰、气点、偷袭骰、术法点、卓越骰、已知祈唤等）、各级选择（战斗风格、专精、魔能祈唤、超魔……）、起始装备。
- 子职业：三分之一施法者的法术位表、扩展法术、随等级变化的资源值。
- 种族与亚种族：属性加值（含人类、变体人类、自选加值）、速度、感官、熟练、语言、抗性与免疫、天生法术、特性的数值效果。
- 背景：熟练（含自选）、语言、起始装备。
- 专长：属性提升、熟练、数值效果、赠送法术、前置条件。
- 特性（职业、子职业、种族、专长、可选特性）：使用次数与恢复方式、数值效果、需要消耗的资源、可执行的行动。
- 状态、疾病、力竭：每个状态对数值与检定的机械效果。
- 物品：护甲与盾牌的 AC 数据、被动加值、魔法物品的效果与行动。
- 法术：每个职业的法术列表完整性、伤害 / 豁免 / 治疗 / 攻击的结构化行动。
- 规则选项：`engine` 与 `group`（见 `docs/units/D1_数据管线.md` §4.7）。
- 标准编号表与公式：技能、属性、伤害类型、状态、语言、工具、护甲与武器类别、学派的稳定编号；公式的写法与解析器。

### 5.2 采用流程（每一类数据都走一遍）

1. **找**：先在 §5.1 的来源里找该数据是否已有结构化版本；本地没有再上网搜（只用公开资料，不登录、不下载来路不明的文件）。
2. **验**：
   - **书目与版本**：只保留 D1 §2 白名单内的 2014 书；2024 版（XPHB、XDMG、XMM）与第三方书一律丢弃，混入则构建失败。
   - **交叉校验**：同一个值至少有两个独立来源一致才算通过（例如 5etools 职业表 与 Foundry 数据 与 5e-database）；只有一个来源的，用官方书人工核对 §8 规定的抽检数量。
   - **有效性**：导入的结构能被本项目的 zod 解析；公式能被 §6.4 的解析器解析；引用的编号都在标准编号表内；`@scale` 引用都能解析。
   - **许可**：确认来源许可与本项目（AGPL-3.0、非商用）兼容，写入 `THIRD_PARTY_NOTICES.md`、`packs/DATA-NOTICE.md` 与条目的 `credit.structured`（§6.1）。许可不明确的不导入。
3. **导**：校验通过的数据通过转换器写进条目，**不手改生成结果**；需要映射的地方（如 Foundry 的 `changes[].key` 对应到本项目的效果种类）写成配置表放在 `tools/data/config/`，并带测试。
4. **报**：每个导入项在 P0 的核对报告里记录：来源、核对方式、结论（采用 / 部分采用 / 不采用）、不一致项与处理。多个来源冲突时，**以官方书人工核对的结果为准**，并把冲突条目与页码写进 `docs/probes/D1.1_抽检.md`。
5. **补**：现成数据没有的部分才自己写（例如从职业表文字列转数字），写成转换器代码，不手填数据；确实需要手填的（少量、无来源的）放 `tools/data/config/` 里的表，每一项注明依据（书名与页码，不抄原文）。

## 6. 数据结构定义

执行 agent 在 `src/rules/dnd5e2014/data/` 里写 zod，字段名以下表为准；若发现需要调整，先写进 `NEXT.md` 待议并在报告中说明，不自行改名。本节获批后，按这些字段更新 `docs/units/D1_数据管线.md` §4。

### 6.1 通用

- 包清单 `dataVersion` 从 1 升到 **2**；`SUPPORTED_DATA_VERSION` 改为 2；安装器仍接受 1（旧包可以装，规则引擎对缺结构化数据的条目返回"缺数据"）。
- 条目 `credit` 增加可选 `structured: { by, license }`：`by` 取 `5etools` / `5etools-foundry` / `foundry-dnd5e` / `5e-database` / `本项目`，表示结构化字段的来源。
- 所有新增字段对旧数据都是可选的；`condition.effects` 由 `string[]` 改为效果数组（旧包里该字段全为空数组，读取时兼容）。

### 6.2 标准编号表 `src/rules/dnd5e2014/data/enums.ts`

稳定、全小写英文编号，附中文名（供界面）：6 项属性；18 项技能与其关联属性；伤害类型；状态；语言；工具（工匠工具、乐器、赌具、其他）；护甲类别、武器类别与武器属性；法术学派；施法进度；恢复方式（`short`、`long`、`shortOrLong`、`dawn`、`dusk`、`turn`、`round`、`special`）。数据里出现的每个枚举值都必须在表内，否则构建失败。现有 UI 层的中文对照（`src/ui/library/zh.ts`）改为引用这张表，不再各写一份（只改引用，不改显示结果；改动要带 `tests/unit/facts.test.ts` 通过）。

### 6.3 职业与子职业

```
spellcasting?: {
  ability, progression: 'full'|'half'|'third'|'pact',
  preparation?: { mode: 'prepared'|'known'|'spellbook',
                  formula?: { ability, level: 'full'|'half'|'none', min: number } },   // 例：法师 智力调整值 + 等级；圣武士 魅力调整值 + 半等级
  cantripsKnown?: number[20],          // 每级已知戏法
  spellsKnown?: number[20],            // 已知法术职业（吟游诗人、游侠、术士、邪术师）
  slotsByLevel: [ { level, slots: number[9] } | { level, pact: { count, level } } ],  // 共 20 行
  ritual?: 'book'|'known'|'prepared'|'none',
  spellbook?: { start: number, perLevel: number },     // 法师
  focus?: string,
}
```

- 契约施法者另有 `invocationsKnown?: number[20]`；奇械师带 `infusionsKnown?: number[20]`、`infusionsActive?: number[20]`。
- 随等级变化的资源值用 D1 §4.3 已定义的 `advancement` 种类 `scaleValue`（`{ id, type: number|dice|distance|text, scale: { 等级: 值 } }`），`id` 全部小写英文（`rage-uses`、`rage-damage`、`martial-arts`、`ki-points`、`unarmored-movement`、`sneak-attack`、`sorcery-points`、`bardic-inspiration`、`superiority-dice`、`channel-divinity` 等）；**`feature.uses` 与 `effects` 通过 `scale.<id>` 引用它们**。
- 各级选择用 `itemChoice`（战斗风格、魔能祈唤、超魔、战技、契约恩赐、猎人技能、游侠的宿敌与天生探险者等）；专精用新增的 `expertise` 进阶：`{ kind: 'expertise', level, count, from: 'proficient'|string[] }`。
- 属性提升（ASI）的等级：保证每个职业都有，战士与游荡者的额外等级也在。
- 子职业：三分之一施法者（奥法骑士、奥法诡术师）的 `spellcasting` 同样带 `slotsByLevel`；`scaleValue` 放子职业的 `advancement`。
- `startingEquipment`（P10）：`[ { fixed?: [{ item, qty }], choice?: [[{ item, qty }|{ category }]], gold?: { dice, multiplier } } ]`，`item` 是条目引用（`$ref`）或名称。

### 6.4 公式 `src/rules/dnd5e2014/data/formula.ts`

受限的算术表达式字符串，数据层只负责**语法校验与求值接口**，规则引擎直接复用：

- 变量：`level`（总等级）、`class.<classId>.level`、`prof`（熟练加值）、`str.mod` … `cha.mod`、`scale.<id>`、`cr`；
- 运算：`+ - * /`、括号、`floor(x)`、`ceil(x)`、`min(a,b)`、`max(a,b)`；
- 例：`5*class.paladin.level`、`max(1,cha.mod)`、`prof`、`scale.rage-uses`。
- 提供 `parseFormula(s)`（失败返回错误位置）、`evalFormula(ast, ctx)`；测试覆盖每种变量与运算、非法语法、除零、未知变量。

### 6.5 使用次数 `uses`（所有特性、专长、物品通用）

```
uses?: { max: number | string /*公式*/, recharge: 恢复方式编号, per?: string, spent?: never }
```

`max` 为公式时必须通过 `parseFormula`；`recharge` 必须在标准编号表内。数据只记**上限与恢复方式**，已用次数属于人物数据，不进内容包。

### 6.6 效果 `effects: Effect[]`（特性、专长、种族、状态、物品通用）

每个效果：`{ kind, …参数, condition?: string, when?: Req[], duration?: { … }, transfer?: boolean }`。`condition` 是给人看的文字；`when` 复用 D1 §4.5 的 `requires` 形式，供引擎判断（如"未穿护甲"、"狂暴中"）。`kind` 取值（引擎认识的种类，扩展包不能自造）：

| kind | 参数 |
|---|---|
| `abilityBonus` | `ability`、`amount`、`max?`（上限，如 20） |
| `abilitySet` | `ability`、`value`（如巨人力量手套设为 19） |
| `skill` | `skill`、`level`: `half` / `proficient` / `expertise` / `advantage` / `bonus`、`amount?` |
| `save` | `ability` 或 `all` 或 `death`、`level`: `proficient` / `advantage` / `disadvantage` / `bonus`、`amount?` |
| `proficiency` | `category`: `armor` / `weapon` / `tool` / `language`、`value`、`choose?: { count, from? }` |
| `ac` | `mode`: `base` / `bonus` / `floor`、`formula` 或 `amount`、`when` |
| `hpMax` | `perLevel?`、`flat?` |
| `speed` | `mode`: `walk` / `fly` / `swim` / `climb` / `burrow`、`amount` 或 `equalsWalk` 或 `bonus` 或 `multiplier` |
| `sense` | `kind`: `darkvision` / `blindsight` / `tremorsense` / `truesight`、`range` |
| `resistance`、`immunity`、`vulnerability` | `damage: 伤害类型[]`、`condition?` |
| `conditionImmunity` | `conditions[]` |
| `initiative` | `bonus?`、`advantage?`、`halfProficiency?` |
| `passive` | `skill`、`bonus` |
| `attackBonus`、`damageBonus`、`saveDcBonus`、`spellAttackBonus` | `amount`、`scope`: `melee` / `ranged` / `spell` / `weapon` / `all` |
| `advantage`、`disadvantage` | `on`: `attack` / `check` / `save` / `initiative`、`scope?`（属性、技能或伤害类型）、`condition?` |
| `extraAttack` | `count` |
| `spellGrant` | `spells: $ref[]`、`mode`: `known` / `prepared` / `alwaysPrepared` / `innate`、`ability?`、`uses?` |
| `carry` | `multiplier` |
| `size` | `value` |
| `note` | 无法结构化的效果，只保留 `text`（引擎不使用，人物界面显示） |

Foundry 数据里的 `changes[].key / mode / value` 通过配置表 `tools/data/config/foundryKeys.ts` 映射到上述 `kind`；**映射不了的写成 `note` 并计入构建报告的"未映射"清单，不丢弃、不报错**。

### 6.7 行动 `activities`

沿用 D1 §4.6，补充：`consumption: { targets: [{ type: 'uses'|'spellSlot'|'resource'|'hitDie'|'itemUses', value, target? }] }`、`effects: [效果引用]`、`duration`、`target`。导入 Foundry 的 `activities`（攻击、豁免、治疗、伤害、施法、使用）后转成该形状；`@scale.…`、`@prof`、`@abilities.…` 等 Foundry 写法统一转成 §6.4 的公式。

### 6.8 种族、背景、专长

- 种族与亚种族：`abilityBonus: { fixed?, choose? }`（补全人类 +1 全属性、变体人类、MPMM 的"+2 / +1 或三项 +1"自选）、`proficiencies: { skills?, tools?, weapons?, armor? }`（带 `choose`）、`languages: { fixed: [], choose?: number }`、`resist`、`immune`、`conditionImmune`、`senses: { darkvision, … }`、`spellGrants`、`effects`。
- 背景：`proficiencies.skills / tools / languages` 支持 `{ fixed: [], choose?: { count, from? } }`；`equipment` 结构化（同 §6.3 的 `startingEquipment`）；`gold`。
- 专长：填写 `abilityIncrease`（zod 已有，数据为空）、`effects`、`spellGrants`、`uses`；`prerequisite` 的文字都有对应的 `requires`（现在只有 32 / 74），解析不了的写 `{ text }` 并计入报告。

### 6.9 状态、疾病、力竭

`condition`、`status`（与有机械效果的 `disease`）的 `effects: Effect[]`；力竭为 `levels: [{ level: 1–6, effects: Effect[] }]`。状态的 `id` 稳定（如 `condition.poisoned.phb`），规则引擎按固定编号套用效果；包里自创的状态只有文字。

### 6.10 规则选项

按 `docs/units/D1_数据管线.md` §4.7：每个选项 `data` 带 `engine`、`group`，删除 `implemented`。
