## 1. 根因（都已实测证实）

1. **换算钥匙认「所有已装官方资料的总版本」**：中文装完、英文装完各变一次，全库旧缓存全部作废。结算小窗只读英文官方文件（`host.ts libraryData`），中文资料变了换算结果不可能变——P3 已用同一理由把自制包排除在钥匙外，没把中文集也排除。
2. **换算放在下载任务里等**：中文任务发布后交出修改权、自己接着换算，英文任务这时开始装并发布，两轮叠着跑；中文那轮算的全挂在被英文改掉的旧版本下，白算，且英文资料正在变时失败 472 条。
3. **战役小窗读旧版资料、缓存钥匙却按最新版算**：战役开着时补装书，发布后、旧版回收前（下载任务都结束后 3 秒）这段时间里现场换算的结果，会记在新版本名下，之后后台换算看到「已有」就跳过（旧代码复现：`sameKey: true, newRow: done`）。
4. **搜索索引缓存写入不带版本号、读取却要核对版本号**：每次搜索都判过期、整份重建重写（每次 2 秒多）。

## 2. 改了什么

| 文件 | 改动 |
|---|---|
| `library/sources.ts` | `kernelDataSource()`：结算小窗读的那套官方资料（英文）声明一处 |
| `rules/kernel/host.ts` | `libraryData` 读 `kernelDataSource()` |
| `schemas/kernel.ts`、`library/revision-data.ts` | 资料版本加可选 `kernelFiles`（只算 `kernelDataSource` 那一套）；`official` 不变，存档的「资料版本变了」照旧 |
| `rules/kernel/cache.ts`、`precompute.ts`、`runtime.ts`、`core/backend.ts`（回收） | 换算钥匙、缓存清理标记改用 `kernelFilesVersion()`（没有 `kernelFiles` 的旧数据退回 `official`，只会多算） |
| `rules/kernel/precompute-queue.ts` | 现有后台队列加：模式（full 盖过 changed）、「还有下载任务在跑就等」、「又开始装资料就停下放回队里」、`state()` 查换算状态 |
| `rules/kernel/convert-schedule.ts`（新） | 欠账：装哪套欠哪套；装的是英文 → 所有语言都欠一轮；记进【库】`kc-pending:语言`，完整跑完才划掉，下次打开插件接着排。插件更新（内核指纹变）照 P3 不自动重跑 |
| `library/tasks.ts` | 官方资料发布后调 `afterInstall`（配对表预热 + 排队），不再在任务里等换算；`startPrecompute` 单独重跑照旧 |
| `library/kernel-check.ts`、`rules/kernel/runtime.ts` | 资料版本可按指定版本算；战役小窗的换算缓存按小窗自己那一版算 |
| `library/cache.ts` | 搜索索引写入带 `version` |

换算状态：`backend.library.precomputeQueue.state()`（在跑 / 排队 / 上一轮结果）+ 原有 `precompute.status(语言)`（完整没有）。下载任务的完成只表示书已发布。

## 5. 没做 / 照实列出

- **页面卡顿没修**：拆开看，卡顿出在作者程序整理资料（配图说明、隐藏条目、搜索索引，每次约 1 秒，WebKit 1.5–2.3 秒）和后台换算时结算小窗内部（开机、每类资料第一次整理，最长 Chrome 1.15 秒、WebKit 3.3 秒）。都是作者程序 / 小窗内部的一次调用，调用之间插等待解决不了。
- **战役开着时补装书，要重进战役才能继续加东西**（原有问题，这次测到）：战役小窗固定在打开时那一版，旧版被回收后取不到条目。修要动战役小窗开关，不在本支线。
- **界面看不到后台换算进度**：下载列表本来就不显示换算任务；后台换算现在在队列里，界面接线等驾驶员排。
- **英文每轮固定 40 条换算失败**：改前改后都是这 40 条，原来就有，没查。
- `p3-3b-full` 旧 e2e 原来就坏（见 NEXT），这次没跑。
