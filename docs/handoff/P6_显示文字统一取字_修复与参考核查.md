# P6 显示文字统一取字：修复与参考核查

最新续修见 §8；§1–7 保留 c270966 的交付记录。

2026-11-18。基线 ab05f9c；只修显示来源、编号和取字通路，不改人物存档和作者条目格式，不新增规则引擎。源码与下列参考仓库均已核查；参考仓库只读。

## 1. 本轮采用的结构

```text
所有建卡与起始装备结果（原值 + 出处）
                 │
       display 自动遍历全部显示字段
                 │
        resolve(requests) 一次提交
                 │
         按出处登记自动分派
      ┌──────────┼──────────┐
   语言包真实键   作者配置编号   作者渲染/原文位置
      │          │          │
   原结算小窗   本战役语言的作者小窗
      └──────────┴──────────┘
                 │
          按原位置一次回填
       未解析：原文 + 具体失败依据
```

业务模块不按种族、职业、专长、法术、物品各接一套翻译。结果内部保留来源身份，统一出口自动发现需要处理的字段。请求中的 source 是文字的出处，不是新的资料类别或存档格式。

- `shown.ts`：FrameText 标出处，Shown 是出口交回的文字。库条目携带类别、来源、hash；作者配置值保留整组编号。
- `display.ts`：递归收集所有 FrameText，批量取字、核对库名、一次回填；不按字段名白名单挑着翻译。
- `author-text.ts`：只有 `resolve(requests)` 负责批量取字；隐藏作者小窗、结算小窗和静态配置缓存。已有库类别名的 labels 方法保留兼容，同样转入这个入口。
- 作者小窗只有一个新批量命令 `authorTexts`，由来源登记调用已有 valueLabels、authorAt、prerequisiteText、Renderer.generic。撤回本轮中途新增的 proficiencyTexts 专用命令。
- `valueLabels` 沿用 P5.5 的自动配置识别，读取作者 Parser 的表和转换函数；不补插件自己的技能、属性、工具或载具译名表。

一个入口可以统一已有来源的接线，不能从一个无出处的英文字符串推断它到底是编号、物品名还是正文。新增业务结果仍须保留原始出处；不能把任意字符串标成“语言包已处理”。

## 2. 查实的根因与修法

| 根因 | 本轮修法 |
|---|---|
| 普通英文可被 sys() 直接标成已本地化，审计不再追查 | 删除该构造方法；语言包来源必须有实际语言键，出口再查当前语言值。未知文字不能冒充已翻译。 |
| 无来源工具名被 valueItemId 默认拆成 DMG 物品 | 删除猜来源的函数；用 Plutonium 自己的熟练渲染入口产生真实物品链接，保留完整编号。三龙牌实际在 PHB/XPHB，不能因 DMG 查询失败说没有中文。 |
| 同一结算武器键能反查到 PHB/XPHB 两个作者编号，旧代码只接受一个 | 作者组件阶段保留本来的完整编号；必须反查时保留所有来源，译名一致才共用，冲突留下完整依据，不任选一个。 |
| 技能、属性、载具配置编号被当成普通文字，或整组中混入物品 UID 导致配置表匹配失败 | 作者条目用编号取名；剩余同类配置值整组交现成 valueLabels。专精等没有原始物品链接的结果也在共同计划阶段保留配置出处。 |
| anyArtisansTool 被当物品；Improvised 没有交回实际语言键 | 前者转调作者 getMappedAnyProficiency；后者从已加载语言字典取得真实键。都经过同一批量入口。 |
| dnd5e 资料包及 Plutonium 生成的标题在正文中没有对应位置 | 优先原文位置；其余标题自动从锁定的资料包进阶和程序显示字段提取，沿已有译名表工具生成语言键，不逐词手翻。 |

数值、选择代码、作者编号和保存格式不变。译名修好不代表原来“暂时无法加到人物卡”的熟练突然可保存；本轮不把名称修复冒充规则自动化修复。

## 4. 三个参考项目对接线/自动化的帮助

### DND-card-web-main

已读 README、RULE-COVERAGE、ARCHITECTURE、RULE-PACKS，并查 `src/core/proficiencyText.ts`、`training.ts`、`automation/training.ts`、`automation/reviewedWeapons.ts` 和 `src/data/adapt.ts`。

- 可借鉴：资料身份保留来源/版本，显示与保存分离，失效来源不抹掉原始选择。
- 不采用其中文化：proficiencyText.ts 有项目自写的 EQUIPMENT_TRAINING、tools 和别名表，正是本项目要避免维护的第二份对照。
- 不能直接取代建卡后端：RULE-COVERAGE 明确采用手动角色卡；复杂选择/前置条件/熟练仍有手动范围。部分 automation 还按审核快照和具体规则身份验证，不能把这些搬过来冒充作者的通用选择接口。

### obr-suite-main

已读 README、AUTOMATION-ASSESSMENT，查 `src/i18n.ts` 与 `modules/characterCards/localization.ts`。

- 可借鉴：在一个地方集中管理界面说明句，保留自动化未支持范围、操作结果与来源证据。
- 不采用其中文化表：它维护自己的中英 TR/TEXT/TERMS，不能代替 5etools/Foundry 配置。
- 评估文档明确区分持续修正、授予选择、动作、资源、效果实例，并明确完整执行系统尚有缺口。其历史判断点百分比不能当作本插件新增覆盖率。
- 不用其独有规则定义替换本项目已经运行的 dnd5e/Plutonium 文档。

### plutonium-addon-automation-master（PAA）

已读 README、CONTRIBUTING、Resolution Order，查 Api、DataManager、DataSourceSelf、DataSourceIntegrations、Integrations 和 module/data。

- 有真实统一入口：`pGetExpandedAddonData`；按类别/身份匹配补充数据，逐属性优先级和 `_merge` 合并。不能改成“整条找到一个来源就停止”。
- 本地原始数组合计 36 条（含官方、自制、多种类别），不是几千条全能规则。外部 CPR 集成及宏需要另外的运行环境。
- effects/itemMacro 的 requires 会按实际模块过滤；不能把“读到了数据”当成“宏已经执行”。
- 它给导入文档补效果和活动，不提供替代 dnd5e Trait 的熟练选择存档接口，也不是中文包。
- 本轮没有新增 PAA 运行接线，也没有测得新的自动化覆盖率。

## 5. “暂时无法添加”下一步应怎样查

本轮只给统一方向，不扩建另一套结算内核：

```text
作者的选择组件
    ↓ 作者自己的表单结果
作者自己的人物写入入口
    ↓
统一检查写入计划 / 原生文档校验
    ├─ 可表达 → 实际写入 → 保存 → 冷重建 → 撤回后恢复
    └─ 不可表达 → 保留原始结果、写入目标和拒绝原因
```

应在上述共用入口核对哪里丢失，而非给三龙牌、载具、武器分别写规则。如果需要扩展原生文档支持，须先证明作者写入结果、保存与冷重建均成立，再按审批范围实施。名称已中文化的候选仍不能因改了显示就算“可添加”。

驾驶员明确批准 `Max Prepared Spells → 法术准备上限` 这一项译文，并要求公共中文取字接到所有业务，后续模块沿用。

### 实际接线

```text
services.backend.texts = library.service.texts（一个实例）
                │
     ┌──────────┼───────────┬───────────┐
   建卡选项    起始装备    库分类名    编辑器可选值
     └──────────┴───────────┴───────────┘
                │
       resolve 一批取字 / values 同组编号
                │
       ┌────────┴────────┐
  登记的语言文件        authorTexts 唯一作者命令
   读取并缓存          复用作者配置与渲染程序
```

- 公共实现搬到 `src/library/texts.ts`，由 `LibraryServiceCore` 创建一次，总后端暴露 `texts`；删除原先位于结算模块内的 `author-text.ts`。
- `src/library/text-packs.ts` 按已有 vendor 总清单、包清单和语言包清单读取；普通业务取语言键无须开结算或作者小窗。同一语言读取一次；读取失败可重试；只接受登记包，不混用其他系统同名键；当前语言缺键不给英文假译文。
- 建卡、起始装备经库服务的同一 `texts.reader(codeSet)` 取得批量读取器，不再自己接系统语言命令；原 `displaySystemTexts` 运行命令删除。
- 库分类经 `services.backend.texts.values`；编辑器字段从直接 valueLabels 调用改为 `library.service.texts.values`，原字段表和候选编号不变。
- 补丁放 `tools/approved-translations.json`，保留原文、译文、所属包、语言和授权说明。生成器写入原有稳定语言键和复核清单，并更新语言包摘要；运行时仍按同一个键读取，不在页面判断英文词。
- 守卫扩到所有业务：禁止绕开公共服务直调取字命令，禁止业务各建 TextService/TextPacks。类型检查继续要求结算显示结果保留出处。

### 后续模块的用法

```ts
const texts = services.backend.texts
const labels = await texts.resolve(codeSet, requests) // 所有出处一批处理
const groups = await texts.values(codeSet, [values]) // 原配置编号不变
```

结算结果继续标为 FrameText 后交同一个 display，自动遍历与回填；新增字段无需增加字段名白名单。条目名保留完整编号与战役范围，正文保留原始出处；不要把裸英文伪装成已本地化文字，也不要复制另一份译名表。原有静态生成的编辑器字段中文名仍沿作者生成管线，不另加运行时翻译器。
