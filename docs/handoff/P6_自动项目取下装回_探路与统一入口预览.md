## 1 任务边界与已定要求

- 人物允许英文名，另填英文副名可选；取消「随行／留守」。
- 自动项目「取下」= 原始项目、来源、选择保留，暂时不参与实际使用／计算；可以装回，不是永久删除。
- 手动添加独立保留，取下／装回／添加均应可撤销、可保存与恢复。
- 不为某个种族、背景、职业编规则，不建第二套条目 schema，不翻译玩家自己填写的名字。
- 参考 Tidy5e 的操作方式及 dnd5e 6.1 的原生效果、文档、成长程序；运行的是插件结算小窗中的原作者程序，不是正版 Foundry 服务器。
- 先看最新交接、P6-7、P6-6、P6-5、P6-1 §4 和当前源码，再沿作者对应目录核查。

## 4 根因：统一收拢，不按条目补丁

### 4.1 能力判断与是否生效混在一起

frame/writings.ts 的 classifyChange 部分依赖「当前人物有没有该属性」。Alert 生效时存在 flags.dnd5e.initiativeAlert，停用后不存在，反而被判不支持。unsupportedFor 又扫描了停用的效果。

同一误判传到 commands.ts 的 operate、people.act 和 runtime.compact：原生操作完成，也可能因整个人物存在诊断而回滚，或拒绝抓取成长记录。

实施应区分「作者能否处理」「目前是否启用」「本次操作是否真正失败」；不能只改 Alert、给 items.hidden 加一个临时白名单，或把所有 unsupported 一律改成 complete。应保留真实未覆盖说明；只读抓取成功、无关的手动状态修改，不应被停用效果的诊断一并拖死。操作所依赖的规则确实不完整时仍须明确提示。

### 4.2 原始分配与当前计算结果不能互相覆盖

同一熟练的第二个固定提供者可能没有出现在当时的 chosen 中。仅保存／回放当前值不能代表原始来源。计算副本中取下了一项，也不能因此把永久来源与原始选择覆盖成「从未拥有」。

实施应保留原作者来源、原生选择及用户的启用安排；每次产生实际计算结果时，让作者重新判断固定授予，恢复有效选择，再应用独立的手动调整与游戏状态。不另定义种族／背景／职业规则表。

### 4.3 条目屏蔽与成长应用是不同执行阶段

items.hidden 能阻止条目使用、恢复及携带效果，但不能撤去已写进人物基础值的成长，也没阻止本样本 prepareRace 继续提供步速。必须在共同的人物准备／成长应用阶段尊重屏蔽安排，不能只在列表隐藏。

本轮熟练原型单独调用作者的 Trait 程序，是验证该执行机制，不是计划给每种资料类别各接一个后端。其他原生成长有不同的数据和顺序要求，不能把这一段循环原样当成所有类型的生产实现。

## 5 统一人物入口：待批准的实施预览

```text
原作者来源／原生选择 ── 保留不删
            │
人物的使用安排：启用／取下 + 独立手动调整
            │
            ▼
共同的人物准备与成长流程
  作者判断固定授予 → 恢复有效选择 → 原生计算
            │
  同一份生效人物：读取、候选、掷骰、资源操作
            │
  公共显示出口 + 已有战役保存／撤销
            ▼
     页头与所有人物分页复用
```

### A 先统一目标定位、结果与保存语义

- 在已有 people.edit 和原生文档操作内统一定位人物、物品及其内嵌效果；使用完整身份和文档归属，不按名字找，不给每个内容类型开一个接口。
- 校正上述能力误判与结果传播，覆盖编辑、掷骰、抓取选择和保存；停用／受抑制与未覆盖分开。原作者真实错误、缺资源、待选择不能被吞掉。
- 把当前反例改成正式链路正向回归：自动效果能停用后保存、普通生命操作不被拖累、刷新后仍停用。

### B 在已有运行时里接原始分配与生效准备

- 用户控制只记录具体作者来源、原生成长身份／等级／子项及启用安排；不是新的资料条目格式。
- 原始来源与选择保留，生效副本按控制准备。装回恢复原身份，不新发另一份；固定授予重新问作者，不能仅复用被去重的 chosen。
- 依据作者自身登记的成长类型和原生流程分派，保持其顺序和返回的数据；不把 Trait 的数据硬套到其他成长类型。
- 手动调整、生命、已用次数等与自动分配分开保存和叠回。对已取下项目保留资源现状；取下／装回不赠送次数或休息恢复。
- 重算限于受影响人物。准备缓存必须考虑来源版本、原生选择及屏蔽安排；不能命中另一种启用状态的旧结果，也不全库重新换算。
- 若必须扩存档管理字段，附兼容读取／迁移；旧档默认沿用原有启用状态，不静默丢弃旧数据。

### C 统一读取、显示和可操作说明

- 扩现有 people.sheet：最终数值、作者实际可提供的计算说明、启用／已取下项目、来源和可操作／不可操作原因。
- 所有给人看的作者文字继续走 display 和 services.backend.texts；原始作者编号、数值和玩家填写的名字不拿去翻译。英文副名接已有个人信息管理；不建第二份译名表。
- 不为每个最终数字虚构可删的来源分解；自动授予项目按真实作者记录展示。

### D 保存、预览、撤销共同闭合

- 取下／装回／添加经现有人物入口和存档短事务一起落地，使用安排与实际状态不能只写成功一半。
- 读取、实际掷骰、候选、条目使用与休息恢复读取同一份生效安排；禁止 UI 自己缓存一张关闭表。
- 升降级仍用作者成长管理器；待选项复用现有建卡显示方式。预览须记基线版本，确认时检查该版本，取消不留下试算改动。
- 撤销恢复安排和人物状态；历史可按人物查看，继续保持战役顺序撤销，不承诺单独跳步撤销某个人。

主要落点是已有 people.ts、runtime.ts、frame/commands-sheet.ts、frame/commands-level.ts、frame/writings.ts 与原保存／状态模块；显示沿用现有 display.ts、library/texts.ts。不因每种职业／种族新增一套服务。

## 6 执行顺序与预计功能

1. 修共用目标定位与判定／结果传播；先让原生效果经正式入口保存、刷新后保持停用。
2. 接共同的原始分配／生效准备，验证重叠来源、单项／整组取下、手动同名项目与循环装回；其他成长类型仍需先验证作者流程，不套用熟练原型。
3. 接统一读取和公共显示，保留完整身份与实际来源。
4. 闭合缓存、版本、保存／重开、撤销、升级和休息，再交前端。

预计完成：前端可统一读取生效与已取下项目；取下不删原始资料，装回不重复；手动添加独立存在；关闭的贡献停止进入实际计算／使用，重叠来源不互相误删；保存、完整页面刷新和撤销保持一致。

## 7 仍未证明的边界

- 尚无正式自动屏蔽管理功能。熟练重算、属性往返仅在克隆原型成立，**没有把这些原型接成正式存档屏蔽功能**。
- 未完整验证其他作者成长类型：授予／选择物品、修改物品、体型、等级生命、随等级变化的数值、子职业；没有宣称「所有自动项目已覆盖」。
- 未完整验证一个成长组中单独取下一项、手动与自动同名、升降级后维持屏蔽、共享授予物品／法术、休息不恢复屏蔽条目次数。
- 未跑真 SillyTavern／TauriTavern、全量 e2e、推送或部署。
- 若下一阶段发现作者公共流程不能安全表示某类屏蔽，应停下报告实际边界，不按具体条目补丁，也不把原型删数据式回退当产品存储方式。
