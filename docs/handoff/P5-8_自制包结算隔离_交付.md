# P5-8 自制包结算隔离

## 改前和改后

```
改前  已装自制包原文 → 英文结算窗口 → 中文复制找不到原件 → 整批自制变空

改后  同一版资料库
        ├─ 战役打开
        └─ 下载结束后的后台换算
                 ↓
        中文复制用中文作者加载器展开临时副本
                 ↓
        Plutonium 用自己的合并和物品预读检查整批
          ├─ 通过 → 当前窗口载入
          └─ 失败 → 带实际依赖逐组复核
                       ├─ 可用包继续结算
                       └─ 无法载入的包返回包名和原因
```

- 作者包原文、原来的类别和编号继续留在库里。展开只处理指向外部官方来源的复制。自制包之间的复制和包内复制交给 Plutonium，保留作者的依赖规则。
- 中文自制物品可以引用中文武器专精。结算窗口用作者加载器查中文官方专精定义，再用 Plutonium 的注册入口提供原定义。多包装载必须连物品预读一起通过，因为职业、背景等导入器也会用这一步。
- 两条入口读取固定库版本。换算缓存记入实际载入的包内容，战役与后台共用同一份结果。后台补换算继续只扫自制条目和备选。包含自制包的换算需先检查装载组，涉及该组的官方条目在用到时换算。纯官方模式仍按需打开结算窗。
- 排除清单经战役 `session().brews.excluded` 和后台报告 `excludedBrews` 返回。建卡、添加与重建会在定位到被排除的包时给出原因。后端可在依赖修好之后用新版本重开。保留已有规则，结算窗口准备本语言已装自制资料，读档仍可解析玩家在战役里关掉的包。

## 证据

- p64 Chrome 多包抽检发起 42 个文件的导入。一个批次因缺 `llspell` 被库导入入口取消，结算窗口收到 36 个已装包并全部载入，前后比对库里的作者原件一致。实际展开三处中文复制，原先触发错误的三个来源均出现在作者合并后的结果里。
- 同一组资料成功建官方战士，自制职业幻术师、武艺游侠，自制子职支配魔法、决斗魔法；给人物添加「守望（蜜蜂）」成功。合并结果含 85 条子职、374 条子职特性、376 条物品。p64 的全部类别断言仍有一处失败，Plutonium 载具导入拒绝「科拉科尔」的地形值「海洋」。另有样本的官方对照和自制使用同一入口都不成功，见测试留档。这里验证的是装载、建卡和换算，规则数值正确性另有自己的对答案测试。
- p63 在 Chrome、WebKit 的断网模拟酒馆中增补真实作者程序的跨包依赖试验。用真实火球术作为测试原件，验证正确的提供者和使用者能一起进入。不存在的复制原件和失去它的依赖包返回原因，官方法术仍能换算。第二次后台换算复用同一批自制资料产生的缓存。
- 定向单元 6 个文件共 27 项通过，构建（含类型检查）和改动范围的 ESLint 通过。
- 证据文件在 `work/e2e-lib/p63-kernel-brew-enter-{chrome,webkit}.json` 与 `work/e2e-lib/p64-kernel-brew-categories-chrome.json`。散装资料、测试浏览器的临时副本均在 `work/`。
