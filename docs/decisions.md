# 设计决定与规则裁定

| 日期 | 决定 | 原因 |
|---|---|---|
| 2026-10-29 | 没有战役时侧栏只有首页、库、设置；首页纯色横幅按钮打开开局向导弹窗（规则 → 资料 → 冒险 → 命名） | 页面组成由规则决定；保留一个能落脚的首页，开局入口一眼可见 |
| 2026-10-29 | 名称详情统一为下划线术语 + 模态详情弹窗；点包名直接看条目列表；弹窗内点条目与关联术语在同一弹窗内换页，「‹」返回 | 驾驶员要求；一个窗口、像翻书一样前进后退 |
| 2026-10-29 | 模态弹窗只用于确认、提示、复杂信息面板、复杂流程，且不叠加任何弹窗或悬浮窗；弹窗内的确认与一页小表单都在弹窗内换页 | 驾驶员要求；避免层层叠叠 |
| 2026-10-29 | 行尾「⋯ 更多」是下拉菜单，只放次要操作 | 常见界面约定 |
| 2026-10-29 | 开关：开 = 圆钮在右 `━●`，关 = 圆钮在左 `○━` | 符合常见开关的直觉 |
| 2026-10-29 | 所有提示条与横条自动消失；失败原因留在出错的行，只读用页头徽章 | 驾驶员要求；不留常驻横条 |
| 2026-10-29 | 库分段为 [本存档][扩展][我的]，原「本存档的内容」并入库；规则切换放到库右上角，安装规则放在开局向导 | 启用一个扩展从 4 步减到 2 步 |
| 2026-10-29 | 骰盘悬浮窗先做基础版（M3，自由掷骰）：独立浮窗，可拖动，不挡后面，点外部不关；D&D 行动结算的完整版随 U3 做（后调整为 M6，见 2026-10-29 人物先行一条）；迷你模式在 M5 | 掷骰尽早可用；迷你模式要等队伍数据才有内容 |
| 2026-10-29 | 下划线只用于术语；自动计算值不加标记，手动覆盖只用「覆」徽章 | 避免同一种下划线有两种含义 |
| 2026-10-29 | 骰盘按「骰式构建器」做：点骰子只改骰式，只有「掷骰」出结果；加减值直接写进骰式；优势/劣势只对单个 1d20；结果用 SVG 骰面显示；「最近」默认折叠，点一行只载入骰式 | 驾驶员要求「先选骰式或骰面、加减值，再点掷骰」（参考 Foundry）；骰式是唯一真相，没有另一套隐藏的加值 |
| 2026-10-29 | 任务次序调整：人物线先行。M4 做派生数值、人物数据层和"加入人物"流程，M5 依次做列表、详情顶部与各人物小 Unit，M6 再做规则引擎其余部分、骰盘完整版与 AI 输出；M7 起不变 | 掷骰卡要用人物的加值、AC、HP，没有人物就没有数值可掷；先做能看到结果的加入流程，再做列表，再做详情 |
| 2026-10-29 | 按游戏逻辑分两层保存：人物卡编辑后点"保存"写进当前数据（暂存但持久，插件里显示的永远是它）；页头按钮叫"● 保存存档"，才把当前数据写进存档（覆盖或分支）。伤害、治疗、状态、法术位、身份等游戏中的即时操作直接写进当前数据，不经编辑草稿 | 驾驶员要求；编辑资料需要确认与取消，游戏中的操作要即点即生效，存档是另一层 |
| 2026-10-29 | 人物页队伍分页的随行 / 留守取代旧版"营地"标记；列表行不常驻"＋标签"，加标签放进行尾"⋯ 更多"和详情 | 沿用基本蓝图 §3 的说法；列表更干净 |
| 2026-10-29 | 加入人物对话框的来源只有"从库里选 / 空白新建"，"复制一个"放在行尾"⋯ 更多"；空白新建只必填名称，其余进入"待填"清单 | 一个对话框一条主线；加入要快，补全可以稍后 |
| 2026-11-01 | 任务次序调整：G2.5 E 站一次做完即结束 G2.5（做不了的当场定为决定项或不做，不留给后面）→ M8 地图提前作为独立模块（先定稿 U8 蓝图）→ G3 → D1.2b → M4…M7 → M9 → M10；所有里程碑执行中不新增站、子站或计划 | 驾驶员要求：数据阶段已拖太久、耗费大量 token；先用一个独立模块检验 agent 能否按蓝图完整做完一个模块 |
