# 数据转换器重构方案：形状驱动、规则即数据、无损镜像（草案；待驾驶员逐步批准）

> 来源：驾驶员 2026-11-05 多轮意见的汇总。状态：**方案已写入，尚未批准任何一步的实施**；每一步动手前仍先给 ASCII＋文字草案，批准后才做。
> 所属任务：`docs/handoff/UNIT3_整体返工排程.md` 的数据线。配套清单：`docs/probes/UNIT3_数据需求与缺陷清单.md`、`U5R2_T2r2_数据形状清单.md`、`U5R2_T2r2_数据修复清单.md`（其中的逐条 F、G 清单从此只作**验收用例**，不是修复清单）。

## 0. 原则（驾驶员定，写死）
1. **禁止逐条手工核对修复。** 按开发规范 §12：原始数据里有、转换器没读对的，修转换器、重建；判断"原始数据里没有"前必须用程序检查；逐条补只用于"源里没有"或"源本身错"的极少数，且只补机器报出来的缺口。
2. **不盯着几个点改转换器。** 转换器要按**数据的形状**自动贴合并导入，贴合参考数据库的形状；规则的单位是"写法"，不是"条目"，也不是"职业名单"。
3. **规则是数据，不是散落的代码。** 规则写成可读、可审的规则文件，由确定性的引擎执行。
4. **数据线先做完，界面线再参考数据形状做。** 界面不臆断、不手写数据（唯一授权例外：标准数组 15/14/13/12/10/8 与购点总点数 27）。
5. **要打破的循环**：界面按"我以为有什么"写 → 发现数据缺 → 回头查参考库形状 → 手写补 → 发现转换器要修 → 重导 → 下一个界面再来一遍。

## 1. 诊断：转换器的问题与漏洞（证据）

| # | 问题 | 证据 |
|---|---|---|
| ① | 手写清单当配置 | `tools/data/config` 约 1911 行手写配置（`CLASS_SCALE_COLUMNS` 只配了一部分职业的成长列、`PROFICIENCY_TRAITS`、`EXTRA_SCALES`、`featureRules`…）；覆盖修正 379 行分在 52 个文件 |
| ② | 每种条目各写一套转换，同一形状处理不一致 | `convert/` 约 7500 行；"选择"（choose／any／from／fromFilter）在种族、背景、职业、专长、法术里各处理一遍 |
| ③ | 登记表 ≠ 实现 | `fieldCoverage` 登记 `subclass.optionalfeatureProgression` 为 mapped，`convertSubclass` 并未调用 `advancementExtras`；另有约 20 项登记目标在包里一条都没有 |
| ④ | 未知写法静默丢弃 | 高等精灵"选一个法师戏法"、天生法术"自选施法属性"（17 个种族/亚种）整条丢失 |

| ⑦ | 范围写死 | `build.ts`：非核心书只收怪物/NPC（D1.2b） |

## 2. 通用数据格式转换工具调研（2026-11-05，英文通用搜索多组；不是"全网没有"的结论）

| 类别 | 代表（链接见搜索记录） | 工作方式 | 对我们 |
|---|---|---|---|
| 声明式映射引擎 | JSONata、JOLT、jq、JSLT、CUE、jsonFlow | 转换写成规则文件 | 规则要人写；JSONata 是 JS 库，和 TypeScript 栈好接 |
| 知识图谱映射语言 | RML、YARRRML；Morph-KGC、SDM-RDFizer；awesome-kgc-tools | 声明式规则把 JSON/XML/CSV 转成统一模型 | 没看到自动生成规则的成熟工具 |
| 字段自动匹配 | Valentine（含 COMA、Cupid、Similarity Flooding）、Magneto、LLM schema 映射（Oregon State 技术报告） | 猜"哪个字段对哪个字段" | 面向表格；对字段名噪声敏感；匹配不了含义（累计 vs 新增） |
| 从示例学转换（PBE） | 微软 PROSE JSON、jq-by-example（LLM 合成 jq）、JSON→关系表的 PBE 论文、Syren | 给输入输出样例，学出转换程序 | PROSE 页面很旧需核实；jq-by-example 是小项目 |
| 模式演进镜头 | Cambria（Ink & Switch、MIT） | 双向镜头描述 schema 版本间变换 | 研究级，没有稳定版 |
| LLM 起草映射规则 | MetaConfigurator（arXiv 2508.05192） | LLM 起草规则、人审规则、确定性执行 | 只有化学领域示例，无准确率数字 |
| D&D 专用 | R20Converter、FG_Converter 等成对平台转换器；5eDataParser（本地，只有怪物，怪物 JSON 状态表标未完成）；dnd5e_json_schema（BrianWendt，GPL-3.0，无背景定义）；RPG-Schema.org（本体，不是 JSON Schema） | 成对手写映射或只定义形状 | 没有现成的"5e 规则数据任意格式自动互转" |

结论：没有一个工具能"给两个格式就自动完成且理解游戏含义"；**含义这一层总要有人审**（5etools 的 `count` 是累计、Foundry 是每级新增；`"level=0|class=法师"` 是筛选写法；`{@spell 名#c}` 是带标记的引用）。可用的是：自动普查形状、规则写成数据、从成对例子归纳规则并考试、确定性执行、自动校验。

## 3. 方案

### 3.1 总图
```
  5etools（主）   Foundry（补＋形状参考）   5e-database（补＋校验，SRD）
        └───────────────┬─────────────────────────────┘
                        ▼
 ① 形状普查器（自动，只读）  扫全部源：每个字段路径有哪些"写法"、各多少条
                             对照规则文件 → 没有规则的写法清单（机器生成的漏洞清单）
                        ▼
 ② 规则起草与考试            用 SRD 里"5etools ↔ Foundry/5e-database"的成对条目当例子，
                             归纳"写法 → 目标形状"的规则；留出一部分条目当考试，自动对答案；
                             考过才采用（起草可用 LLM／示例合成工具，人审的是规则不是条目）
                        ▼
 ③ 规则文件（声明式数据）＋确定性引擎   JSONata 等为候选；规则可读、可审、可回退
                        ▼
 ④ 包 ＝ 结构化字段（对齐参考库形状，只加字段）＋ 无损镜像（5etools 原始记录整条原样存，
        仅人物要用的类型：职业、子职业、种族、背景、专长、可选特性、特性、条件、语言）
                        ▼
 ⑤ 三道自动关（构建时自动跑）
      A 未知写法 → 报"缺口"（原件还在，数据不丢）
      B 字段落地校验：登记为已映射的源字段，输出里必须有
      C 参考库交叉校验：SRD 范围里成长数值、法术位、属性加成、熟练项与参考库自动比对
                        ▼
 ⑥ 读取层（界面唯一读数入口）  先读结构化字段，没有就从镜像原件按规则取
 ⑦ 界面数据契约               每个界面声明"我要读这些字段"，自动出覆盖率报告
```

### 3.2 "含义"住在哪
- 以前住在转换器里：导入时翻译，翻错就要重导。
- 现在拆成两处：**规则文件**（导入时、可审、可回退）＋**读取层**（运行时、改代码不用重导）；镜像原件保证数据不丢。
- 不消灭"写规则"，只让它出错时不丢数据、不被迫重导，并且可被机器考试。

### 3.3 对界面开发的效果
```
 你点名一个界面（如 S5）
   → 契约报告（自动）：N 个字段，M 个已 100%，K 个只在原件里，J 个源里本来就没有
   → 缺口在读取层补一个"读法"（改代码），不改数据、不重导
   → 界面不再臆断，不再做到一半发现数据缺
```

### 3.4 对数据导入的效果
```
 导入新书（非核心书、冒险）→ 原样进包 → 形状普查对比 → 列出没规则的新写法 → 补规则重跑
 补之前数据不丢；规则补一次，所有书一起受益。
```

## 5. 风险与代价（直说）
1. 无损镜像让包变大（人物相关原始 JSON 约 4.2MB 未压缩；PHB 包现 0.98MB、SRD 包 1.16MB）；旧扩展对新字段的兼容要真机验证；`g2-additive` 放行表要加通配规则。
2. 读取层是新增的一层；界面今后只能经它读数。现有 24 个文件、约 3100 行引用旧形状，要逐个迁移（每迁一个界面，删对应的旧结构化字段）。
3. 示例学规则只覆盖 SRD；非 SRD 的特殊写法学不到，靠"未知写法即报缺口"暴露。
4. "累计 ↔ 新增"这类含义能否从例子里学出，要在 DL-1 小规模试。
5. 源数据本来没有的内容（如 96 个语言没分类，5etools 里就没有），通用算法造不出来：先按名字去参考库找，找不到就显式记"未知"并出现在缺口报告里，界面显示"其他"，不编。
6. 外部工具（PROSE、jq-by-example、MetaConfigurator、Cambria）成熟度参差，**一个都没试用过**，DL-1 才会真正试。
