# 人物页面框架提案（参考主流 VTT / TRPG 平台）

状态：规划者提案（2026-11-02），待驾驶员审批。审批后并入 `docs/units/U5_人物卡.md`（改为 v2）与 `docs/units/U6_人物管理.md`，作为「新人物界面」的目标；人物骨架的数据层（U6.1、R1.1）按本提案的数据骨架定稿。

---

## 0. 结论

**推荐「一个顶栏 + 一排属性 + 七个分页 + 点哪都能看详情」的结构，数据按「来源 → 选择 → 覆盖 → 当场状态」四层存。**

- 顶栏常驻：头像、名字、生命值（主角）、AC、先攻、速度、状态。打仗时眼睛只看这里。
- 七个分页按「在桌上要干什么」分：**行动、法术、背包、特性、能力、背景、笔记**。
- 宽屏时「能力」不再占一个分页，常驻在左边一栏（和 D&D Beyond 一样）。
- 查看和编辑分开：平时干净只读，点「编辑」才出现输入框（Foundry 的做法）。
- 怪物与 NPC 用同一个骨架的紧凑版（属性块），只有三个分页。

这和 `U5_人物卡.md` 草案的方向一致。本提案补四件 U5 草案没写清楚的事：数据怎么存才不乱、「行动」页怎么做成一站式、宽屏怎么排、和酒馆 AI 的结合点。

## 1. 参考了谁、各自最值得学的一点

> 依据：各平台公开版本的界面（2024–2026）与我对它们的了解；近期小改版细节可能有出入，不影响下面的结论。

| 平台 | 页面骨架 | 最值得学 | 不学 |
|---|---|---|---|
| **D&D Beyond** | 顶栏（名字、休息、生命值）→ 属性一行 → 左栏豁免、感官、熟练 → 中栏技能 → 右侧大分页（动作、法术、背包、特性与特质、背景、笔记、其他） | **「动作」页一站式**：攻击、动作、附赠动作、反应、有限次数全在一处，可按类别筛；有限次数的勾选格就挨着那个特性；点任何东西右侧滑出详情 | 建卡器和人物卡是两套界面，改一个等级要跳出去 |
| **Foundry VTT（dnd5e 官方表）** | 左侧边栏（头像、生命值、生命骰、死亡豁免、AC/先攻/速度）→ 顶部属性 → 分页（详情、背包、特性、法术、效果、传记） | **「游玩 / 编辑」模式开关**：游玩时只读、干净；**「效果」单独管理**，每个效果带持续时间与来源 | 靠拖拽从合集拖条目进人物卡，手机上很难用 |
| **Tidy 5e（Foundry 最流行的替代表）** | 同上，侧边栏可收起 | **「收藏」页**：把常用的武器、法术、特性钉到第一屏 | 选项太多，设置页很深 |
| **Roll20（5e 2014 与 2024 两种表）** | 核心、传记、选项、法术几页；2024 表把建卡器并进人物卡 | 掷骰结果一键发到聊天；**建卡和人物卡合一**（2024 表的方向） | 旧表一页塞满、字小 |
| **Fantasy Grounds** | 主页、技能、能力、背包、笔记、**动作**几页 | 「动作」页把武器、法术、能力的每一个可用效果列成行，带次数 | 界面老派、窗口叠窗口 |
| **Dicecloud** | 所有数值都是从「属性树」算出来的 | **每个数字都能展开看来源**（这一项从哪来、加了多少） | 自己写公式，门槛高 |
| **Pathbuilder 2e / Wanderer's Guide**（PF2 的建卡器） | 按等级的时间线：1 级选了什么、2 级选了什么… | **「待选」标记**：哪一级还有没选的，一眼看出；升级、多职业不会乱 | 只管建卡，不管跑团中的状态 |
| **Fight Club 5e（手机应用）** | 单列，左右滑动换页 | 手机上一屏一件事 | 功能少 |

## 2. 从这些平台提炼的 8 条原则（对应旧插件的毛病）

| # | 原则 | 学自 | 解决旧插件的哪个毛病 |
|---|---|---|---|
| 1 | **数据分四层存**：来源（引用库条目）→ 选择（每个来源里选了什么）→ 覆盖（手动改的数）→ 当场状态（伤害、用掉的法术位） | Dicecloud、Pathbuilder | 数据参差、填不全、升级和多职业难管——旧插件把算出来的数和填进去的数混着存 |
| 2 | **算出来的数不存**，每次由规则纯函数算（R1.1），每个数都能点开看来源 | Dicecloud、D&D Beyond | 改了一个地方别处不跟着变 |
| 3 | **查看 / 编辑分开**；跑团中的即时操作（扣血、用法术位）两种状态下都能点 | Foundry | 按钮太多、点错、无效按钮 |
| 4 | **一个「行动」页装下回合里能做的一切**，按动作类型筛 | D&D Beyond、Fantasy Grounds | 找不到要用的东西 |
| 5 | **次数就近**：有限次数的勾选格挨着那个特性 / 物品，顶栏不重复列 | D&D Beyond | 资源散在几页 |
| 6 | **「待填 N 项」与「待选」**：缺什么一眼看出，点一下跳过去 | Pathbuilder | 填数据没有引导 |
| 7 | **点哪都能看详情**，在弹窗内换页，不叠弹窗 | D&D Beyond | 交互混乱 |
| 8 | **手机一屏一件事**：顶栏收成一行，分页可横滑 | Fight Club、D&D Beyond 手机版 | 窄屏挤 |

另外两条是本项目独有的（主流平台没有）：

- **和酒馆 AI 结合**：每个人物有「给 AI」级别（自动 / 只给名字 / 完整 / 不提供），状态变化（扣血、倒地、加状态）自动进摘要（U4.0）；「背景」页的 RP 资料可以和酒馆角色卡互相参考。
- **队伍与身份**：队伍成员、NPC、敌人三种身份共用一个人物页，敌人可以一组多只（A、B、C 切换）。

## 3. 数据骨架（人物骨架 U6.1 按这个定）

```
人物 Person
├─ 身份        名字、头像、身份（队伍成员/NPC/敌人）、队伍、随行/留守、标签、给 AI 级别
├─ 来源        引用库条目，不复制内容
│   ├─ 种族（+ 亚种）、背景
│   ├─ 职业列表  [{ 职业, 子职业, 等级 }, …]          ← 多职业就是多行
│   └─ 模板      怪物 / NPC 属性块（敌人与 NPC 用）
├─ 选择        「哪个来源 · 第几级 · 选了什么」的记录
│   例：战士 1 级 · 战斗风格 → 防御；人类 · 额外语言 → 精灵语；法师 · 法术书 → [魔法飞弹, 护盾术…]
├─ 覆盖        手动改的数（带「手动」标记，可「恢复自动」）
├─ 物品        [{ 引用库物品 或 自定义, 数量, 装备中, 同调, 放在哪个容器, 充能 }]
├─ 当场状态    生命值、临时生命值、死亡豁免、已用法术位、已用次数、状态与效果（含持续时间、专注）、力竭
├─ RP          外貌、性格、理想、牵挂、缺陷、经历、口癖
└─ 笔记

派生（不存，每次算）：属性调整值、熟练加值、豁免、技能、被动值、AC、先攻、生命值上限、法术位上限、法术攻击与 DC、负重 …
每个派生值都带「来源」：例如 AC 16 = 链甲 16；或 AC 14 = 皮甲 11 + 敏捷 2 + 防御风格 1
```

为什么这样能解决「升级、多职业、物品难管」：

- **升级** = 职业列表里某一行等级 +1，再把这一级要选的东西补进「选择」。待选的会被「待填 N 项」标出来。
- **多职业** = 职业列表多一行。法术位、熟练加值由规则函数按多职业规则算，不用手填。
- **物品** = 引用库条目，名字、重量、伤害都从库里读；只有数量、装备、同调、充能是人物自己的。自定义物品存在「我的库」，同样被引用。
- **怪物 / NPC** = 来源是属性块，数值直接取数据，不重算；只有当场状态是自己的（D1.2b 的 2,682 个怪物、21 个 NPC 一键加入就是这样）。

### 4.3 七个分页各放什么

| 分页 | 内容 | 主动作 | 学自 |
|---|---|---|---|
| **行动** | 「常用」钉住区；武器攻击、可施放的法术、职业 / 种族 / 物品给的动作，按 动作 / 附赠 / 反应 / 其他 分组；每行：名字、命中或 DC、伤害、范围、次数格、🎲 | 点 🎲 打开掷骰窗并预填（M6 起结算） | D&D Beyond 动作页、Tidy 收藏 |
| **法术** | 顶部法术位与契约位；按环阶列出，多职业按职业分组；准备开关、专注 / 仪式标记；施法属性、攻击加值、DC | 准备 / 施放 | D&D Beyond、Foundry |
| **背包** | 装备中 / 背包 / 各容器（可折叠树）；负重条；货币；同调 3 格；「从库里加」（L1B 选择器）、自定义物品 | 加物品 | D&D Beyond |
| **特性** | 顶部「当前效果」（持续时间、来源、专注）；按来源分组：职业（按等级）、种族、背景、专长、物品、其他；次数格就近；「待选」标记 | 处理待选 | Foundry 效果页、Pathbuilder |
| **能力** | 豁免、技能、被动值、感官、熟练（护甲、武器、工具）、语言、抗性 / 免疫 / 易伤；每个数可点开看来源 | 无（查看） | D&D Beyond 左栏、Dicecloud |
| **背景** | 外貌、性格、理想、牵挂、缺陷、经历；种族与背景的描述；随机表一键掷（G3 做的掷表） | 编辑 | 各平台传记页 |
| **笔记** | 自由笔记；「给 AI」设置与预览（U4.0）；最近变化记录（扣血、加状态） | 写笔记 | 本项目独有 |

宽屏时「能力」常驻左栏，分页变成六个。

- 头像用 G3 做好的 `EntityAvatar`（立绘按焦点裁切 / 类型图标 / NPC 借属性块头像）。

- 「⋯」里有「转成完整卡」（以后做：把属性块拆成来源 + 选择，变成可升级的人物）。

### 4.5 编辑与即时操作

| 操作 | 查看状态 | 编辑状态 | 写到哪 |
|---|---|---|---|
| 扣血、治疗、临时生命值、死亡豁免 | 能点 | 能点 | 当场状态，立即生效，提示条带「撤销」 |
| 用掉 / 恢复法术位、次数 | 能点 | 能点 | 当场状态 |
| 加减状态、效果 | 能点 | 能点 | 当场状态 |
| 改名字、属性值、熟练、等级、职业 | — | 能改 | 编辑草稿 →「保存」 |
| 覆盖一个算出来的数（如 AC） | — | 能改，带「手动」与「恢复自动」 | 覆盖层 |
| 升级 | 顶栏「升级」按钮 | 同 | 来源 + 选择（人物骨架阶段做最简版：等级 +1、列出这一级要选的） |
| 短休 / 长休 | 顶栏按钮 | 同 | 骨架阶段只记一条记录；自动恢复归【活动模块】与结算模块 |

## 5. 对现有计划的影响

1. **U5 草案的七个分页**（行动、法术、背包、特性、数值、背景、笔记）基本不变，只把「数值」改名「能力」，并规定宽屏时常驻左栏。
2. **U6.1 + 实体底座**：按 §3 的四层定数据结构。这是本提案最重要的部分——数据结构对了，旧界面先搬过来用、以后换新界面都只是换显示。
3. **R1.1**：每个派生值都带「来源」列表（已在草案里），加上多职业的法术位与熟练加值规则。
4. **U6-L 旧界面移植**：建议**按本提案的分页顺序摆放旧界面的内容**（内容和交互照旧，只是位置按新框架）。以后「新人物界面替换旧界面」时改动最小。是否这样做请驾驶员定（见 §6 第 2 条）。
5. **G3 的头像组件**直接被人物页复用。

## 6. 请驾驶员定

1. 总体结构：顶栏 + 属性条 + 七个分页（宽屏六个 + 左栏）。**推荐：同意。**
2. 旧界面移植（U6-L）是否按这个分页顺序摆放旧内容？**推荐：是**（不新增工作量，以后替换更省事）。
3. 「行动」页是否作为打开人物时默认显示的分页？**推荐：是**（跑团中最常用）；不跑团时也可以记住上次看的分页。
4. 顶栏「升级」「短休」「长休」在人物骨架阶段是否先放最简版（只改等级 / 只记一条记录）？**推荐：是**，完整结算在后面的模块。
