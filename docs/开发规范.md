# 开发规范

## 1. 技术栈

| 用途 | 选型 |
|---|---|
| 框架 | Vue 3（`<script setup>` + TypeScript strict） |
| 构建 | Vite（library 模式输出单个 ES 模块 + CSS，供 `manifest.json` 引用） |
| 状态 | Pinia |
| 控件底层 | Reka UI（无样式、可访问）+ @floating-ui/dom（弹层定位、翻转、限位） |
| 数据校验 | zod |
| 本地存储 | Dexie（IndexedDB） |
| 搜索 | MiniSearch（中文二元切分），在 Web Worker 中建索引 |
| 骰子 | @dice-roller/rpg-dice-roller |
| 测试 | Vitest（单元）、playwright-core（e2e，模拟宿主页；本机 Chrome + Playwright WebKit，`npx playwright-core install webkit`） |
| 代码检查 | ESLint（含 `no-empty`）+ Prettier + `vue-tsc` |

新增依赖须为与 AGPL-3.0 兼容的协议，并记入 `THIRD_PARTY_NOTICES.md`。

## 3. 架构规则

1. 依赖方向：`ui → stores → core / rules → schemas`；`host` 只被 `stores` 调用；`rules` 与 `core` 不依赖 Vue。
2. 业务状态唯一来源是 store；组件只读 store、只调 action。不在组件中保存业务副本。
3. 不对宿主 DOM 做补丁式修改，不用定时器修正界面；需要宿主能力时经 `host` 的公开函数。
4. 规则计算全部是纯函数，输入输出可序列化，配单元测试。
5. 资料、模板、模组只存在于内容包；代码只依赖 schema。
6. 持久结构带 `schemaVersion`；任何结构变更同时提交迁移函数与迁移测试，旧数据自动升级。
7. 结算是原子操作：预览不改数据；确认时一次写入全部变化并生成日志条目；同一结算 id 重复确认不重复生效；撤销按日志反向数据恢复。
8. 错误必须可见：不写空 catch；错误进入界面提示（就近显示或提示条）并 `console.error`。
9. 单个源码文件不超过 400 行（生成的数据文件除外）；一个组件只承担一个职责。
10. 同一能力只实现一次；新增前先查已有实现。

## 4. 宿主集成

- 入口：`manifest.json` 的 `js` 指向构建产物；初始化幂等，重复调用不重复挂载；所有 `eventSource` 监听在卸载时移除。
- 宿主能力只经 `SillyTavern.getContext()` 取得；不导入宿主内部文件路径。
- TauriTavern：检测 `window.__TAURITAVERN__`，可用时使用其 `api.chat.searchMessages`、`store.*`、`api.layout`（安全区与输入法高度）；不可用时退回 SillyTavern 通用能力。
- 存储：大数据（内容包、当前数据、存档、底图）存 IndexedDB；`extensionSettings[模块名]` 只存小型设置。
- 当前数据键：角色卡用其头像文件名，群组用群组 ID；无聊天时面板显示"请先打开一个聊天"。
- 输入框写入、提示词注入挂载点、注释是否进入请求：以 `docs/probes/M0.md` 的实测结论为准。
- 插入页面的任何来自数据包、玩家输入或 AI 的文本，按纯文本渲染；必须渲染 HTML 时先经 `SillyTavern.libs.DOMPurify`。
- 界面挂载在 Shadow DOM 内；弹层渲染进同一 Shadow Root；样式不泄漏到宿主，也不受宿主影响。

## 5. UI/UX 规范

### 5.1 设计令牌

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| paper | `#F4ECDD` | `#20231F` | 窗口底 |
| panel | `#EEE5D3` | `#2B3029` | 区块、工具条 |
| card | `#FFFCF6` | `#181C18` | 输入、行卡 |
| line | `#CBBCA3` | `#515849` | 边框、分隔 |
| ink | `#2B211C` | `#F1EBDC` | 正文 |
| ink-2 | `#6C6255` | `#BCBBAA` | 次要文字 |
| primary | `#7A2E26` | `#E6BF73` | 主操作、选中（画面占比 ≤10%） |
| gold | `#B8954A` | `#E6BF73` | 细分隔、少量强调 |
| danger | `#A3352B` | `#E07A6E` | 危险操作、低血 |
| unsaved | `#D9892B` | `#E8A13A` | 未保存标记 |

- 字体：标题与大数字用衬线（`"Songti SC","Noto Serif SC",Georgia,serif`）；正文用系统无衬线（`"PingFang SC","Microsoft YaHei",system-ui`）。正文 ≥14px，辅助文字 ≥12px，数字 `tabular-nums`。
- 间距 4px 网格；圆角：容器 8px、内部控件 6px；容器内边距与子元素间距相同。
- 状态不只靠颜色：同时使用文字、图标或形状。

### 5.2 布局与视口

- 检查宽度：390、900、1440（窗口内部宽度）。≤480 为窄屏：列表与详情逐层进入；481–1023 为中宽：列表 + 详情两栏可收起；≥1024 为宽屏。
- 不出现整窗横向滚动；长列表在自身区域滚动；触控目标 ≥44×44px。
- 每屏一个主角、一个主操作；同一功能只有一个入口（快捷键除外）。
- 悬浮窗不能被拖出屏幕；手机默认铺满可视区，避开安全区与输入法。

### 5.3 控件选型（硬性）

| 场景 | 控件 | 规则 |
|---|---|---|
| 2–5 个固定选项 | 分段按钮 | 全部可见，一点即切 |
| 6–15 个固定选项 | 下拉选择（按钮触发 + listbox） | 不用原生 `<select>`；列表最多 8 行，内部滚动；靠近边缘自动翻转；宽度不小于触发器 |
| 大量条目 | 可搜索下拉（combobox） | 边输边筛；每行显示中文名、英文名、类型或来源徽章；↑↓ 移动、Enter 选择、Esc 关闭；显示结果数 |
| 输入时匹配模板 | 输入建议 | 只建议不覆盖；套用须点"从模板填入" |
| 多值标签 | 药丸标签（带 ×） | 新增用可搜索下拉 |
| 只读状态 | 方块徽章 | 不可点击；可点击的一律为药丸按钮，二者外观可区分 |
| 即时生效的设置 | 开关 | 无需保存按钮 |
| 表单选项、批量多选 | 勾选框 | 统一尺寸，文字可点，与框对齐 |
| 搜索与筛选 | 顶部搜索框 + 第二行筛选药丸 | 显示"共 N 条"与"清除" |
| 资料详情 | 悬浮卡（popover） | 不跳页；可钉住；Esc 关闭并还焦点 |
| 复杂或分步操作 | 二级悬浮窗 + 步骤条 | 一次一步；可返回上一步；保留已填内容 |
| 危险且不可撤销的操作 | 确认对话框 | 可撤销的操作改用提示条 + 撤销按钮 |
| 列表与详情 | 主从布局 | 宽屏并排；窄屏逐层进入 |

所有弹层（下拉、悬浮卡、菜单）不被裁切、不超出窗口、不遮住其触发器所需的确认按钮。

**弹层行为（硬性）**
- 任何时刻最多打开一个弹层；打开弹层时，面板其余部分不响应点击，点击外部只关闭弹层。
- 面板内任何元素不得显式设置 `pointer-events`（`auto`/`none`）；`:host` 保持 `pointer-events: inherit`，由浮层库管理 `body` 的点击屏蔽。`.trpg-root` 为零尺寸定位容器，不铺满视口。
- 每个弹层控件在上线前必须有 e2e：打开 → 点选项 → 界面稳定后值已变化 → 弹层关闭且 `body.style.pointerEvents` 恢复为空；覆盖"同类控件相继打开"、键盘操作（Enter 打开、方向键移动、Enter 选择、Esc 关闭后焦点回到触发器）、打开后等待 0/150/800ms 再点选项。
- 读取结果须在界面稳定后（≥250ms 或等待具体状态）再断言；打开列表后的断言不能只检查"列表出现"。

### 5.4 交互通则

- 数字输入：失焦或回车时校验；点击全选；Esc 还原；↑↓ 加减 1；禁用滚轮改值；中文输入法组合期间不提交、不重建输入框。
- 自动值与覆盖：自动计算值以虚线下划线显示；手动覆盖以实线下划线 + "覆"徽章显示，点徽章恢复自动；上游变化不改覆盖，旁注"计算值已变 17→19"。
- 切换标签、人物、抽屉时保留滚动位置、内部分页、展开项、筛选、排序、未提交输入与焦点；切换本身不保存、不结算、不写入酒馆输入框。
- 数值显示最多两位小数并去掉尾零，计算保留实际精度；规则要求整数的数值（数量、等级、钱币、资源次数）按整数处理；未知数据显示"未填写"，不当作 0。
- 按钮与图标有可读名称（例如药丸上的 × 读作"移除盖尔的『风暴岛』标签"）；标签文字与 × 的点击范围分开。
- 当前数据自动持久化；顶栏以 ● 标记"与存档不同"。
- 反馈：成功与信息提示条 4–6 秒自动消失；错误提示保留到关闭；可撤销操作的提示条带"撤销"。
- 空状态：一句说明 + 一个主操作；搜索无结果时提供"清除筛选"。
- 加载：内容区用占位骨架，不显示空白；超过 300ms 才显示。
- 键盘：所有操作可用键盘完成；焦点环可见；弹层打开时焦点进入，关闭后回到触发器。
- 界面文案使用玩家语言，不出现开发术语、不出现大段说明；需要说明时使用就近的简短提示。

### 5.5 动效

- 只用于说明状态变化：展开/收起、弹层出现、骰子结果揭示、数值变化高亮；时长 120–240ms。
- 只动画 `transform` 与 `opacity`；尊重 `prefers-reduced-motion`。

### 5.6 设计流程

新视图：读单元蓝图 → 灰度结构 → 视觉实现 → 三宽度截图自查 → 修正。视觉方向与评审使用 `oil-ui` Skill；控件状态与可访问性按 `~/.codex/skills/ux-ui-agent-skills/components/` 的规范。

## 6. 规则正确性

- 规则基准：D&D 5e 2014（PHB、DMG、MM 及已安装扩展）。每条规则实现的单元测试注明出处（书名 + 页码或 SRD 条目）。
- 规则未明确或需要 DM 判断的情形（掩护、可见性、目标合法性等）在界面上显示为"待裁定"，由玩家填写，不自行补规则。
- 掷骰结果完整透明：每颗骰、优劣势取舍、每项加值来源都可展开查看。
- 规则疑点写入 `docs/decisions.md`，由驾驶员裁定后实现。

## 7. 性能

- 内容包按"索引 + 分片详情"存储，详情按需加载；搜索索引在 Worker 中构建并缓存。
- 长列表虚拟滚动；状态摘要构建做 100ms 防抖；IndexedDB 写入合并批量提交。
- 初始包体（不含数据）目标 ≤500 KB gzip；打开悬浮窗到可交互 ≤300ms（中端手机）。

## 8. 验证与证据

| 级别 | 方法 | 负责 |
|---|---|---|
| 自动 | `npm run check`（类型 + lint + 单元测试）、`npm run e2e`（Chrome 与 WebKit 两种内核；宿主 TauriTavern 使用 WebKit） | Agent |
