# 开发规范

## 0. Agent 执行守则（2026-11-05 驾驶员定，优先于本文件其他章节）

**流程**
1. **草案先行**：写任何文件（代码、文档、数据、配置）之前，先在 chat 给驾驶员看 ASCII 示意图＋大白话草案；驾驶员明确同意才动手。**严禁跳过草案直接写文档。**
2. **汇报格式**：完成后用同一格式（ASCII 示意图＋大白话）汇报，必须详细、覆盖全面、不得省略：改了哪些文件与模块、改前改后、证据、未验证项、下一道门；有界面时附截图并写出每张截图的完整路径。
3. **界面只由驾驶员验收**：禁止用子 agent 或自评给任务、界面判"通过"；自己逐张看截图只算交付前自查。
4. **每个任务固定四段**：① 数据一键导入 → ② 后端数据规范（登记式）→ ③ 界面规划与编写（模块化）→ ④ 按驾驶员意见修订。

**数据红线**
5. 数据内容是否正确归上游（5etools 等的维护者）管。**禁止逐条对照原书、逐条抽检、逐条手工修复。**
6. 数据只走管线：源 → 原样入库 → 按官方 Schema 的写法转换 → 包。缺口只修"写法处理函数"，不按条目修。
7. 不认识的写法让构建失败并列清单；不静默丢弃，不在界面里补数据。
8. 新旧数据只用工具全量比对，按类别汇报，由驾驶员按类别决定。
9. 补丁层只收驾驶员点名的条目，每条写上游链接或原因；不主动新增。
10. 源里本来就没有的：界面显示"未知"或"其他"，不编造、不手写。
11. 做界面时撞上缺数据：记进数据待办，界面先显示"未知"，继续做；不当场改转换器、不查原书。

**开发方式**
12. 后端声明式＋登记式：数据格式、规则（成长项）、转换写法、界面组件都写成登记表，由统一引擎执行；不给单个职业、种族、条目写特例代码。
13. 前端模块 Unit 化：一种规则类型一个组件，经注册表自动拼装；界面不认识具体内容的名字。
14. **界面禁止手写数据**：所有界面都是模块化、数据驱动的；名称、规则文字、数值、选项、页码、表格一律从数据库读，读不到就显示"未知"或不显示。唯一授权例外：标准数组 15/14/13/12/10/8、购点总点数 27。
15. **做界面先做两件事并写进草案**：① 看数据形状——用程序读真实的包，列出本界面要用的字段及其实际形状与条数；② 搜可参考的界面——查同类项目（Foundry、5etools、Roll20 等），附参考链接或截图并说明借鉴哪一点。缺这两项的界面草案不算完整。
16. 不读旧档：各 `归档/` 目录、`docs/probes/` 的旧报告不读，除非驾驶员点名。

## 3. 架构规则

1. 依赖方向：`ui → stores → core / rules → schemas`；`host` 只被 `stores` 调用；`rules` 与 `core` 不依赖 Vue。
2. 业务状态唯一来源是 store；组件只读 store、只调 action。不在组件中保存业务副本。
3. 不对宿主 DOM 做补丁式修改，不用定时器修正界面；需要宿主能力时经 `host` 的公开函数。
4. 规则计算全部是纯函数，输入输出可序列化，配单元测试。
5. 资料、模板、模组只存在于内容包；代码只依赖 schema。规则算法及其自带的常量表（属性调整值、熟练加值、技能与属性对照、多职业施法表、状态的机械效果）属于规则引擎代码，不算资料。
6. 持久结构带 `schemaVersion`；任何结构变更同时提交迁移函数与迁移测试，旧数据自动升级。
7. 结算是原子操作：预览不改数据；确认时一次写入全部变化并生成日志条目；同一结算 id 重复确认不重复生效；撤销按日志反向数据恢复。
8. 错误必须可见：不写空 catch；错误进入界面提示（就近显示或提示条）并 `console.error`。
9. 单个源码文件不超过 400 行（生成的数据文件除外）；一个组件只承担一个职责。
10. 同一能力只实现一次；新增前先查已有实现。

## 4. 宿主集成

- 入口：`manifest.json` 的 `js` 指向构建产物；初始化幂等，重复调用不重复挂载；所有 `eventSource` 监听在卸载时移除。
- 宿主能力只经 `SillyTavern.getContext()` 取得；不导入宿主内部文件路径。
- TauriTavern：检测 `window.__TAURITAVERN__`，可用时使用其 `api.chat.searchMessages`、`store.*`、`api.layout`（安全区与输入法高度）；不可用时退回 SillyTavern 通用能力。
- 存储：大数据（内容包、当前数据、存档、底图）存 IndexedDB；`extensionSettings[模块名]` 只存小型设置。
- 当前数据键：角色卡用其头像文件名，群组用群组 ID；无聊天时面板显示"请先打开一个聊天"。
- 输入框写入：用原生 `value` 写入器赋值，再派发 `input` 事件；追加内容保留玩家原文。
- 注释输出：输入框中的 `<!-- … -->` 原样进入发给 AI 的请求，楼层渲染中不显示；注释随消息保存在聊天记录中，后续每次生成都会带上。
- 提示词注入：`getContext().setExtensionPrompt(key, text, 1, 0, false, 0)`（位置 IN_CHAT、深度 0、system 角色；`extension_prompt_types` 不在上下文中，使用数值）。注入文本是一条 system 消息，位于聊天记录末尾、预设尾部指令之前。清除：同 key 传空字符串。
- 事件：`GENERATION_STARTED(type, params, dryRun)` 先于 `MESSAGE_SENT` 触发，此时新消息尚未进入聊天记录；在生成前读取上下文（如提及扫描）须同时读取输入框文字。忽略 `dryRun` 为 true 与 `type` 为 `quiet` 的生成。请求内容可在 `chat_completion_prompt_ready` 与 `generate_after_data` 事件中读取。
- libs（`localforage`、`DOMPurify`、`Fuse`、`lodash` 等）位于 `window.SillyTavern.libs`，不在 `getContext()` 中。
- `extensionSettings` 的保存带防抖，快速刷新可能丢失最后一次写入；存档与内容包不得存放其中。
- 当前数据键：使用 `characters[characterId].avatar`（头像文件名）；`characterId` 是数组下标字符串，不稳定。
- TauriTavern：`await window.__TAURITAVERN__.ready` 后可用；`api.chat.current.handle()` 取得聊天 handle，提供 `searchMessages`、`locate.findLastMessage`、`history`、`metadata`、`store`（每个聊天一份 JSON KV）；`api.extension.store` 提供扩展全局的 JSON KV 与 Blob；`api.dev.llmApiLogs` 可读取已发出请求的原文。`api.chat.current` 本身是对象，不是 handle。
- 不使用 `crypto.subtle`、`crypto.randomUUID`（非安全上下文不可用，如经 http 局域网访问酒馆）：哈希用 `@noble/hashes`，ID 用 `crypto.getRandomValues`。
- 诊断报告与日志只记录结构（数量、字段名、长度），不得带出聊天内容、预设内容与聊天元数据。
- 插入页面的任何来自数据包、玩家输入或 AI 的文本，按纯文本渲染；必须渲染 HTML 时先经 `SillyTavern.libs.DOMPurify`。
- 界面挂载在 Shadow DOM 内；弹层渲染进同一 Shadow Root；样式不泄漏到宿主，也不受宿主影响。

| line | `#CBBCA3` | `#515849` | 边框、分隔 |

| ink-2 | `#6C6255` | `#BCBBAA` | 次要文字 |

| gold | `#B8954A` | `#E6BF73` | 细分隔、少量强调 |

- 字体：标题与大数字用衬线（`"Songti SC","Noto Serif SC",Georgia,serif`）；正文用系统无衬线（`"PingFang SC","Microsoft YaHei",system-ui`）。正文 ≥14px，辅助文字 ≥12px，数字 `tabular-nums`。
- 间距 4px 网格；圆角：卡片与窗口 10px、内部控件 6px、徽章 4px、药丸 999px；容器内边距与子元素间距相同。
- 阴影两级：卡片 `0 1px 2px rgb(43 33 28 / 8%), 0 2px 8px rgb(43 33 28 / 6%)`；浮层与悬浮窗 `0 8px 28px rgb(0 0 0 / 28%)`。
- 图标：Phosphor（MIT，Regular，尺寸为字号的 1–1.25 倍）；TRPG 专属图标用 game-icons.net（CC BY 3.0，关于页署名）。一个界面只用这两套。
- 状态不只靠颜色：同时使用文字、图标或形状。

### 5.2 布局与视口

- 检查宽度：390、900、1440（窗口内部宽度）。≤480 为窄屏；481–1023 为中宽；≥1024 为宽屏。列表在三种宽度下都是同一张单列列表，只调整列宽；对象详情用详情弹窗（§5.3），需要编辑的对象进入子页（顶部「‹ 上一级」）。
- 不出现整窗横向滚动；长列表在自身区域滚动；触控目标 ≥44×44px。
- 每屏一个主角、一个主操作；同一操作只有一个执行入口。例外：首页概览格是带实时数据的页面导航；页头"● 保存存档"是高频操作的快捷入口；快捷键。
- 元素从严：一行只放名称、一句状态和一个主操作；次要操作收进行尾的「⋯ 更多」菜单；能由分组标题、位置或状态表达的，不再加筛选药丸、说明文字或重复按钮。
- 悬浮窗（主悬浮窗、骰盘悬浮窗）不能被拖出屏幕；会改变内容高度的控件（下拉、展开列表）一律以浮层方式显示，不得撑开所在窗口或页面的布局；手机默认铺满可视区，避开安全区与输入法。

### 5.3 控件选型（硬性）

| 场景 | 控件 | 规则 |
|---|---|---|
| 2–5 个固定选项 | 分段按钮 | 全部可见，一点即切 |
| 6–15 个固定选项 | 下拉选择（按钮触发 + listbox） | 不用原生 `<select>`；列表最多 8 行，内部滚动；靠近边缘自动翻转；宽度不小于触发器 |
| 大量条目 | 可搜索下拉（combobox） | 边输边筛；每行显示中文名、英文名、类型或来源徽章；↑↓ 移动、Enter 选择、Esc 关闭；显示结果数 |
| 输入时匹配模板 | 输入建议 | 只建议不覆盖；套用须点"从模板填入" |
| 多值标签 | 药丸标签（带 ×） | 新增用可搜索下拉 |
| 只读状态 | 方块徽章 | 不可点击；可点击的一律为药丸按钮，二者外观可区分 |
| 即时生效的设置 | 开关 | 无需保存按钮；**开 = 圆钮在右、轨道填充主色（`━●`）；关 = 圆钮在左、轨道空心（`○━`）**；旁边不另写"开/关" |
| 表单选项、批量多选 | 勾选框 | 统一尺寸，文字可点，与框对齐 |
| 搜索与筛选 | 顶部搜索框；必要时加一个分段按钮或下拉 | 显示"共 N 条"与"清除"；列表 ≤8 项时不出现搜索框 |
| 术语、对象名称的详情 | 下划线术语 + 详情弹窗（模态） | 见下方「术语与详情」 |
| 一个对象的次要操作 | 行尾「⋯ 更多」→ 下拉菜单 | 菜单项为动词短语；危险项放最后、红色；菜单不放查看类入口 |
| 复杂或分步操作 | 模态弹窗 + 步骤条 | 一次一步；可返回上一步；保留已填内容 |
| 危险且不可撤销的操作 | 确认（模态） | 可撤销的操作改用提示条 + 撤销按钮 |
| 列表 | 单列列表 + 行分隔线 | 详情走详情弹窗；编辑走子页 |

**术语与详情（硬性）**
- 凡是能查看详情的名称（包名、书名、规则名、冒险名、条目名、规则选项名、随机表名等）都显示为下划线术语：正文色 + 虚点下划线；悬停时下划线变为金色实线；可用 Tab 聚焦，Enter 打开。术语只负责查看，与同一行的开关、勾选框、按钮点击范围分开。
- 点击术语打开**详情弹窗**（模态）：背后变暗；宽屏宽 640px、高不超过窗口的 80%，内部滚动；窄屏铺满为整页。点 ✕、遮罩或 Esc 关闭，焦点回到原术语。
- 点击包名（数据库）打开的详情弹窗，主体就是该包的内容列表：顶部一行概况，下面是类别下拉 + 搜索 + 虚拟滚动的条目列表。
- 弹窗内的一切都在**同一个弹窗里前进**：点条目名、关联术语、「对比」等，弹窗内容切换为新的一页，标题左侧出现「‹ 上一页名称」返回；返回时恢复上一页的滚动位置、类别与搜索词。任何地方查看详情或关联内容都不使用行内展开或下拉。
- 详情弹窗以查看为主：包详情弹窗的标题栏复用列表行的状态按钮与「⋯ 更多」菜单（同一组件，状态同步），主体只看不改；条目自身的版本条（L1 §4.12）照常可用。

**模态弹窗（硬性）**
- 只用于四种情况：确认与取消、需要玩家回应的提示、复杂信息面板（详情、包内容、存档抽屉）、复杂流程与操作面板（向导、导入、导出、更新对比）。
- 同一时间只有一个模态弹窗，**不得在其上叠加任何模态弹窗或悬浮窗**。在弹窗内需要确认或填一页小表单（如「存到我的库」）时，作为弹窗内的一页显示（「‹ 返回」= 取消）；在弹窗内触发多步流程（向导、导入、导出）时，当前弹窗先关闭（有未保存内容先在本弹窗内确认），再打开新的。
- 弹窗内可以使用弹层（下拉、菜单、选择卡）。
- 实现为一个全局弹窗宿主：内部维护页面栈（前进 = 入栈，「‹」与 Esc = 出栈，栈底按 Esc 关闭弹窗），所有弹窗内容都以「页」的形式交给它。
- 模态弹窗的遮罩只盖住主悬浮窗；骰盘悬浮窗是独立窗口，不被遮住，也不由弹窗打开。

**浮层种类与层级**

| 种类 | 例子 | 挡住后面 | 点外部 | 同时最多 |
|---|---|---|---|---|
| 悬浮窗 | 主悬浮窗、骰盘悬浮窗 | 否 | 不关闭 | 各 1 个 |
| 模态弹窗 | 详情、包内容、存档抽屉、向导、导入导出、确认 | 是（只盖主悬浮窗） | 关闭（有未保存内容时先在弹窗内确认） | 1 个，不叠加 |
| 弹层 | 下拉、「⋯ 更多」菜单、选择卡 | 否 | 关闭 | 1 个 |

层级从低到高：主悬浮窗 → 模态弹窗 → 骰盘悬浮窗 → 弹层 → 提示条。

所有弹层（下拉、菜单、选择卡）不被裁切、不超出窗口、不遮住其触发器所需的确认按钮。

**弹层行为（硬性）**
- 任何时刻最多打开一个弹层；打开弹层时，面板其余部分不响应点击，点击外部只关闭弹层。悬浮窗与模态弹窗不算弹层。
- 面板内任何元素不得显式设置 `pointer-events`（`auto`/`none`）；`:host` 保持 `pointer-events: inherit`，由浮层库管理 `body` 的点击屏蔽。`.trpg-root` 为零尺寸定位容器，不铺满视口。
- 每个弹层控件在上线前必须有 e2e：打开 → 点选项 → 界面稳定后值已变化 → 弹层关闭且 `body.style.pointerEvents` 恢复为空；覆盖"同类控件相继打开"、键盘操作（Enter 打开、方向键移动、Enter 选择、Esc 关闭后焦点回到触发器）、打开后等待 0/150/800ms 再点选项。
- 读取结果须在界面稳定后（≥250ms 或等待具体状态）再断言；打开列表后的断言不能只检查"列表出现"。
- 详情弹窗、「⋯ 更多」菜单与骰盘悬浮窗同样要有 e2e（Chrome 与 WebKit）：点术语 → 弹窗出现；弹窗内点条目与关联术语 → 同一弹窗换页、「‹」返回且滚动位置与搜索词恢复；弹窗内触发确认 → 仍只有一个弹窗；Esc 逐页返回、栈底关闭后焦点回到术语；任何操作后页面上最多一个模态弹窗。「⋯ 更多」按开发规范的弹层用例真实点选菜单项。骰盘悬浮窗：点外部不关闭、后面仍可点击、模态弹窗打开时仍可掷骰。开关的 e2e 断言圆钮位置与 `aria-checked` 一致。

### 5.4 交互通则

- 数字输入：失焦或回车时校验；点击全选；Esc 还原；↑↓ 加减 1；禁用滚轮改值；中文输入法组合期间不提交、不重建输入框。
- 自动值与手填值（2026-11-02 驾驶员定，见 `docs/规划/人物模块框架.md` §1）：能算的自动算；想要别的数就直接在输入框里改，**不加任何标记**（不显示「覆」「已改」「来源」等字样）；把输入框清空就回到自动值，清空时框内用灰字显示自动值；上游变化不改玩家填的值，也不提示；改错了用撤销。下划线只留给术语。
- 切换标签、人物、抽屉时保留滚动位置、内部分页、展开项、筛选、排序、未提交输入与焦点；切换本身不保存、不结算、不写入酒馆输入框。
- 数值显示最多两位小数并去掉尾零，计算保留实际精度；规则要求整数的数值（数量、等级、钱币、资源次数）按整数处理；未知数据**留空**，不当作 0，也不写「未填写」「无」之类的字样；需要提示时只用输入框的灰色占位文字。
- 按钮与图标有可读名称（例如药丸上的 × 读作"移除盖尔的『风暴岛』标签"）；标签文字与 × 的点击范围分开。
- 当前数据自动持久化；页头存档芯片以 ● 标记"与存档不同"。
- 反馈：所有提示条与横条都自动消失，不需要手动关闭；鼠标悬停或焦点在提示条内时暂停计时。

  | 类型 | 停留 | 之后信息留在哪里 |
  |---|---|---|
  | 成功、信息 | 4 秒 | — |
  | 可撤销的操作 | 6 秒，带「撤销」 | — |
  | 失败 | 8 秒 | 出错的那一行显示 ⚠、一句原因与「重试」；侧栏对应页面图标显示 ⚠ |
  | 状态提醒（只读窗口、下载开始等） | 6 秒，只提示一次 | 只读看页头 `只读` 徽章；下载看行内进度与侧栏「库」图标上的进度环 |

  同时最多 3 条，新的在下，最旧的先消失。没有常驻横条。
- 空状态：一句说明 + 一个主操作；搜索无结果时提供"清除筛选"。
- 加载：内容区用占位骨架，不显示空白；超过 300ms 才显示。
- 键盘：所有操作可用键盘完成；焦点环可见；弹层打开时焦点进入，关闭后回到触发器。
- 界面文案使用玩家语言，不出现开发术语、不出现大段说明；需要说明时使用就近的简短提示。

### 5.5 动效

- 只用于说明状态变化：展开/收起、弹层出现、骰子结果揭示、数值变化高亮、开关圆钮滑动；时长 120–240ms。
- 只动画 `transform` 与 `opacity`；尊重 `prefers-reduced-motion`。
