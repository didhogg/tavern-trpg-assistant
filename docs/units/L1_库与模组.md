# L1 库与模组 · 单元蓝图

状态：草案（待驾驶员审批）

## 0. 范围与归属

本单元负责：
- 内容包格式（含冒险内容与图片）
- 图片仓库
- 引用与固定
- 存档体检
- 【库】（规则、数据包、模组包）的安装、下载、更新、卸载、重新安装、恢复内置，以及首次使用规则时的推荐包安装
- 存档的「数据与模组」
- 把模组导入存档、更新、移除
- 导出为模组包

以上各项的全部界面也由本单元负责。

## 1. 核心保证（硬性）

1. **存档自足**：存档只靠自身数据与图片仓库就能完整打开、游玩、导出。库里的包无论安装、卸载、重新安装、升级、降级，都不写入任何当前数据或存档。
2. **存档优先**：存档里已有的内容（副本、冒险内容、存档内模板、固定引用）优先于库里的包。包的内容只在玩家于存档中执行「导入 / 更新 / 重新固定 / 体检修复」并确认后才进入存档。
3. **不静默删除**：存档内容只有在玩家确认后才会被移除，移除的内容进回收站。
4. **原子**：每个操作要么全部完成，要么数据完全不变。
5. **先备份后改**：导入模组、更新模组、移除模组、体检修复前，先写一个自动存档，原因为「改动模组前」（并入 U2 §3.6 的滚动保留）。
6. **可降级**：引用找不到、图片缺失、内容结构不合法时，界面显示占位和原因，存档照常打开。数据保持原样，不自动修复，也不自动删除。
7. **保存不丢数据**：无法识别或校验失败的内容在保存时原样写回。
8. 规则作用域沿用 U2 §1。

## 2. 数据

### 2.1 概念

| 名称 | 存放 | 内容 | 存档如何使用 |
|---|---|---|---|
| 规则 | 代码注册 | 游戏系统 | 每个存档属于一个规则 |
| 数据包 | 库（全局） | 条目：法术、怪物、物品、职业等 | 启用后可查、可引用；被引用或生成副本时固定一份到存档（§3.2） |
| 模组包 | 库（全局） | 冒险内容（地点、底图、点位、人物、任务、遭遇、文档）与模组条目 | 导入时整套复制进存档（§3.8） |
| 冒险内容 | 存档 | 从模组包复制来的或在存档中新建的地点、人物、任务、遭遇、文档 | 随意编辑 |
| 存档内模板 | 存档 `localEntries` | 模组自带条目、玩家"存为模板"的条目 | 与数据包条目同样可引用、可生成副本 |
| 固定引用 | 存档 `pins` | 存档用到的数据包条目原版的冻结副本 | 作为原版使用 |
| 修改版 | 存档 `variants` | 模组、带修改的数据包或本存档房规为某个官方条目提供的替代版本 | 每个条目同时只使用一个版本（原版或一个修改版），只在本存档生效 |
| 图片 | 图片仓库 `blobs` | 按内容哈希存放的图片 | 包与存档只保存哈希 |

库这一侧，数据包和模组包是同一种格式，安装、覆盖、同名、下载、更新、卸载、导出流程完全相同，界面文字中的 `{类型名}` 按 `kind` 替换。差别只在存档这一侧：数据包是"启用"，模组包是"导入"。

### 2.2 内容包文件 `.trpgpack`（formatVersion 2）

```
trpg-manifest.json         { "format": "trpg-pack", "formatVersion": 2, "pack": PackManifest }
entries/<type>.json        条目数组（可引用的模板）
adventure/adventure.json   仅模组：开局与概要
adventure/<kind>.json      仅模组：冒险内容项数组，按类型分文件
blobs/<sha256>             图片原始字节，文件名即内容哈希
```

**PackManifest 新增字段**（其余同 U2 §2.1）

| 字段 | 说明 |
|---|---|
| `lineage` | 包的来源编号（uuid），首次导出时生成，之后各版本不变 |
| `author` | 作者名 |
| `blobs` | `[{ hash, mime, size }]` |
| `adventure` | 仅模组：`{ counts: { location, person, quest, encounter, handout }, recommended: { levelMin, levelMax, partySize, sessions } }` |
| `dataVersion` | 条目与冒险内容按规则数据定义的版本 |

**`adventure/adventure.json`**：`{ start: { locationId?, intro? }, cover?: { $asset }, description }`

**修改版条目**：`entries/` 中带 `override` 字段的条目，数据包和模组包都可以有。

| 字段 | 说明 |
|---|---|
| `override.target` | `{ packId, entryId }`，被修改的官方条目；`packId` 必须在 `dependsOn` 中 |
| `override.mode` | `replace`（整条替换）/ `patch`（局部修改，按 JSON Merge Patch 合并到原条目）/ `hide`（在本存档的搜索与新建列表中隐藏） |
| `override.note` | 一句话说明，如"本模组中石像鬼不惧魔法武器" |
| `override.baseVersion` | 制作时原条目的版本（仅 `patch`） |

修改版条目自身的 `id` 在包内唯一、各版本不变，不会进入资料搜索，只通过 §3.15 生效。同一个包对同一个官方条目最多一个修改版。

**识别与限制**（在 U2 §2.3 的识别顺序之后继续检查）

| 检查 | 失败提示 |
|---|---|
| 解压总量 ≤ 256MB，文件数 ≤ 20,000 | 文件过大或文件数过多，无法导入 |
| 路径只含 `a-z 0-9 / . _ -`，不含 `..` 和开头的 `/` | 文件内容损坏：包含不合法的路径 |
| 每张图片 ≤ 10MB；按文件头判定为 png / jpeg / webp / gif，且哈希与文件名一致 | 文件内容损坏：图片「…」不合法 |
| `blobs` 清单与 `blobs/` 目录一一对应 | 文件内容损坏：缺少图片「…」 |
| 包内 `$ref` 都能在包内或 `dependsOn` 的包中解析 | 文件内容损坏：「…」引用了不存在的内容 |
| `dataVersion` ≤ 当前规则支持的版本 | 这个内容包由更新版本的扩展制作，请先更新扩展 |
| 修改版条目的 `target.packId` 在 `dependsOn` 中，且同一 target 只出现一次 | 文件内容损坏：「…」修改的条目所在的包未声明为依赖，或被修改了两次 |

formatVersion 1 的文件照常识别：`assets/` 下的文件按内容哈希转入图片仓库，路径引用改写为 `$asset`。

### 2.3 冒险内容项

`AdventureItem`：`{ kind, id, name, data, origin? }`

各单元在登记表中登记自己的类型：

| kind | 所属单元 |
|---|---|
| `location`（含底图、点位、区块） | U8 |
| `person` | U6 |
| `quest`、`encounter`、`handout` | U9 |

登记项 `AdventureKindSpec`：

| 成员 | 说明 |
|---|---|
| `kind` / `label` | 类型标识与中文名 |
| `schema` | zod 定义 |
| `storeKey` | 存放在当前数据中的键 |
| `definitionOf(item)` | 去掉游玩状态后的定义部分（用于哈希与导出） |
| `resetPlayState(item)` | 恢复到初始游玩状态（导出时用） |
| `isInPlay(item, data)` | 是否被游玩状态引用：队伍成员、当前地点、进行中的遭遇或任务 |
| `trash(ids)` / `restore(ids)` | 移入、移出该类内容的回收站 |

`origin`：`{ importId, itemId, baseHash }`
- `baseHash` = 导入或上次更新时 `definitionOf` 的哈希。

### 2.4 引用

存档和包里所有指向其他内容的字段都只能用下面三种写法，体检和导出靠通用扫描找到它们：

| 写法 | 指向 |
|---|---|
| `{ "$ref": "pack", "packId", "entryId", "name" }` | 数据包条目；`name` 为显示用的后备名 |
| `{ "$ref": "local", "id", "name" }` | 存档内模板或冒险内容项 |
| `{ "$asset": "<sha256>" }` | 图片 |

包文件内部用 `{ "$ref": "item", "id", "name" }` 指向本包的条目或冒险内容项，导入时改写为 `local`。U2 的 `Instance.sourceRef` 视为一个 `pack` 引用。

### 2.5 当前数据中由本单元拥有的键

| 键 | 内容 |
|---|---|
| `pins` | `{ "<packId>/<entryId>": { version, entry, pinnedAt } }` |
| `localEntries` | `[Entry & { origin? }]` |
| `adventures` | `[AdventureImport]`，见下 |
| `authored` | `[{ packId, lineage, name, lastVersion, idMap: { localId: itemId } }]` |
| `variants` | `{ "<packId>/<entryId>": VariantSlot }`，只为有修改版的条目建立 |

`VariantSlot`：`{ candidates: Variant[], active, manual, history }`
- `active`：当前使用的版本，`'original'` 或某个修改版的 `key`。
- `manual`：玩家是否亲自选过这个条目的版本。
- `history`：之前使用过的版本 `key`，最近的在最后，最多保留 10 个。

`Variant`：`{ key, source, sourceName, mode, payload, note, baseVersion? }`
- `key`：`module:<lineage>/<条目 id>` / `datapack:<packId>/<条目 id>` / `house`。
- `source`：`{ type: 'module', lineage, importIds }` / `{ type: 'datapack', packId }` / `{ type: 'house' }`。
- `payload`：`replace` 时为完整条目，`patch` 时为合并补丁，`hide` 时为空。
- 来自模组和数据包的修改版只读；每个条目最多一个 `house` 版本。

设置（U2 `Settings`）新增 `variantDefault: 'apply' | 'skip'`，默认 `apply`；设置页显示为「导入模组或启用数据包时，对官方条目的修改：默认应用 / 默认不应用」。

`AdventureImport`：

| 字段 | 说明 |
|---|---|
| `importId` | 本次导入的编号 |
| `packId` / `lineage` / `packName` | 来源包 |
| `version` / `sha256` | 导入或上次更新时的包版本与校验值 |
| `copyIndex` | 同一个包在本存档中的第几份（从 1 起） |
| `importedAt` / `updatedAt` | — |
| `idMap` | `{ itemId: localId }`，包内 id 与存档内 id 的对应 |
| `removedItemIds` | 玩家在存档中删除过的包内 id |

存档快照包含以上全部键。

### 2.6 存储

IndexedDB 升级到第 2 版：
- 新增表 `blobs`：主键 `hash`，字段 `bytes, mime, size, createdAt`。
- `packs` 新增 `blobHashes`。
- 原 `assets` 表的数据按哈希迁入 `blobs`，然后删除 `assets`。
- 迁移在一个事务内完成，失败时保持第 1 版数据不变，并显示错误提示。

`meta` 新增：

| 键 | 内容 |
|---|---|
| `builtinRemoved` | 玩家卸载过的内置包 id |
| `autoInstall` | `{ [ruleId]: { done, at } }` |
| `userRemoved` | 玩家卸载过的推荐包 id |

### 2.7 数据仓库目录

`catalog.json` 的每个包增加：
- `recommended`：是否在首次使用规则时自动安装
- `group`：分组名，如"官方扩展 · 一档"
- `lineage`

### 2.8 存档文件

`.trpgsave` 增加 `blobs/<sha256>`：存档与当前数据引用到的全部图片。导入时校验哈希；缺少的图片按 §3.12 显示为缺失，不阻止导入。

## 3. 行为规则

### 3.1 引用解析

`resolveRef(ref, data) → { status, value, from }`

| 引用 | 查找顺序 | 找不到 |
|---|---|---|
| `pack` | 原版 = `pins` → 已安装包的条目（版本不限）；再按 §3.15 取当前使用的版本 | `status: 'missing'`，显示 `name`（缺失）；当前使用 `replace` 修改版时仍可解析 |
| `local` | `localEntries` → 各类冒险内容 | 同上 |
| `$asset` | `blobs` | 显示图片占位"图片缺失" |

- 所有界面都经 `resolveRef` 读取引用，不直接访问包或表。
- `from`：`pin` / `library` / `local`，供界面标注"已固定"或"来自库"。
- `variant`：当前使用的修改版及其他可选版本的数量（使用原版且没有候选时为空），供版本条（§4.12）与 `改` 徽章使用。
- 资料页、搜索、新建、AI 摘要、官方锁（R1）读取的都是当前使用的版本。资料搜索 = 库索引 ∪ 存档内模板，排除当前使用隐藏版本的条目，显示内容经 `resolveRef` 得到（U11 实现）。

### 3.2 固定

- `refs.link(target)`：写入 `pack` 引用的唯一入口。若尚未固定，就从已安装的包复制该条目到 `pins`。U2 §3.18 的 `materialize` 同样会固定。
- 已固定的条目在包升级、降级、卸载后保持不变。
- 想把固定内容换成库里的新版本：
  - 由人物与资料单元提供差异界面，本单元提供 `outdatedPins(data)` 和 `repin(data, key)`。
  - `repin` 前先写自动存档。
- 手动保存时，扫描整个当前数据，删除不再被任何引用指向的固定条目。

### 3.3 内置包与推荐包

**内置包**

| 包 | 能否卸载 | 说明 |
|---|---|---|
| SRD 基础规则 | 不能 | 规则必选 |
| 示例模组 | 能 | 卸载后 id 记入 `builtinRemoved` |

- 启动时安装内置包：跳过 `builtinRemoved` 中的 id；其余按 U2 规则只升级、不降级。
- 「恢复内置」：从 `builtinRemoved` 移除该 id，再从扩展目录中的文件安装，不需要联网。

**推荐包**

- 新存档向导中选中某规则时，若 `autoInstall[ruleId].done` 为否，就把目录中该规则 `recommended` 的包加入下载队列，跳过 `userRemoved` 中的 id。
- 全部成功后标记完成；有失败时保留未完成状态，下次进入向导继续，同时在【库】中显示"重试"。
- 玩家卸载推荐包：id 记入 `userRemoved`，以后不再自动安装；在【库】的"可安装"中照常显示，带"推荐"标记。

### 3.4 库操作队列

- 以下操作在同一个队列里依次执行：安装、下载完成后的安装、卸载、恢复内置、图片清理、导入模组到存档、更新模组、移除模组、导出模组。
- 排队中的操作显示"等待中"。
- U2 §3.16 的只读窗口不能发起任何队列操作。

### 3.5 安装与覆盖

沿用 U2 §3.9 的识别、覆盖、同名处理，另加三条：

| 情况 | 处理 |
|---|---|
| 同 id、`lineage` 不同 | 拒绝，提示"已安装的「X」与这个文件编号相同但来源不同。先卸载已安装的，或请作者更换编号。" |
| 同 id、同版本、`sha256` 不同 | 覆盖对话框标注"内容与已安装的不同"，主按钮"重新安装" |
| 依赖的包未安装 | 预览中列出缺少的包，每个带「安装」（目录中有时）；未全部安装前，主按钮不可用 |

- 安装、覆盖、重新安装都不写入当前数据和存档。`enabledPacks` 里的 `version` 只记录启用时的版本，界面显示以库为准。
- 图片：包里的图片按哈希写入 `blobs`（已存在则跳过），`packs.blobHashes` 记录该包用到的哈希。

### 3.6 卸载与重新安装

- 卸载：在一个事务内删除包记录、条目和搜索索引；图片按 §3.12 清理。不写入任何当前数据或存档。
- 确认文字按使用情况拼接，三类各只在数量 > 0 时出现：
  - 「N 个存档启用了它」
  - 「N 个存档导入过它的冒险内容」
  - 「N 个存档固定了它的条目」

  后面统一接一句：「存档里已经用到的内容都有副本，不受影响；没用过的条目在重新安装前查不到。」
- 重新安装（从数据仓库、导入文件或恢复内置）等同于一次新的安装，存档不受影响。存档里的状态只在显示时重新计算（§3.7）。

### 3.7 存档的模组状态（只用于显示）

每个 `AdventureImport` 对照库里同 `packId` 的包：

| 库中情况 | 显示 | 可做 |
|---|---|---|
| 同 lineage、同版本、同校验值 | 已是最新 | — |
| 同 lineage、版本更高 | 有新版 vX | 更新 |
| 同 lineage、同版本、校验值不同 | 库里的包内容有变化 | 更新 |
| 同 lineage、版本更低 | 库里是旧版 vX | —（不提供降级） |
| lineage 不同 | 库里的同名包来源不同 | — |
| 未安装 | 库里没有这个模组包，游玩不受影响 | 去库里安装 |

已启用的数据包在库里未安装时，显示"未安装：已用到的条目照常可用"，并提供「去库里安装」。

### 3.8 导入模组到存档

**前提**：包已安装、规则一致、依赖的包都已安装、不是只读窗口。

**过程**：先计算出完整结果，预览，确认后一次写入。

1. 读取包内冒险内容与模组条目，按规则迁移到当前 `dataVersion`。
2. 为每一项生成存档内 id，并记录 `idMap`；把 `$ref: item` 改写为 `$ref: local`。
3. 包内的 `$ref: pack` 逐个固定（§3.2）。
4. 每一项写入 `origin`，`baseHash = hash(definitionOf(item))`。
5. 模组条目写入 `localEntries`，修改版按预览中的选择与 §3.15 加入 `variants`，冒险内容按 `storeKey` 写入各单元的键；写入 `AdventureImport`。
6. 开局设置（预览中勾选）：
   - 当前地点设为 `start.locationId`：只在存档没有当前地点时默认勾选。
   - 显示开场说明：默认勾选。
7. 写自动存档「改动模组前」→ 一次写入当前数据 → 提示条「已加入《X》」，带"撤销"（8 秒，恢复为导入前的当前数据）。

**同一个包（同 lineage）已经导入过、且未移除时**，预览改为三选一：
- 更新到库里的版本：仅当版本或校验值不同，转到 §3.9。
- 再加一份：新的 `importId`，`copyIndex` 加 1，界面显示为「X（第 2 份）」。
- 取消。

**名称与存档内已有内容重复时**：预览中列出重复的名称，并说明"名字相同会让对话提及时同时命中"。不自动改名。

### 3.9 更新模组

以三方比较逐项决定：
- `base` = 该项 `origin.baseHash`
- `mine` = 存档中该项的定义哈希
- `theirs` = 新版包中该项的定义哈希

| 情况 | 默认 | 玩家可改 |
|---|---|---|
| mine = base，theirs ≠ base | 采用新版的定义，保留本项的游玩状态 | — |
| mine ≠ base，theirs = base | 保留我的 | — |
| mine ≠ base，theirs ≠ base | 保留我的 | 逐项改为"用新版"（我的版本进回收站） |
| 新版新增 | 加入 | 可取消勾选 |
| 新版删除，mine = base，且不在游玩中 | 移入回收站 | 可改为保留（解除与模组的关联） |
| 新版删除，mine ≠ base 或正在游玩中 | 保留，解除与模组的关联 | 不在游玩中时可改为移入回收站 |
| 在 `removedItemIds` 中（我删过的） | 不恢复 | 可勾选恢复 |

- 模组条目（`localEntries`）按同一张表处理。修改版只读，不做三方比较，按 §3.15「模组更新」处理。
- 完成后：
  - 所有参与比较的项，`baseHash` 改为新版哈希。
  - 新增项建立 `origin` 与 `idMap`。
  - `AdventureImport.version`、`sha256`、`updatedAt` 更新。
- 新版带来的 `$ref: pack` 引用逐个固定；已有的固定条目不变。
- 只能升级，或在同版本内容变化时更新，不提供降级。
- 前后流程同 §3.8 第 7 步。

`removedItemIds` 的维护：玩家删除一个带 `origin` 的项时，由所属单元调用 `adventures.noteRemoved(origin)` 记入；从回收站恢复时调用 `adventures.noteRestored(origin)` 移出。

### 3.10 从存档移除模组

逐项决定：

| 项 | 默认 | 玩家可改 |
|---|---|---|
| mine = base，不在游玩中，且不被保留下来的内容引用 | 移入回收站 | 可改为保留 |
| mine ≠ base，或在游玩中，或被保留下来的内容引用 | 保留，解除与模组的关联 | 不在游玩中时可改为移入回收站 |

- 解除关联 = 删除 `origin`，该项变为「本存档原创」。
- 修改版按 §3.15「撤下」处理。
- 之后删除 `AdventureImport`。再次导入同一个包视为全新导入。
- 前后流程同 §3.8 第 7 步。

### 3.11 导出为模组包

**内容范围**
- 「全部冒险内容」或「自选」。
- 自动补齐：沿着 `$ref: local` 把被引用的项和存档内模板一并带上，并在界面列出。

**引用与数据包**
- `$ref: pack` 保持为引用，`dependsOn` 自动生成：`minVersion` 取固定时的版本。
- 某个人物的定义与它的来源条目相同时，只写来源引用；不同时写完整数据。

**游玩痕迹**（默认全部清除）
- 对每一项执行 `resetPlayState`。
- 选项：
  - 玩家角色：默认不导出，可勾选「作为预设角色导出」。
  - DM 秘密：默认保留，可选去掉。
- 日志、掷骰记录、队伍、金币变化从不导出。

**来源**：来自其他模组的项（`origin` 指向非本人导出的包）写入 `derivedFrom: { packId, lineage, name }`。导出窗口提示「包含来自《X》的 N 项，请确认原作者允许再分发」。

**身份**

| 选项 | id | lineage | 版本 | 项 id |
|---|---|---|---|---|
| 新模组 | `m-` + 10 位随机字符 | 新的 uuid | 1.0.0 | 新生成 |
| 更新我导出过的《X》（仅当 `authored` 中有记录） | 沿用 | 沿用 | 默认次版本号加 1；必须高于 `lastVersion` 和库中同 id 的版本 | 已导出过的沿用 `authored.idMap`，新增项生成新 id |

**校验**
- 生成文件后先用安装器的识别流程完整检查一遍：格式、引用、图片、限制。
- 不通过就不提供文件，并显示第一处原因。

**完成**
- 保存 `.trpgpack`，文件名为 `<名称>_v<版本>.trpgpack`。
- 写入或更新 `authored`；这会产生"未保存"状态。
- 可勾选「同时安装到我的库」，默认不勾。

### 3.12 图片

**上传**：`assets.put(bytes)`
1. 按文件头判定类型，只接受 png / jpeg / webp / gif。
2. 超过 10MB 时提示：「压缩为 webp（长边 2560px）」或「取消」。
3. 计算哈希，`blobs` 中没有时才写入；返回 `{ $asset }`。

**清理**（标记后删除）
- 在一个读写事务内扫描 `packs`、`workspaces`、`saves`（包括自动存档和最近删除）中的全部 `$asset` 与 `blobHashes`。
- 删除没有被引用、且创建超过 24 小时的图片。
- 触发时机：卸载包后、彻底删除存档后、清空最近删除后。

**空间**：导入模组、下载包、上传图片前，用 `navigator.storage.estimate()` 检查剩余空间。所需空间超过剩余的 90% 时拒绝，提示「存储空间不足：可以删除不用的内容包，或清空最近删除」。

### 3.13 存档体检

`checkIntegrity(data) → Issue[]`：读取存档后在后台运行一次；也可以在「数据与模组」中手动运行。

| 问题 | 修复（逐项由玩家点击；每次修复前写自动存档） |
|---|---|
| `pack` 引用既未固定、所在包也未安装 | 去库里安装；或"改为纯文字"（保留名字，去掉引用） |
| `pack` 引用未固定、但包已安装 | 固定 |
| `local` 引用找不到 | 改为纯文字 |
| 图片缺失 | 重新选择图片；或移除图片 |
| 项不符合数据定义 | 移入回收站，原始数据一并保留，可导出为 JSON |
| id 重复 | 为重复项生成新 id |
| `origin.importId` 不存在 | 解除与模组的关联 |

- 读取时，不符合定义的项不参与游戏，原样留在当前数据中，保存时原样写回。
- 列表中显示"无法读取的内容 N 项"。

### 3.14 版本与迁移

- 包文件 formatVersion 1 → 2 按 §2.2 转换。
- 包的 `dataVersion` 低于当前规则时，导入存档前按规则的迁移链升级；高于时拒绝。
- 存档中的 `pins`、`localEntries`、`variants` 随存档迁移一起升级（U2 §2.5）。

### 3.15 修改版

**规则**
1. 每个官方条目在一个存档中同时只使用一个版本：原版，或一个修改版。多个修改版不叠加。
2. 修改版只在存档中生效；库和其他存档始终是原版。
3. 正在使用的版本，不会被新加入的修改版自动替换。
4. 来自模组和数据包的修改版只读；要在它的基础上再改，就另存为本存档的房规版本。

| mode | 效果 |
|---|---|
| `replace` | 整条换成修改版的内容 |
| `patch` | 在原版基础上改动部分字段（JSON Merge Patch） |
| `hide` | 内容仍是原版；在本存档的搜索和新建列表中隐藏，已有的引用照常显示 |

**加入候选**：导入模组、启用带修改的数据包、模组更新带来新的修改版时，对每个修改版：

| 该条目当前的情况 | 默认 |
|---|---|
| 正在使用原版，且玩家没有亲自选过版本 | 按 `variantDefault`：应用（默认）或不应用 |
| 正在使用其他修改版，或玩家亲自选过版本 | 保持现状；在预览中标为"冲突" |

- 预览（§4.7、§4.13）中，玩家可以整体「全部应用 / 全部不用」、按类型勾选、逐条勾选；冲突条目逐条选「改用新的 / 保持现状」。
- 不勾选或「保持现状」的修改版照样加入候选，只是不使用；之后随时可以在版本条中改用。冲突行中「正在用」显示当前版本，玩家亲自选过的会标「你选的」。
- 同一 lineage 的模组导入多份时，修改版只算一份（`importIds` 记录各份）。
- 产生候选前先固定原版（§3.2），以保证随时能回到原版。

**切换**
- 在版本条（§4.12）或修改版管理（§4.6.1）中切换，即时生效，产生"未保存"状态，提示条带"撤销"。
- 切换时 `manual = true`，原来的 `active` 推入 `history`。

**撤下**：移除模组、停用数据包、模组新版不再包含某修改版、删除房规版本时：
1. 从候选中删除。同一 lineage 还有其他导入份时不删除，只从 `importIds` 中去掉这一份。
2. 若它正在使用：回到 `history` 中最近一个仍存在的版本；没有就回到原版。
3. 确认窗口中列出会改回的条目，例如「石像鬼：改回《迷雾渡口》的版本」。

**模组更新**：同一 `key` 的修改版内容直接换成新版，使用状态不变；新增的按「加入候选」处理；不再包含的按「撤下」处理。

**房规版本**
- 版本条中的「在当前版本基础上修改…」：以当前使用的内容为起点打开条目编辑器（U11 提供），保存后成为该条目唯一的 `house` 版本，并立即使用。
- 已有房规版本时，入口变为「编辑房规版本」。删除房规版本按「撤下」处理。
- 模组更新不会改动房规版本。

**原版的来源**
- 原版所在包卸载且未固定：`patch` 和 `hide` 版本无法显示内容（体检列出），`replace` 版本照常使用。
- 原版在库里升级：仍以已固定的原版为准。重新固定后，若某个 `patch` 的 `baseVersion` 与新原版不同，体检提示「『X』的修改基于旧版原版，请确认」。
- 套用后的结果不符合数据定义：本次解析使用原版，体检列出「『X』的修改版无法使用」。

**与副本的关系**
- 已生成的副本不变。
- 版本条与导入预览中显示「已在游戏中的 N 个副本来自这个条目」，并提供「去同步」：打开人物单元的模板差异界面，以当前使用的版本为准。

**导出**
- 导出范围中多一组「官方条目的修改」：本存档的房规版本，以及来自本人导出模组的修改版。
- 房规版本按与原版的差异写成 `patch`，只写改动的字段。

## 5. 风险清单

每一行都对应 §6.1 中的一个自动测试。

| 角度 | 情况 | 结果 |
|---|---|---|
| 生命周期 | 卸载存档导入过的模组包 | 存档不变，可照常游玩 |

| 原子性 | 安装包与导入模组同时发生 | 队列依次执行 |

| 修改版 | 卸载原版所在的数据包 | 原版已固定，照常显示 |
| 修改版 | 原版在库里升级 | 仍用已固定的原版；重新固定后版本不一致时体检提示 |
| 修改版 | 套用后的结果不符合数据定义 | 本次使用原版，体检列出，不崩溃 |
| 修改版 | 隐藏的条目已被存档引用 | 引用照常显示；只在搜索与新建中隐藏 |
| 修改版 | 导出房规版本 | 只写改动的字段，不整条复制官方内容 |
