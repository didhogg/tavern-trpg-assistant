# U2 存档 · 单元蓝图

状态：定稿

## 0. 范围与归属

本单元负责：首页（战役概览）、当前数据、存档（保存、分支、读取、自动存档、最近删除）、新存档向导、存档导出导入、扩展包安装器的基础规则（§3.9、§3.10、§3.12），以及这些功能的全部界面。扩展包格式、库、本存档的内容、冒险与我的库由 L1 负责（`docs/units/L1_库与模组.md`）。

| 里程碑 | 交付 |
|---|---|
| M1 | §1 规则作用域、§2 数据、§3 行为规则的数据层与 store action（无界面）；含规则注册表、统一安装器、模板副本机制、迁移框架、导出导入、下载函数（目录读取与单文件下载校验）；真机自检按钮（探针面板） |
| M3 | §4.2 首页、§4.3 页头存档芯片、§4.4 开始一场新的冒险、§4.5 新存档向导、§4.6–4.7 存档抽屉及其弹出物、§4.10 导出与导入存档 |

依赖：M2 提供内置包文件与数据仓库目录；L1 提供库、扩展包格式与本存档的内容；U1 提供外壳、侧栏、标签栏与控件库。首页概览格读取其他单元的数据，所属单元尚未完成时该格不显示。

本单元读取：规则注册表、宿主角色卡/群组标识、其他单元公开的概览 getter。本单元写入：IndexedDB（§2.2）。其他单元通过 store 读取当前数据与已启用扩展包，不直接访问存储。

## 1. 规则作用域（硬性）

1. 每个当前数据、存档、扩展包都属于且只属于一个规则（`ruleId`）。
2. 界面按当前数据的规则渲染：人物卡、骰盘、活动、资料分类、库的默认规则都由当前规则决定。
3. 只有同一规则的数据可以相互作用：存档列表、启用扩展包、模组、导入。不匹配一律拒绝并写明原因，不做转换或"尽量兼容"。
4. 读取其他规则的存档等于换一场游戏：必须经过"切换规则并读取"确认（§4.7.4），界面随之整体切换。
5. 安装扩展包或导入存档时，所需规则必须已安装；否则拒绝，提示"需要先安装规则『X』"。

## 2. 数据

### 2.1 实体

**规则目录项 `RuleCatalogEntry`**：`{ id, name, nameShort, status, description }`；`status` 为 `installed`（代码中已注册）/ `installable`（可从数据仓库安装）/ `coming`（即将推出）。已安装规则来自规则注册表；其余来自数据仓库目录。规则安装器接口 `RuleInstaller.install(id)` 在 A7 实现；V1 数据仓库目录中的规则只有 `coming` 状态。

**扩展包清单 `PackManifest`**（formatVersion 2 的新增字段见 L1 §2.2）

| 字段 | 说明 |
|---|---|
| `id` | 小写短横线标识，如 `dnd5e2014-srd`、`dnd5e2014-xge`；同一 id 视为同一个包 |
| `ruleId` | 所属规则，如 `dnd5e2014` |
| `category` | 库中的分组，见 L1 §2.2 |
| `name` / `nameEn` | 显示名称 |
| `version` | 语义化版本 `1.0.0` |
| `minAppVersion` | 需要的最低扩展版本 |
| `source` | `builtin` / `download` / `import` / `user`（安装时写入；`user` 为我的包） |
| `license` / `attribution` | 协议与署名文本 |
| `description` | 一句话简介 |
| `entryCount` / `byteSize` / `sha256` | 条目数、文件大小、校验值 |
| `typeCounts` | 按条目类型的数量，如 `{ spell: 95, feature: 312 }` |
| `relationships` | 需要 / 推荐 / 冲突的包，见 L1 §2.2 |

**条目 `Entry`**：`{ id, type, name, nameEn, keywords[], unique, summary, data }`；`type` 与 `data` 结构由规则包的 schema 定义。地点条目可带 `image`（`{ $asset }`，见 L1 §2.4）。

**当前数据 `Workspace`**

| 字段 | 说明 |
|---|---|
| `ownerKey` | `char:<头像文件名>` 或 `group:<群组 id>` |
| `ownerLabel` | 角色卡名或群组名（显示用） |
| `ruleId` | 所属规则 |
| `currentSaveId` | 当前关联的存档 |
| `enabledPacks` | `[{ id, version }]`，含必选的内置包；`version` 为启用时的版本 |
| `data` | 游戏内全部数据 `WorkspaceData`：`instances`（本单元定义，见下）与其他单元各自拥有的键（人物、队伍、标签、地点、任务、遭遇、日志…）；本单元只负责整体读写、哈希、快照，不解释其他单元的键 |
| `savedHash` | 当前存档快照的哈希，用于判断"有未保存改动" |
| `schemaVersion` / `updatedAt` | — |

**存档 `SaveSlot`**

| 字段 | 说明 |
|---|---|
| `id` | uuid |
| `ownerKey` / `ownerLabel` / `ruleId` | 所属卡与规则 |
| `name` / `note` | 存档名（必填，≤40 字）/ 备注（可空，≤200 字） |
| `kind` | `manual` / `auto` |
| `autoReason` | 自动存档原因：读档前 / 新存档前 / 切换规则前 / 恢复备份前 / 改动模组前 |
| `branchedFrom` | 分支来源存档 id（可空） |
| `createdAt` / `updatedAt` / `deletedAt` | `deletedAt` 非空即在"最近删除" |
| `summary` | `{ partyNames: 前 3 名, partyCount, location, round }` |
| `packs` | `[{ id, version, name }]` 引用的扩展包 |
| `snapshot` / `hash` | Workspace.data 快照与其哈希 |
| `schemaVersion` | — |

**实例 `Instance`**（`WorkspaceData.instances` 的元素）：`{ id, type, name, label?, sourceRef?: { packId, version, entryId }, data }`。`data` 是条目 `data` 的深拷贝，之后与模板互不影响；`label` 是同一批新建时的编号（A、B、C…）。

**备份状态 `BackupState`**（meta 键 `backup`）：`lastExportAt`、`savesSinceExport`、`persistRequested`、`persistGranted`。
**设置 `Settings`**（meta 键 `settings`，随完整备份导出）：`reminderDays`（默认 7）、`reminderSaves`（默认 10）、`catalogUrl`。

### 2.2 存储布局

IndexedDB 库 `tavern-trpg-assistant`（Dexie）：

| 表 | 主键 | 索引 | 内容 |
|---|---|---|---|
| `packs` | `id` | `ruleId`、`category`、`name` | 已安装扩展包清单（每个 id 只保留一个版本） |
| `entries` | `[packId+entryId]` | `packId`、`[ruleId+type]` | 条目 |
| `searchIndex` | `packId` | — | MiniSearch 序列化索引（可重建） |
| `blobs` | `hash` | — | 图片仓库（L1 §2.6；第 2 版数据库起取代 `assets`） |
| `workspaces` | `ownerKey` | `ruleId` | 当前数据 |
| `saves` | `id` | `[ownerKey+ruleId]`、`ruleId`、`kind`、`deletedAt` | 存档 |
| `meta` | `key` | — | 备份状态、库设置、目录缓存 |

- 一次用户操作涉及的多表写入放在同一个事务中。
- 当前数据在改动后 500ms 写入；页面隐藏或卸载前立即写入。
- 首次启动调用一次 `navigator.storage.persist()`，结果记入 `BackupState`。

### 2.3 文件格式

两种文件都是 zip（fflate），根目录有 `trpg-manifest.json`。

**`.trpgpack`（扩展包）**：见 L1 §2.2。

**`.trpgsave`（存档 / 完整备份）**
```
trpg-manifest.json     { "format": "trpg-save" | "trpg-backup", "formatVersion": 1,
                         "appVersion", "exportedAt", "ruleIds": [...] }
saves/<id>.json        SaveSlot（完整备份含自动存档，不含最近删除）
workspaces/<key>.json  仅完整备份：各卡当前数据
settings.json          仅完整备份：Settings
packs.json             已安装扩展包清单（id、版本、名称）
packs/<id>@<ver>.trpgpack  可选：勾选"附带所用扩展包"时（不含内置包）
blobs/<sha256>         存档引用到的图片（L1 §2.8）
mypacks/、packtrash/   仅完整备份：全部我的包与库回收站（L1 §2.8）
```

**识别顺序与失败提示**（逐条检查，第一处失败即停止并显示对应提示）

| 检查 | 失败提示 |
|---|---|
| 是 zip | 无法识别：这不是 TRPG 跑团助手的文件 |
| 有 `trpg-manifest.json` | 无法识别：缺少说明文件，可能不是本扩展导出的文件 |
| `format` 已知 | 无法识别：未知的文件类型 |
| `formatVersion` 受支持 | 这个文件由更新版本的扩展创建，请先更新扩展 |
| 规则已安装 | 需要先安装规则『X』 |
| 数据结构校验通过 | 文件内容损坏：第 N 项「名称」字段不合法（只显示第一处） |
| 校验值一致（下载时） | 下载的文件不完整，请重试 |

**数据仓库目录 `catalog.json`**（默认地址 `https://cdn.jsdelivr.net/gh/didhogg/tavern-trpg-data@main/catalog.json`，可在设置中修改）
```
{ "formatVersion": 1,
  "rules": [ { "id", "name", "nameShort", "status", "description" } ],
  "packs": [ { "id", "ruleId", "category", "name", "nameEn", "version", "byteSize", "sha256",
               "url", "license", "description", "typeCounts", "updatedAt" } ] }
```

**内置包**：扩展目录 `packs/` 中的 SRD 基础规则与示例模组《迷雾渡口》，附 `packs/DATA-NOTICE.md`。首次启动、或扩展更新带来更高版本时，经同一个安装器安装；卸载与恢复见 L1 §3.3。

**规则默认横幅**：每个规则在注册表中提供自己的默认战役横幅 `defaultBanner: { wide, narrow, alt }`，不同规则互不共用。D&D 5e（2014）：
- 宽屏 `https://a1.ax1x.com/2026/10/28/wwHs9.png`（800×450）
- 窄屏 `https://a1.ax1x.com/2026/10/28/wwHs9.md.png`
- `alt`："D&D 5e 默认战役横幅"
未提供 `defaultBanner` 的规则直接使用纹样底图。

### 2.4 首页横幅取图接口

`getCampaignBanner(workspace) → { src, alt, source: 'location' | 'parentLocation' | 'default' | 'pattern' }`

取图顺序：当前地点的参考图 → 上级地点的参考图（逐级向上）→ 当前数据所属规则的 `defaultBanner` → 纹样底图（CSS 生成，无外部资源；任一图片加载失败时也退回到它）。地点参考图由地图单元（U8）写入地点条目；本单元只读取。

"开始一场新的冒险"页尚无当前数据：使用已安装规则中第一个的 `defaultBanner`；向导中选定规则后，横幅随之切换为该规则的图。

### 2.5 版本与迁移

- Workspace、SaveSlot、PackManifest 都带 `schemaVersion`；读取旧版本数据时按迁移链逐级升级，升级后写回。
- 数据版本高于当前扩展能处理的版本时：拒绝打开，提示"这个存档由更新版本的扩展创建，请先更新扩展"，不写入任何内容。

## 3. 行为规则

### 3.1 当前数据与"未保存"
- "有未保存改动" = 当前数据的哈希 ≠ 当前存档的 `hash`。
- 显示：页头存档芯片的 ● 与快捷"保存"按钮；首页横幅的状态行；存档抽屉当前区。

### 3.2 保存
- 用当前数据覆盖当前存档的快照、摘要、扩展包引用与 `updatedAt`；`savesSinceExport` 加 1。
- 入口：页头快捷"保存"（仅有改动时出现）、存档抽屉"保存"、快捷键 ⌘/Ctrl+S（焦点在助手内时）。
- 没有改动时：抽屉中"保存"不可用并显示"已是最新"；快捷键无动作。
- 成功：提示条"已保存「龙金劫-2」"（4 秒）。失败：常驻错误提示条，数据不变。

### 3.3 分支存档
- 用当前数据新建一个存档（默认名"<原名> 分支"，重名时加序号），`branchedFrom` 指向原存档，并切换为当前存档。
- 原存档保持它上次保存时的样子；当前未保存的改动只进入新分支。

### 3.4 新存档
- 通过新存档向导（§4.5）创建：新的当前数据（所选规则与扩展包）+ 第一个存档位。
- 已有当前数据时，先写一个自动存档（原因"新存档前"）。

### 3.5 读取
- 有未保存改动时先弹确认（§4.7.2）。
- 读取前总是为当前数据写一个自动存档（原因"读档前"）。
- 读取后：当前数据 = 存档快照；已启用扩展包 = 存档引用的扩展包；引用了未安装的包时，在存档抽屉与「本存档的内容」中显示缺失提示，已加入游戏的副本照常可用。
- 读取同规则、其他卡的存档：先复制为当前卡的新存档（名称"<原名>（来自 <卡名>）"），再读取这个副本；原存档不变。
- 读取其他规则的存档：见 §4.7.4。

### 3.6 自动存档
- 每张卡、每个规则保留最新 3 个；触发：读档前、新存档前、切换规则前、恢复备份前、改动模组前（L1）。
- 自动存档可读取、可"另存为存档"（转为手动存档），不能改名。

### 3.7 删除、恢复、彻底删除
- 删除：存档移入"最近删除"，提示条带"撤销"（6 秒）。
- 正在使用的存档不能删除（菜单项不可用，说明"正在使用的存档不能删除，请先读取或新建其他存档"）。
- 恢复：移回存档列表。彻底删除 / 清空最近删除：确认对话框后不可恢复。

### 3.8 本存档的内容

扩展包的启用与停用、功能、修改版、冒险见 L1 §3.8–§3.10、§3.15、§3.16。

### 3.9 扩展包安装（内置、下载、导入共用）

**扩展包只有一种格式**：识别、校验、安装、覆盖、同名处理、更新、导出、卸载、启停、依赖、存档引用的全部规则与界面相同，没有按分组区分的流程。L1 §3.5 在此基础上增加 lineage、关系与功能的检查。
1. 读取文件 → 按 §2.3 识别与校验。
2. 冲突判定：
   - **同 id 已安装**（导入时）→ 弹出"覆盖扩展包？"（§4.9.5）：显示已安装与导入两边的版本、条目数、来源；按钮文字随版本关系变化：较新"覆盖"、相同"重新安装"、较旧"覆盖（降级）"。内置包不允许降级。
   - **不同 id、同规则、同名**（导入时）→ 弹出"已有同名扩展包"（§4.9.6）：取消 / 保留两个（导入的包名称后加"（2）"）/ 替换已安装的（删除旧包后安装；旧包被存档引用时附带 L1 §3.6 的说明）。
   - **下载与更新**：用户已明确选择"下载/更新"，同 id 直接覆盖为目录中的版本，不再询问。
3. 在一个事务中写入清单、条目与附件；失败时整体回滚，不留下半个包。之后在后台重建搜索索引（完成前资料页显示"正在建立索引"）。
4. 覆盖或升级不改动任何存档里已加入游戏的副本；引用旧版本的存档读取时照常可用，模板差异的同步界面由人物与资料相关单元提供。

### 3.10 下载与更新
- 打开库或展开向导中的"可下载"时读取数据仓库目录（10 秒超时，成功结果缓存 1 小时）；失败时照常显示已安装内容，并写明原因与"重试"。
- 下载：流式读取并显示进度，最多同时 2 个；完成后核对大小与校验值，再交给安装器。可取消。
- 错误：网络中断、文件不存在（404）、校验不符、存储空间不足，各有明确提示与"重试"。
- 更新：有更高版本时行内显示"有更新 vX"与"更新"；有 2 个及以上更新时，区头显示"全部更新（N）"。

### 3.11 卸载扩展包

见 L1 §3.6。

### 3.12 规则
- 已安装规则（代码注册）不能卸载。
- `installable` 规则的安装经 `RuleInstaller` 完成（A7）；`coming` 规则只展示，不提供按钮。

### 3.13 导出
- 范围：当前存档 / 全部（完整备份）；可勾选"附带所用扩展包"（不含内置包）。完整备份总是包含全部我的包与库回收站。
- 存档引用到的图片总是一并写入（L1 §2.8）。
- 文件名：`<存档名>_<yyyy-mm-dd>.trpgsave` / `TRPG备份_<yyyy-mm-dd>.trpgsave`。
- 完整备份成功后：`lastExportAt` = 现在，`savesSinceExport` = 0。
- 宿主下载行为：通过 `<a download>` 保存文件；在 TauriTavern 中的表现须在 M3 真机验证，不可用时改用 TauriTavern 文件导出接口（`docs/CurrentState/FileTransfer.md`）。

### 3.14 导入存档与恢复备份
- 存档文件：列出其中的存档供勾选；导入为当前卡的存档（重名时加"（导入）"）；规则未安装的存档不可勾选并说明原因；附带的扩展包逐个经安装器安装（冲突时按 §3.9 弹窗）。
- 完整备份：选择"合并"（默认，只添加尚不存在的存档与当前数据）或"覆盖"（用备份替换**已安装规则**的全部存档、当前数据与设置，随后把覆盖前各卡的当前数据写成"恢复备份前"自动存档）。属于未安装规则的存档与当前数据不被改动。

### 3.15 备份提醒
- 距上次完整备份 ≥ `reminderDays` 天，或之后保存 ≥ `reminderSaves` 次 → 文字变为琥珀色"建议导出备份"。
- 从未导出过 → "还没有导出过备份"。只做文字提示，不弹窗。

### 3.16 多窗口
- 使用 BroadcastChannel 检测同一浏览器中其他打开的助手；检测到时，后打开的窗口顶部显示"另一个窗口正在使用助手，此窗口为只读"，并禁用所有写入操作。

### 3.17 错误
- 任何写入失败：数据保持原状，显示常驻错误提示条，写明原因与可做的事。
- 存储空间不足：提示"存储空间不足：可以删除不用的扩展包，或清空最近删除"。

### 3.18 模板与副本

- 扩展包条目可直接查看、引用、交给 AI；对条目执行需要记录状态的操作时，调用 `materialize(workspace, { packId, entryId })` 生成副本（`Instance`）：
  - 条目所在扩展包必须已在当前数据中启用，否则拒绝（"该扩展包已停用，不能再从它新建"）。
  - `unique: true`（具名 NPC、首领、唯一物品）：当前数据中已存在同一 `sourceRef`（packId + entryId）的副本时，直接返回它，不新建。
  - 普通条目：每次调用新建一个副本；`materializeBatch(..., count)` 一次新建 count 个，count > 1 时在批内按 A、B、C… 编号（超过 26 个继续 AA、AB…），count = 1 时不编号。
  - `data` 为条目当前使用版本（L1 §3.15）的深拷贝；`sourceRef` 记录 packId、当时的版本与 entryId；同时按 L1 §3.2 固定原版。
- 副本的字段含义、编辑与"存为模板"、模板更新差异同步由人物、战役等单元定义；本单元只保证：副本独立于扩展包存在（扩展包停用、覆盖、删除后副本不变），存档快照包含全部副本。

## 4. 界面

### 4.1 设计约定（本单元）

**每屏一个主角、一个主动作**

| 界面 | 主角 | 主动作 |
|---|---|---|
| 首页（有战役） | 战役横幅与概览格 | 点概览格进入对应页面 |
| 首页（无战役） | "开始一场新的冒险"横幅 | 开始新冒险 |
| 新存档向导 | 当前步骤的选项 | 下一步 / 开始冒险 |
| 存档抽屉 | 当前存档区 | 保存 |
| 导出窗口 | 范围选择 | 导出 |

**规则**
- 同一操作只有一个执行入口；首页概览格是"带数据的导航"，页头快捷保存是高频操作的快捷入口，二者不算重复。
- 即时生效用开关；表单提交用勾选框；2–5 个选项用分段按钮；更多用下拉；不可撤销用确认对话框；可撤销用带"撤销"的提示条。
- 层级：一个页面同时最多一个抽屉或二级悬浮窗，其上最多再叠一个确认对话框；下拉、弹出卡片任何时刻最多一个。
- 搜索框只在列表超过 8 项时出现。
- 窄屏（≤480px）：抽屉与二级悬浮窗铺满为整页（标题栏左侧返回）；确认对话框贴底显示为底部面板，按钮纵向排列、主按钮在最上方；弹出卡片改为底部面板。
- 徽章（方块、浅底色、不可点）：`当前`、`内置`、`已安装`、`有更新`、`未安装`、`下载中`、`自动`、`即将推出`；徽章上始终有文字。
- 卡片只用于首页横幅、概览格、规则卡与详情面板；存档与扩展包列表用行 + 细分隔线。
- 动效：抽屉右侧滑入 200ms；对话框淡入 + 轻微放大 160ms；进度条平滑推进；列表增删项淡入淡出 160ms；横幅图片加载完成后淡入 240ms；遵守"减少动态效果"。

### 4.11 状态与反馈汇总

| 场景 | 表现 |

### 4.12 键盘与可访问性

- 抽屉、二级悬浮窗与对话框打开时焦点进入，Esc 关闭并把焦点还给触发按钮；对话框内 Tab 循环。
- ⌘/Ctrl+S 保存（焦点在助手内时）。
- 存档行：↑↓ 在行间移动，Enter = 读取，F2 = 改名，Delete = 删除（当前存档无效）。
- 概览格可用 Tab 依次聚焦，Enter 打开对应页面。
- 开关、勾选框、分段按钮可用空格切换；所有图标按钮有可读名称（如"龙金劫-1 的更多操作"）。
- 进度条有 `aria-valuenow`；识别、安装、导出结果通过 `aria-live` 播报。

### 5.2 M1 真机自检（驾驶员，TauriTavern）

### 5.3 真机验收（驾驶员，TauriTavern，M3 与 M9 完成后）

1. 在一张没有数据的角色卡上：首页显示 D&D 5e 默认横幅与"开始一场新的冒险" → 走完新存档向导 → 首页显示战役概览，概览格逐个点击能到达对应页面。
2. 改动后页头出现"● 保存"，点击后消失；用 ⌘+S 再试一次。分支存档后列表出现两个存档。
3. 读取另一个存档（含未保存确认）→ 自动存档区出现记录。
4. 删除一个存档 → 撤销；再删除 → 最近删除中恢复 → 彻底删除。
5. 在库里**下载**一个扩展包 → 在「本存档的内容」中启用 → 资料页能搜到其内容。

7. 导出完整备份（含扩展包）→ 文件出现在下载位置；导入该文件（合并）→ 存档齐全。
8. 完全退出 TauriTavern 再打开 → 当前数据与存档仍在。
9. 群组聊天与未打开聊天时，首页与存档芯片的表现符合 §4.4、§4.11。
