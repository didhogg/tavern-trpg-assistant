状态：草案（U6.1、U6.2、U6.3 待驾驶员定稿；U6.4 起在各自开工前补全）

## 0. 范围与归属

本单元负责：人物、队伍、标签的数据；人物页；加入人物的全部流程；人物列表；以及这些功能的全部界面。人物详情与各分页由 U5 负责（`docs/units/U5_人物卡.md`）；派生数值由 R1.1 负责（`docs/units/R1_规则引擎.md`）。

按小 Unit 逐个交付，每个交付经驾驶员验收后再做下一个：

| U6.2 外壳与加入流程 | M4 | §3.1 设计约定、§3.2 人物页外壳、§3.3 加入人物对话框、§3.4 最简列表、§3.5 首页概览格 |
| U6.3 通用列表 | M5 | §3.6 搜索、筛选、排序、范围、成组、状态保留、行尾"⋯ 更多" |
| U6.4 标签 | M5 | §3.7 |
| U6.5 队伍 | M5 | §3.8 |

| U6.8 队伍公共背包 | M5 | §3.11（待 U5.4 背包完成后补全） |

## 1. 数据（U6.1）

### 1.1 人物 `Person`

| 字段 | 类型与取值 | 说明 |
|---|---|---|
| `id` | 字符串 | 唯一 |
| `name` | 字符串，1–40 字符，去首尾空白 | 显示名；允许重名 |
| `serial` | 正整数，可选 | 从库里选的人物在同一 `sourceRef` 内的流水号，创建时递增、永不复用；用于显示 A、B、C |
| `alias` | 字符串，可选 | 对外称呼；给 AI 的摘要优先用它 |
| `keywords` | 字符串数组 | 名字、对外称呼、别名；用于提及激活（U4） |
| `cardType` | `full` 完整卡 / `block` 属性块 | 创建时选定；名称由规则提供 |
| `identity` | `party` 队伍成员 / `npc` / `enemy` | 见 §2.5 |
| `partyId` | 队伍 id 或 `null` | 只有 `party` 有值 |
| `away` | 布尔 | 留守；只对 `party` 有意义，默认 `false`（随行） |
| `isPlayer` | 布尔 | ★玩家角色；同一队伍至多一人 |
| `pinned` | 布尔 | 📌 常驻 |
| `giveAi` | `auto` / `nameOnly` / `full` / `none` | 给 AI 的级别，默认 `auto`（U4 使用） |
| `tags` | 标签 id 数组 | |
| `state` | `draft` / `normal` / `trash` | §2.3 |
| `trash` | `{ at, identity, partyId, away }`，可选 | 进入回收站时记录，用于找回 |
| `sourceRef` | `{ packId, version, entryId }`，可选 | 从库里选时记录，规则同 U2 §3.18（固定原版） |
| `unique` | 布尔，可选 | 来自唯一条目 |
| `hp` | `{ current, temp, deathSaves: { success, fail } }` | 生命值上限不存这里：属性块的上限在 `data`，完整卡由 R1.1 计算，`overrides.hpMax` 可手动覆盖 |
| `conditions` | `[{ ref?: { packId, entryId }, name, note? }]` | 当前状态与效果，U5.6 扩展来源与持续时间 |
| `data` | 对象 | 卡片数据，按 `cardType` 由 U5 定义；`block` 为怪物数据的深拷贝；`full` 含职业、种族、背景、属性、熟练、`overrides` 等 |
| `order` | 数字 | 同一分组内的顺序（队伍成员的成员顺序） |
| `createdAt`、`updatedAt` | 时间戳 | |

零值规则：未知的数据保持 `null` 或缺省，不写 0（R1 §1 第 4 条）。

### 1.2 队伍 `Party`

`{ id, name, order, createdAt }`。名称 1–40 字符，不能与已有队伍重名（不区分大小写）。公共背包与金币在 U6.8 增加。

### 1.3 标签 `Tag`

`{ id, name }`。名称 1–24 字符，去首尾空白，不区分大小写不可重名；标签只用于分类、搜索、筛选，不改变任何规则状态。

### 1.4 存储与迁移

- 存入 `workspace.data`：`people: Person[]`、`parties: Party[]`、`tags: Tag[]`、`currentPartyId: string | null`；`workspaceDataSchema` 为宽松对象，新增键带默认值（空数组与 `null`）。
- 存档快照包含这些键；回收站人物随快照保存。
- 新增一步迁移（按 `src/core/migrate.ts` 的框架）：旧数据补齐四个键；高版本数据拒绝读取。
- Zod 定义放 `src/schemas/people.ts`；`data` 的内部结构由 U5 在 `src/rules/dnd5e2014/` 下按卡型定义，本单元只校验外层字段。

### 1.5 Store

`usePeopleStore`（Pinia）。所有写入经 action，action 通过当前数据的 store 写入当前数据（持久），并使存档进入"有未保存到存档的改动"状态（U2 §3.1）；写进存档只能经 U2 的保存存档或分支存档。人物卡的编辑草稿由 U5 管理（U5 §1），本 store 只接收已保存的修改。

| action | 说明 |
|---|---|
| `addFromEntry({ ref, identity, count, partyId?, hpMode })` | §2.1；返回 `{ created, existing, token }` |
| `addBlank({ name, cardType, identity, partyId?, base? })` | §2.2；返回 `{ person, token }` |
| `update(id, patch)` | 改外层字段或 `data`；每次更新重算 `state`（§2.3） |
| `duplicate(id)` | §2.6 |
| `setIdentity(id, identity, partyId?)` | §2.5 |
| `setParty(ids, partyId)`、`setAway(ids, away)`、`setPlayer(id, on)`、`setPinned(ids, on)` | |
| `trash(ids)`、`restore(ids)`、`purge(ids)` | 回收站（U6.7 完成界面） |
| `addTag(ids, tagId)`、`removeTag(ids, tagId)`、`createTag(name)`、`renameTag`、`deleteTag` | 标签（U6.4 完成界面） |
| `createParty(name, { current? })`、`renameParty`、`dissolveParty`、`setCurrentParty` | 队伍（U6.5 完成界面） |
| `undo(token)` | §2.7 |

只读 getter：`list({ identity, range, search, tags, partyId, sort })`、`counts()`、`summaryOf(id)`（取 R1.1 的 `derive.summary`）、`groupsOf(identity)`（§3.4 成组）。

## 2. 行为规则

### 2.1 从库里选（`addFromEntry`）

1. 条目必须来自当前数据已启用的扩展包，且规则与当前数据一致；否则拒绝并写明原因（"该扩展包已停用，不能再从它新建"）。
2. `unique` 条目：当前数据中已存在同一 `sourceRef`（packId + entryId）且未进回收站的人物时不新建，返回 `existing`；已在回收站时返回 `existing` 并提示"在回收站里，找回？"。
3. 普通条目：每次新建 `count` 个（1–30）；`serial` 在同一 `sourceRef` 内取当前最大值 + 1 起递增。
4. `data` 为条目当前使用版本的深拷贝，`sourceRef` 记录当时版本，并按 L1 §3.2 固定原版（与 U2 §3.18 同一套规则，实现上复用同一个函数）。
5. 生命值：`hpMode = 'average'`（默认）取条目的平均生命值；`'roll'` 对每个新人物按条目的生命值公式各掷一次，没有公式（或为"特殊"类生命值）时取平均值，并在返回值里标出哪几个没能掷骰。掷骰使用 `src/rules/dice/` 的引擎与 `cryptoRng`。
6. 创建后 `hp.current` 等于生命值上限、`temp` 为 0、`state` 为 `normal`、`cardType` 为 `block`。
7. `identity = party` 时需要 `partyId`；缺省使用当前冒险队伍；没有任何队伍时由调用方先 `createParty`（§3.3）。

### 2.2 空白新建（`addBlank`）

1. 只有名称必填；名称为空（去空白后）拒绝，提示在名称框旁。
2. 完整卡的 `base` 可带职业与等级、种族、背景；属性块的 `base` 可带生命值上限与 AC。没带的留空。
3. 创建后按 §2.3 判定 `state`。

### 2.3 草稿与正常

- `state = draft`：R1.1 的 `summary.pending` 非空。完整卡必填：至少一个职业与等级、六项属性、生命值上限（可由职业与体质计算）；属性块必填：生命值上限、AC。
- 每次 `update` 后重算；`pending` 变空时自动转 `normal`，再次出现缺项时回到 `draft`（例如删除了职业）。
- 草稿可以出现在列表、被搜索和多选，但不参与提及激活与给 AI 的摘要（U4）；界面显示"待填 N 项"。

### 2.4 队伍的创建

- 队友加入时没有任何队伍：对话框里显示"队伍名称"输入框（默认"冒险队"），提交时先建队伍并设为当前冒险队伍，再加入人物，作为一次可整体撤销的操作。
- 当前冒险队伍只决定默认候选，不搬人。

### 2.5 身份

- `party → npc / enemy`：移出队伍（`partyId`、`away`、`isPlayer` 清空）；`npc / enemy → party`：必须选队伍；`npc ↔ enemy`：只改身份。
- 标签、给 AI 级别、常驻、数据保持不变。
- 每次改身份，提示条给"撤销"。

### 2.6 复制

`duplicate(id)`：生成新人物，名称、数据、标签、给 AI 保留，`serial` 在同一 `sourceRef` 内递增（没有 `sourceRef` 则不编号，名称加"（副本）"）；`isPlayer`、`pinned` 清空；生命值回到满。唯一条目的人物不能复制（菜单项灰显并写原因）。

### 2.7 撤销

- 加入、改身份、移入回收站、复制每次产生一个撤销令牌，对应提示条上的"撤销"；提示条消失后令牌作废，撤销按钮不再出现。
- 撤销只还原这一次操作的结果；其间如果被撤销的人物已被别的操作改过，撤销返回"已无法撤销"，不强行覆盖。
- 撤销"加入"：删除这批新人物与同批创建的队伍；`serial` 不回收。

### 2.8 规则作用域

人物页、人物与库条目都属于当前数据的规则（U2 §1）；切换规则读取其他存档时，人物页按新规则重建。

## 3. 界面

### 3.1 设计约定（本单元）

**每屏一个主角、一个主动作**

| 界面 | 主角 | 主动作 |
|---|---|---|
| 人物页 | 当前分页的人物列表 | 加入（按钮文字随分页：＋ 新建队友 / ＋ 新建 NPC / ＋ 添加敌人） |
| 加入人物对话框 | 当前来源下的选择区（模板列表或名称框） | 加入 / 新建（文字写明数量与对象） |

**规则**（在 U2 §4.1 与开发规范 §5.3 的基础上）
- 状态徽章（方块、浅底色、不可点、必须有文字）：`倒地`、`倒下`、`死亡`、`待填 N 项`、规则状态（中毒、专注等）；自定义标签用药丸（可点，点击加入筛选）。
- 控件：身份与来源用分段按钮（2–3 个选项）；队伍、职业、种族、背景用可搜索下拉；数量用步进器；"加入后继续添加"用勾选框；行尾"⋯ 更多"是下拉菜单。
- 生命值条：红棕色填充，低于一半时变暗；0 时不靠颜色，写"倒地"或"倒下"；有临时生命值时在条右侧接一段金色。
- 窄屏（≤ 480px）：加入人物对话框铺满为整页（标题栏左侧返回），主按钮固定在底部；筛选与排序收进"筛选"按钮的底部面板。
- 动效：列表新增行淡入并高亮 1.2 秒；成组行展开与折叠 160ms；对话框遵守 U2 §4.1；遵守"减少动态效果"。

### 3.6 通用列表（U6.3）

在 §3.4 的基础上加入：

```
│ ⌕ [ 搜名字、称呼、种族、职业、标签 ]  [标签 ▾]  [排序：名称 ▾]  [选择]    │
│ 显示 4 / 共 4                                                            │
```

- **搜索**：匹配名称、对外称呼、种族、职业、标签名；不搜来源编号；中文输入法组合期间不重建输入框；搜索框的 × 只清搜索。
- **标签筛选**：`[标签 ▾]` 下拉列出全部标签（已选的不再出现），多个标签为"同时具备"；已选标签以药丸显示在搜索框下方，药丸 × 只移除这一筛选条件；点人物行上的标签也加入筛选；下拉底部是"标签管理"（U6.4）。
- **排序**：名称（默认）、生命值（高 → 低、低 → 高）、等级或 CR、最近修改；点排序符号切换升降。
- **范围**（NPC 与敌人分页）：`( ●相关 | 全部 | 模组库 )`，默认"相关"。
  - 相关 = 最近对话提到的、此地关联的、当前遭遇参战的、📌 常驻的（U4、U8、U7 提供数据；各自未完成时只用已有的部分），列表上方一行小字说明，每行副标题尾部显示"为什么相关"（"提到于 2 层前"、"此地"）。
  - 全部 = 当前数据里的全部人物。
  - 模组库 = 已启用扩展包与存档内模板中的人物条目，行尾为"加入 ▾"（加为 NPC 或敌人），不是"⋯ 更多"。
- **显示 N / 共 M**：始终显示；无结果时保留条件与"清除条件"，清除条件保留排序。
- **状态保留**：搜索、筛选、排序、范围、分组展开、滚动位置在切换页面、进入详情再返回后保持。
- **行尾"⋯ 更多"**按身份变化：
  - 队伍成员：加标签、换队伍、改为 NPC、设为留守 / 设为随行、📌 常驻 / 取消常驻、复制一个、移入回收站。
  - NPC：加标签、改为队友、改为敌人、📌 常驻、复制一个、移入回收站。
  - 敌人：加标签、改为 NPC、复制一个、移入回收站。
- 窄屏：标签筛选与排序收进搜索框右侧的"筛选"按钮，点开为底部面板。

### 4.2 真机验收（驾驶员，TauriTavern；U6.2 完成后）

1. 在有战役的存档里点侧栏"人物"：三个分页都是空状态，各有对应按钮。
2. 敌人分页点"＋ 添加敌人"→ 搜"狗头"→ 选"狗头人"→ 数量改 3 → 加入：列表出现"狗头人 ×3"，展开看到 A、B、C，提示条的"撤销"能撤回，"查看"定位到新行。
3. 同一个对话框里勾选"加入后继续添加"，再加两个不同的怪物。
4. 队伍分页"＋ 新建队友"→ 来源是空白新建 → 只填名称"盖尔"→ 提交：自动建了队伍，列表里出现盖尔与"待填 N 项"。
5. NPC 分页加入一个唯一角色，再加一次：提示已有，按钮变为"查看已有"。
6. 行尾"⋯ 更多"复制一个、移入回收站，并撤销。
7. 窄屏（手机）上重复第 2、4 步；对话框铺满且主按钮始终可见；整个过程屏幕上从未同时出现两个弹窗。
8. 首页的"人物"概览格数字正确，点击进入人物页。
9. 不保存存档，完全退出 TauriTavern 再打开：人物、队伍都在（当前数据持久）；再保存存档后读取一个旧存档、再读回来：人物跟着存档变化。

## 5. 待议

1. **人物与副本的关系**：本蓝图让人物独立于 `instances`（§1.4），创建时复用 U2 §3.18 的规则；`instances` 保留给物品等非人物条目的副本。若驾驶员希望人物也放进 `instances`，需要改 U2。
2. **A、B、C 的显示**：字母由 `serial` 在显示时转换，组内只有一个时不显示；移入回收站后剩一个时，另一个的字母也会隐藏，反之找回后再出现。
3. 敌人 0 生命值的显示（倒下或死亡）见 R1 §4 待议 2。
4. 从酒馆角色卡导入为 NPC、预设角色（D2、U12）的加入方式，到对应单元时再定。
