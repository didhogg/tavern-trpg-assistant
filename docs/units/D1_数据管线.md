# D1 数据管线 · 单元蓝图

状态：定稿

## 0. 范围与归属

本单元负责基础数据管线：
- D&D 5e（2014）条目的数据定义（zod，`dataVersion` 3；v1、v2 包仍可安装）
- 冒险内容项的通用外壳（各类型的具体字段由所属单元定义）
- 从参考数据构建 SRD 与十本官方书的扩展包
- 每个条目的来源与许可标注
- 校验、构建报告、抽检清单
- 每一种要管理的数据都能导入、导出、使用的往返验证（§8）
- 数据仓库的目录与发布脚本

官方冒险《凡戴尔的失落矿坑》的冒险包与地区示意图不在本单元，由 D2 负责（M10）。

| 里程碑 | 交付 |
|---|---|
| M2 | 本文件全部内容；同时交付 L1 里程碑表中 M2 一行（扩展包格式 2 的识别、数据库第 2 版、推荐包自动安装的数据层，不含界面） |

依赖：
- L1 §2.2（包格式）、§2.2.1（功能贡献）、§2.4（引用）
- U2 安装器

读取：`reference/` 中的参考数据，只在构建时读取，不进入扩展运行时。

写入：
- 扩展仓库：`packs/`、`src/rules/dnd5e2014/data/`（条目定义）、`src/schemas/adventure/`（冒险内容项通用外壳）、`tools/data/`、`tests/fixtures/packs/`
- 数据仓库工作目录 `../tavern-trpg-data`
- `docs/probes/D1_构建报告.md`、`docs/probes/D1_抽检.md`

## 1. 原则

1. 只收 2014 年规则的官方书。书目在白名单内；2024 版（XPHB、XDMG、XMM）与第三方书不收；遇到白名单外的来源，构建失败。
2. 不替玩家做取舍：所有限制（专长前置、兼职门槛、法术职业表等）都结构化保留在 `requires` 中，由官方锁（R1）使用；构建时不因"不合规"删除条目。
3. 可重现：同样的输入得到逐字节相同的输出。内容变了而版本号没变时，构建失败。
4. 构建时的校验与扩展运行时的校验，共用同一份 zod 定义。
5. 官方书 PDF 只用于人工抽检，不进入数据。
6. 不猜：解析不了的部分保留原文，写进构建报告。
7. 每个条目都标明来源与许可（§4.1 `credit`），界面能显示出来。
8. 项目非商用。

## 3. 产物

### 3.1 扩展包清单

| id | 名称 | 分组 | 内容 | 位置 | 默认 |
|---|---|---|---|---|---|
| `dnd5e2014-srd` | SRD 基础规则 | 资料与规则 | 全部带 `srd` 标记的条目、SRD 内的随机表与规则选项 | 扩展仓库 `packs/`（内置） | 必选，不能卸载 |
| `dnd5e2014-phb` / `-dmg` / `-mm` / `-xge` / `-tce` / `-scag` | 一档官方扩展 | 资料与规则 | 该书 SRD 之外的条目、随机表、规则选项 | 数据仓库 | 推荐，一档 |
| `dnd5e2014-vgm` / `-mtf` / `-mpmm` / `-bmt` | 二档官方扩展 | 资料与规则 | 同上 | 数据仓库 | 推荐，二档 |

- 每个书籍包 `requires` SRD 包。书中内容引用另一本书的条目时（如 XGE 子职业属于 PHB 职业），被引用的书加入 `requires`；软引用（如怪物会的某个法术）不加入。
- 条目 `id` 中的书名保持原书，例如 SRD 包里的火球术为 `spell.fireball.phb`。

- 扩展仓库中只有 SRD 内容；所有非 SRD 的官方内容只在数据仓库中。

## 4. 条目数据定义

### 4.1 通用

条目信封沿用 U2 §2.1 的 `Entry`；`data` 中各类型都有以下字段：

| 字段 | 说明 |
|---|---|
| `src` | `{ book, page }`：原书与页码 |
| `credit` | `{ by, license, machine, missing[], structured? }`：中文来源与许可（见下表）；`structured` 记录结构化字段来源 |
| `text` | 正文，块数组（§4.4） |
| `requires` | 可选：官方锁使用的限制（§4.5） |
| `activities` | 可选：可执行的行动（§4.6） |

**`credit.structured`**：可选 `{ by: 5etools / 5etools-foundry / foundry-dnd5e / 5e-database / 本项目, license }`，表示数字与效果字段的导入来源；中文正文仍由 `credit.by/license` 标注。

**`credit.by` 与 `license`**

| by | 条件 | license |
|---|---|---|
| `不全书` | 5etools-cn 记录带 `translator: 不全书` | `GPL-3.0` |
| `共库` | 5etools-cn 其他中文记录 | `CC-BY-NC-SA-4.0` |
| `共库机翻` | 所属书目标注为机翻 | `CC-BY-NC-SA-4.0` |
| `dnd-data` | 中文缺失、用英文兜底的字段 | `MIT` |
| `本项目` | 本项目原创 | `CC-BY-NC-SA-4.0` |

- `machine`：是否为机翻。
- `missing`：用英文兜底的字段名。
- SRD 条目另外带 SRD 5.1（CC BY 4.0，Wizards of the Coast）的署名。

资料卡底部显示一行来源，例如「出自《玩家手册》第 241 页 · 中文：不全书（GPL-3.0）」；机翻条目显示 `机翻` 徽章（U11 实现）。

**id**：`<类型>.<英文名转写>.<书>`，全部小写，空格改为 `-`，去掉撇号与其他符号。

| 情况 | 写法 | 例子 |
|---|---|---|
| 一般 | 类型.名称.书 | `spell.fireball.phb` |
| 子职业 | 加上所属职业 | `subclass.fighter-battle-master.phb` |
| 职业与子职业特性 | 加上所属职业或子职业 | `feature.fighter-action-surge.phb` |
| 亚种族 | 加上所属种族 | `subrace.elf-high.phb` |
| 魔法变体 | 名称中带加值 | `item.longsword-plus-1.dmg` |
| 随机表 | 类型为 table | `table.trinkets.phb`、`table.treasure-hoard-cr-5-10.dmg` |

同一类型、同一本书内重名时加 `-2`，并写进构建报告。

**unique**：具名生物（`isNamedCreature`）与神器（`rarity: artifact`）为 `true`。

**keywords**：中文名、英文名、5etools 的别名。

**summary**：按类型模板生成，≤ 80 字，例如：
- 法术：「火球术｜3环 塑能｜1动作｜150尺｜敏捷豁免 8d6火焰」
- 怪物：「成年红龙｜巨型龙类｜CR17｜AC19 HP256｜啃咬+14 2d10+8」
- 物品：「长剑 +1｜武器·罕见｜1d8+1 挥砍」
- 特性：「动作如潮｜战士 2级｜额外获得一个动作」
- 随机表：「饰品｜d100｜100 项」

### 4.2 各类型字段

参照 Foundry dnd5e 的数据模型，按本插件的条目信封组织。

| 类型 `type` | 结构化字段 | Foundry 对应 |
|---|---|---|
| `spell` | `level`、`school`、`castTime[{ n, unit, condition? }]`、`range{ type, amount?, unit? }`、`components{ v, s, m?{ text, cost?, consumed? } }`、`duration[{ type, amount?, unit?, concentration }]`、`ritual`、`classes[classId]`、`subclasses[subclassId]`、`higherLevel`（文本）、`cantripScaling?` | spell + activities |
| `monster` | `size[]`、`creatureType{ type, tags[], swarm? }`、`alignment`、`ac[{ value, from? }]`、`hp{ average, formula }`、`speed{ walk, fly?, swim?, climb?, burrow?, hover? }`、`abilities{ str…cha }`、`saves{}`、`skills{}`、`senses[]`、`passive`、`languages[]`、`cr{ value, lair?, coven? }`、`xp`、`resist[]`、`immune[]`、`vulnerable[]`、`conditionImmune[]`、`traits[]`、`actions[]`、`bonusActions[]`、`reactions[]`、`legendary{ count, actions[] }?`、`mythic?`、`spellcasting[{ ability, dc, attack, atWill[], perDay{}, slots{} }]` | npc 角色 |
| `item` | `category`（weapon / armor / shield / gear / tool / consumable / wondrous / ammunition / mount / vehicle / treasure）、`baseItem?`、`rarity`、`attunement{ required, by? }`、`weight`、`value`（铜币）、`weapon?{ category, damage[{ dice, type }], versatile?, properties[], range? }`、`armor?{ category, ac, dexCap?, strReq?, stealthDisadvantage }`、`charges?{ max, recharge? }`、`bonuses?{ ac, attack, damage, save, spellAttack, spellDc }` | weapon / equipment / consumable / tool / loot |
| `class` | `hitDie`、`primaryAbility[]`、`saves[]`、`proficiencies{ armor, weapons, tools, skills{ choose, from[] } }`、`startingEquipment`、`spellcasting?{ ability, progression: full / half / third / pact, preparation, slotsByLevel? }`、`table`（按等级的列）、`subclassLevel`、`subclassTitle`、`multiclass{ requires, proficiencies }`、`advancement[]` | class + advancement |
| `subclass` | `classId`、`spellcasting?{ …, slotsByLevel? }`（奥法骑士、奥法诡术师等三分之一施法者在此带自己的法术位表）、`expandedSpells?`、`advancement[]` | subclass |
| `feature` | `owner{ type, id }`、`level?`、`featureType?`（战技、魔能祈唤、融合、战斗风格…）、`uses?{ max, recharge }`、`choices?` | feat（特性） |
| `race` / `subrace` | `parentRace?`、`size[]`、`speed{}`、`abilityBonus{ fixed{} } \| { choose{ count, amount, from[] } }`、`flexibleAbility?`（MPMM 式）、`darkvision?`、`languages`、`proficiencies`、`traits[featureId]`、`advancement[]` | race + advancement |
| `background` | `proficiencies{ skills, tools, languages }`、`equipment`、`feature`（featureId）、`characteristics`（随机表 id） | background |
| `feat` | `abilityIncrease?`、`advancement[]` | feat（专长） |
| `condition` / `disease` / `status` | `effects?`（R1 能识别的简单效果标签，如 `attack-disadvantage`） | — |
| `table`（随机表） | `dice`（如 `1d100`、`2d6`）、`cols[]`（多列表头）、`rows[{ min, max, cells[], refs[], then?{ table, times? }, qty? }]`、`group?{ id, name }`（同组表，如按挑战等级分的宝藏表） | RollTable |
| `rule` | 变体规则、动作说明、感官、技能说明 | 日志条目 |

职业 `table` 等按等级的数据，以及 `traits[]`、`actions[]` 中的每一项，都是 `{ name, text, activities? }`。

### 4.2.1 人物规则结构化（D1.1）

以下字段是 §4.2 的补充；旧包缺这些字段时规则引擎按「缺数据」处理，不猜。

| 类型 | 新增/补充字段 |
|---|---|
| `class` | `spellcasting.slotsByLevel[20]`（`slots[9]` 或 `pact{count,level}`）、`cantripsKnown[20]`、`spellsKnown[20]`、`preparation{ mode, formula? }`、`ritual`、`spellbook`、`invocationsKnown[20]`、`infusionsKnown/Active[20]`；`advancement` 增加 `scaleValue`、`itemChoice`、`expertise` |
| `subclass` | 三分之一施法者的 `spellcasting.slotsByLevel[20]`；子职业资源 `scaleValue` |
| `feature` | `uses{ max: number|公式, recharge, per? }`、`effects[]`、`activities[].consumption/effects/duration/target` |
| `race`/`subrace` | `abilityBonus`/`flexibleAbility`、结构化 `languages`、`senses`、`resist/immune/conditionImmune`、`proficiencies`、`spellGrants`、`effects` |
| `background` | 结构化 `proficiencies`、`equipment`（`fixed/choice/gold`）、`gold` |
| `feat` | `abilityIncrease`、`effects`、`spellGrants`、`uses`；`requires` 覆盖可解析的前置 |
| `condition`/`status` | `effects[]`；力竭另有 `levels[{ level, effects }]` 六行 |
| `item` | `effects[]`；护甲 `dexCap`、盾牌 AC；魔法物品行动 |
| `spell` | 完整 `classes`、攻击/豁免/伤害/治疗 `activities`、升环 `scaling` 由正文与结构化字段生成 |
| `rule` | 动作类带 `activation`、`activities`、`effects` |

公式、效果与标准编号的字段名以 `docs/handoff/D1.1_人物规则数据_交接.md` §6 为准；实现位于 `src/rules/dnd5e2014/data/{enums,formula,effects,starting}.ts`。`uses.max` 与效果公式必须通过 `parseFormula`；`effects.kind` 只允许 §6.6 表内种类；`@scale` 引用必须能解析到同包或依赖包的 `scaleValue.id`。

### 4.3 进阶 `advancement`

| 种类 | 用途 | 主要字段 |
|---|---|---|
| `itemGrant` | 到某级获得特性 | `level`、`items[featureId]`、`optional` |
| `itemChoice` | 到某级从一组中选（战斗风格、魔能祈唤） | `level`、`count`、`pool[]` 或 `featureType` |
| `scaleValue` | 随等级变化的数值（偷袭骰、狂暴次数） | `id`、`type`（number / dice / distance）、`scale{ 等级: 值 }` |
| `trait` | 熟练项、语言、抗性 | `level`、`grants[]`、`choices[{ count, pool[] }]` |
| `abilityScoreImprovement` | 属性值提升或专长 | `level`、`points`、`fixed?` |
| `subclass` | 选择子职业 | `level` |
| `size` | 种族体型 | `sizes[]` |

### 4.4 正文与标记

`text: Block[]`

| 块 | 形状 |
|---|---|
| 段落 | `{ p: string }` |
| 小节 | `{ h: string, body: Block[] }` |
| 列表 | `{ list: string[] }` |
| 表格 | `{ table: { caption?, cols: string[], rows: string[][] } }` |
| 引文 | `{ quote: string, by? }` |
| 朗读 | `{ read: Block[] }`：朗读给玩家的文字（来自 `insetReadaloud`） |

行内标记写成 `{{种类:参数|显示文字}}`；界面渲染成可点的骰子、链接或强调；渲染器同时输出纯文本，供摘要与 AI 使用。

| 标记 | 例子 | 来自 5etools |
|---|---|---|
| `roll` | `{{roll:8d6|8d6}}` | `@dice` `@damage` `@d20` `@scaledice` `@scaledamage` |
| `hit` | `{{hit:+5}}` | `@hit` |
| `dc` | `{{dc:15}}` | `@dc` |
| `ref` | `{{ref:spell.fireball.phb|火球术}}` | `@spell` `@creature` `@item` `@class` `@feat` `@race` `@background` `@condition` 等 |
| `atk` | `{{atk:mw|近战武器攻击}}` | `@atk` |
| `em` | `{{em:斜体文字}}` | `@i` `@b` `@note` |

- 标签对照表放在 `tools/data/markup/tags.ts`；遇到表中没有的标签，构建失败。
- 引用对象不在本包及其 `requires` 的包中时，写成纯文字，并计入构建报告的"软引用"。

### 4.5 限制 `requires`

`requires: { all?: Req[], any?: Req[] }`

| Req | 例子 |
|---|---|
| `{ ability: { str: 13 } }` | 力量 13 |
| `{ level: 4 }` | 4 级 |
| `{ race: [id] }` / `{ class: [id] }` | 种族或职业 |
| `{ proficiency: { armor: 'heavy' } }` | 重甲熟练 |
| `{ spellcasting: true }` | 能施放至少一个法术 |
| `{ feature: id }` | 拥有某特性 |
| `{ text: '…' }` | 解析不了的原文，只显示，不判定 |

- 用到 `requires` 的地方：专长前置、可选特性前置、兼职门槛（职业 `multiclass.requires`）、物品同调对象、子职业等级。
- 法术职业表、技能可选范围、属性提升等级不放在 `requires` 里，分别在 `spell.classes`、`class.proficiencies.skills`、`advancement` 中，由官方锁直接读取。

### 4.6 行动 `activities`

| 种类 | 字段 |
|---|---|
| `attack` | `kind`（mw / rw / ms / rs）、`bonus?` 或 `ability?`、`damage[{ dice, type }]` |
| `save` | `ability`、`dc`（数值或 `'spell'`）、`onSave`（half / none / 文本）、`damage[]?`、`condition?` |
| `damage` | `parts[{ dice, type }]` |
| `heal` | `formula` |
| `check` | `ability`、`skill?`、`dc?` |
| `cast` | `spell`（spellId）、`level?` |
| `utility` | 文本 |

每个行动都有 `{ id, name, activation{ type: action / bonus / reaction / minute / hour / special, cost? }, range?, target?{ area?{ shape, size } }, uses? }`。从正文识别不出结构时，只保留文本，并计入构建报告。

### 4.7 随机表与功能贡献

**随机表**是条目类型 `table`（§4.2），不是功能贡献：
- 来源：5etools `tables.json`、条目正文与背景中能掷骰的表（第一列为骰子范围），如 DMG 宝藏表、XGE 饰品与停工期表、背景的个性、理想、牵绊、缺点表。
- 没有骰子列的参照表（如按等级的熟练加值表）保留为所在条目正文中的表格。
- 每行的范围必须恰好覆盖骰子的全部结果，否则构建失败。
- 结果中的「再掷一次某表」写成 `then`；结果中的条目写进 `refs`。

**法术位表 `slotsByLevel`**：职业（或三分之一施法者的子职业）的每个职业等级的法术位，供规则引擎读取：全 / 半 / 三分之一施法者为 `[{ level, slots: [第 1 环…第 9 环的数量] }]`；契约施法者为 `[{ level, pact: { count, level } }]`。构建时从职业表中的"每环法术位""法术位数量""法术位环阶"列转成数字；列缺失、数字不是整数、或与 `progression` 不一致时构建失败。职业表的原文列保留。单职业施法者的法术位始终读这张表；多职业合并使用的施法表不进内容包，属于规则引擎（R1 §2.5）。

### 4.8 全量导入（D1.2）

收录范围、来源、字段与工作包见 `docs/handoff/D1.2_全量结构化导入_交接.md`，要点：

- 收录 5etools 中出版早于 2024-09-17 的全部官方书与冒险；书目分档在 `tools/data/config/books.ts`。
- 每个来源字段在 `tools/data/config/fieldCoverage.ts` 登记为 `mapped`、`text` 或 `dropped`，未登记即构建失败。
- 新增条目类型：`language`、`deity`、`reward`、`cult`、`hazard`、`object`、`vehicle`、`location`、`book`。
- 通用字段：`lore`、`supersededBy`、`versionGroup`、`playable`、`nameSuffix`、`tags`。
- 条目信封增加 `i18n.en`：`{ name, summary?, fields: { <data 内的字段路径>: 字符串或正文块数组 } }`，英文原文来自 5etools 英文原版数据。
- 库里的 `location` 条目是地点模板；冒险包里的地点是 L1 §2.3 的 `location` 冒险内容项，由 U8 在此基础上增加底图、点位、区块等游玩字段。
- 包的层级与引用方向：核心书层级 `SRD < PHB < SCAG < DMG < MM < XGE < TCE < VGM < MTF < MPMM < BMT`；条目只能引用本包与更低层包里的条目，`requires` 只指向更低层的包；展开物品放进模板与基础物品所在包中层级更高者；家族条目放进来源组与全部成员所在包中层级最高者；成员不存指向家族的字段。唯一允许的向上引用是升级操作中带 `optional: 'tce-ocf'` 的特性授予（目标未安装时忽略）。
- 描述文字不是 SRD 内容：内嵌在非 SRD 包的条目里；目标在 SRD 包时，用隐藏类型 `lore` 的补丁条目放进来源书的包，`data.target` 指向 SRD 条目（引用向下）。`_copy` 衍生的记录不继承 `srd` 标记。
- `dataVersion` 为 3。
- 字段覆盖矩阵（5,896 条路径）里没有 `lost`：每条来源字段都是 `mapped`（2,900）、`text`（1,308）或 `dropped`（1,688，带 `kind` 与具体理由）；`assertFieldCoverage` 对 `lost` 与未登记路径都让构建失败。
- 分类标签放进共有可选字段 `facets: Record<string, string[]>`（值保持来源代码，如怪物的 `sense`、`language`、`trait`、`action`、`spellcasting`、`saveForced`、`conditionInflict`、`damageSpell`；物品的 `misc`、`reqAttune`、`poison`、`scf`）；其余标量与短文本放进共有可选字段 `extra.<来源字段名>`。`data.tags` 不动。
- 顶层新增键只有：怪物 `attachedItems`（物品条目 id）、`effects`（Foundry 效果的说明）；物品 `attachedSpells`（`ability`、`will`、`daily`、`charges`、`limited`、`other`，法术写条目 id，升环写成 `id#环数`）、`abilityGrant`、`optionalFeatures`、`tier`、`wondrous`；法术 `abilityCheck`；规则 `seeAlso`。基础物品、物品的 `additionalEntries` 追加进 `text`。
- 怪物与传奇动作组里的模板元数据（`monster-template`、`legendary-group-template` 等）不输出，展开后的结果已体现在条目里；这类 `dropped` 理由写在 `docs/probes/D1.2a_R15_lost分诊.json`。
- TCE 的可选变体特性（牧师 8 级「受祝击」14 份、战斗大师「战技选项」、驯兽师「原初伴侣」）在子职业里是 `optional: 'tce-ocf'` 的授予，并用 `replaces` 写明取代哪个特性；构建的软引用（可选的向上引用）共 42 个；塔莎包声明依赖 PHB、SCAG、DMG、XGE。
- 别的书给子职业加的选项（如剑湾给图腾武者加麋鹿、猛虎）：特性放在来源书的包里，`owner` 指向子职业（向下），并带 `joinsChoice: { id, level }`「报名」加入该子职业某等级的选择名单；子职业自己的名单不改。界面生成名单 = 子职业列出的 + 已安装的包里报名的。带该字段的特性不算孤儿特性。
- 卸载确认窗（`uninstallImpact`）列出已安装的、依赖该包的包，只提示不拦截。
- 体检（`tools/data/validate/health.ts`）里目标为 0 的指标（D1、D2、D4、D5、D6、D7、A5、B2b 等）非 0 即构建失败。
- 怪物制作部件正文里的 `<$short_name$>`、`<$dc__dex$>` 等占位符是有意保留的（构建时逐个校验已登记）；界面在显示时换成「该生物」「DC（8＋熟练加值＋敏捷调整值）」等文字（`src/ui/library/tokens.ts`），数据不改。
- 已知的来源与规则瑕疵清单见 `docs/probes/D1.2a_R15_抽检.md` §2：`uses` 被文字规则误判（21 条弱匹配里 13 条不对）、学者套组羊皮纸数量等。

## 5. 冒险内容项通用外壳

`src/schemas/adventure/` 提供 L1 §2.3 冒险内容项的通用外壳，`schemaVersion` 1：

`{ kind, id, name, description: Block[], dmSecret: Block[], keywords[], src?, credit?, data }`

- `kind`：L1 §2.3 列出的类型。
- `data`：各类型自己的字段，由所属单元（U6 人物、U8 地点、U9 派系、任务、遭遇、事件、文档）在其单元蓝图中定义；本单元只要求它是对象，并原样保存与往返。
- `description` 是玩家可知的内容，进入 AI 事实层；`dmSecret` 属于第四面墙层。

## 6. 构建管线

```
tools/data/
  build.ts            入口：node tools/data/build.ts [--pack <id>] [--update-snapshot]
  publish.ts          生成数据仓库目录与 catalog.json（推送由驾驶员授权后执行）
  config/books.ts     书目白名单、书名与 id、分包、分组、推荐档位、版本号
  config/ruleOptions.ts
  snapshot.json       输入快照
  published.json      已发布版本与内容哈希
  extract/  expand/  convert/  markup/  summary/  validate/  pack/  report/
```

1. **抽取**：按类型读取 5etools-cn，只保留白名单内的书；遇到未知来源，构建失败。
2. **展开**：处理 `_copy` / `_mod` 继承；把魔法变体展开成具体物品；把职业与子职业特性展开为 `feature` 条目。
3. **转换**：每种类型一个转换器，产出 §4 的结构；生成 `advancement`、`activities`、`requires`。
4. **标记**：按 §4.4 对照表改写标签；遇到未知标签，构建失败。
5. **兜底**：缺中文的字段从 dnd-data 补，并写入 `credit.missing`。
6. **来源与摘要**：生成 `src`、`credit`、`summary`、`id`、`keywords`、`unique`。
7. **分包**：带 `srd` 标记的进入 SRD 包，其余按书分包；计算 `requires` 与 `contributes`。
8. **校验**：§7。
9. **打包**：生成确定性的 `.trpgpack`：
    - 文件与键按固定顺序排列；
    - zip 中文件时间固定为 1980-01-01，压缩级别固定。
10. **版本检查**：对照 `published.json`。内容哈希变了而版本号没变时，构建失败；版本号变了而内容没变时，给出警告。
11. **报告**：§9。

## 7. 校验（任何一条不过，构建就失败）

- 每个条目通过运行时的 zod 定义；`id` 符合规则且唯一。
- 每个条目都有 `src` 与 `credit`；`credit.license` 与 `credit.by` 相符。
- `requires` 中的包都存在；包内引用都能在本包或 `requires` 的包中解析。
- 所有骰式都能被扩展自己的掷骰解析器识别。
- 随机表的范围恰好覆盖骰子结果。
- `summary` ≤ 80 字。
- 包内只有 L1 §2.2 允许的文件；体积在 §3.4 上限内。
- **确定性**：连续构建两次，所有包的 sha256 相同。
- **真实安装**：用扩展的安装器把全部包装进测试数据库（fake-indexeddb），读回的条数与校验值一致；随机抽 200 个引用，经 `resolveRef` 解析成功。

## 8. 每种数据的往返验证

`tests/fixtures/packs/` 中放两个由测试代码生成的小包（内容为测试用的假数据）：
- `fixture-data`：每种条目类型至少 1 条、1 张带「再掷一次」的随机表、1 个修改版、1 个规则选项、1 个 AI 基调、1 个本版本不认识的功能种类、1 张图片。
- `fixture-adventure`：1 个冒险，含 L1 §2.3 每种冒险内容项各 1 个（只有通用外壳与少量 `data`），项之间互相引用，并引用 `fixture-data` 的条目。

每种数据都走一遍「导入 → 读取 → 使用 → 导出 → 再导入」，结果必须与原样一致：

| 数据 | 导入 | 使用 | 导出 |
|---|---|---|---|
| 各类型条目 | 装入后按 `[ruleId+type]` 查得到，字段完整 | 生成副本（U2 §3.18）；副本进存档快照 | 导出为包后再装，逐字节一致 |
| 随机表 | 同上；范围校验通过 | 读出 `rows` 与 `then` 引用，能找到被引用的表 | 同上 |
| 修改版 | 作为带 `override` 的条目装入 | 能按 `target` 找到原条目 | 同上 |
| 规则选项、AI 基调 | 功能定义装入 | 能按包读出定义与默认值 | 同上 |
| 不认识的功能种类 | 照常装入，标记为暂不支持 | 不运行 | 原样写回 |
| 图片 | 写入图片仓库，按哈希去重 | 按 `$asset` 读出相同字节 | 同上 |
| 冒险内容项 | 装入包 | 读出每一项，项之间的引用与对数据包条目的引用都能找到 | 同上 |
| 存档 | — | 生成副本后保存 | `.trpgsave` 导出再导入，快照与图片一致 |

官方包也按同样方式验证：全部装入测试数据库，每个包导出后再装，校验值一致；每种类型抽 20 条生成副本，存档往返一致。

L1 §3.1 的引用解析、§3.15 的修改版选择、随机表的掷骰在 M3 及以后实现，不在本单元验证。
