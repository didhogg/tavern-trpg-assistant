## 1. 总规则

以下规则优先于人物模块框架 §1 与开发规范 §5.4 的同名条目；没写到的照它们。

### 1.1 两层写入：当场状态即点即写，设定类先进草稿

| 层 | 内容 | 怎么写 |
|---|---|---|
| **当场状态** | 当前生命、临时生命、死亡豁免、生命骰已用、灵感、力竭、法术位已用、资源已用、效果（增删） | 点一下就写进当前数据（等同 U5 §1 第 3 条「游戏中的即时操作」）。不进草稿，不计入「未保存」 |
| **设定类** | 其余全部：名字、英文名、阵营、头像、种族、亚种族、背景、属性基础值与其他、豁免与技能熟练、各项覆盖与「其他」、档案区各列表、移动方式、生命上限的手填值 | 进编辑草稿；点「保存」才写进当前数据；直接离开 = 丢弃草稿，**不弹任何框**（框架 §1.1） |

- 生命的 ✎ 编辑里，当前与临时是当场状态（即时写），上限是设定类（进草稿）。界面上上限框旁不加标记，顶栏「未保存」计数 +1。
- 当前数据与存档是两层（U5 §1 第 1 条不变）：点「保存」只写进当前数据；页头「保存存档」另一回事。
- 战役只读时（`campaign.readOnly`），所有输入禁用，保存禁用。
- 「未保存 N」的 N = 草稿里改过的**顶层字段个数**（同一字段改多次只算一个）。

### 1.2 撤销：整页只有一个

- 顶栏「撤销」（图标 + 文字）和 Ctrl / Cmd + Z；**不在任何别处放撤销图标**（驾驶员 2026-11-03）。
- 一个撤销栈，最多 50 步，覆盖这张卡里的全部操作（当场状态与设定类）。撤销当场状态 = 把旧值写回；撤销设定类 = 回到上一个草稿快照。
- 什么算一步：一次输入框提交（失焦或回车）；一次点击改动；一次「全部自动计算」；一次「写入基础」。输入框里连续打字只在提交时算一步。
- 栈空时按钮禁用。点「保存」后清空撤销栈；离开这张卡时清空。
- 当场状态没有提示条（改动就在眼前）；撤销也不弹提示。

### 1.3 手填与自动：清空回自动，一个按钮全部回自动

- 能手改的数字都是输入框：失焦或回车提交，Esc 还原，点击全选，↑↓ 加减 1，不响应滚轮，中文输入法组合期间不提交（开发规范 §5.4 沿用）。
- **清空输入框 = 回到自动算出来的值。**
- **不显示灰字「自动 N」，不显示「覆」「已改」之类的标记**（取代 §5.4 里「清空时框内用灰字显示自动值」一句；驾驶员 2026-11-03）。
- 三处完整视图（属性抽屉、读数抽屉、技能抽屉）各有两个按钮：
  - **[覆盖]**：切换「覆盖视图」。最终值那一列变成输入框，直接填你要的最终值；再点一次退出。
  - **[全部自动计算]**：清空本抽屉里所有「其他（手动）」和覆盖值，全部回到算出来的值。不动属性基础值，不动熟练勾选 / 图标。
- 上游数据变化时，已手填的值不变，也不提示（§5.4 沿用）。
- 范围钳制在失焦时做，超出范围的输入在输入框下方显示一行红字，**不静默改成别的数**。范围见 §5.1 字段表。

### 1.4 来源与自动分配（本任务只定数据和显示，分配动作在 UNIT4）

- 熟练项（技能、豁免、语言、武器、护甲、工具）每条带 `sources`：这个条目**从哪里来**。来源有三种：`manual`（手动添加）、`auto`（自动分配，附条目编号，如种族「精灵」）、`template`（模板原样带来）。同一项有多个来源时都记。
- **自动分配是一个动作，不是实时推算**（驾驶员 2026-11-03）：UNIT4 里种族 / 背景 / 职业 / 专长的选择页各有 [自动分配熟练项目]，可以按条目分别点，也可以一次全部点；条目里是「选 N 项」的，让用户从该条目允许的范围里自己选；点完后，条目带着来源出现在对应的熟练项、技能、语言里。**本任务不做这个按钮，不做任何自动分配**。
- 界面上**不加来源缩写标签**（`[族][景]` 之类，框架 §1.4）。想知道来源，点那个药丸，弹出来源弹层（抽屉文件 §5.9）：写明「自动分配 / 手动 / 模板」和具体来源名称（可点开资料卡）。
- 同一项只出现一次；熟练取最高、不叠加（框架 §1.5）。技能写入时已有的等级取较高者，来源合并。
- 属性加成不走自动分配：种族的固定加成由派生函数**直接读取已选的种族与亚种族**，显示在属性计算表的「种族 / 背景」列（只读）。「自选 +1」那类要选的部分在 UNIT4。

### 1.5 图标：只有这几个，各管一件事

| 图标（Phosphor Regular，单色线条） | 意思 | 放哪里 |
|---|---|---|
| 骰子 `dice-five` | 这个数字点了去骰盘 | 属性栏图例、先攻格、技能 / 行动的列标题与数字格；**图例里的两个骰子图标一模一样**，和文字同样大 |
| 铅笔 `pencil-simple` | 写入、修改数值 | 栏目标题行右端；生命数字旁（原地编辑） |
| 齿轮 `gear` | 这个列表怎么显示（排序、筛选） | 目前只有「技能抽屉」。没有显示选项的栏目不放 |
| 问号 `question` | 这里怎么操作 | 顶栏（整页图例）、属性栏、读数格、技能栏。**点圆点、点星、点圆圈就能操作的栏目不放** |
| 加号 `plus` | 往列表里加一项 | 档案区药丸、效果行、行动标题行 |
| 叉 `x` | 移除一项 | 药丸、效果 |
| 星 `star` / `star-fill` | 灵感：没有 / 有 | 基本信息卡 |
| 月亮 `moon` | 休息（占位按钮） | 生命区右上 |

- 一个界面只用这一套图标（开发规范 §5.1），不出现彩色或表情符号。现有 `src/ui/kit/icons.ts` 已有 `dice-five`、`pencil-simple`、`gear`、`plus`、`x`、`caret-*`、`arrow-counter-clockwise`、`upload-simple`、`check`、`trash`；本任务要补进的只有 `question`、`star`、`star-fill`、`moon`、`minus`，同一套（Phosphor Regular）、同一画法。
- 点圆点、点星、点圆圈、点圆这类「点一点就行」的**直接点，不放 ✎ ⚙ ？**，旁边只写一行 12px 说明（例如「点圆点：实心 = 还有，空心 = 已用」）。
- 图标按钮有可读名称；触屏点击区域 ≥44px；键盘能到达；不靠悬停才出现。

### 1.6 数字的三种外观

| 外观 | 含义 | 样子（细节见视觉规格） |
|---|---|---|
| 可掷 | 点了交给骰盘 | 圆角描边方框按钮，按下缩到 0.97 |
| 可改 | 输入框 | 下划线 / 描边输入框，聚焦时 `--primary` 焦点环 |
| 只读 | 算出来、只看 | 纯文字，无边框 |

同一个数字在「玩」的地方是可掷的方框，在「改」的地方（抽屉里的计算表）是输入框；**不在同一个位置做两件事**。

### 1.7 掷骰：详情页只交给骰盘

- 所有带骰子的数字点一下，只做一件事：**把「谁、哪一项、加值多少」交给骰盘**，由骰盘去选难度、优势 / 劣势、备注并掷骰。**详情页里没有结果条、没有掷法开关、没有算式小窗、不用灵感**（这些归掷骰 UNIT；驾驶员 2026-11-03）。
- 交出去的内容：

| 字段 | 例子 |
|---|---|
| 对象 | 盖尔 |
| 类型 | `check`（属性检定）/ `save`（豁免）/ `skill`（技能）/ `initiative`（先攻）/ `attack`（命中）/ `damage`（伤害） |
| 项目 | 洞悉检定、敏捷豁免、先攻、弯刀命中 |
| 加值或骰式 | `+6`；伤害给骰式 `1d6+2` |

- 可掷的数字：六属性的检定与豁免、先攻、技能（主界面和技能抽屉）、行动的命中与伤害。
- **新增入口** `useDiceStore().prefill(payload)`：打开骰盘悬浮窗，骰式写成 `1d20+6`（负数 `1d20-1`；伤害写它的骰式），说明写成「盖尔 洞悉检定」，**不自动掷**。骰盘的最近记录、读取与保存逻辑一律不动。
- 掷骰 UNIT 做好之后，同一个入口升级为「打开骰盘的对应标签页并填好对象、项目、加值」，详情页不需要改。
- 骰盘是独立悬浮窗，不受弹窗遮罩影响（开发规范 §5.3）；抽屉打开时点抽屉里的可掷数字，骰盘照常打开。

### 1.8 抽屉与弹层

- 抽屉就是 `ModalHost` 的 `drawer` 变体（右侧滑出，页面栈）；弹层是下拉、小弹出层。同一时间最多一个模态（抽屉 / 弹窗）；抽屉里前进一页 = 入栈，左上「‹」返回；✕、Esc、遮罩关闭，焦点回到触发处（开发规范 §5.3，不叠加）。
- **本任务的抽屉都是单页，没有标签页**：身份、属性、读数、技能。多个内容放在同一页里按区块排，不做浏览器式标签（驾驶员 2026-11-03：生成、编辑覆盖、豁免要么同一个页面里做好）。
- 抽屉宽度：`ModalPage` 增加可选 `width`（默认 440，保持现有存档抽屉不变）；属性与读数抽屉 680，技能 560（两列技能），身份 480；窗口比它窄时 `min(width, 100%)`；≤480 铺满，底部上拉（视觉规格）。
- 抽屉里的改动**即时进草稿**（设定类）或即时写入（当场状态），实时反映在概览带；**抽屉没有「确定」这一步，也不设「完成」按钮**，关闭就是 ✕ / Esc / 遮罩（原地编辑生命的「完成」是另一回事）。含设定类内容的抽屉底部一行 12px 小字：「改动进入草稿，点右上「保存」后生效」。
- 抽屉里的页面也带入栈规则：头像截取页、药丸来源弹层的「资料卡」都在同一个抽屉 / 弹窗里前进，不叠加。

所有「＋ 自定义…」「＋ 添加」（自制条目）按钮先留在那里，**不画自定义面板**，点了弹出 6 秒自动消失的提示条：「这个面板之后再做。」之后逐个敲定面板规格。清单：

| 位置 | 按钮 |
|---|---|
| 行动栏标题行 | ＋ 添加 |
| 添加效果弹层 | ＋ 自定义… |
| 语言、武器、工具、其他防御弹窗 | ＋ 自定义… |

### 1.10 文案规则

- 界面文案是玩家语言；不出现开发术语、制作说明（「面板之后做」之类只出现在 §1.9 与 §4.2.4 的占位提示条里）。
- **删掉所有「（变体规则，需 DM 同意）」「（需 DM 许可）」这类括号说明**（驾驶员 2026-11-03）。购点就叫「购点」，不加注释；秘密语言就叫「盗贼黑话」「德鲁伊语」，不加注释。想调整的人自己去身份抽屉。
- 技能、语言、工具、伤害类型、状态的中文名一律用 `enums.ts` 里的名字（杂技、驯兽、奥秘、运动、欺瞒、历史、洞悉、威吓、调查、医药、自然、察觉、表演、游说、宗教、巧手、隐匿、求生；伤害类型「寒冷」「暗蚀」…），不另起名。
- 未知数据留空，不写「未填写」「无」「—」以外的字样（开发规范 §5.4）。「—」只用在计算表里「这一列没有值」。

### 2.2 断点

| 宽度（窗口内部宽度，开发规范 §5.2） | 布局 |
|---|---|

### 2.3 滚动与迷你条

- 页面（含概览带）整体随内容滚动；A 卡滚出视口后，顶栏中部淡入名字（透明 0→1，位移 4→0，160ms；`prefers-reduced-motion` 时直接显示）。
- 同时在顶栏下面粘一行**迷你条**：「盖尔　12/18　AC 12　▾」；点它平滑回到 A 卡。迷你条只显示名字、当前 / 上限、AC，不放任何操作。
- 分页标签 E 滚到顶栏下方时也粘住（在迷你条下面）。
- 切分页保留各页滚动位置、内部展开、输入焦点。

### 2.4 分页

五个分页：**行动与技能**（默认）、职业与特性、背包、法术、背景故事；名称与顺序固定，一行放下，窄屏可横向滑动并自动把当前项滚入视野。

- UNIT2：五个分页全部显示「本分页尚未开放」占位（`EmptyState`：说明一句，无按钮）。
- UNIT3：「行动与技能」开放；其余四个仍是占位。

### 2.5 进入与返回

- 入口不变：`openPersonCard({ id })`（点列表行）、`openPersonCard({ draft, from? })`（＋ 新建 / 编辑后加入）。整页替换 `PersonCardStub`，调用方不改。
- 顶栏「‹ 人物」回列表，列表的滚动、搜索、筛选、排序、所在分类保持不变（U6 §3.3）。窄屏是整页，宽屏在人物页内替换列表。
- 空白新建：进卡即草稿；名字为空时「保存」禁用；保存后写进列表并 `touch`。从模板「编辑后加入」同理。
- **库模式**（U6 §5.3）：同一张卡，顶栏文字改为「‹ 我的资料　库里的「某某」」，「保存」按钮改为「保存到库」。其余不变。
- **套用模板**：A 卡里名字下的「套用模板」打开 U6 §7 的模板弹窗（套用模式）；套用 = 用所选怪物 / 具名 NPC 的属性块替换当前人物的 `block`（草稿，点保存才生效）。
- 动效：列表 → 详情 160ms 淡入并向右移 8px，返回反向（U5 §2.5）。

### 2.6 键盘与无障碍

- 所有操作可用键盘完成，焦点环可见；抽屉、弹层打开时焦点进入，关闭后回到触发处。
- 可掷数字读作「力量检定 负 1」「豁免 正 2，有熟练」；图标按钮有可读名称（「编辑生命」「添加语言」…）。
- 状态不只靠颜色：熟练用图标形状（○ ◐ ● ◆）、死亡豁免用「成功」「失败」文字、灵感用实心 / 空心星、未保存用文字加圆点。
- 数字使用 `tabular-nums`；输入框 `inputmode="numeric"`。
- `aria-live="polite"`：死亡豁免与生命的数值变化。

#### 4.2.1 头像

- **点头像 = 直接选图、自动截取、上传**，不进入截取窗口（驾驶员 2026-11-03）：点击 → 系统文件选择 → 选好后自动截取并保存进草稿，头像框立刻换成新图。取消选择什么都不发生。
- 已有头像时再点头像：同样是选新图并替换。**清除、重新截取只在身份抽屉里**（抽屉文件 §5.2、§5.3）。
- 自动截取规则（纯函数 `autoCropAvatar(width, height)`，带单测）：
  - 截取框比例固定 4:5（与头像框 72×90、96×120 一致）。
  - 取原图里能放下的**最大**框；水平居中；垂直位置 = 溢出高度的 20%（与 `AvatarFrame` 默认 `50% 20%` 一致，通常能留住头部）。
  - 原图正好 4:5 时整张使用；宽图（比 4:5 更宽）高度取满、水平居中；窄长图宽度取满、垂直取上 20% 处。
- 保存的内容：截取后的图（输出 320×400，原图更小时按原尺寸）作为 `avatar`；**原图与截取框另存**（`avatarSource`，§5.2），身份抽屉里「重新截取」靠它。两张图都进图片仓库（按内容哈希，L1 §4）。
- 图片限制遵守 L1 §2.2（类型与大小）；不合规时在头像框下方显示一行红字原因，不改变现有头像。
- 没有头像：显示生物类型图标（`AvatarFrame` 现有规则，U6 视觉规格 §2.3 与 decisions 2026-11-02：有立绘用立绘；只有 token 或都没有显示生物类型图标）。
- 等级角标：人物有职业（`block.classes` 非空）时显示总等级；模板怪物没有职业时不显示，改显示原来的生物类型徽章。

#### 4.2.2 名字与身份

- 名字：衬线大字；后接英文名（`nameEn`，灰字，基线对齐）。**点名字 = 打开身份抽屉**（抽屉文件 §5.2），名字在抽屉里改，A 卡上不直接出现名字输入框（一个数据只有一个编辑处）。
- 身份行：「法师 3 级 · 人类 · 塑能学派」；多职业「战士 3 级 · 法师 2 级 · 人类」；来自模板的「地精 · 挑战 1/4」（同 U6 视觉规格 §2.3）。
- 身份行里的各项是**文字按钮**（悬停 `--panel` 底）：
  - 职业、等级、子职业 → 跳到「职业与特性」分页（UNIT4 前显示占位页）；
  - 种族、亚种族 → 打开身份抽屉并滚到种族。
- 没有职业的人物（空白新建、怪物模板）不显示职业与等级；UNIT4 开放后空白人物出现虚线「选职业 ›」。种族没选时显示虚线「选种族 ›」（点开身份抽屉）。

#### 4.2.3 灵感、套用模板、升级、降级

- **灵感**：星形开关（`star` 没有 / `star-fill` 有），旁边文字「灵感」；点一下切换，写 `inspiration`（当场状态）。只有「有 / 没有」，不能累积（《玩家手册》p125）。无障碍：`aria-pressed`，读作「灵感：有」。
- **套用模板**：次按钮，打开模板弹窗（§2.5）。只读战役时隐藏。
- **[升级] [降级]**：人物（没有挑战等级 `cr`）时显示，两个次按钮并排，占位：点了提示条「升级、降级面板之后再做。现在请直接改生命、属性。」（6 秒自动消失）。模板怪物不显示。升级降级的规则留给 UNIT4（《玩家手册》p163：升级所需经验取总等级；只有 1 级才拿首级生命值，之后每升一级加所升职业的生命值；熟练加值取总等级）。

#### 4.2.4 生命

```
 平时：
   生命                                   [✎]  [休息]
   12 / 18          临时 3
   ████████░░░░░░
   死亡豁免  成功 ○○○   失败 ○○○
   生命骰 d6 ●●○

 点 ✎ 之后（同一位置，数字变成输入框）：
   生命                                   [完成]
   +---------+    +---------+    +---------+
   | 当前 12  |    | 上限 18  |    | 临时 3  |
   +---------+    +---------+    +---------+
   [自动计算]      上限 = 1 级 6 + 体质 +1；2、3 级各 平均 4 + 体质 +1 = 18
```

- 平时显示：当前 / 上限（衬线大字）、临时（金色小标签，为 0 时不显示）、红色血条（临时生命接在红色后面一段金色）。**没有伤害、治疗、临时三个按钮**。0 生命不做任何特殊显示（decisions 2026-11-02）。
- **✎ 原地编辑**：当前、上限、临时三个数字变成方框输入框，同位置不换页。回车提交并退出编辑；失焦也提交并退出；Esc 还原；「完成」按钮同回车。
  - 当前、临时即时写入（当场状态）；上限进草稿（设定类）。
  - 当前超过上限时，提交时自动压到上限（《玩家手册》p197）；负数按 0。临时生命没有上限，不并入血条上限（p198）；临时生命怎么处理「获得新的临时生命时保留还是换新」（p198），玩家直接改这个数字即可，不弹窗。
  - 上限框清空 = 回到自动算出来的上限；「自动计算」按钮清空上限的手填值。
  - 上限下面一行 12px 写明自动算法（见 §6.7）。数据缺失（没有职业且模板无生命）时整栏留空，不当 0。
- **死亡豁免**：固定显示在生命旁，随时可点，不与生命联动（decisions 2026-11-02）。文字写全「成功」「失败」，各三个圆圈。点第 N 个圆圈把该组设为 N；点当前最高的已填圆圈清空该组（`deathSaves`，当场状态）。无障碍名称「死亡豁免成功 2 次」。规则只写在页面「？」里，不联动：d20 ≥ 10 成功、掷 1 算两次失败、掷 20 恢复 1 点生命；三次成功稳定、三次失败死亡；0 生命时受伤记一次失败（重击两次）；溢出伤害 ≥ 上限即死亡（p197）。
- **生命骰**：每个骰型一行「生命骰 d6 ●●○」（多职业分行），实心 = 还有，空心 = 已用。点第 n 个圆：若它是实心，剩余变 n−1；若是空心，剩余变 n（`hitDiceUsed`，当场状态）。总数 = 该骰型各职业等级之和（p163）。没有职业的模板怪物按 `hp.formula` 里的骰数、骰面读（如 `2d6+0` → d6 两颗）；读不出就整行不显示。
- **休息**：占位按钮（`moon` 图标 + 文字「休息」）。点了提示条「短休、长休在之后的「活动」里做。现在请直接改生命、生命骰、法术位。」不做清单、不回血、不重置资源。

#### 4.2.5 读数

| 格 | 显示 | 下面一行小字 | 怎么来 |
|---|---|---|---|

## 5. 数据

**原则**（人物模块框架 §5）：所有人共用怪物属性块这一个结构；新增字段全部**可选**；怪物填怪物的、人物填人物的；来源给的东西不存（属性的种族加成、等级、装备由派生函数读取），只存「你选了什么、你手填了什么」（`docs/模块数据约定.md` §6）。

每个结果带明细（R1 §1 第 2 条的 `sources` 思路）：计算表直接显示它，不在界面里再算一遍。

### 6.1 属性（每项属性）

`最终 = clamp(基础 + 种族/背景 + 成长/专长 + 装备/魔法物品 + 其他, 上限)`，然后：

1. `装备/魔法物品` 列 = 已装备（及同调）物品效果里的 `abilityBonus`（加）与 `abilitySet`（设为固定值：最终取 `max(计算值, 固定值)`，列里显示「设为 20」）。**数据里只有 2 件魔法物品（维克那魔掌）有 `abilitySet`，其余魔法物品的属性效果只有文字**（`docs/模块数据约定.md` §13），所以这一列目前几乎为空；其余靠「其他」手填。
2. `种族/背景` 列 = 所选种族与亚种族的 `abilityBonus.fixed` 相加；`choose`（如半精灵的「选 2 项各 +1」）归 UNIT4，此前不计入。2014 的背景没有属性加成字段，所以实际只有种族与亚种族在给值。变体人类等数据缺口（登记 a12-abilities）先靠「其他」填。
3. 上限默认 20；效果 `abilityBonus.max` 给更高上限的按效果（野蛮人 20 级原初斗士等由 UNIT4 写）。超过上限时最终显示上限值，下面小字「上限 20」。
4. `overrides.abilities[键]` 有值时，最终 = 该值（覆盖视图）。
5. 调整值 = ⌊(最终 − 10) ÷ 2⌋（p7 向下取整、p13 对照表）。

### 6.2 总等级与熟练加值

- 总等级 = 各职业等级之和，上限 20。
- 熟练加值 = 2 + ⌊(总等级 − 1) ÷ 4⌋，**取总等级，不是某个职业的等级**（p163）。模板怪物按挑战等级（R1 §2.1 表）；两者都没有时为 `null`。
- `adjust.proficiency`、`overrides.proficiency` 同样适用。

### 6.3 豁免

`豁免 = 属性调整值 + (有熟练 ? 熟练加值 : 0) + 其他`；熟练来自 `proficiencies.saves`。覆盖值优先。模板怪物 `saves[键]` 有写死值时读作覆盖值（§5.1）。

### 6.4 技能

`技能 = 属性调整值 + 熟练项 + 其他`，其中熟练项：无 0；半熟练 ⌊熟练加值 ÷ 2⌋；熟练 +熟练加值；专精 +2 × 熟练加值。技能与属性的对应用 `enums.ts` 的 `SKILLS`。覆盖值优先；模板的写死值读作覆盖值。「其他」：技能的 `adjust` 不单独存，直接用覆盖视图（技能没有「其他」列，避免两个调整入口）。

### 6.5 先攻与被动

- 先攻 = 敏捷调整值 + 效果里 `initiative.bonus` + `adjust.initiative`（p177：先攻是一次敏捷检定）；覆盖优先。
- 被动 = 10 + 该技能总值 + 效果里 `passive` 加值（如观察者专长 +5）+ `adjust.passive`；覆盖优先。有优势 +5 / 劣势 −5（p175）只在掷骰那一次才有意义，**不写入基础值**，本任务不处理。

### 6.6 AC

- 本任务只算：**没装备时 10 + 敏捷调整值**（p14）+ 效果里 `ac` 的 `bonus` + `adjust.ac`；覆盖优先。
- 模板怪物：`ac[0].value` 就是它的值（书上写死的值照填，填了就用填的）；下面一行依据写 `ac[0].from`。
- **装备护甲、盾牌、无甲防御（蛮人、武僧）、法师护甲等算法由 UNIT5 / UNIT4 接入**，接口留好：`derive` 接受「AC 候选列表」，取最高的可用项（R1 §2.3）。本任务没有候选来源，所以不做 AC 算法下拉。无甲防御的条件在数据里只有文字（`docs/模块数据约定.md` §6），到时由 UNIT4 决定读法。

### 6.7 生命上限与生命骰

- 上限 = `overrides.hpMax`（有则取）；否则有职业时：1 级（首个职业）生命骰最大值 + 体质调整值，之后每级所升职业的平均值（骰面 ÷ 2 + 1）+ 体质调整值，**每级至少 1**；再加效果里 `hpMax` 的 `perLevel × 总等级 + flat`（强健专长每级 +2 能算；矮人坚韧等数据里还是占位 0，见 `docs/模块数据约定.md` §6）。升级时的掷骰记录由 UNIT4 的升级面板写，本任务取平均值。体质调整值变化时按级数补算（p177）。
- 没有职业的模板怪物：取 `block.hp.average`。
- 生命骰：按骰面汇总，总数 = 该骰型各职业等级之和（p163）；已用取 `hitDiceUsed`。
- 说明文字（生命编辑里那一行）由这个函数返回的明细生成。

### 6.8 速度

- 步行基础 = `block.speed.walk`，没有则种族（及亚种族）的 `speed.walk`；其他移动方式（飞、攀、游、掘）读 `block.speed`，各自的基础只在读数抽屉里新增的行中填写。
- 速度的最终值 = 基础 + `adjust.speed[方式]`；覆盖优先。**不自动套用**力竭减半、重甲力量不足 −10、束缚 0、负重变体这些情况（只写说明文字，p291、p144、p292、p176）；快速移动等特性的 `amount` 在数据里还是 0 占位，不读。
- 速度格只显示步行；其他方式作为小字附在后面。

### 6.9 法术位上限（只读显示用）

读职业 `spellcasting.slotsByLevel`（单职业）或多职业表（≥ 2 个施法职业，全施法等级相加 + 半施法 ÷ 2 向下取整 + 三分之一施法 ÷ 3 向下取整），契约位单列（`docs/模块数据约定.md` §3、§6）。没有职业数据时返回 `null`，该行不显示。

### 6.10 单测要求

每个函数一组：用例注明出处页码；用例构造数据，**不写死库里的条目数量**（开发规范 §12.5）。至少覆盖：属性调整值全表；熟练加值 1–20 级与 CR；盖尔样例（法师 3 级、体质 12 → 上限 17；熟练 +2）；专精 / 半熟练 / 熟练 / 无的技能；覆盖优先于计算；上限 20 与 `abilitySet`；兼职总等级取熟练加值（战士 3 / 游荡者 2 → +3）；缺数据返回 `null`；模板怪物写死值读作覆盖。
