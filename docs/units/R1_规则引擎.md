# R1 5e2014 规则引擎 · 单元蓝图

状态：草案（R1.1 待驾驶员定稿；R1.2 在 M6 开工前补全）

## 0. 范围与归属

R1 是 D&D 5e（2014）规则的纯函数实现，分两次交付：

| 交付 | 里程碑 | 内容 |
|---|---|---|
| R1.1 派生数值 | M4 | 属性调整值、熟练加值、豁免与技能、被动值、先攻、AC、生命值上限、生命骰、法术位上限、法术豁免 DC 与攻击加值、生命值变化（伤害、治疗、临时生命值） |
| R1.2 掷骰与结算 | M6 | 掷骰构建、优势劣势来源、命中与重击、伤害倍率、行动结算、状态与专注、短休与长休（本节在 M6 开工前补全） |

R1 没有界面。界面读取它的结果：U6（列表行的 HP 与 AC）、U5（详情顶部与各分页）、U3（掷骰卡，M6）。

**规则通用**：界面不直接引用 5e 的文件，只通过规则注册表的 `RuleSystem.derive` 接口取数；接口的返回值自带标签与顺序，换成别的规则（A7 CoC）时界面不改。

**读取**：人物数据（U6 §2.1）、已启用扩展包中的职业、种族、物品条目（用于生命骰、豁免熟练、施法进度、法术位表、护甲）、本存档已开启的规则选项（`featureState`，§2.8）。**写入**：无；R1 只返回结果，写入由 store action 完成。

## 1. 约定

1. 全部是纯函数：同样的输入永远得到同样的输出，不读时间、不读随机数、不访问存储。
2. 每个结果带来源列表（`sources`），例如 `[{ label: '感知调整值', value: 2 }, { label: '熟练', value: 2 }]`；界面的"展开来源"直接显示它，U3 的"加值来源"同样使用。
3. 覆盖优先：人物数据里手填的覆盖值（`overrides`）优先于计算值；结果同时返回计算值与是否被覆盖，界面标出"手动"。
4. 数据不全不猜：缺职业、缺属性等无法计算时，对应结果为 `null` 并附 `missing` 列表（如 `['职业', '体质']`），界面显示"待填"，不当作 0。
5. 数字显示：整数；除法一律向下取整，规则另有说明时（见 §2.7 半施法者）照规则。
6. 规则不明或需要 DM 裁定的情形不在 R1 内判断，返回 `needsRuling` 标记，由玩家填写。
7. **数据与引擎的分工**：

| 放哪里 | 内容 |
|---|---|
| 内容包（结构化字段） | 职业的生命骰、豁免、施法属性与进度、法术位表；种族的加值、速度、熟练；物品的 AC、伤害、属性；怪物的数值；状态、动作与规则的文字；规则选项的名称、说明、`engine`、`group` |
| 规则引擎代码（常量与算法） | 调整值公式、熟练加值表（等级与 CR）、技能与属性对照、多职业施法表、状态的机械效果（按状态的固定 id）、倒地与死亡豁免、各项结算算法 |
| 存档 | 人物数据；规则选项的开关（`featureState`） |

   规则文字条目（动作、状态、规则说明）只供查阅与交给 AI，本身不改变任何数值；规则引擎读取状态条目的固定 id 套用机械效果，包里自创、引擎不认识的状态只有文字。

## 2. R1.1 函数

### 2.1 属性与熟练

| 函数 | 输入 → 输出 | 规则 |
|---|---|---|
| `abilityModifier(score)` | 属性值 → 调整值 | ⌊(值 − 10) ÷ 2⌋；负数向下取整（9 → −1，8 → −1，7 → −2） |
| `proficiencyBonus({ level })` | 总等级 1–20 → 熟练加值 | 2 + ⌊(等级 − 1) ÷ 4⌋ |
| `proficiencyBonus({ cr })` | 怪物 CR → 熟练加值 | CR 0–4：+2；5–8：+3；9–12：+4；13–16：+5；17–20：+6；21–24：+7；25–28：+8；29–30：+9；分数 CR 按 +2 |
| `totalLevel(classes)` | 职业等级列表 → 总等级 | 各职业等级之和，上限 20 |
| `abilityScoreFinal(base, bonuses, override)` | → 最终属性值与来源 | 基础值 + 各来源加值，上限 20（规则另有说明的来源除外，来源自带 `max` 字段）；有覆盖用覆盖 |

### 2.2 豁免、技能与被动值

| 函数 | 说明 |
|---|---|
| `SKILLS` | 18 项技能与其关联属性（运动→力量，杂技/妙手/隐匿→敏捷，奥秘/历史/调查/自然/宗教→智力，驯兽/洞悉/医药/察觉/求生→感知，欺瞒/威吓/表演/游说→魅力）。这是规则自带的常量表，随规则注册，不是内容包条目 |
| `skillBonus(person, skillKey)` | 调整值 + 熟练等级 × 熟练加值；熟练等级：无 0、半熟练 ⌊½⌋（吟游诗人的万事通等来源）、熟练 1、专精 2；返回 `{ total, sources }` |
| `saveBonus(person, abilityKey)` | 同上，熟练只有无 / 有两档；完整卡的豁免熟练来自第一个职业，兼职不叠加（兼职获得的职业熟练按职业条目的 `multiclass.proficiencies`，豁免熟练不包含在内） |
| `passiveScore(person, skillKey)` | 10 + 技能加值；有优势 +5、劣势 −5（来源给出时） |
| `initiative(person)` | 敏捷调整值 + 来源给出的额外加值 |

### 2.3 AC

`armorClassOptions(person)` 返回候选算法列表，每项 `{ id, label, value, sources, requires, usable, reason }`，默认选中数值最高的可用项，人物数据可保存所选项或手动覆盖。

| 候选 | 计算 |
|---|---|
| 无甲 | 10 + 敏捷调整值 |
| 蛮人无甲防御 | 10 + 敏捷 + 体质（无护甲，可持盾） |
| 武僧无甲防御 | 10 + 敏捷 + 感知（无护甲无盾） |
| 法师护甲 | 13 + 敏捷（来源为法术效果时才列出） |
| 护甲 | 护甲基础 AC + 敏捷（轻甲全额；中甲上限 +2；重甲不加）；力量不足、不熟练时 `usable: false` 并写原因 |
| 盾牌 | 在以上结果上 +2（独立加值，不是候选） |

不叠加多个基础算法（盾牌与魔法加值除外）。属性块（敌人与 NPC）的 AC 直接取数据中的值与说明，不计算。

### 2.4 生命值上限与生命骰

`hitPointMax(person)`：

1. 第一个职业的 1 级：生命骰最大值 + 体质调整值。
2. 之后每个等级：该职业生命骰平均值（骰面 ÷ 2 + 1）+ 体质调整值；人物数据里若记录了"掷骰得到的值"（`hpRolls`），该级用记录值。
3. 每一级至少得到 1 点（体质调整值为负时）。
4. 加上额外来源（如矮人坚韧、强健专长）：每级加值 × 总等级。
5. 有覆盖时用覆盖。

`hitDice(person)`：按骰面汇总 `{ d6: { total, remaining }, d8: … }`；`remaining` 取自人物数据，R1.1 不推进休息。

### 2.5 法术位与施法数值

- `casterLevel(classes)`：只在有多个施法职业时使用 = 全施法者等级之和 + ⌊半施法者等级 ÷ 2⌋ + ⌊三分之一施法者等级 ÷ 3⌋（均向下取整）。契约施法者不并入。
- `spellSlots(person)`：
  - 只有一个施法职业：读该职业条目的 `spellcasting.slotsByLevel`（三分之一施法者读其子职业条目的 `slotsByLevel`），按职业等级取出 1–9 环的数量；
  - 有多个施法职业：用 `casterLevel` 查引擎常量 `MULTICLASS_SPELL_SLOTS`（多职业施法表，共 20 行）；
  - 契约位始终单列：读邪术师条目的 `slotsByLevel` 中的 `pact`，返回 `{ level, count }`，不与普通位合并；
  - 职业条目没有 `slotsByLevel` 时返回 `null` 并附 `missing: ['法术位表']`，不用常量表代替；
  - 只返回拥有的环阶，一个法术位都没有时返回空列表；人物数据里的"已用"数不参与计算。
- `spellSaveDC(person, classId)` = 8 + 熟练加值 + 施法属性调整值；`spellAttackBonus` = 熟练加值 + 施法属性调整值；施法属性取自职业条目的 `spellcasting.ability`。

### 2.6 生命值变化

这些函数只返回结果与预览文字，不写数据。

| 函数 | 规则 |
|---|---|
| `applyDamage(hp, amount, { identity, cardType })` | 先扣临时生命值，剩余伤害扣当前生命值；当前生命值降到 0 时：完整卡的人物为"倒地"并开始死亡豁免，属性块的人物为"倒下"；扣到 0 后剩余伤害 ≥ 生命值上限时直接死亡（完整卡） |
| `applyHealing(hp, amount)` | 当前生命值不超过上限；临时生命值不受治疗影响；从 0 恢复到 ≥ 1 时清除倒地与死亡豁免记录 |
| `setTemporaryHp(hp, amount)` | 临时生命值不叠加，取较大值；返回"保留较大值"的说明 |
| `deathSaveOutcome(saves)` | 3 次成功稳定；3 次失败死亡；返回当前状态 |

返回值形如 `{ hp: { current, max, temp }, steps: ['临时 3 → 0', '当前 12 → 8'], state: 'ok' | 'down' | 'dead', needsRuling }`；`steps` 供界面预览与提示条使用。

### 2.7 摘要接口

`RuleSystem.derive.summary(person)` 汇总以上结果，供列表与详情顶部使用，返回：

```
{
  header:  { proficiency, initiative, speed, passives: [{ label, value, sources }] },
  hp:      { current, max, temp, hitDice, state },
  ac:      { value, options, overridden },
  abilities: [{ key, label, score, modifier, save: { bonus, proficient }, sources }],
  slots:   [{ label, remaining, total }],
  pending: [{ key, label }]          // 缺哪些必填项（草稿的"待填"清单）
}
```

属性块（敌人与 NPC）用数据里的数值填同一结构，`sources` 为空；`pending` 只检查生命值上限与 AC。

### 2.8 规则选项的生效

- 规则引擎维护三样东西：`IMPLEMENTED_OPTIONS`（已实现的 `engine` 名清单）、`OPTION_GROUPS`（互斥分组）、各函数读取的"本存档开启的实现名集合"`ctx.options`。
- 需要读规则选项的函数多接收一个 `ctx`；开关为开且 `engine` 在已实现清单里才改变结算；其余情况函数行为与不开时完全相同。
- 界面向规则引擎询问某个选项的状态：`optionStatus(optionDef, enabledIds)` → `effective`（会改变结算）/ `descriptive`（仅说明）；"仅说明"徽章据此显示。
- R1.1 没有可选规则会改变其结果；`rest.gritty`、`rest.epic`、`damage.massive`、`initiative.side` 在 R1.2 实现；`character.multiclassing` 与 `character.feats` 由 U5 读取，决定详情里是否出现"添加职业""添加专长"。

## 3. 验收

### 3.1 单元测试

| 类别 | 用例 |
|---|---|
| 调整值与熟练 | 属性值 1–30 全部对照；等级 1–20 熟练加值；CR 全档（含 0、1/8、1/4、1/2） |
| 豁免与技能 | 18 项技能的关联属性；无 / 半 / 熟练 / 专精四档；兼职不叠加豁免熟练 |
| AC | 每个候选单独一例；轻、中、重甲与敏捷上限；盾牌 +2；力量不足不可用并写原因；覆盖优先 |
| 生命值上限 | 单职业 1–20 级；兼职不同生命骰；体质为负时每级至少 1；额外每级加值；掷骰记录取代平均值 |
| 法术位 | 单职业读自己的表（全、半、三分之一、契约各取若干等级，半与三分之一施法者的单职业表与多职业表结果不同）；多职业按施法者等级查常量表；契约位单列；无施法职业返回空；缺 `slotsByLevel` 返回 `null` 与 `missing` |
| 生命值变化 | 临时先扣；刚好扣到 0；扣到 0 且溢出 ≥ 上限即死；治疗不超上限；治疗不增加临时；临时取较大值；0 治疗到 1 清除死亡豁免；属性块"倒下" |
| 缺数据 | 缺职业、缺属性、缺体质时各返回 `null` 与 `missing`，不返回 0 |
| 规则选项 | `optionStatus` 的生效与仅说明；互斥分组；开关为开但清单里没有实现名时行为与不开一致 |
| 摘要 | 完整卡与属性块（取自数据）的摘要形状一致；`pending` 清单正确 |

每个用例注释出处页码：实现时对照 `reference/龙与地下城官方资料` 逐条核对后写入（本文不预填页码，页码未核对前不得写进用例）。

### 3.2 真机

R1.1 没有界面，不单独验收；经 U6.2 的列表（HP、AC）与 U5.1 的详情顶部由驾驶员间接验收。

## 4. 待议

1. **0 生命值的状态**：完整卡为"倒地 + 死亡豁免"，属性块为"倒下"是默认约定（2014 规则由 DM 裁定怪物倒下时是否死亡），可在设置里改为"敌人 0 生命值即死亡"。
2. 半精灵、人类变体等"属性自选"来源如何在 `abilityScoreFinal` 里表示，随 U5.2（数值）的数据定义一起定。
3. 专长与特性的数值加成（如强健每级 +2 生命值、警觉先攻 +5）需要内容包里的结构化"效果"字段；该格式在 U5.2 之前确定，确定之前这些加成通过手动覆盖填写。
