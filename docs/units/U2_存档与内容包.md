# U2 存档与内容包 · 单元蓝图

状态：草案（待驾驶员批准后定稿）

## 0. 范围与归属

本单元负责：当前数据、存档（保存、分支、读取、自动存档、最近删除）、新存档、导出导入、内容包（数据包与模组扩展）的安装、下载、更新、删除与启停，以及这些功能的全部界面。

| 里程碑 | 交付 |
|---|---|
| M1 | §1 规则作用域、§2 数据、§3 行为规则的全部数据层与 store action（无界面） |
| M3 | §4.2 首页战役卡、§4.3 开始一场新的冒险、§4.4 新存档向导、§4.5–4.6 存档抽屉及其弹出物、§4.9 导出与导入存档 |
| M9 | §4.7 当前存档的数据与模组、§4.8 规则与扩展库（下载、更新、导入、删除） |

依赖：M2 提供内置核心包文件与数据仓库目录文件；U1 提供外壳、页头芯片、首页框架与控件库。

本单元读取：规则注册表、宿主角色卡/群组标识。本单元写入：IndexedDB（§2.2）。其他单元通过 store 读取当前数据与已启用内容包，不直接访问存储。

## 1. 规则作用域（硬性）

1. 每个当前数据、存档、内容包都属于且只属于一个规则（`ruleId`）。
2. 界面按当前数据的规则渲染：人物卡、骰盘、活动、资料分类、库的默认规则都由当前规则决定。
3. 只有同一规则的数据可以相互作用：存档列表、启用内容包、模组、导入。不匹配一律拒绝并写明原因，不做转换或"尽量兼容"。
4. 读取其他规则的存档等于换一场游戏：必须经过"切换规则并读取"确认（§4.6.4），界面随之整体切换。
5. 安装内容包或导入存档时，所需规则必须已安装；否则拒绝，提示"需要先安装规则『X』"。

## 2. 数据

### 2.1 实体

**内容包清单 `PackManifest`**

| 字段 | 说明 |
|---|---|
| `id` | 小写短横线标识，如 `dnd5e2014-core`、`dnd5e2014-xge` |
| `ruleId` | 所属规则，如 `dnd5e2014` |
| `kind` | `data`（数据包）/ `module`（模组扩展） |
| `name` / `nameEn` | 显示名称 |
| `version` | 语义化版本 `1.0.0` |
| `minAppVersion` | 需要的最低扩展版本 |
| `source` | `builtin` / `download` / `import`（安装时写入） |
| `license` / `attribution` | 协议与署名文本 |
| `description` | 一句话简介 |
| `entryCount` / `byteSize` / `sha256` | 条目数、文件大小、校验值 |
| `dependsOn` | 模组依赖的数据包 `[{ id, minVersion }]` |

**条目 `Entry`**：`{ id, type, name, nameEn, keywords[], unique, summary, data }`；`type` 与 `data` 结构由规则包的 schema 定义。

**当前数据 `Workspace`**

| 字段 | 说明 |
|---|---|
| `ownerKey` | `char:<头像文件名>` 或 `group:<群组 id>` |
| `ownerLabel` | 角色卡名或群组名（显示用） |
| `ruleId` | 所属规则 |
| `currentSaveId` | 当前关联的存档 |
| `enabledPacks` | `[{ id, version }]`，含必选的核心包 |
| `data` | 游戏内全部数据（人物、队伍、标签、地点、任务、遭遇、日志、设置） |
| `savedHash` | 当前存档快照的哈希，用于判断"有未保存改动" |
| `schemaVersion` / `updatedAt` | — |

**存档 `SaveSlot`**

| 字段 | 说明 |
|---|---|
| `id` | uuid |
| `ownerKey` / `ownerLabel` / `ruleId` | 所属卡与规则 |
| `name` / `note` | 存档名（必填，≤40 字）/ 备注（可空，≤200 字） |
| `kind` | `manual` / `auto` |
| `autoReason` | 自动存档的原因：读档前 / 新存档前 / 切换规则前 / 恢复备份前 |
| `branchedFrom` | 分支来源存档 id（可空） |
| `createdAt` / `updatedAt` / `deletedAt` | `deletedAt` 非空即在"最近删除" |
| `summary` | `{ partyNames: 前 3 名, partyCount, location }` |
| `packs` | `[{ id, version, name }]` 引用的内容包 |
| `snapshot` / `hash` | Workspace.data 快照与其哈希 |
| `schemaVersion` | — |

**备份状态 `BackupState`**（存于 meta）：`lastExportAt`、`savesSinceExport`、`reminderDays`（默认 7）、`reminderSaves`（默认 10）、`persistRequested`、`persistGranted`。

### 2.2 存储布局

IndexedDB 库 `tavern-trpg-assistant`（Dexie）：

| 表 | 主键 | 索引 | 内容 |
|---|---|---|---|
| `packs` | `id` | `ruleId`、`kind` | 已安装内容包清单（每个 id 只保留一个版本） |
| `entries` | `[packId+entryId]` | `packId`、`[ruleId+type]` | 条目 |
| `searchIndex` | `packId` | — | MiniSearch 序列化索引（可重建） |
| `assets` | `[packId+path]` | `packId` | 模组附带的图片等二进制 |
| `workspaces` | `ownerKey` | `ruleId` | 当前数据 |
| `saves` | `id` | `[ownerKey+ruleId]`、`ruleId`、`kind`、`deletedAt` | 存档 |
| `meta` | `key` | — | 备份状态、库设置 |

- 一次用户操作涉及的多表写入放在同一个事务中。
- 当前数据在改动后 500ms 写入；页面隐藏或卸载前立即写入。
- 首次启动调用一次 `navigator.storage.persist()`，结果记入 `BackupState`。

### 2.3 文件格式

两种文件都是 zip（fflate），根目录有 `trpg-manifest.json`。

**`.trpgpack`（内容包）**
```
trpg-manifest.json   { "format": "trpg-pack", "formatVersion": 1, "pack": PackManifest }
entries/<type>.json  条目数组，按类型分文件
assets/…             可选：模组底图等
```

**`.trpgsave`（存档 / 完整备份）**
```
trpg-manifest.json   { "format": "trpg-save" | "trpg-backup", "formatVersion": 1,
                       "appVersion", "exportedAt", "ruleIds": [...] }
saves/<id>.json      SaveSlot
workspaces/<key>.json  仅完整备份：各卡当前数据
settings.json          仅完整备份：扩展设置
packs.json             已安装内容包清单（id、版本、名称）
packs/<id>@<ver>.trpgpack  可选：勾选"附带所用内容包"时（不含内置核心包）
```

**识别顺序与失败提示**（导入时逐条检查，第一处失败即停止并显示对应提示）

| 检查 | 失败提示 |
|---|---|
| 是 zip | 无法识别：这不是 TRPG 跑团助手的文件 |
| 有 `trpg-manifest.json` | 无法识别：缺少说明文件，可能不是本扩展导出的文件 |
| `format` 已知 | 无法识别：未知的文件类型 |
| `formatVersion` 受支持 | 这个文件由更新版本的扩展创建，请先更新扩展 |
| 规则已安装 | 需要先安装规则『X』 |
| 数据结构校验通过 | 文件内容损坏：第 N 项「名称」字段不合法（只显示第一处） |
| 校验值一致（下载时） | 下载的文件不完整，请重试 |

**数据仓库目录 `catalog.json`**（默认地址 `https://cdn.jsdelivr.net/gh/didhogg/tavern-trpg-data@main/catalog.json`，可在设置中修改）
```
{ "formatVersion": 1,
  "packs": [ { "id", "ruleId", "kind", "name", "version", "byteSize", "sha256",
               "url", "license", "description", "updatedAt" } ] }
```

**内置核心包**：扩展目录 `packs/dnd5e2014-core.trpgpack`（PHB、DMG、MM，含 SRD），附 `packs/DATA-NOTICE.md`。首次启动、或扩展更新带来更高版本时，经同一个安装器安装。

### 2.4 版本与迁移

- Workspace、SaveSlot、PackManifest 都带 `schemaVersion`；读取旧版本数据时按迁移链逐级升级，升级后写回。
- 数据版本高于当前扩展能处理的版本时：拒绝打开，提示"这个存档由更新版本的扩展创建，请先更新扩展"，不写入任何内容。

## 3. 行为规则

### 3.1 当前数据与"未保存"
- "有未保存改动" = 当前数据的哈希 ≠ 当前存档的 `hash`。
- 显示位置：页头存档芯片的 ●，首页战役卡的"● 有未保存改动"，存档抽屉当前区。

### 3.2 保存
- 用当前数据覆盖当前存档的快照、摘要、内容包引用与 `updatedAt`；`savesSinceExport` 加 1。
- 没有改动时"保存"不可用，旁边显示"已是最新"。
- 成功：提示条"已保存「龙金劫-2」"（4 秒）。失败：错误提示条（常驻），数据不变。

### 3.3 分支存档
- 用当前数据新建一个存档（默认名"<原名> 分支"，重名时加序号），`branchedFrom` 指向原存档，并切换为当前存档。
- 原存档保持它上次保存时的样子；当前未保存的改动只进入新分支。

### 3.4 新存档
- 通过新存档向导（§4.4）创建：新的当前数据（所选规则与内容包）+ 第一个存档位。
- 已有当前数据时，先写一个自动存档（原因"新存档前"）。

### 3.5 读取
- 有未保存改动时先弹确认（§4.6.2）。
- 读取前总是为当前数据写一个自动存档（原因"读档前"）。
- 读取后：当前数据 = 存档快照；已启用内容包 = 存档引用的内容包；引用了未安装的包时，在存档抽屉与"数据与模组"中显示缺失提示，已加入游戏的副本照常可用。
- 读取同规则、其他卡的存档：先复制为当前卡的新存档（名称"<原名>（来自 <卡名>）"），再读取这个副本；原存档不变。
- 读取其他规则的存档：见 §4.6.4。

### 3.6 自动存档
- 每张卡、每个规则保留最新 3 个；触发：读档前、新存档前、切换规则前、恢复备份前。
- 自动存档可读取、可"另存为存档"（转为手动存档），不能改名。

### 3.7 删除、恢复、彻底删除
- 删除：存档移入"最近删除"，提示条带"撤销"（6 秒）。
- 正在使用的存档不能删除（菜单项不可用，说明"正在使用的存档不能删除，请先读取或新建其他存档"）。
- 恢复：移回存档列表。彻底删除 / 清空最近删除：确认对话框后不可恢复。

### 3.8 当前存档的数据与模组
- 开关即时生效，写入当前数据（产生"未保存"状态）。
- 停用：之后搜不到、也不能再从它新建；已加入游戏的副本不受影响。核心包始终启用，开关锁定。
- 启用一个模组时，其依赖的数据包若未启用，自动一并启用并提示；停用一个被已启用模组依赖的数据包时，开关不可用并说明"『风暴岛』依赖它"。

### 3.9 内容包安装（内置、下载、导入共用）
1. 读取文件 → 按 §2.3 识别与校验。
2. 与已安装版本比较：未安装 → 安装；更高版本 → 升级；相同版本 → 提示"已安装"，不重复写入；更低版本 → 确认"将从 v1.1.0 降级到 v1.0.0？"。
3. 在一个事务中写入清单、条目与附件；之后在后台重建搜索索引（完成前资料页显示"正在建立索引"）。
4. 升级不改动任何存档里已加入游戏的副本；引用旧版本的存档读取时照常可用，模板差异的同步界面由人物与资料相关单元提供。

### 3.10 下载与更新
- 打开库时读取数据仓库目录（10 秒超时）；失败时库照常显示已安装内容，并在"可下载"区写明原因与"重试"。
- 下载：流式读取并显示进度，最多同时 2 个；完成后核对大小与校验值，再交给安装器。可取消。
- 错误：网络中断、文件不存在（404）、校验不符、存储空间不足（QuotaExceeded），各有明确提示与"重试"。
- 更新：有更高版本时行内显示"有更新 vX"与"更新"；存在多个更新时，区头显示"全部更新（N）"。

### 3.11 删除内容包
- 内置包不能删除。
- 被存档引用时，先确认"有 N 个存档用到了它。删除后，这些存档中已加入游戏的内容不受影响，但尚未加入的条目将无法查看"。
- 删除清单、条目、附件与索引；存档中的引用保留，显示为"未安装"。

### 3.12 导出
- 范围：当前存档 / 全部（完整备份）；可勾选"附带所用内容包"（不含内置核心包）。
- 文件名：`<存档名>_<yyyy-mm-dd>.trpgsave` / `TRPG备份_<yyyy-mm-dd>.trpgsave`。
- 完整备份成功后：`lastExportAt` = 现在，`savesSinceExport` = 0。
- 宿主下载行为：通过 `<a download>` 保存文件；在 TauriTavern 中的表现须在 M3 真机验证，不可用时改用 TauriTavern 文件导出接口（`docs/CurrentState/FileTransfer.md`）。

### 3.13 导入存档与恢复备份
- 存档文件：列出其中的存档供勾选；导入为当前卡的存档（重名时加"（导入）"）；规则未安装的存档不可勾选并说明原因；附带的内容包一并经安装器安装。
- 完整备份：选择"合并"（默认，只添加尚不存在的存档与当前数据）或"覆盖"（先写自动存档，再用备份替换全部存档、当前数据与设置）。

### 3.14 备份提醒
- 距上次完整备份 ≥ `reminderDays` 天，或之后保存 ≥ `reminderSaves` 次 → 文字变为琥珀色"建议导出备份"。
- 从未导出过 → "还没有导出过备份"。只做文字提示，不弹窗。

### 3.15 多窗口
- 使用 BroadcastChannel 检测同一浏览器中其他打开的助手；检测到时，后打开的窗口顶部显示"另一个窗口正在使用助手，此窗口为只读"，并禁用所有写入操作。

### 3.16 错误
- 任何写入失败：数据保持原状，显示常驻错误提示条，写明原因与可做的事。
- 存储空间不足：提示"存储空间不足：可以删除不用的内容包，或清空最近删除"。

## 4. 界面

### 4.1 设计约定（本单元）

- **每屏一个主角、一个主动作**：

| 界面 | 主角 | 主动作 |
|---|---|---|
| 首页（有战役） | 当前战役卡 | 继续冒险 |
| 首页（无战役） | "开始一场新的冒险" 横幅 | 开始新冒险 |
| 新存档向导 | 当前步骤的选项 | 下一步 / 开始冒险 |
| 存档抽屉 | 当前存档区 | 保存 |
| 数据与模组 | 内容包开关列表 | （即时生效，无提交按钮） |
| 规则与扩展库 | 内容包列表 | 下载 / 导入文件 |
| 导出窗口 | 范围选择 | 导出 |

- **控件**：即时生效用开关；表单提交用勾选框；2–5 个选项用分段按钮；规则选择用下拉；不可撤销用确认对话框；可撤销用带"撤销"的提示条。
- **徽章**（方块、浅底色、不可点）：`当前`、`内置`、`已安装`、`有更新`、`未安装`、`下载中`、`自动`。颜色仅作辅助，徽章上始终有文字。
- **层级**：一个页面上最多同时打开一个抽屉或二级悬浮窗，其上只允许再叠一个确认对话框；下拉、弹出卡片任何时刻最多一个。
- **卡片**只用于战役卡、存档行的当前项高亮、内容包详情；存档列表与内容包列表使用行 + 细分隔线。
- **动效**：抽屉从右侧滑入 200ms；对话框淡入 + 轻微放大 160ms；下载进度条平滑推进；列表增删项淡入淡出 160ms；遵守"减少动态效果"设置。

### 4.2 首页 · 当前战役卡（有当前数据时）

首页整体属于 U1；本单元提供"当前战役卡"。

**宽屏**
```

```
- 标题（衬线 24px）为存档名；第二行为规则名与当前地点（次要文字）。
- 下方三格关键数字：队伍人数、当前轮次（无遭遇时显示"未在战斗"）、存档状态（"已保存 · 13:05" / "● 有未保存改动"）。

| 队伍 3 人 | 打开人物页·队伍 |
| 第 2 轮 | 打开战斗页 |

**窄屏**：横幅高度减半，标题 20px；"继续冒险"占满一行置于数字格下方；三格数字横排不换行。

### 4.10 状态与反馈汇总

| 场景 | 表现 |
|---|---|
| 保存、分支、读取、导出、安装成功 | 底部提示条，4 秒自动消失 |
| 删除存档 | 提示条带"撤销"，6 秒 |
| 任何失败 | 常驻错误提示条（红色左边线 + ⚠ + 原因 + 可做的事），手动关闭 |
| 列表读取中（> 300ms） | 行骨架占位 |
| 下载中 | 行内进度条与百分比；页头不显示全局进度 |
| 只读窗口（§3.15） | 内容区顶部常驻黄色横条，写入类按钮全部不可用 |
| 未打开聊天 | 首页显示"请先在酒馆中打开一个聊天"；存档抽屉不可打开 |

### 4.11 键盘与可访问性

- 抽屉与对话框打开时焦点进入，Esc 关闭并把焦点还给触发按钮；对话框内 Tab 循环。
- 存档行：↑↓ 在行间移动，Enter = 读取，F2 = 改名，Delete = 删除（当前存档无效）。
- 开关、勾选框、分段按钮可用空格切换；所有图标按钮有可读名称（如"龙金劫-1 的更多操作"）。
- 进度条有 `aria-valuenow`；识别、安装结果通过 `aria-live` 播报。

### 5.2 真机验收（驾驶员，TauriTavern）

1. 在一张没有数据的角色卡上：首页出现"开始一场新的冒险" → 走完新存档向导 → 首页显示战役卡。
2. 改动后存档芯片出现 ● → 保存后消失；分支存档后列表出现两个存档。
3. 读取另一个存档（含未保存确认）→ 自动存档区出现记录。
4. 删除一个存档 → 撤销；再删除 → 最近删除中恢复 → 彻底删除。
5. 在库里**下载**一个扩展数据包 → 在当前存档的数据与模组中启用 → 资料页能搜到其内容。
6. 用"导入文件"**导入**一个 `.trpgpack` → 安装成功；再导入一个错误文件 → 显示原因。
7. 导出完整备份（含内容包）→ 文件出现在下载位置；导入该文件（合并）→ 存档齐全。
8. 完全退出 TauriTavern 再打开 → 当前数据与存档仍在。
9. 群组聊天与未打开聊天时，首页与存档抽屉的表现符合 §4.3、§4.10。
