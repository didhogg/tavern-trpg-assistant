## 1. 总规则修订

### 1.1 容器：只有三种（取代：基本 §1.8、抽屉 §5.1）

| 容器 | 用在哪里 | 规则 |
|---|---|---|
| **原地编辑** | 生命、灵感、力竭、圆点、药丸 ×、字段框内输入 | 不换页、不遮挡、位置不跳（预留高度） |
| **居中弹窗** | 所有「管理 / 选择 / 资料」：身份、属性、读数、技能、档案三类、添加效果、资料、帮助、重新截取 | 宽屏居中（宽见各节，高度 = 内容、最高 86%，超出时内容区滚动）；有标题栏（标题 + ✕）、可选标签栏、内容区、**固定底栏**；Esc / ✕ / 点遮罩关闭，焦点回到触发处；一次只开一个，弹窗里前进 = 换页（‹ 返回），**不叠加** |
| **悬停气泡** | 来源、算法、溢出药丸、提示 | **只读**，鼠标放上去才出现，不抢焦点；触屏上长按或点一下「ⓘ」显示；**气泡里没有按钮，也不遮住触发它的元素** |

- **手机（≤ 480）**：居中弹窗变**底部整页**（高 92%，顶角 12，顶部 36×4 拖动条），**底栏固定**（操作按钮不随内容滚走）。标签栏横向可滑。
- 弹窗宽（宽屏）：身份 760–980（流程步骤里 980）、属性 760、读数 720、技能 720、档案三类 640、添加效果 940、资料 480–520、帮助 520、重新截取 640。窄于它时 `min(宽, 100%)`。
- 弹窗里**不放键盘说明**（「方向键移动 2%」之类只在 `hover: hover` 设备上显示在 tooltip）。
- 下拉 / 选择控件按开发规范 §5.3：**浮层列表**（浮在最上层，不撑开弹窗、不裁切、不出现「展开 / 收起」手风琴）。输入框里的清除 ✕ **封装在框内右侧**（与下拉箭头并列），不画在框外。

### 1.2 悬停与点击（全页统一）

| 对象 | 悬停 | 点击 |
|---|---|---|
| 药丸（档案、效果） | 气泡：名称、获得方式、来源 | **资料弹窗**（§10.9） |
| 溢出药丸「+N」 | 气泡：被折叠的全部药丸名 | 打开**对应类别**的管理弹窗，直接进该类别标签 |
| 派生数字（AC、先攻、速度、熟练加值、被动、属性、技能、豁免） | 气泡：**全部来源明细**（逐项「名称 值 · 来源」，最后合计；有覆盖时写「已被覆盖」） | 见各节（可掷的去骰盘；读数类打开读数弹窗对应标签） |
| ✎ / ＋ | 名称（「编辑生命」「添加效果」） | 打开 / 进入编辑 |
| 熟练图标 | 等级 + 来源 | 技能弹窗里：切换等级 |

气泡文字用「小字 + 数字等宽」，一行不超过 28 字，最多 8 行；窄屏（无悬停）读数类派生数字的来源改在**对应弹窗**里完整显示。

### 1.3 「自动」与「手动」：来源、算法、覆盖，一个统一的写法（取代：基本 §1.3 的按钮部分、抽屉 §5.4–5.6 的两个按钮）

凡是「自动算出来 / 自动分配来的」项目，在管理页里都是同一种**项目卡**：

```
 速度 · 步行                                      30 尺      ← 最终值（大）
 ┌─ 来源与算法（只读，灰字，无输入框）─────────────────────┐
 │ 基础 25 尺      来自 种族 · 矮人                        │
 │ 手动调整 +5 尺  你填的                                  │
 └──────────────────────────────────────────────────────┘
 手动调整  [ +5 ]尺          ← 输入框（只有「可以手填」的才画框）
 覆盖为    ( ) 关   ( ) 开 [   ]   ← 开启后最终值 = 你填的数，不改原来的值
 [自动计算]   ← 只有存在手动调整 / 覆盖 / 被移除的自动项时才可点；一键回到自动
```

- **只读的东西是纯文字**（灰色、无边框、无底色方框）；**能填的才画输入框**（白底 + 描边）。同一屏里看一眼就分得清。
- 手动覆盖是**盖在上面**的：原来的自动值始终保留并显示（灰字「自动 30」），关掉覆盖或点 **[自动计算]** 立刻回来。覆盖开着的项目在页面上最终值旁没有任何标记（沿用基本 §1.3：不加「覆」字），只在管理页里看得到。
- **自动分配来的项目（带 `auto` 来源）被移除或改掉后**，该项目的管理页里出现「**可恢复的自动项**」一行（药丸 + ↺），点一下加回来，并带原来的来源；另有 **[按来源重新分配]** 按钮（重新读当前的种族 / 职业 / 背景 / 等级，补回缺的、不动手动加的）。
- 属性抽屉的 **[全部自动计算]** 改名 **[清除手动修正]**，点之前说清楚会清什么（§10.4）。

### 1.4 来源标记（取代：基本 §1.4 的「界面上不加来源缩写标签」）

- 界面上**仍然不加** `[族][景]` 这类缩写标签；来源只在悬停气泡、资料弹窗、管理页里写。
- 来源三种不变：`manual`、`auto`（附条目编号与显示名）、`template`。**本任务开始真的写 `auto`**（§10.2）。

### 1.5 保存与撤销（沿用基本 §1.1–1.2，补充）

- 弹窗里**直接改的东西**即时进草稿（沿用）；**例外**：属性点池放入、等级管理、种族 / 职业 / 背景流程、添加修正表单——这几处先在弹窗里**暂存**，点**弹窗内的确认按钮**才写进草稿（按钮名见各节）。关闭弹窗 = 放弃暂存，不弹确认。
- 顶栏撤销栈沿用（50 步）；一次「确认写入」算一步。

### 1.6 提示条（取代：抽屉 §5.10 的措辞，保留机制）

只有这几条会弹：首次进入提示、保存成功「已保存 盖尔」、保存失败、占位按钮（休息、套用模板、＋ 自定义…）。**当场状态与撤销不弹提示条**（沿用）。弹窗里的校验用框下红字。

### 1.7 同一排的框线统一

同一排并列的控件**只用实线**：药丸、字段框、按钮、胶囊同一线型；**不用虚线**表示「待填写」（取代视觉 §4.2 虚线「选种族 ›」）。待填写 = 实线字段框里写灰字「未选职业」+ 旁边的主操作按钮。

## 2. 页面结构修订（取代：基本 §2.1、视觉 §2）

### 2.1 区域

沿用驾驶员在 Figma 与评审原型里敲定的版式（**不再用原文「一张大 A 卡」**）：

```
宽屏 ≥ 1024
┌─ 顶栏（三组）─────────────────────────────────────────────────────────────┐
│ ‹ 人物  盖尔*│ [角色|敌人] │ ● 未保存 3 · 撤销 │ [保存] │ ⋯  ？             │
├───────────────────────────────┬──────────────────────────────────────────┤
│ 身份卡 A                       │ 战斗卡 B（AC 先攻 速度 熟练 / 被动）      │
│  头像 名字 职业框 种族 背景 灵感 ├──────────────────────────────────────────┤
│  ─────────                     │ 属性卡 C（六张等高）                       │
│  生命 ✎（当前 临时 血条           │                                          │
│   死亡豁免 生命骰 力竭）          │                                          │
├───────────────────────────────┴──────────────────────────────────────────┤
│ 法术位（单行；没有法术位的人整卡不显示）                                    │
│ 状态与效果 ＋（状态一行、效果一行）                                         │
├───────────────────────────┬─────────────────────────┬────────────────────┤
│ 防御 ✎                     │ 感官 ✎                   │ 熟练 ✎              │
├───────────────────────────┴─────────────────────────┴────────────────────┤
│ 分页：行动与技能 · 法术 · 职业与特性 · 背包 · 背景故事（下划线标签）          │
│ 行动 ＋ │ 技能 ✎                                                          │
└──────────────────────────────────────────────────────────────────────────┘
* 名字在 A 卡滚出视口后淡入顶栏（沿用基本 §2.3）
```

- 每张卡**标题行右端固定**一个 ✎（或列表型的 ＋）；法术位卡因为没有可编辑内容所以没有；**整页只有顶栏一个 ？**（取代各栏 ？）。
- 身份卡与右列（战斗 + 属性）**底边对齐**（网格 `align-items: stretch`）；生命区贴身份卡底部，中间留白由头像加大、间距补，不靠拉伸卡片。
- 窄屏（≤ 480）：单列；A 拆为「头像 + 名字 + 职业框 + 灵感」「生命」两段；战斗卡读数 2 × 2；属性 3 × 2；档案三卡上下排，每类最多 3 个药丸 + 「+N」，**不会把分页标签顶出屏幕**（每张卡最多 3 行，超出折成「+N」）。
- **粘住**：顶栏粘顶；A 卡滚出后顶栏下出现迷你条（名字　当前/上限　AC　▾）；分页标签栏再粘在迷你条下面（沿用基本 §2.3）。
- 分页标签：**下划线标签**（不再用实心大按钮托盘；取代：视觉 §8.1、基本 §4.6）；选中项下划线 `--primary`，文字 `--ink`；其余 `--ink-2`；高 46。顺序以驾驶员版式为准：**行动与技能 · 法术 · 职业与特性 · 背包 · 背景故事**（取代：基本 §2.4 顺序）。
- 其余四个分页本任务仍是「本分页尚未开放」占位（EmptyState：48px 书本图标 + 一句话）。

### 2.2 顶栏三组（取代：基本 §4.1 的排列）

```
[‹ 人物]   名字（滚出后淡入）   ……   [角色｜敌人]  │  ● 未保存 3  [↶ 撤销]  │  [保存]  │  [⋯] [？]
 导航组                                类型切换        数据组                  主按钮     系统组
```

- 组与组之间 1px 竖分隔线（高 22，`--line`）；数据组 = 保存状态 + 撤销；系统组 = ⋯ 与 ？。
- 「保存」是**整页唯一实心按钮**；无改动且非新人物时灰；名字为空时灰。
- 窄屏（≤ 760 的容器宽）：隐藏「撤销」文字、类型切换、顶栏名字（名字由迷你条显示），**名字绝不被截成「卡…」**；保存状态只留圆点 + 数字。
- `[角色｜敌人]` 是**这张卡的显示类型**切换（同一数据两种外壳排版，**不改数据**；见 §2.3）。

### 2.3 敌人视图 = 人物视图（取代：基本 §4.2.1 末段、视觉 §4.1 末段、本节前的口头隐藏约定）

> 决定依据：`docs/decisions.md` 2026-11-02「所有人共用一个人物面板……不按人物种类分视图」与驾驶员 2026-11-04「敌人视图除了挑战和经验多显示，其他和人物页面**同构**」。

- 敌人视图与角色视图**区域、控件、位置完全相同**：灵感、生命与 ✎、死亡豁免、生命骰、力竭、休息、套用模板、职业框、等级管理、法术位、状态与效果、档案三卡、分页，全部照常显示、照常可点。
- 只多：名字旁的两枚**金色实线徽章**「挑战 1/4」「50 经验」（经验由挑战等级查 `docs/模块数据约定.md` §16 表，数据里没有经验字段就查表；表里没有就不显示该徽章）。

- 顶栏 `[角色｜敌人]` 切换的是**外壳的显示类型**：敌人类型额外显示上面两枚徽章；其余一样。

```
 生命骰数量   d6 [  ] 颗（自动 3）   d10 [  ] 颗（自动 3）
```

### 10.2 种族 / 职业 / 背景：选择 → 补选 → 分配（取代：抽屉 §5.2「下拉」做法；提前自 UNIT4）

标签页**未在流程中**时显示「当前」卡：

```
   语言  (通用语)(矮人语)    武器 (战斧)(手斧)(轻锤)(战锤)    抗性 (毒素) …
```

点「更换 / 选择」进入三步流程（顶部步骤条 ① 选择种族 ② 补选 ③ 分配）：

**① 选择**：左列表（搜索框 placeholder「搜种族（中文或英文）」；每行中文名、英文名灰字、来源书徽章）+ 右**资料片**（种族：属性加成、速度、体型、感官、语言、特性、亚种族；职业：生命骰、豁免、护甲、武器、技能选择数、1 级特性、子职业等级；背景：技能、工具、语言、背景特性——**全部读自该条目，不手写**）。底栏：`[取消]` `[只选用，先不分配]` ……右侧主按钮「**选用{名称}**」（例「选用精灵」；**不写括号说明**）。

**② 补选**：条目里「选 N 项」的逐项给选择（亚种族可不选；额外语言、技能、工具从条目允许的范围里选；`已选 1/2` 计数）。没有要补的写一句「没有需要补选的项」。**补选可以空着**，下一步照样能应用，没选的就不写入。底栏：`[‹ 上一步]` `[取消]` `[只选用，先不分配]` 主按钮「下一步：看分配」。

**③ 分配**：

```
 移除旧种族「人类」带来的内容（默认勾选）
   [✓] 语言    (通用语)         从 熟练 · 语言 移除
 写入新种族「矮人 · 丘陵矮人」的内容（默认勾选；全不勾也能应用）
   [✓] 感官  (黑暗视觉 60 尺)   写入 感官
   [✓] 语言  (通用语)(矮人语)   写入 熟练 · 语言
   [✓] 武器  (战斧)(手斧)(轻锤)(战锤)
   [✓] 抗性  (毒素)
 只读说明（不进分配）
   属性  体质 +2 · 感知 +1   种族加成直接读取，显示在属性表「种族/背景」列
```

- 每行一个勾选框 + 类别 + 药丸 + 一行「写入到哪」；**默认全勾**；可取消一部分，**全取消也能点「应用」**（只记录选择）。
- **更换已有选择**时，分配页**最上面**多一个「移除旧{种族}带来的内容」区，**默认全勾**：只移除**来源只有旧条目**的项；有多个来源的只去掉这一个来源（沿用基本 §1.4「来源合并」）；技能的熟练、特性、豁免、语言、武器、护甲、工具、感官、抗性都算。
- 只读说明：属性加成、速度、特性名——这些**不进分配**（属性与速度由派生函数直接读取；特性在「职业与特性」页）。
- 「应用（N 项）」：把勾选项写进人物，每项带 `auto` 来源（条目编号 + 显示名，亚种族写「矮人·丘陵矮人」）；写完回到该标签的「当前」卡。**一次应用算撤销栈一步。**
- **「只选用，先不分配」**：只写种族 / 职业 / 背景的选择本身（`block.race` 等），不写任何熟练 / 语言 / 武器，也不移除旧来源内容（驾驶员：可以什么都不分配也能正常创建完角色）。
- **职业**额外：写入豁免熟练、护甲、武器、技能（选 N）、生命骰 d 值（读取，不写）；等级默认 1（已有职业更换时保持原等级）。**背景**：技能、工具、语言（选 N）。**特性只显示在「只读说明」**，不进分配（归职业与特性页）。
- 数据来源：`race / subrace / class / background` 条目的 `abilityBonus`、`speed`、`senses`、`languages`、`proficiencies`、`advancement` 与 `traits`（`docs/模块数据约定.md` §1–2）；「任选」的语言约定为标准 + 特种（不含秘密）；工具记号（`anyGamingSet` 等）展开成对应工具列表。**所有名称用数据库条目名**。

### 10.3 等级管理（取代：基本 §4.2.3 升降级占位；提前自 UNIT4 的一部分）

身份弹窗第五个标签（宽 980）。**只管当前职业的升降级**；多职业、专长、子职业的选择登记后做（§17）。

```
 法师    3 级 → 4 级                                [−]  4  [+]
 升到 4 级会得到
   4 级   生命  (平均 4) (掷骰)  + 体质 +1        熟练 +2（不变）
          特性  (属性值提升)         法术位  1环 4 · 2环 3
          属性值提升  [选属性▾] [再选一项▾]   ← +2 一项，或各 +1
 [应用等级变更]  [还原]
```

- 目标等级用 [−][+] 选（1–20）。**升级**：逐级列出——生命（`平均 n` 或 `掷骰` + 骰面输入，也可点骰子按钮掷；记 `hpRolls[级数]`，派生函数取记录值，基本 §6.7）、熟练加值变化、新特性名（读 `advancement`）、法术位变化（读 `slotsByLevel`）、到子职业等级时提示「到这一级要选择子职业」、属性值提升级（4、8、12、16、19，战士 + 6、14，游荡者 + 10；读 `asiLevels`）给两个下拉（选同一项 = +2，选不同两项 = 各 +1；写 `abilityGrowth`，**超 20 不加**）。
- **降级**：逐级列出会失去的特性、生命上限重算（按每级累计）、属性提升（默认勾选「移除该级属性提升」）；**默认勾选移除这些等级带来的内容**，可取消。
- 生命骰已用数压到新总数；当前生命压到新上限。「应用」算一步撤销。
- 没有职业：显示「还没有职业」+「去选择职业」。

### 10.4 属性弹窗（取代：抽屉 §5.4 的交互；表格列沿用）

宽 760；窄屏每项一张小卡。**内容区三块：生成基础值｜计算表｜底栏确认。**

- **生成区**：分段 `标准数组｜4d6 去最低｜购点`（沿用抽屉 §5.4；`cryptoRng`；数字总分 + 可选展开点数明细）。
- **点数池放入（交互取代）**：
  1. 点池里一个数字 → 该数字**高亮选中**；
  2. 点计算表某一行（基础格或整行）→ **放入**：该行整行出现 **`--primary` 红色框高亮**（表示「这一项已完成分配」），池里该数字**变灰且带「已放入」描边虚线**；
  3. **再点已高亮的行（或点池里变灰的那个数字）= 退回**：行恢复放入前的值与样式，池里数字恢复可用；
  4. 把另一个数字放到已有放入值的行上 = 替换，原数字回到池里；
  5. 池与放入状态**只在弹窗内存里**；**关闭 = 放弃**（取代抽屉 §5.4 末的「已写进 abilities 的值保留」）。
- 购点：基础格变 `[−] 8 [+]` 步进器（范围 8–15，剩余点数不足时 [+] 灰）；规则沿用抽屉。
- **计算表**：9 列沿用；**灰色只读列用纯灰字无框**（种族/背景、成长/专长、装备/魔法物品、最终、调整值），可改列（基础、其他）用白底描边输入框；种族 / 背景列悬停显示来源（「矮人 +2」）；最终列超上限显示「上限 20」小字（行高不变）。
- **底栏**（固定）：左灰字「放入的点数点「保存」才写进属性」；右 `[取消]` `[保存并写入属性点]`（**主按钮**；没有任何暂存改动时灰）。点「保存并写入属性点」：把放入的基础值与「其他 / 覆盖 / 豁免」改动一次写入草稿（顶栏「未保存」计数 +1 个字段 `block.abilities` 等），关闭弹窗。
  - **「其他(手动)」「覆盖」「豁免勾选」也先暂存，一起在这个按钮写入**（取代「即时进草稿」；理由：用户填完看到的数要确认才写，不会写不进去也不知道是否已写）。
- **[覆盖]**：切换覆盖视图（最终列变输入框，沿用）；**[清除手动修正]**（取代「全部自动计算」）：按钮旁小字写「会清空 N 项「其他」和 M 项覆盖，基础值不动」；N、M 为 0 时灰；点后**弹窗内原地**显示「已清空，点「保存并写入」生效」，不立刻写。
- 豁免勾选：勾 / 取消只在暂存；来自职业的豁免熟练被取消勾选后，进入**档案「可恢复」**类似逻辑：属性弹窗豁免列下方一行「可恢复的自动项」药丸 + ↺（沿用 §1.3）。

## 11. 骰盘：检定与豁免（取代：基本 §1.7；其余标签留给后面的掷骰 UNIT）

**本任务只做「检定」「豁免」，外加「自由」保底。**「自由」就是现有基础版（骰式、d4–d100、加减值、说明、最近）原样，用来接住攻击 / 伤害 / 法术攻击 / 生命骰这些之后才做专用标签的点击（它们点了把骰式与说明填进「自由」，不自动掷）。

### 11.1 外形

- 浮动窗，可拖，位置记忆；**左侧附着浏览器式标签**：检定｜豁免｜自由（竖排文字；窄屏变成顶部横向标签 + 底部整页）；z-index **高于弹窗遮罩**（弹窗打开时点弹窗里的数字，骰盘照常打开，沿用）。
- 面板高度固定 `min(90vh, 820px)`，**切标签、选项目、选难度都不改变各分区位置**；分区：`行动者｜项目｜加值｜难度/对手｜掷法｜（底栏固定）公式预览、结果区（固定 104 高占位）、「掷骰」按钮`。

### 11.2 一个检定 / 豁免的流程（D&D 实际流程：p173–175、p177、p179）

```
 ① 谁掷         行动者 [ 盖尔 ▾ ]                ← 真下拉：人物列表（队伍 / NPC / 敌人分组）
 ② 掷什么       属性 [ 敏捷 ▾ ]  技能 [ 杂技 ▾ ]   ← 两个真下拉；技能可选「不用技能」
                = 敏捷（杂技）检定
 ③ 加值与骰式   d20
                敏捷调整值 +2      ⓘ 悬停：敏捷 14
                熟练 +2            ⓘ 悬停：杂技熟练 · 来源 背景 · 智者
                祝福 …（只有「结构化效果」带来的才会自动出现，可 ×）
                [＋ 自定义加值 ▾]  → 常数 / 骰式 / 来自资料
 ④ 难度 / 对手  (固定 DC)(对抗)(不设)
                DC [−] 15 [+]  5 10 15 20 25 30  [🎲]
 ⑤ 掷法         (优势)(普通)(劣势)  + 来源列表  → 最终：普通
 底栏           公式预览 1d20 +4            [结果卡/占位]      [掷骰]
```

- **没有手风琴「展开 / 收起」，没有下面平铺的六属性 / 十八技能网格**（取代评审原型 v2 的做法；它们与上面的属性、技能下拉产生数据冲突）。选项目**只用 ② 的两个下拉**；点人物页数字进来时 ① ② 已填好。
- **② 属性与技能**：选技能时属性自动填成它的默认属性（`SKILLS[...].ability`），**可改**（体质（运动）、力量（威吓）：玩家手册 p175 变体）；有熟练的技能在下拉里带 ●；「不用技能」= 纯属性检定。选 **先攻** = 敏捷检定，项目标签写「先攻」。
- **豁免标签**：② 只有「属性」一个下拉（六属性 + **死亡豁免**；死亡豁免不加任何加值、不受优势劣势影响，DC 固定 10，沿用基本 §4.2.4）。
- **③ 加值与骰式**（取代评审原型 v2 的「附加骰」预制按钮）：
  - **自动来源（只读行，带悬停来源）**：属性调整值；熟练（技能 / 豁免有熟练才有，倍数按半 / 熟练 / 专精；覆盖值存在时只显示一行「覆盖值」）；**结构化效果**带来的加值（§12.3 `rollBonus`、`skill`/`save` 的 `bonus`）。**没有结构化数据的效果不自动出现**（不手写「神导术 +1d4」之类预制）。
  - **效果带来的行有 ×**（用户可忽略这次）；自动行与手动行同款。
  - **[＋ 自定义加值 ▾]**：下拉里选「常数」「骰式」；展开一行 `[名称] [值：+2 / −1 / 1d4 / 2d6] [添加]`；校验格式；一行 ×。**不提供预制的法术名**；同一行旁有链接「查资料」，点 = 打开**资料弹窗**（搜索法术 / 特性 / 物品条目，看这次到底怎么加点、加什么骰式），**用户读完回来自己填**。
  - 公式显示：`1d20 +4 +1d4`；悬停每一行显示来源。
- **④ 难度 / 对手**：
  - **固定 DC**：数字输入框（步进 ± + 手输）+ 一行 6 个**纯数字**快捷（5/10/15/20/25/30，统一大小，**没有「很易 / 易 / 中等」文字，没有在小框里塞字**）+ 🎲 随机一个 DC（整数 **1–25**，每个数等概率）。
  - **对抗**（仅检定标签，p174）：`对手 [ 魔法师 ▾ ]`（真下拉：人物列表 +「手动输入」）、`对手的检定 [属性 ▾][技能 ▾]`（同 ②，默认读对手的数据）、`对手加值`（自动算好、可改）、对手掷法（优势 / 普通 / 劣势）。结果：胜 / 负 / **平局：局面维持原样**。
  - **不设**：只给总值。
- **⑤ 掷法**（p173）：分段「优势｜普通｜劣势」是**你手动加的一个来源**；下面列出所有来源，**每个有悬停说明、可 ×（忽略）**：
  - 状态的结构化效果（`condition.effects` 里 `kind: advantage / disadvantage`，`on` = `check` / `save` / `initiative`，带 `scope` 的按属性筛，如束缚只对敏捷豁免）；
  - 力竭等级（1 级起检定劣势；3 级起攻击与豁免劣势；读 `exhaustion.levels`）；
  - 协助（p192，检定标签）；灵感（人物有灵感时可选，用掉）；
  - **同时有优势和劣势 = 互相抵消，只掷一颗 d20，不管两边各有几个**（页面写明 p173）。
  - 自动失败类提示（目盲：依赖视觉的检定自动失败；麻痹 / 石化 / 震慑 / 昏迷：力量与敏捷豁免自动失败）以黄色提示行显示，**由用户判断**，不拦截掷骰。
- **底栏「掷骰」**：掷、显示结果卡（总值、成功 / 失败（对照 DC 或对手）、天然 20 / 1 标记**但不自动判成败**——规则只有攻击检定有这条）、两颗 d20 的明细、逐项算式、「填入输入框」「复制」；**掷完优势 / 劣势回到普通**；结果区位置不变。

### 11.3 快捷掷骰（从人物页点数字进来）

点属性大数字 / 豁免 / 技能 / 先攻：骰盘打开到对应标签，**行动者、属性、技能、加值全部预先填好，用户只需要选「掷法」和「DC」再掷**（光标落在 DC 上）。点「全部技能 18 项」（窄屏）= 打开检定标签并展开「技能」下拉。**点击只填入，不自动掷**（驾驶员 2026-11-04）。

### 11.4 被动（取代：基本 §4.2.5 / 抽屉 §5.5 里的「被动只是看」）

点战斗卡的被动徽章：骰盘打开**检定**标签，项目已选好技能，**模式切到「被动」**，并**随机一个 DC** 填入（整数 **1–25**，可改、可再随机）。被动 = **10 + 加值**，有优势 +5、有劣势 −5（p175）；底栏按钮写「对比 DC」，结果写「通过 / 未通过」。想主动掷就把模式切回「主动」。**这是给「由用户当 DM、AI 只写描述」的用法准备的**：被动值本来是 DM 脑子里记着的数，这里让用户把它拿出来对一个 DC。

### 11.5 数据钩子（取代：`prefill(payload)`）

`useDiceStore().openRoll(payload)`：

```ts
type RollPayload = {
  actorId: string                           // 人物 id
  kind: 'check' | 'save' | 'initiative' | 'death-save' | 'passive' | 'free'
  ability?: AbilityKey                      // 检定 / 豁免的属性
  skill?: SkillKey                          // 技能（可与别的属性搭配）
  expression?: string                       // kind='free' 才用
  note?: string
  dc?: number                               // 被动时随机给的
}
```

- 加值与来源**由骰盘现算**（调用派生函数 + 结构化效果），不由调用方传死；`prefill` 保留为旧入口并转调 `openRoll`（kind=`free`）。
- 骰盘的最近记录、读取与保存逻辑一律不动；「填入输入框」的注释格式沿用（基础版）。

### 11.6 不做（登记，§17）

攻击、伤害（含重击翻倍）、先攻追踪、随机表、记录标签；团体检定（p175）；协助以外的合作规则；骰盘「行动者」里的待发送队列。

## 12. 数据：效果结构化（驾驶员 2026-11-04：状态与效果必须是结构化数据，不是文字）

### 12.1 现状（规划者已查，执行 agent 批 0 复核）

- **状态**：15 个状态（`condition`）与专注、突袭（`status`）的 `effects` 已是结构化（`effects.ts` 22 种之一，如恐慌 `disadvantage on check/attack`、束缚 `disadvantage on save scope dex`），力竭 6 级逐级结构化；**但**「针对它的攻击优势 / 自动重击」「魅惑者社交检定优势」等只有文字（见 `docs/模块数据约定.md` §10 登记）。
- **法术**：`duration[]` 已有 `type / amount / unit / concentration`（结构化）；**但**祝福术「攻击与豁免 +1d4」、神导术「一次属性检定 +1d4 后终止」只在正文里，`effects` 的 `skill` / `save` 的 `amount` 只能是整数，**表达不了骰式加值**。
- **疾病、特性、物品（药水）、环境规则（掩护、困难地形、水下战斗、视野与光照）**：条目只有正文，**没有结构化时长 / 专注 / 效果**。
- **人物里的效果**：`personEffectSchema = { name, ref?, note?, duration?: 文字 }`，全是文字，没有类别、是否专注。

### 12.2 要做的事（顺序：先修管线，再逐条；**不手写每条数据**）

按 `docs/规划者守则.md`、`docs/开发规范.md` §12.5 与决定「先修管线再逐条」：

2. **转换器**：在 `tools/data/convert/` 里找到每类的转换位置，能从来源（5etools）结构化读出的（疾病、特性与物品的时长、法术的专注）**修转换器重建**；来源本身没有结构的，才进 `tools/data/overlay/*.json` 逐条补（带 `reason`）。

### 12.3 骰盘怎么用它

骰盘「③ 加值与骰式」的自动行**只来自** `rollBonus`、`skill`/`save` 的 `bonus`、`advantage`/`disadvantage`、`hpMax`、`ac` 等**已结构化的 `effects`**；没有结构化的效果只在资料弹窗里给用户读，用户自己用「自定义加值」填。

### 12.4 人物里的效果与新字段（取代：基本 §5.2 `effects` 一行；其余字段沿用）

```ts
personEffectSchema = {
  id: string                         // 实例编号
  ref?: string                       // 条目编号（custom 没有）
  category: 'condition' | 'status' | 'disease' | 'spell' | 'other'
  name: string
  nameEn?: string
  duration?: { type: string; amount?: number; unit?: string; concentration: boolean }
  concentration: boolean             // 冗余便于列表筛，来自 duration
  effects?: Effect[]                 // 加入时的结构化 effects 快照
  note?: string                      // 仅自定义
  addedAt: timestamp
}
```

- **迁移**：旧 `{name, ref?, note?, duration?: 文字}` → 新结构（`category` 由 `ref` 前缀推断，推不出的 `other`；`duration` 文字保留进 `note`；`concentration:false`）；`schemaVersion` 按开发规范 §3 第 6 条判断，需要就带迁移与迁移测试。
- 新增（设定类）：`block.hpMax` 之外 → `hpAdj: Array<{label, flat?, perLevel?, source}>`、`hitDiceOverride?: Record<骰面, 数量>`；新增（当场）：无。**`hp.current` 等沿用。**
- `hpRolls?: Record<级数, 整数>`（升级掷骰记录，派生 §6.7 已写「取记录值」）。
- 所有熟练类条目的 `sources` 沿用基本 §5.1；**新增**：被移除的自动项的「可恢复」不另存数据——由「当前种族 / 职业 / 背景 / 等级应分配的内容」减去「当前已有」现算（所以「按来源重新分配」不需要额外字段，也不会因为旧数据而错）。
