# 内容包格式说明（D&D 5e 2014 数据）

适用对象：**官方包与自制包完全一样**。官方书籍包、SRD 包、你导入的别人的包、你自己做的包，走同一个格式、同一个安装校验（`src/rules/dnd5e2014/data/check.ts`，构建端用同一个引用提取函数）。

本文件只讲「包怎么写、包之间怎么扩展」。条目各类型的字段见 `docs/units/D1_数据管线.md` §4；容器格式（zip、文件名）见 `docs/units/L1_*.md`。

## 1. 包清单（`trpg-manifest.json` 里的 `pack`）

| 字段 | 含义 |
|---|---|
| `id`、`ruleId`、`category` | 包编号、规则（`dnd5e2014`）、分类（规则 / 冒险 / 设定 / 工具） |
| `name`、`nameEn`、`version` | 名称与语义化版本。**内容变了就升版本**，否则设备上已装的不会更新 |
| `lineage` | 同一个包所有版本共用的编号；换了 lineage 就是另一个包 |
| `dataVersion` | 数据格式代际。当前为 **3**；扩展只接受不高于自己支持的版本。代际 ≥ 3 的包按本文的严格规则校验；更老的包照常安装，只在控制台提示 |
| `relationships.requires` | 依赖的包。条目里的结构引用只能指向本包、SRD、以及这里列出的包（含它们的依赖） |
| `sourceNames` | 本包条目里出现的来源代号 → 书名，例如 `{ "PHB": { "name": "玩家手册（2014）" } }`。界面据此显示「出自《玩家手册》第 N 页」，不用任何写死的书名表；自制包写自己的来源代号即可 |
| `entryCount`、`typeCounts`、`contributes` | 数量，安装时校验 |

## 2. 引用规则（一条规则，三个地方用）

**结构引用**：条目数据里指向别的条目的字段。写在 `src/rules/dnd5e2014/data/refs.ts` 的 `structuralRefs`，包括：`owner.id`、`classId`、`parentRace`、`baseItem`、`variantOf`、`feature`、`traits`（编号列表）、`members`、`contents[].item`、`advancement[].items / pool / explain / replaces`、`joins[].to / replaces / pool`、`requires.*`、`effects[].spells`、正文里的 `tableRef` 等。

规则：

1. **目标必须存在**。
2. **目标必须在本包或本包声明的依赖里（含依赖的依赖）或 SRD 里**。方向只能向下，不能指向没有声明的包。
3. 正文里的行内引用 `{{ref:条目编号|显示文字}}` 是「软」的：目标不在依赖里时，官方构建会把它剪成纯文字；自制包可以写，目标不在时界面显示「未安装的条目」。
4. `supersededBy`、`versionGroup` 这类「版本标记」允许指向更高层的包，不算依赖。

**为什么这样**：包是积木，只装一部分书也不能出现指向没装的书的断链；依赖写明了，装一个包时就知道要先装什么。

## 3. 跨包扩展：只有一条通用规则——「扩展包自己登记」

**一个包给别的包的条目加东西，只能写在自己身上，不能改别人。** 被扩展的一方（比如 SRD 里的牧师）不写任何指向扩展包的内容；扩展包装上了才出现，卸掉就消失。

扩展有四种，且只有这四种：

### 3.1 `joins`：加入职业 / 子职业的某一级，或加入物品家族

条目（特性）自己带一个数组 `joins`：

```jsonc
{
  "id": "feature.my-blessing.hb", "type": "feature", "name": "自制祝福",
  "data": {
    "owner": { "type": "class", "id": "class.cleric.phb" },
    "level": 2, "optional": true,
    "joins": [
      { "to": "class.cleric.phb", "level": 2, "as": "optional", "replaces": "feature.cleric-spellcasting.phb" }
    ]
  }
}
```

| 字段 | 含义 |
|---|---|
| `to` | 被加入的条目：职业、子职业（`as` 为 `optional`、`option`）或物品家族（`as` 为 `member`） |
| `level` | 加入的等级，1–20，职业 / 子职业必填 |
| `as` | `optional`：可选授予，玩家可以选择获得；`option`：加入该等级已有的「选择池」（如图腾武者 3 级的熊 / 鹰 / 狼）；`member`：成为物品家族的成员 |
| `replaces` | `as: optional` 时：选择它就不再获得的那个特性，必须是 `to` 自己的特性 |
| `pool` | `as: option` 时：`to` 在该等级有多个选择池才需要，写其中任一现有成员的编号 |

**校验**（安装与构建都做）：目标存在且在依赖里；只有特性能登记 `optional` / `option`；目标必须是职业或子职业、等级合法；`option` 的目标在该等级必须有选择池（多个必须用 `pool` 指明）；`member` 的目标必须是物品家族；`replaces` 必须存在并属于目标。

**读法**（界面、人物模块都按这个读）：

- 某职业 / 子职业在某一级的「可选特性」= 已安装的包里所有 `joins` 指向它、`as: optional`、`level` 相同的特性。
- 某选择池的选项 = 池里原有的 + 所有 `as: option` 指向它的特性。
- 官方例子：塔莎的 29 条可选职业特性与受祝击等 16 份子职业变体（`optional`）、剑湾的麋鹿与猛虎（`option`）。

### 3.2 补丁：给条目补背景描述

类型 `lore` 的条目，`data.target` 指向被补充的条目，`data.lore` 是背景描述正文。补丁放在来源书的包里，目标可以在更低层的包（如 SRD）。界面在目标的详情页显示「背景描述」，并注明出自哪个包。

### 3.3 修改版

条目带 `override: { target: { packId, entryId } }`，目标所在的包必须声明为依赖，同一个目标只能被同一个包修改一次。用户在库里可以选用、停用、回到原版。

### 3.4 系列（物品家族）

一条魔法变体展开成很多具体物品时（如卓尔 +1/+2/+3 的全部武器与护甲），用一个**家族条目**（`category: "family"`）汇总：`data.members` 列出全部成员。成员自己不写指向家族的字段；界面按「哪个家族列出了我」反查并显示「系列：…」。成员也可以用 `joins` 的 `as: member` 主动加入别人的家族。

## 4. 自制包示例

目标：做一个叫「我的牧师扩展」的包，给 SRD 的牧师 2 级加一个可选特性。

1. 新建包（库 › 我的 › 新建），或导入别人写好的 `.trpgpack`。
2. 清单：`requires` 写上 SRD 或你依赖的书的包编号；`dataVersion` 写 3；`sourceNames` 写你的来源代号（如 `{ "HB1": { "name": "我的牧师扩展" } }`）。
3. 写一个特性条目，`data.owner` 指向牧师，`data.joins` 写 3.1 的样子，`data.src.book` 写你的来源代号。
4. 安装。装上后，牧师详情页出现一行「可选特性」，名字后面是灰色小字的包名；卸载这个包，那一行消失，SRD 里的牧师一字不改。

安装时如果写错了（目标不存在、没声明依赖、等级不对、替代的特性不属于目标），会被拒绝，提示具体是哪个条目的哪个字段。

## 5. 与官方构建的关系

- 书目由政策表 `tools/data/config/bookPolicy.ts` 登记，书名默认取 5etools 的 `books.json`；加一本书是加一行政策，不改代码。
- 包的依赖由条目的结构引用推出（`structuralRefs(data, 'dependency')`），政策表只在「引用经裁剪后没有硬引用、但规则上要求先装那本书」时额外写明。
- 构建会检查：依赖只指向层级更低的包、没有环、所有引用存在且在依赖里、所有 `joins` 合规。
