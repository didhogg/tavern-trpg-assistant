# 任务总纲

## 1. 产品目标

开发 SillyTavern / TauriTavern 前端扩展「TRPG 跑团助手」：玩家在酒馆中手动管理一场 TRPG 战役，快速掷骰与结算，把已确认的战役事实以省 token 的格式交给 AI，让酒馆 AI 按结果写出剧情。

- 首个规则：D&D 5e（2014）及其官方扩展包。
- 架构对规则通用：规则作为可切换的规则包接入。
- 角色分工：玩家是最终裁决者；规则引擎负责数字（掷骰、加值、HP、资源）；酒馆 AI 负责叙事；DM/KP 助手（进阶版）按规则给出裁决建议，玩家确认后生效。

## 2. 版本与里程碑

按顺序执行。一次只激活一个里程碑；当前里程碑以 `NEXT.md` 为准。
每个 Unit 在开工前须有已定稿的单元蓝图 `docs/units/<Unit编号>_<名称>.md`；没有定稿蓝图的 Unit 不开工。

## 3. 执行协议

1. 开工：读 `AGENTS.md` → `NEXT.md` → 本文件当前里程碑 → `docs/开发规范.md` 相关章节 → 当前 Unit 的单元蓝图。
2. 复述：用三句话写出本次的目标、红线、验收，写入 `NEXT.md` 的“当前任务”。
3. 实施：只改当前里程碑范围内的文件；范围外发现写入 `NEXT.md` 的“待议”。
4. 验证：按 `docs/开发规范.md` §8 取证；未取得的证据如实标为未验证。
5. 收尾：更新 `NEXT.md`（已完成、证据位置、下一步、阻塞）；本地 Git 提交。
6. 需要驾驶员决定的事项（规则裁定、范围变化、单元蓝图定稿、真机验收）停下询问，不自行决定。
