# D1.2-G2 数据可用性体检 报告

本报告随各段（G2a → G2b → G2c → G2d）逐段增补。**现在写到：G2c 怪物与战斗。**

## G2a 人物底子

### 结果

- **19 项检查全部有自动测试**（新增 26 个测试，分 14 个文件）：职业熟练与技能、起始装备、法术位表、戏法与已知法术、职业表各列、属性值提升、兼职要求、逐级授予、子职业、跨包登记、种族与亚种、背景、专长、物品基础、法术本身、职业法术表、「任选」展开、使用次数。
- **发现 36 项**：数据缺陷 30、来源本身的问题 2、需驾驶员决定 4（明细见 `docs/probes/D1.2-G2_登记汇总_g2a.md`，由登记表生成）。
- **数据没改**：11 个包的哈希与开工快照一致（`docs/probes/D1.2-G2_快照.json`），包版本仍是 1.3.0。
- 验证：`npm run check` 276 个通过（类型检查、代码规范、单元测试）；`npm run test:data` 325 个通过（原 299 + 新增 26）。
- **整套 e2e 未运行；真机未看；数据未改。**

### 最该先看的发现

#### 1. 起始装备：「任选一件武器」这类选项几乎全丢了（11 个职业）

PHB 里很多职业的起始装备有「（a）某某或（b）任意简易/军用武器」「（a）鲁特琴或（b）其它乐器」「（a）材料包或（b）奥术法器」。数据里这些选项**整条被丢掉**，只剩第一个具体物品。我逐个职业对照 PHB 原文核实过：

| 职业 | 书上 | 数据里 |
|---|---|---|
| 野蛮人 | 巨斧，或任意军用近战武器；两把手斧，或任意简易武器 | 只有巨斧、手斧 |
| 战士 | 军用武器和盾牌，或两把军用武器 | 只有盾牌 |
| 圣武士 | 军用武器和盾牌，或两把军用武器；五支标枪，或任意简易近战武器；固定给链甲**和圣徽** | 只有盾牌、标枪、链甲 |
| 牧师 | 轻弩和弩矢，或任意简易武器；固定给盾牌**和圣徽** | 轻弩；固定只有盾牌 |
| 法师、术士、魔契师 | 材料包，或奥术法器；魔契师固定给「任意简易武器」 | 只有材料包 |
| 德鲁伊 | 木盾，或任意简易武器；弯刀，或任意简易近战武器；固定给**德鲁伊法器** | 只有木盾（写成「盾牌」）、弯刀 |
| 吟游诗人、武僧、游侠、奇械师 | 各自缺类别选项（其它乐器、任意简易武器、任意两把简易武器） | 缺 |

背景的起始装备里 49 项物品名（38 种）对不上物品条目：5 项是漏配（纸、羊皮纸、墨水笔、墨水），3 项是带描述的版本（作弊骰子、标记过的扑克牌、虚构公爵的印章戒指），41 项书上本来就是描述性文字（家系族谱、情书、信物等）。（执行文档写的 51 项是用名字精确比较量的，去掉括号后有 2 项能对上，所以是 49。）

#### 2. 法术：核心列表和可选扩展混在一起，奇械师几乎没有法术表

- **奇械师**的法术表只有 7 个法术；TCE 的完整列表是 85 个，其中 80 个在库里有条目。PHB 的法术包不能指向塔莎里的奇械师，所以缺了 73 个。
- **塔莎等书的「可选扩展法术列表」被直接写进了 PHB 法术的「职业」里**（65 处，如援助术多了吟游诗人和游侠）。核心列表和可选规则分不开。这正是 G2.5 要用 `joins` 的 `as: "spell"` 解决的。
- **子职业的扩展法术少了**：18 个子职业共 34 个等级里缺法术（共 37 个法术）。涉及奇械师（炼金师、战斗铁匠）、牧师领域（奥秘、死亡、锻造、和平、暮光）、德鲁伊（大地结社、野火结社）、圣武士誓言（征服、救赎、王冠、守望者、背誓者）、魔契师（深海、精类、咒剑、不死者）。缺的法术在库里都有条目，是转换时没挂上。例如死亡领域缺致病射线、锻造领域缺炽焰斩与元素武器、咒剑魔契师 1/3/4/5 级各缺一个。
- **法术区域没有结构化**：SRD 里 74 个有区域的法术（火球术 20 尺球形、探测魔法 30 尺球形……），区域大小只在文字里。
- **伤害类型错或缺**：延迟爆裂火球的伤害类型是力场（应为火焰）；烈焰风暴、冰风暴、流星爆各缺一种伤害；虔诚护卫没有伤害。

#### 3. 使用次数（uses）：29 个特性的 `uses` 有问题

文字自洽检查、Foundry 的 SRD 特性对照、**逐个读原文**三条线索合并、去重后共 **29 个特性**（更正记录：初稿写 43 个，其中 12 个是龙裔各色吐息武器及荒野形态本身——它们自己就是次数池；第二稿写 31 个，逐个读原文后又发现传播鼓舞〔魅力调整值次/长休〕、活化表演〔1 次/长休〕的次数本来就对。均已在测试里放行）：

- **14 个消耗别的池**，自己又有一份 `uses`，会重复计数：诗人激励 9（语出惊人、超凡技艺、三种剑舞、心灵之刃等）、荒野形态 5（星耀形态、元素荒野形态〔消耗 2 次〕、野火精魂等）、吐息武器 1（龙之威怖）。
- **6 个其实是给别的池恢复**：激励之源、先发激励、有箭无患、不懈、术法复苏、奥术回想。
- **3 个是休息时要重置的状态**：坚韧狂暴（DC 递增）、卡瑟利之链（按目标）、邪魔体魄（休息后重选抗性）。
- **1 个**地狱遗赠：两个法术各一次，数据只有一份 `uses`。
- **7 个本身没有次数限制**：额外攻击（两条）、怒不畏死、狂醉乱舞、妖精漫游者魔法、剑舞大师、书之魔契。
- **1 个特殊资源**：逝者遗物（灵魂饰品，上限熟练加值，靠生物死亡获得）。
- 合理的已核对放行：幸运、招牌法术、奥术回想（每天 1 次）、传播鼓舞、活化表演、龙裔吐息武器、荒野形态。

修法按驾驶员批准的「资源与休息」结构（`consumes`、`restores`、`tracker`），见 G2.5 文档第 2.5 节。

#### 4. 种族、背景、专长

- **4 个亚种体型写成中型**（森林侏儒、岩侏儒、轻足半身人、强健半身人），而种族是小型。读取器按「亚种覆盖种族」读就读错。
- **变体人类**是「替换」人类的属性加值，数据没有表达替换，叠加读会读成全属性 +1 再加两项自选。
- **天生法术**：提夫林的地狱遗赠、卓尔魔法、灰矮人魔法的解锁等级（3 级、5 级）没有字段；深侏儒的天生施法没有对应的授予法术。
- **11 个剑湾背景没有结构化的特征表引用**：书上就是一句话「使用某某背景的特征表」。
- **2 个专长**（精灵准确、天赋异禀）的种族前置只写成纯文字，程序读不出。
- 战士兼职要求「力量 13 **或** 敏捷 13」写成一个对象里的两个属性，没有约定它表示「或」。

#### 5. 小问题

- 魔契师职业表「法术位环阶」列写法不统一（「1环」和「5th」混用）。
- 「任选」记号同一意思有多种写法：`animal-handling` 与 `animal handling`、`smiths-tools` 与 `smith's tools`、`gaming set` 与 `anyGamingSet`，共 11 个条目；`lang:other` 含义不明（3 个条目）；`lang:aquan/auran/terran` 与 `tool:vehicles` 指向没有条目的东西（11 个条目）。
- 四象武僧、先祖守护者带了 `progression=full` 的施法标记，却没有法术位表（先祖守护者本来就没有施法）。
- 套组：牧师套组缺 4 项（施舍箱、香块、香炉、祭袍）、学者套组缺小刀与沙袋且羊皮纸数量 1（书上 10）、窃贼套组缺一条细绳；这些东西在物品库里没有对应条目（共 10 件 SRD 装备没有条目）。
- 弹丸（单件 0.2 铜币）价格被取整成 0；牧笛没有价格。

### 对得上的（好消息）

下面这些逐项核对后**完全一致**，人物模块可以直接依赖：

- **法术位表**：全施法、半施法、三分之一施法（奥法骑士、奥法诡术师）、奇械师、契约魔法，11 个施法职业或子职业（吟游诗人、牧师、德鲁伊、术士、法师、圣武士、游侠、魔契师、奇械师、奥法骑士、奥法诡术师）× 20 级 × 9 环逐格一致；我自己打的期望表先和 5e API 对过一遍。
- **戏法数、已知法术数、准备法术公式**（法师法术书、牧师/德鲁伊、圣武士、奇械师）。
- **职业基础**：生命骰、豁免、护甲/武器/工具熟练、技能选项、子职业等级、兼职先决条件与兼职熟练（除战士那一项写法）。
- **属性值提升等级**：13 个职业与 PHB 一致，其中 12 个 SRD 职业另与 5e API 对过。
- **职业表各列**：20 级都有值；狂暴次数、武艺、气点、无甲移动、偷袭、术法点等与 5e API 一致；法术列与施法数据自洽。
- **跨包登记（joins）**：塔莎的 45 项可选特性与变体 45/45 与原始数据一致；图腾武者 3/6/14 级的选择池读得出五种图腾。
- **PHB 种族与亚种**：属性加值、速度、黑暗视觉、语言、熟练 208 项检查，仅上述体型与变体人类两处不对。
- **PHB 背景**：技能、工具、语言、特征表行数 126 项检查全部一致。
- **PHB 专长**：42 个专长的前置条件与属性提升全部一致（除精灵准确、天赋异禀两个写法）。
- **武器表与护甲表**：SRD 的 227 件装备、667 项检查，伤害骰、伤害类型、射程、属性、护甲等级、敏捷上限、力量需求、隐匿劣势、价格、重量一致。
- **法术本身**：319 个 SRD 法术、2795 项检查（环级、学派、施法时间、射程、成分、持续时间、专注、仪式、豁免、攻击），除上述区域与伤害外一致。
- **逐级授予**：1,573 个授予的条目编号全部存在；每级特性数与 5e API 只有 7 处粒度差异（领域/誓言法术单列、游侠 6 级合并），没有缺漏。

### 方法与独立来源

- 期望值不读构建输出。来源：PHB 中译原文（含解析第 11 章全部职业法术列表）、TCE 英文 PDF、5e API（SRD 职业逐级表、法术、装备，下载到 `reference/dnd5eapi-SRD法术（核对用）/`）、Foundry dnd5e 系统的 SRD 特性与法术、5etools 原始数据（子职业扩展法术、变体特性、奇械师列表）。这些都放在被 git 忽略的 `reference/`，**不进数据包**。
- **5e API 自己有 5 处与 PHB 不符，已逐个核实并在测试里写明**（数据与 PHB 一致，不算数据缺陷）：回生术、群体疗伤术、群体医疗术的学派（API 用了 2024 版）；环甲具装价格（API 写 12 gp，PHB 是 4 倍 120 gp）；铁钉与特种鞍座重量；铁蒺藜价格口径；忠诚护卫犬的攻击类型。API 的职业法术列表也混入了 2024 年改动，所以职业法术表改用 PHB 原文做期望值。
- 「自洽检查」（数据与自己的文字或自己的另一种写法互相核对）在登记表里标了 `selfCheck`：使用次数的两项。
- 测试里读 `reference/` 的部分在文件不存在时自动跳过；在本机都已执行。

### 限制（没覆盖的）

- XGE、TCE、BMT 的非 SRD 法术：只核对了职业列表（对 PHB 列表之外的可选扩展）和子职业扩展法术，没有逐项核对施法时间等字段（没有独立来源）。
- 非 PHB 的种族、背景、专长：只做结构与代码的自洽检查（148 个种族/亚种行），没有逐项对书。
- 非 SRD 的物品：只检查了内容物与家族成员是否存在，没有逐项核对价格重量。
- 「升环施法」「戏法成长」「材料成分价格」「法术攻击与豁免难度」这些归 G2b。

### 需要驾驶员决定的

1. **`lang:other` 的含义**（吉斯人、穴蜥人、啵灵蛙）。
2. **原初语方言（水、风、土）与载具熟练要不要补条目**；不补的话约定为代码。
3. **战士兼职要求的「或」怎么写**（约定「一项里多个属性 = 或」，还是改成 `any`）。
4. **奇械师的火器熟练**：TCE 写的是「DM 使用火器规则且你接触过火器时才熟练」，数据写成了无条件；怎么表示条件性熟练。
5. **坚韧狂暴、卡瑟利之链**这类「不是每长休几次」的限制用什么字段表示。
6. **无独立 `uses` 的特性**（29 个）怎么处理——已定：按「资源与休息」结构处理（G2.5 第 2.5 节）。
7. 剑湾背景「使用某某背景特征表」：补结构化引用，还是保持文字。
8. **工具选择只有文字**（吟游诗人自选三种乐器、武僧一种工匠工具或乐器、奇械师一种工匠工具）：要不要给它加结构（类别 + 数量）。

- **新增发现 43 项**（数据缺陷 38、需驾驶员决定 5），汇总见 `docs/probes/D1.2-G2_登记汇总_g2b.md`；纯文字特性分诊清单见 `docs/probes/D1.2-G2_纯文字特性分诊.json`。
- **数据没改**：11 个包哈希与开工快照一致，包版本仍是 1.3.0。
- 验证：`npm run check` 276 个通过、`npm run test:data` 341 个通过（原 299 个；G2 新增 42 个）；**整套 e2e 未运行；真机未看；数据未改。**

### 最该先看的发现

**1. 样卡：19 张卡、141 项手算对照，135 项对，6 项错，全部能追到下面的缺陷**
- 全对的有：野蛮人和武僧的无甲防御、警觉专长（先攻 +5）、强健专长（生命 +2/级）、观察者专长（被动察觉 +5）、各职业的法术位、法术豁免难度与攻击加值、生命值、豁免、技能、被动察觉、黑暗视觉、速度（种族）。
- 错的 6 项：龙脉术士的无甲护甲等级（读出 12，应为 15）和每级 +1 生命（缺）；丘陵矮人的矮人坚韧（缺）；武僧 5 级和野蛮人 5 级的速度（读出 30，应为 40）。原因都是效果里的数值被写成了 0 占位，或条件只是文字。

**2. 效果里有占位和说不清的条件**
- **13 个条目的效果数值是 0 的占位**：双持客、灵活移动、快速移动、无甲移动（五种移动方式）、矮人坚韧、蜥蜴人天生护甲、盗贼手套、神枪手奥术火器等。书上都有具体数字，是 Foundry 公式没解析出来。
- **18 个条目把影响数值的效果留在了说明文字里**：龙脉术士的龙族韧性、魔鬼视界、石之符文、兔人先攻、凶蛮重击（暴击额外骰）、冠军强化重击（暴击范围）、觉知头盔等。
- **3 个效果的触发条件只有文字**（「狂暴中」「未穿护甲」「未穿护甲且未持盾」）；读取器只能按关键词猜。
- 1 个公式（奥术守御）用了公式引擎不认识的变量。
- 601 条效果的格式本身全部合法。

**3. 行动：3,320 条全部能被读取**
- 2,672 个伤害/治疗骰式全部被项目自己的掷骰器读通；伤害类型、豁免属性、难度写法全部合法；法术的 201 个豁免动作难度都是「按施法者」或书上的固定数字。
- 只有一个问题：**41 个行动的「消耗资源」指向的是中文名（卓越骰、奥术射击），不是特性编号**，指向不到资源池。

**4. 资源池**
- 13 个职业成长数值（狂暴次数、狂暴伤害、吟游诗人激励骰、休憩之歌、引导神力、动作如潮、不屈、武艺、气点、无甲移动、偷袭骰、术法点）逐级 260 项与 5e API **全部一致**；魔契师已知祈唤与 PHB 职业表一致（5e API 在 4、6 级与书不符，已核实以书为准）。
- 我又逐个读了 15 个 PHB 资源池的原文：**4 个最大次数与书不符**——卓越战技写 1（应为 4/5/6 个卓越骰）、圣武士引导神力 7 级起写 2（PHB 只有 1 次）、神圣感知写 1（应为 1+魅力调整值）、预兆写 1（应为 2 个骰，14 级 3 个）。另有 4 个限制不是「N 次/休息」：神圣干预（成功后 7 天冷却）、催眠凝视（按目标）、混沌之潮和王车易位（有事件触发的额外恢复）。

**5. 休息盘点（为【活动】系统准备）**
- 354 个特性和专长的文字提到短休、长休或黎明，其中 312 个有 `uses`，42 个没有。
- 这 42 个里 16 个需要结构：6 个「每长休免费施展某法术 1 次」却没有次数（奇械学徒、精类之触、影界之触、心灵感应、巨蛇法术、超魔导师）；7 个「每次长休后重选或重新获得」（卡牌占卜师、灵药、钢铁守卫、原初伴侣、巫咒战士、死亡之友、宁神境）；2 个按目标/冷却（读心、有限祈愿术）；1 个每天 1 次（法力恢复戒指）。其余 26 个是通用规则（施法职业的法术位恢复）或叙述，不是缺陷。
- **29 个种族特质提到多个法术、却只有一份 `uses`**：其中 27 个所属种族自己的 `spellGrant` 已经给每个法术各带次数，特质上的 `uses` 是多余的；另 2 个种族连 `spellGrant` 都没有。
- 魔法物品充能：193 个，**`charges.rechargeAmount`（字段已有）全是空的**，约 166 个的文字里写着「黎明恢复 1d6+1」之类；7 个没有恢复时机。

**6. 状态：15 个状态、50 项机制要点**
- 力竭 6 级逐级正确；法术与怪物里用到的 15 个状态代码全部合法。
- 缺的：倒地、束缚没有「自己的攻击劣势」结构；石化缺毒素与疾病免疫；魅惑者的社交检定优势、麻痹/石化/昏迷时针对它的攻击优势，连文字里都没写。
- **8 项「针对该生物的攻击有优势/劣势/自动重击」只有说明文字**（目盲、隐形、倒地、束缚、震慑、麻痹、昏迷）：现有效果只能表达「自己」的优势劣势。

**7. 施法**
- **升环施法**：154 个法术的升环效果全是文字。其中 **74 个在 5etools 里带结构化标签，可直接导入；我拿 5e API 验证过——能逐环比较的 32 个 SRD 法术，标签算出的每环骰式 32/32 一致**。其余 80 个没有标签（目标数 32、召唤物 20、持续时间 12、其他 10、范围 3、治疗 3），要自己对照原书结构化。
- **戏法成长**：44 个戏法里 9 个能和 5e API 逐等级比较，全对；只有魔能爆缺（射线数 1/2/3/4 道）。
- **材料成分**：73 个写着价值，价格（铜币）为空；32 个写着会被消耗（另 1 个可选消耗），「是否消耗」为空。5etools 里都有，价格与材料文字里的 gp 数 73/73 一致。
- **对得上的**：6 个反应法术都有触发条件；仪式施法方式 9 个职业全对；术士灵活施法转换表（1–5 环花 2/3/5/6/7 点）与 5e API 一致；法术卷轴的豁免 DC 与攻击加值表 10 行全对（但稀有度被译成「通用语」、环阶有「6th/7th/8th」，5 处）；206 个物品的附带法术编号全部存在。
- **专长**：魔法学徒、仪式施法者、法术射手、精类之触、影界之触要玩家「选职业、选 N 个戏法和 1 个法术」，数据没有选项池，建卡时无法弹出选择。

**8. 背包**
- 425 件普通装备里 191 件没有重量、38 件没有价格——**这是书上本来就没写**（PHB 装备表里蜡烛、纸、肥皂、麦酒等重量写「—」），不算缺陷。
- 143 个物品的同调限制（「由术士、法师同调」）只是文字；21 个消耗品（药水、油、灵药）没有行动，点「使用」无法结算（治疗药水已有）。

**9. 纯文字机制特性分诊**：1,140 个纯文字机制特性经关键词初筛，**A 类（影响派生数值）144 个**、B 类（影响行动与资源）412 个、C 类（叙述）584 个。A 类的构成：熟练 64、抗性与免疫 47、速度 18、感官 7、先攻与被动 4、生命上限 4、属性值 3、护甲等级 2。我抽 30 条人工看过，约 85% 确是 A 类，其余是误报（如「抑制元素」是反应动作）。

### 对得上的（好消息）

- 力竭逐级、15 个状态的代码、行动的骰式与伤害类型、201 个法术豁免难度、13 个职业成长数值的 260 项、术士灵活施法表、法术卷轴数值表、反应法术触发条件、仪式施法方式、物品附带法术编号。
- 5etools 的升环标签对 SRD 法术 32/32 正确，材料价格 73/73 正确——这说明**升环和材料成分走「导入」这条路是可靠的**。

### 方法与独立来源

- 样卡的期望值是我按 PHB 规则逐张手算的（算式写在 `tests/data/consumer/expected/samples.ts`）；资源池对 5e API 和 PHB 原文；状态对 PHB 附录 A；升环、戏法成长、材料成分对 5e API 与 5etools 原始数据；法术卷轴表、灵活施法表对 DMG/PHB 与 5e API。
- 本轮又发现 5e API 一处与 PHB 不符：魔契师已知祈唤在 4 级、6 级写 3 和 4（书上是 2 和 3），测试以书为准。
- 「初筛」的分类（A/B/C、使用次数的归类）都标在登记表里，人工读过原文确认的与关键词筛的分开写。

### 限制

- 纯文字特性分诊是关键词初筛，A 类有约 15% 误报，需要结构化时逐条对照原书。
- 样卡覆盖 13 个基础职业 1 级、5 个高等级和 1 组兼职施法者规则；没有覆盖全部子职业和种族的组合。
- 怪物、危害、物件、规则速查等归 G2c；随机表、搜索字段、交给 AI 的文字归 G2d。

### 需要驾驶员决定的（G2b 产生，6 项，推荐在 G2.5 文档 2.10）

1. 状态里「针对该生物的攻击优势/劣势/自动重击」要不要结构化——推荐做（优势/劣势效果加可选 `against` 标记）。
2. 奇械师注法对物品的改动要不要结构化——推荐不做。
3. 同伴随主人等级变强的数值——推荐放到 G2c 一起设计。
4. 143 个物品的同调限制——推荐不做。
5. 暴击范围、暴击额外骰要不要新增效果类型——推荐做。
6. 专长「选职业、选 N 个法术」的选项池写法——推荐做。


## G2c 怪物与战斗

### 结果

- **检查项全部有自动测试**：怪物基础（护甲、生命值、速度、属性）、挑战等级与经验值、豁免与技能、攻击与伤害（含充能、多重攻击、传奇动作）、怪物施法、抗性与免疫、怪物部件、重印版本标记、危害与疾病、物件与载具、规则速查、经验值与遭遇数字表、召唤与同伴。G2 现共 51 个测试、35 个文件。
- **新增发现 30 项**（数据缺陷 18、来源本身的问题 6、需驾驶员决定 6），汇总见 `docs/probes/D1.2-G2_登记汇总_g2c.md`。
- **数据没改**：11 个包哈希与开工快照一致，包版本仍是 1.3.0。
- 验证：`npm run check` 276 个通过、`npm run test:data` 350 个通过（原 299 个；G2 新增 51 个）。
- **整套 e2e 未运行；真机未看；数据未改。**

### 最该先看的

**1. 怪物图鉴中译文本不能当裁判。** 我把怪物图鉴的每个怪物数据块解析出来逐项对照（369 个怪物、5,376 项），数据与它不一致的 49 处，我逐个读了原文，结论是**除了灰矮人、枯藤怪的生命骰式，其余全是中译文本自己的印刷或识别错误**：
- 大地精长官的属性被抄成了普通大地精的；魔兽人、烟魔蝠、观察者眼魔的属性与英文原书不符；
- 远古黄铜龙体质豁免写成 +16（按属性和熟练加值算应为 +13，数据是对的）；石人的速度读成了滚动时的 60 尺；
- 怪物图鉴原文里黄铜龙雏龙的经验值写 450（应为 200）。

5e API 也不全对：它的蜥蜴人护甲等级、石化蜥蜴护甲等级、邪教狂信者生命值、灰矮人生命骰式、闪现犬和巨蜘蛛的被动察觉、鳄鱼游泳速度、几处经验值（怯魔写 25，应为 50）都抄错了。所以**两个来源都只当参考，不当裁判**；真正确认的缺陷下面单列。

**2. 确认的缺陷**
- **生命骰式抄错 3 个条目 4 条**：灰矮人、枯藤怪应为 4d8+8（生命值 26）；噬魂怪（VGM 和 MPMM 两个版本）应为 17d10+34（生命值 127，MPMM 英文原文已核对）。另有 4–5 个怪物骰式与生命值对不上，手边没有对应原书，先不改。

**3. 抗性写成了「伤害代码（条件文字）」的整串字符串，约 300 条（占全部抗性的 17%）**
- 例如「bludgeoning、piercing、slashing（来自非魔法攻击）」。主要是非魔法攻击约 190 个、非银质武器约 70 个、非精金武器约 16 个、微光或黑暗中约 14 个。
- 影响：战斗里自动减伤读不出「哪些伤害类型、什么条件下」，会把魔法武器也减半。

**4. 召唤物与同伴（45 个）读不到数值**
- 37 个法术召唤物（TCE 灵魄系列、死神灵魄）和 8 个同伴（兽伙伴、钢铁守卫、人工生命仆从、野火灵魄等）的护甲、生命值、攻击加值随法术环级、主人职业等级或熟练加值变化，**数据里只有占位**：生命值平均 0 加文字公式，护甲等级 10 加文字「11+法术等级」。
- 51 个攻击的结构化伤害只是某一环的快照，丢了「+ 法术环级」和第二种伤害。

**5. 战斗里要手动的文字**
- 342 个「（充能 5–6）」动作：充能条件只写在动作名里；
- 55 个传奇动作：花费只写在名字里；
- 677 个多重攻击只有文字。

**6. 其他**
- 8 个陷阱没有危险等级；9 个载具/器械（弩炮、火炮…）的攻击只有文字；魔能炮台和三种星界船缺护甲与生命值。
- 经验值阈值表和当日冒险经验表的「等级」列写成「1环」「6th」「19th」（40 处）；126 处怪物施法列表里的法术是没加链接的纯文字名。

### 对得上的（好消息）

- **挑战等级**：1,191 个怪物全部在 0 到 30（含 1/8、1/4、1/2、巢穴和集会挑战等级）；挑战等级到经验值、熟练加值的两张表数值逐项一致。
- **动作**：1,886 个攻击和 946 个豁免的骰式全部能被项目的掷骰器读通；结构里的攻击加值、豁免难度与动作文字 100% 一致；2,460 项结构伤害对照文字只有召唤物那 51 个是快照。攻击加值明显高于「最高属性 + 熟练」的 10 个我逐个看过，都是魔法武器或特殊武器。
- **怪物施法**：408 块、3,299 次法术提及，**没有一处断引用**（更正：我在写 G2.5 计划初稿时统计的「18 处断引用」是把引用里夹的怪物链接也算成了坏引用，这是我的统计错误，已改）；374 个法术豁免难度里 363 个符合 8+熟练+调整值，12 个来自冬灵鬼婆集会等，来源如此。
- **版本标记**：299 个重印旧版的目标全部存在、无环；19 个跨类型的（亚种改种族、魔鬼恩赐并进魔王教派）是合理的重印。
- **规则速查**：PHB 13 个战斗动作和掩护、休息、坠落、窒息、躲藏速查都能找到。
- **经验值与遭遇数字表**：248 项逐表手写期望值对照，数值全对（阈值、倍率、升级经验、当日冒险经验）。

### 方法与限制

- 期望值：怪物图鉴中译文本（解析后）、5e API 的 334 个 SRD 怪物（下载到 `reference/`）、DMG 与 MM 的数字表（手写期望值）、MPMM 英文原文、动作文字与结构的自洽。
- **没有覆盖**：非 MM 怪物（VGM、MTF、MPMM、TCE、BMT 的）的逐项数值没有独立来源，只做了自洽检查；没有 VGM、MTF 原书文本，所以 4–5 个生命骰式没核对；怪物的传奇动作、巢穴动作文字只读了结构。
- 自洽检查（数据自己与自己对）在登记表里标了 `selfCheck`。
