## 4. 冲突与处理

1. **Foundry 半施法者取整**：6.1.x 的 `half` 配置带 `roundUp: true`，会让圣武士/游侠在奇数等级多出法术位，属于 2024 写法。处理：不采用 Foundry 的运行时取整；2014 圣武士/游侠用 5etools 职业表，奇械师按 TCE 自己的表。
2. **5etools foundry 覆盖不足**：2014 职业特性 50 条、子职业特性 192 条，`system` 仅 5 + 63 条。处理：能匹配的导入；其余按 5etools 正文和职业表提取，未映射项进入报告，不假装覆盖。
3. **5etools foundry 书目混杂**：`class/foundry.json` 的 `class` 多数是 XPHB，`foundry-items.json` 多数是 XDMG。处理：所有 foundry 文件先按 D1.1 白名单与 2014 过滤，XPHB/XDMG/XMM/第三方来源一律丢弃。
4. **人类基础加值缺失**：`races.json` 的人类基础条目没有 `ability`，+1 全属性在无名称的隐藏亚种里。处理：转换时把该隐藏亚种的 `ability` 合入基础人类；不把空名称亚种当独立种族导出。
5. **5e-bits/Open5e 许可**：5e-bits 代码 MIT、底层 SRD 为 OGL；Open5e 为修改版 MIT、SRD 为 OGL。两者都只用于公开值对照，不复制文件、不写入 `credit.structured`。
6. **Foundry 6.1.x 的 SRD 内容**：只有 SRD 5.1，非 SRD 部分仍以 5etools 为准；不把 6.1.x 的系统代码或非 SRD 内容搬进包。

## 5. 结论

- 主数据：5etools-cn；结构化覆盖不足的字段用 5etools 职业表/正文 + 少量带页码的配置补齐。
- 交叉校验：5e-bits 2014 API（法术位、资源值）与 Foundry 6.1.x（SRD activities/effects/conditions）。
- 不导入：`dnd-data-main`、`dnddata-master`、XPHB/XDMG/XMM、第三方书、许可不明来源。
- P1 起所有导入项在条目 `credit.structured` 记录来源；P11 报告统计“导入 / 回退 / 未映射”。
